# VA04 视觉精修、动效交付与跨端边界

> visual_downgrade：本章未绑定可审阅的插图、原型帧或动效视频；以下文字、表格与伪代码提供可执行的视觉降级说明，不能替代设计稿、浏览器实测和辅助技术实测。

## 学习目标

完成本章后，学习者能够把一个已可用的界面从“功能完成”推进到“可交付的视觉系统”。

能够建立精修清单，并按影响、风险和验证成本排序。

能够设计进入、状态变化和退出动效，同时为减少动效用户提供等价路径。

能够解释浏览器、字体回退、渲染性能和辅助技术之间的边界。

能够处理多端尺寸、输入方式、语言长度和书写方向的变化。

能够把设计决策交接为工程可消费的令牌、组件状态和验收证据。

## 一、精修不是装饰

精修的对象是用户完成任务时接收到的信号：层级、状态、因果、反馈和信任。

颜色、间距和圆角只有在改善识别、操作和错误恢复时才有价值。

精修前先冻结结构问题清单，避免用阴影掩盖信息架构错误。

任何视觉改动都应回答三个问题：改变了什么判断、减少了什么成本、如何验证。

建议先做“可读性—可操作性—一致性—品牌表达”四轮检查。

每轮只解决同一类问题，避免视觉噪声和回归范围失控。

### 精修清单

- 页面标题是否在首屏建立当前任务和完成条件。
- 主要行动是否只有一个视觉主导入口。
- 次要行动是否保持可见但不争夺焦点。
- 输入框标签是否在失焦后仍能被理解。
- 错误是否靠文字、图标和位置共同表达。
- 禁用状态是否说明原因，而不是只降低对比度。
- 加载状态是否明确作用范围和预计等待行为。
- 成功状态是否告诉用户下一步可做什么。
- 空状态是否提供恢复或探索路径。
- 触控目标是否适合手指和辅助输入。
- 文字与背景的对比度是否满足目标规范。
- 焦点环是否在浅色和深色背景上都可见。
- 表格、卡片和弹层的边界是否稳定。
- 图标是否有可理解的无障碍名称。
- 同一语义是否跨页面使用同一颜色和词语。
- 长标题、长数字和异常状态是否有布局空间。
- 视口缩放后是否仍能完成核心任务。
- 浏览器缩放到两百百分比后，内容是否可读且不被遮挡。
- 高对比度或强制颜色模式下，信息是否仍可区分。
- 断网、慢网和接口失败时，界面是否诚实。

## 二、精修工作流

先记录基线：浏览器、操作系统、视口、缩放比例、字体加载状态和数据样本。

再按任务路径截取关键状态，不能只审查首页静态画面。

为每个缺陷记录触发条件、可见表现、影响、建议修复和验证方式。

优先处理会阻断任务或产生错误信任的缺陷。

其次处理跨组件不一致，再处理品牌与细节层面的微调。

每次修改后重走同一条任务路径，防止局部精修破坏状态连续性。

精修完成需留下前后截图、令牌变更、回归结果和未解决风险。

visual_downgrade：无截图资产时，以状态表代替视觉证据，不能声称已完成像素级验收。

## 三、动效的因果设计

动效应解释界面状态变化的因果关系，而不是延长等待时间。

进入动效回答“对象从哪里来”，退出动效回答“对象去了哪里”。

共享元素过渡适合保持对象身份，淡入淡出适合弱化非核心变化。

位移动效要有稳定的空间参照，避免让用户误判页面位置。

加载动效不能暗示后台已完成尚未完成的工作。

成功动效应短、可中断，并提供文本或结构化状态作为等价信息。

复杂动效必须定义时长、缓动、触发、取消和异常分支。

推荐先用静态状态验证流程，再增加动效，避免动效掩盖交互缺陷。

### 动效规格表

| 项目 | 必填内容 |
|---|---|
| 目的 | 要解释的状态或空间关系 |
| 触发 | 点击、聚焦、加载完成或系统事件 |
| 起始/结束 | 属性、位置、透明度和层级 |
| 时长 | 默认值、快速值和最长上限 |
| 缓动 | 曲线名称及使用理由 |
| 可取消 | 用户如何中断或跳过 |
| 减少动效 | 替代表现与保留信息 |
| 失败处理 | 动画中断、超时或数据失败时的静态状态 |
| 验证 | 浏览器、辅助技术和性能检查 |

## 四、减少动效与辅助技术

尊重操作系统的 `prefers-reduced-motion` 设置，并允许产品内再次关闭非必要动效。

减少动效不等于删除反馈；应保留焦点、进度、成功和错误的可感知信号。

可以把大范围位移替换为短淡入、颜色变化、即时布局更新或无动画切换。

避免使用持续旋转、视差、弹跳和大面积缩放表达普通状态。

动效不能成为获取重要信息的唯一渠道。

屏幕阅读器通常不会朗读视觉动画，应通过状态节点、实时区域或文本反馈提供信息。

焦点移动应与视觉过渡同步，但不能把焦点留在已隐藏元素上。

弹层关闭后，焦点应返回触发控件或明确的替代位置。

### CSS 示例

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    scroll-behavior: auto !important;
    transition-duration: 0.01ms !important;
  }
}
```

该示例只是起点，工程仍需检查由脚本触发的动画、视频和画布。

如果动画承担进度含义，减少动效模式应改为数字进度、阶段文本或稳定的进度条。

## 五、浏览器与字体回退边界

字体在本地、网络、嵌入和系统回退时可能有不同度量，不能只凭设计工具截图锁定高度。

为正文、数字和代码分别定义字体栈，并记录可接受的字宽变化。

使用 `font-display` 时，要权衡首屏可见速度与字体交换造成的布局跳动。

关键按钮和导航不能依赖某个字体恰好占据的宽度。

长文本应通过换行、截断和展开策略处理，而不是强制溢出隐藏。

浏览器对 `line-height: normal` 的计算存在差异，关键组件应设明确行高。

不要把字体文件加载失败误判为用户浏览器故障；界面仍要有可读回退。

字体许可、子集化和本地化字符覆盖要在工程交接中记录。

### 文字回退检查

- 拉丁、中文、阿拉伯文、日文和带组合字符的样本均能显示。
- 粗体、斜体和数字等宽需求有明确替代方案。
- 字体交换前后按钮宽度不会遮挡操作。
- 回退字体的字重映射不会制造假粗体导致模糊。
- 高缩放和系统大字设置下不出现裁切。

## 六、性能与渲染边界

动效性能目标应以用户设备和任务场景为依据，不能只看开发机帧率。

优先动画化 `transform` 和 `opacity`，谨慎触发布局和绘制的大面积属性。

避免在滚动事件中同步执行昂贵测量；使用观察器和节流策略。

图片、字体和阴影都是首屏预算的一部分，视觉质量必须服从可接受的交互响应。

当低端设备掉帧时，提供简化阴影、关闭背景视频和降低粒子数量的策略。

性能优化不能删除必要的焦点、错误和状态反馈。

工程应记录设备、浏览器、网络、帧率、长任务和内存观察结果。

性能数据只代表测试样本，不应直接宣称所有用户体验改善。

## 七、多端与国际化

响应式不是把桌面布局缩小，而是按任务优先级重排信息和操作。

触控端需要更大的目标和更少的悬停依赖，键盘端需要清晰焦点和快捷路径。

移动端软键盘出现时，表单错误和提交按钮仍应可见或可恢复。

折叠屏、横竖屏切换和浏览器地址栏变化会改变可用高度。

国际化必须测试词长膨胀、复数、日期、数字、小数点和货币符号。

阿拉伯文等从右到左语言要求镜像空间关系，但品牌图形和媒体方向不应盲目镜像。

避免把文字拼接成句；使用带变量和复数规则的翻译资源。

翻译缺失时显示可理解的回退状态，不把键名直接暴露给用户。

### 两个方向的实践

**方向一：动效降级。** 给一个带页面转场和骨架屏的工作台，设计正常模式、减少动效模式、慢设备模式三套规格；说明每套仍保留的任务反馈，并列出至少五个验证断言。

**方向二：国际化精修。** 将含中文标题、日期、金额和错误提示的表单扩展到英文、德文和阿拉伯文；分别处理词长、RTL、数字格式和回退字体，交付状态表与截图清单。

## 八、工程交付合同

设计交付应包括令牌表、组件状态、动效规格、断点、字体策略、内容样本和无障碍说明。

每个组件至少交付默认、聚焦、悬停、按下、禁用、加载、错误和成功状态。

动效交付要标出哪些属性由CSS实现，哪些由脚本协调，哪些在减少动效模式下替换。

前端实现需要知道哪些尺寸是约束，哪些只是建议；不确定项必须登记。

设计令牌应使用稳定语义名，例如 `color-surface-warning`，避免只用视觉色名。

交接文档应绑定版本、来源、负责人、验收样本和已知浏览器限制。

不要以“与设计稿一致”作为唯一验收条件，应绑定任务可完成、可感知和可恢复证据。

### 工程验收断言

- 关键路径在目标浏览器完成且无控制台阻断错误。
- 键盘可访问所有操作，焦点顺序与视觉顺序一致。
- 减少动效设置下仍能获取状态和进度。
- 字体加载失败时内容仍可读，布局仍可操作。
- 语言切换后没有截断、溢出或方向错误。
- 低性能设备下核心操作有可接受响应。
- 错误、重试和撤销状态能被视觉和辅助技术感知。

## 九、失败轨迹与修复

失败轨迹一：团队用大幅页面转场掩盖信息架构混乱，用户在返回后找不到焦点。修复是先固定状态和焦点回归，再把转场缩小为共享元素过渡。

失败轨迹二：设计只提供单一字体截图，德文按钮溢出，工程通过缩小字号解决。修复是保留字号层级，改用弹性容器、换行和本地化长度测试。

失败轨迹三：减少动效模式直接隐藏加载指示，用户误以为按钮失效。修复是保留文本进度、禁用期间的状态和可取消操作。

失败轨迹四：阴影和低对比边框在高对比模式中消失，卡片分组失去意义。修复是增加结构、标题和语义关系，颜色只作辅助。

失败轨迹五：前端只测高端设备，低端机滚动掉帧并触发误点击。修复是建立设备矩阵，降低非必要绘制，并在慢设备上复验触控目标。

失败轨迹六：阿拉伯文界面机械镜像图标，导致播放和时间轴方向被误解。修复是区分空间布局镜像与具有约定方向的媒体符号。

## 十、分层练习

### L1 识别练习

从一个登录页列出二十项精修检查，标注每项属于可读性、可操作性、一致性或品牌表达。

为三个动效写出目的、触发和减少动效替代方案。

为同一按钮写出正常、加载、错误和成功的可见文本。

### L2 应用练习

建立一个包含四个断点和三种语言的工作台状态矩阵。

为字体加载失败、接口超时和屏幕阅读器三种情境写恢复路径。

用性能预算约束一个卡片列表的阴影、图片和滚动动效。

### L3 综合练习

选择一个真实任务，交付精修清单、动效规格、减少动效方案、多端状态、国际化样本和工程合同。

附上至少一条失败轨迹，说明原假设、证据、修复和复验。

visual_downgrade：没有真实设计稿或浏览器录屏时，提交状态表和可复现步骤，明确标注证据缺口。

## 十一、参考分析

高质量答案不会只说“加动画、注意适配”，而会把每项视觉决定连接到用户判断和验证证据。

例如，提交按钮加载时，合理分析应说明按钮是否锁定、焦点是否保留、屏幕阅读器如何获知提交中、超时后如何重试，以及减少动效模式如何表达同一状态。

对于字体回退，合理分析应同时讨论字宽、行高、许可、字符覆盖、布局跳动和低网络条件，而不是只列一个字体栈。

对于多端设计，合理分析应说明哪些操作顺序保持不变，哪些布局关系可以重排，以及触控、键盘和读屏如何获得等价能力。

对于性能，合理分析应给出设备与网络样本、测量指标、预算和降级策略，不能把单次开发机测量当普遍结论。

对于国际化，合理分析应覆盖词长、复数、日期数字、RTL、字体回退和翻译缺失，并绑定真实样本。

最终交付的价值在于让设计、工程、测试和辅助技术使用者共享同一套状态定义。

## 自检与边界

本章是视觉精修与交付方法，不构成特定浏览器、字体供应商或辅助技术的兼容承诺。

未运行的代码、未实测的动效、未验证的屏幕阅读器行为必须标记为未验证。

参考分析展示推理方式，不能代替产品经理的范围确认、设计师的视觉稿、工程师的实现和测试工程师的独立验收。
