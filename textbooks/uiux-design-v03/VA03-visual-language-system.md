# VA03 视觉语言系统：从视觉命题到可治理的组件状态

## 本章要解决的工程问题

> visual_downgrade：本节没有可复用的独立图稿。用“命题→Token→组件状态→复验”的文字流程替代；该流程是教学构造，未在真实产品中验证。

“可信、克制、温暖”不能直接交给开发或测试。它必须变成字体、色彩、形状、图标、材质和动效的约束，并且在正常、错误、无结果和结果未知时保持同一套语义。本章以合成的“澄明售后工作台”工单 R-81 为贯穿案例。

R-81 包含客户、退款金额、证据来源、请求状态、当前动作和更新时间。发送后未收到权威回执时，状态是“结果未知”，而不是失败。案例用于练习设计推理；它不代表真实业务、品牌批准、浏览器渲染、可访问性合规或用户理解结果。

本章采用“视觉语言系统”的定义：一组有命名、有层级、有消费边界、能在状态变化中保持语义的设计决策。单张漂亮截图不是系统；只有组件在不同主题、方向和异常状态下仍能表达正确含义，才称为系统。

## 从视觉命题推导不可变约束

> visual_downgrade：无现成独立图。读者应在纸上画四列：受众、任务、证据、不可牺牲语义；绘图动作是教学构造，未验证读者是否能仅靠图理解。

视觉命题先写“为谁、在何时、要辨认什么、哪些语义不能被风格覆盖”。R-81 的命题是“可信的处理秩序”：复核人员能先看到风险与证据，再看到品牌表达。

| 维度 | 本案例约束 | 可观察证据 | 不得推出的结论 |
|---|---|---|---|
| 受众 | 售后主管和复核人员，高频桌面操作 | 姓名、金额、日期在密集列表中仍可定位 | 不推出所有角色都偏好该风格 |
| 任务 | 定位请求、核对来源、决定下一步 | 状态、证据、动作紧邻呈现 | 不推出实际任务时间下降 |
| 渠道 | 桌面、窄屏、深色与高对比模式 | 关键状态不靠颜色单独表达 | 不推出浏览器和读屏已通过 |
| 品牌 | 稳定、清楚、不过度戏剧化 | 装饰层不覆盖风险层 | 不推出品牌部门已批准 |
| 不可变语义 | 错误、无结果、结果未知必须可区分 | 标题、图标、形状、动作和文字冗余 | 不允许主题换色改变状态含义 |

先把命题写成约束，再做方向板。品牌可以要求暖橙标题或纸张质感，但不能让“结果未知”看起来像“退款成功”。品牌层改变允许变化的外观；语义层维护状态名称、动作合同、来源身份和焦点规则。

一个可核对的命题句应包含四部分：`对象 + 情境 + 首要判断 + 不可牺牲语义`。例如：“R-81 的复核人员在高频列表中先判断证据是否可用；未知回执必须与错误和成功分开。”只写“高级感”无法推导 Token，也无法给测试员验收条件。

## 两个可行方向与选择条件

> visual_downgrade：本节没有独立方向板文件。用文字对照表代替图板；两方向均为教学构造，未做真实 A/B 测试。

方向 A“证据工作台”采用高可读无衬线字体、近中性表面、细边界、有限蓝绿强调、小圆角和低频动效。它把视觉差异集中在状态、证据和动作，适合高频比较与审计。

方向 A 的代价是品牌叙事空间小，所有边界都用线条时可能显得机械。补偿方式是只在标题区使用稳定色带或轻材质，不把渐变、阴影和插画引入状态卡。

方向 B“温和叙事工作台”采用较大的标题层级、较松的组间距、暖色纸张质感和圆角容器。它给错误原因和证据说明更多垂直空间，适合需要解释上下文的复核场景。

方向 B 的代价是长列表比较变慢；暖橙可能与危险状态混淆；材质在灰度、深色和低端设备上需要回退。工单从 20 条增至 200 条时，必须提供分组列表或比较视图，不能只继续加长卡片。

| 判断条件 | 方向 A | 方向 B |
|---|---|---|
| 高频比较 | 强：状态差异集中 | 弱：叙事间距增加扫描成本 |
| 长错误说明 | 需增加组件间距 | 强：天然保留解释空间 |
| 品牌叙事 | 低到中 | 中到高 |
| 灰度/高对比风险 | 较低 | 材质与暖色需回退 |
| 迁移成本 | Token 边界清楚 | 需要审查材质和层叠 |

本案例选择方向 A，因为 R-81 的关键动作是快速确认证据与回执，而非沉浸阅读。这个选择会在受众、工单量、渠道或法规约束改变时反转。选择记录必须同时写“为何选”和“什么事实出现后放弃”。

## 六个协同层：字体、颜色、形状、图标、材质、动效

> visual_downgrade：没有现成六层示意图。使用编号清单表达依赖关系；读者可自行画六层同心环，绘图为教学构造，未验证布局效果。

### 1. 字体层：先服务层级，再表达气质

字体 Token 表达功能层级：`font.family.ui`、`font.size.body`、`font.size.title`、`font.weight.emphasis`、`font.line.body` 和 `font.numeric.tabular`。金额、工单号和时间需要稳定数字宽度时，优先核对字体是否真的提供等宽数字特性，不能因 Token 名称包含 `tabular` 就假设浏览器已启用。

中文、拉丁字母和阿拉伯数字可能来自不同字体回退链。登记主字体、回退顺序、缺字行为、版本和许可证。长姓名、RTL 文本、200% 字号和大行距会改变卡片高度，必须以真实渲染核对。字体包的具体许可以随包文件为准；[SIL Open Font License 1.1](https://openfontlicense.org/) 只是规范入口，不是本项目已获许可的证明。

### 2. 色彩层：品牌色与语义色分离

品牌色回答“产品是谁”，语义色回答“当前发生什么”。先定义原始色板，再映射语义 Token：

```text
color.brand.primary    = palette.indigo.700
color.brand.accent     = palette.teal.600
color.semantic.info    = palette.blue.700
color.semantic.success = palette.green.700
color.semantic.warning = palette.amber.800
color.semantic.danger  = palette.red.700
color.semantic.unknown = palette.violet.800
```

这是接口级教学伪代码，不是框架 API，也未在浏览器运行。`semantic.unknown` 不能因品牌不喜欢紫色而删除；可以换成经对比验证的另一组色值，但必须保留“未知”文字、图标和动作。错误、危险和焦点还应由标题、形状、位置和键盘路径表达，颜色不能成为唯一线索。

对比度、焦点可见性和非颜色线索应按 [WCAG 2.2](https://www.w3.org/TR/WCAG22/) 相应成功标准与目标平台复核。本文不宣称任何 Token 自动合规；色值只有在目标字体、字号、背景、渲染器和状态组合中检查后才有证据。

### 3. 形状层：把边界变成语法

形状 Token 不等于“全部圆角”。`shape.radius.sm` 可用于标签，`shape.radius.md` 可用于可操作卡片；危险确认框可以使用更强边界表达阻断，而不是任意增大圆角。边框宽度、虚线、填充和位置要有状态含义，并在组件状态表中登记。

### 4. 图标层：来源、光学盒和冗余线索

图标记录来源、名称、视图盒、线宽、填充规则和光学修正。相同数学尺寸不代表相同视觉重量；警告三角、成功勾、未知问号要在同一基线中校正，并配文字。第三方图标逐个登记许可证、版本和随包许可证文件，不能只写“开源”。

方向性图标尤其要谨慎。向右箭头在 RTL 中可能需要镜像，下载、外部链接和时间线图标不一定能镜像。镜像前先问它表达空间方向还是动作类型，再由本地化和交互合同决定。

### 5. 材质层：只为层级服务并可退化

方向 A 只允许中性表面、单层阴影和一条结构线。阴影表达浮层或分离，不给每张卡制造焦点。渐变、纹理、玻璃效果必须说明它改变的是品牌气质还是状态理解；若在灰度、暗背景或低带宽设备中消失，应有纯色回退。

### 6. 动效层：说明变化，不替代状态

动效 Token 可包括 `motion.duration.short`、`motion.ease.standard` 和 `motion.reduce`。提交后的短进度动画只说明“等待回执”；回执未到时，动画结束不能伪装成功。减少动效设置下仍要保留状态、焦点和顺序变化。

动效要定义触发、停止、重复和中断条件。R-81 的等待动画在收到权威回执、用户停止本地等待或发生本地错误时停止；网络断开不应让无限旋转变成“仍在处理”的暗示。真实时间、性能、辅助技术和平台行为交给工程与 QA 验证，静态稿不能证明动效成立。

## Token 分层与组件合同

> visual_downgrade：无独立 Token 图。使用表格与状态矩阵，明确材料→语义→组件的关系；表格是教学构造，未验证团队协作效率。

Token 至少分三层。基础 Token 描述材料，如原始色值、字体族、间距和半径；语义 Token 描述状态和行为，如 `semantic.danger`、`semantic.unknown`、`focus.visible`；组件 Token 描述消费方式，如 `status-card.border.unknown`、`button.primary.focus-ring`。

组件可以组合语义 Token，但不能在内部硬编码另一套危险色。主题只能覆盖基础层与获准的品牌层；语义 Token 的替换必须经过状态矩阵复验。命名应包含对象和用途，避免 `blue2`、`nice-orange` 这类无法表达责任的名字。

| 层级 | 示例 | 允许租户覆盖 | 失败信号 |
|---|---|---|---|
| 基础 | `palette.indigo.700`、`radius.md` | 通常允许 | 材料被直接当状态 |
| 语义 | `semantic.unknown`、`focus.visible` | 需治理批准 | 状态消失或焦点不可见 |
| 组件 | `status-card.border.unknown` | 仅按组件合同 | 同一状态跨组件不一致 |

状态合同至少写：状态名称、输入事实、可见标题、冗余线索、允许动作、禁止表达、焦点位置、来源标识和恢复条件。R-81 的“结果未知”必须保存 requestId、发送时间和参数摘要；组件不得凭超时就写失败。

## 例外治理、许可与版本记录

> visual_downgrade：没有现成审批流程图。用文字状态机替代，流程为教学构造；未验证真实组织权限与审批时效。

当租户要求品牌橙覆盖危险状态，先分类请求。如果只改变标题装饰，设计师可按语义对比和回退规则提出批准；如果改变危险、未知、焦点或错误表达，产品经理确认语义合同，设计师给替代方案，工程师核实主题边界，QA复验默认屏、灰度、高对比、大字号、窄屏和键盘路径。

例外记录至少包括：请求人和理由、受影响 Token/组件、不可变语义、替代方案、批准责任人、起止版本、失效日期、回退 Token、验证证据和未验证项。没有期限的例外会逐渐变成第二套系统。

来源登记至少区分三类：字体与图标包、参考截图或照片、生成式素材。每条记录作者、网址或文件版本、访问日期、许可证、允许用途、修改方式和归档位置。截图放进 moodboard 不会自动获得商用许可；生成式图像在相似性和许可未核对前只能作为内部候选。

版本迁移时先跑组件状态清单，再逐页检查；“全局换色成功”不是迁移完成。若历史 Token 无法追溯到来源，迁移记录应标记 `source_unknown`，禁止把未知来源包装成已许可资产。

## 四种状态的机制轨迹

> visual_downgrade：无状态板独立图。用同一 R-81 的四条事件轨迹替代；这些轨迹是合成教学构造，未在服务端或浏览器运行。

### 正常：已定位

输入是可匹配的请求标识和可用来源。系统显示“已找到请求”、来源名称、版本日期和“查看证据”。蓝色信息色只作辅助，标题和时间线节点承担主要语义。点击证据后仍回到 R-81 上下文，不生成没有身份的新卡片。

成立条件是来源匹配规则完成且版本日期可读。若来源被截断或版本未知，就不能使用“已核对”徽章；应转为“来源尚未核对”。

### 错误：本地拒绝

输入缺少退款金额时，本地校验拒绝提交。组件显示“无法提交：缺少退款金额”，错误靠近字段，字段获得焦点并保留其他输入。红色边界、警告图标和标题共同表达错误。修复是补齐字段后重新校验，不是盲目重试网络请求。

本地拒绝与远端失败不可合并：前者没有产生远端副作用，后者可能已发送请求。若把两者都叫“提交失败”，恢复动作和审计记录就会错误。

### 无结果：检索完成但没有匹配

页面显示“未找到与 R-81 相符的记录”，说明检索范围与版本，并提供修改条件或查看全部记录。空状态不使用成功勾或“已处理”色彩。无结果只表示当前范围没有匹配，不等于远端不存在该请求。

### 结果未知：发送后没有权威回执

发送动作产生 `requestId`，本地等待超时但没有权威回执。页面保留请求身份、发送时间和参数摘要，显示“结果未知：尚未收到远端回执”，提供“查询状态”“停止本地等待”“转人工核对”。停止本地等待只停止客户端等待，不撤销远端动作。

只有匹配回执或人工核对结果，才能更新为成功或失败。新建 requestId 不能证明是新业务意图；重复提交可能造成重复退款，必须由业务幂等合同处理。

## 失败轨迹：只换皮的系统如何失去语义

> visual_downgrade：无失败对照板。采用“触发→信号→后果→修复→验证”的文字轨迹，教学构造且未做真实用户测试。

失败版本把所有组件改成大圆角、暖橙渐变和玻璃阴影，删除“未知”文字，只留下深浅色块。截图看起来统一，但用户把结果未知读成警告失败；灰度下普通信息和危险状态也无法区分。

触发条件是主题层直接覆盖语义 Token，组件状态表缺少未知行，动效结束没有回执条件。可观察信号包括：状态标题消失、`semantic.unknown` 被删除、所有卡片共享一个 `brand.accent`、错误动作出现“再次发送”而非“查询状态”。

修复顺序是：恢复状态文字和动作合同；分离品牌与语义 Token；为未知、冲突、过期补形状、位置和日期线索；减少装饰层；复查默认、错误、无结果、未知、灰度、大字号和窄屏。若新主题仍混淆危险和未知，应拒绝主题或限制作用域，而不是降低语义要求。

## 分层练习与逐步参考分析

> visual_downgrade：练习不依赖外部图稿。学员可用纸笔画状态矩阵；这是教学构造，未验证练习难度与完成率。

### 基础练习：归类 Token

给定 `blue.700`、`semantic.info`、`button.primary.bg`、`radius.md`、`semantic.unknown`、`font.body`、`status-card.unknown.border`、`neutral.0`、`focus.visible`、`motion.reduce`。将它们归入基础、语义和组件层，并指出两个不能被品牌主题直接覆盖的 Token。

第一步，问 Token 回答的是材料、状态/行为还是组件消费。`blue.700`、`radius.md`、`font.body`、`neutral.0` 属基础层；`semantic.info`、`semantic.unknown`、`focus.visible`、`motion.reduce` 属语义或行为层；`button.primary.bg` 和 `status-card.unknown.border` 属组件层。

第二步，检查覆盖后是否会改变状态含义。`semantic.unknown` 不能被主题删除，`focus.visible` 不能被变成不可见。若团队把 `focus.visible` 归为基础色，仍按消费语义治理，而非只看命名。

### 进阶练习：设计一个不靠颜色的未知状态

要求在灰度、深色和减少动效设置下，R-81 仍能与错误和成功区分。写出标题、图标、形状、位置、动作和来源信息。

参考分析先固定事实：没有权威回执。标题写“结果未知”，使用问号或断开连接图标，边界采用与错误不同的点划线或中性结构，保留发送时间和 requestId，并提供查询状态与人工核对。不能使用红色或成功勾作为主要线索，也不能用无限旋转代替状态。

### 综合练习：品牌紫色与四种来源状态冲突

租户要求所有状态都用品牌紫色，而来源卡要同时表达“已定位、未核对、冲突、过期”。提出两个方向并选择一个，写出例外责任、回退和复验。

方向一保留紫色作为品牌层，用文字、形状、边界、时间标签和图标区分四种来源状态。优点是品牌连续，代价是结构和对比验证更复杂。方向二让语义层使用高对比中性或状态色，紫色只用于标题、选中和装饰。优点是状态清晰，代价是品牌曝光减少。

选择方向一的前提是四种状态在灰度、高对比、大字号和窄屏仍可分辨；任一状态混淆就退回方向二。产品语义负责人批准映射，设计师维护 Token，工程实现主题边界，QA复验状态矩阵。例外必须有版本、失效日期和回退 Token。

### 挑战练习：从失败轨迹反推缺失合同

给出一个截图描述：卡片显示紫色圆点、文字“处理中”，按钮写“再试一次”，没有 requestId 和来源日期。请指出至少四个缺失合同，并按风险排序。

参考分析：第一，状态事实不明，“处理中”可能是等待、未知或失败；第二，缺少请求身份，无法查询或幂等；第三，重试按钮可能重复产生副作用；第四，来源日期缺失，无法判断证据新鲜度；第五，只有颜色和圆点，灰度和读屏下不完整。优先补状态定义、requestId、权威回执动作，再补品牌和装饰。
