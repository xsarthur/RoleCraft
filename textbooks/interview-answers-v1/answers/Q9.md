# Q9 · 从演示原型到可交付的 Agent 服务，需要补齐哪些工程能力？

版本：interview-answers-v1 / Q9-r1。本文为完整参考解析；案例和验证方案除特别注明外均为教学构造，未在本次写作中执行。

演示原型通常证明一条理想输入能产生可看的结果；可交付服务还要证明在允许的输入、权限和故障范围内，结果可核、状态可恢复、失败可解释，且别人能接手运行。补齐的顺序应由业务风险决定，不能先堆所有“高级 Agent”组件。

## 从一条路径查工程缺口

先冻结最小任务和验收，列正常、缺证、无权限、未批准、超时和取消的允许结局。接着按风险落地：

1. **数据与权限边界**：身份来自可信会话，读取前按对象授权；只向模型传必要资料；写前核准确内容与批准。原型中的全局管理员密钥和硬编码资料不能直接带入服务。
2. **候选与真实效果分离**：完整模型响应经结构、事实、引用和业务校验；模型说“完成”只产生候选，外部效果须有可关联回执。
3. **恢复与资源控制**：发送前保存意图、稳定键和尝试；写超时保留未知并核对；等待跨重启；预算、队列和取消有限，错误分类不能一律重试。
4. **观察、回归和交付**：日志关联版本、任务、动作与尝试，脱敏且可追踪；故障/边界回归覆盖原反例；锁定依赖、配置和数据快照，写操作说明、报警、恢复与发布回退办法。

## 一次完整的验收轨迹

教学任务先读 R71，生成带出处草稿，故意修改已批准正文，应被拒绝；恢复原稿重新批准，模拟远端创建成功而回执丢失，再重启工作者，应查得原工单而不创建第二条。另测缺规则时输出缺项、不作确定根因断言。由非作者从干净环境按文档复现这些路径，核对原证据和当前构建版本。

发布先在隔离环境验证，再依事前条件给少量新任务；旧在途任务按原语义继续，不能只换镜像就假设状态兼容。关键失败时停止新领取，保留已接受任务查询和未决效果核对。若数据和调度尚不支持安全在线迁移，可以明确采用停机发布，而不是声称自动无损回滚。

交付结论还须分层：工程检查通过只说明本范围机制；真实用户是否节省时间、内容是否专业正确、成本是否成立仍需要对应证据。未发生真实模型或生产运行，就如实保留待验证项，不能把本地演示、测试数量或文档齐全当成完整产品完成。
