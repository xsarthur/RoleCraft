# Agent 开发者学习路径与阶段产物

这条路线同时训练专业工程判断和从0到1创造产品。先确定真实问题、任务完成条件与风险，再学习可判错的组件，将组件接成固定流程，最后研究需要动态决策的运行时。会写教材例题、能运行教学替身、能处理真实接口、完成独立作品和获得行业比较结论，是不同层次的证据。

本版是教学架构交接。当前原十二模块、二十四目标和四十八知识点保持，新增入口、预备和短导读不改变既有量规与产品门槛。正文和原题的完整映射见[章节规格](/Users/shengxiong/Documents/ChatGPT/一人公司建设/sites/rolecraft/team/textbook-v09-spec.md)与[机器映射](/Users/shengxiong/Documents/ChatGPT/一人公司建设/sites/rolecraft/team/textbook-v09-manifest.json)；实际学习效果需真实学习者及独立评阅。

## 两类读者的入口

零基础读者先看学习入口和问题发现，知道要解决什么，再完成预备课的独立诊断。诊断要求能运行短脚本、识别文本与字典列表、解释函数分支、区分解析失败和业务错误、写断言并定位一次故意失败。缺一项回到预备课的对应小节，不要求先读整份外部API代码。保留输入、实际输出、环境和修改记录；通过这些诊断只支持继续学习。

已有软件与模型基础的读者也先做同一诊断。能提供相同能力证据可以跳过补学，随后沿专业深读学习；只跳过已具备的基础，不跳过真实问题、验收和风险。已有业务作品可作练习输入，但需记录数据权限、版本和实际证据，不能直接继承原作品的行业或职业判断。

## 概要预览

先读学习入口、问题发现、任务验收与信任边界，形成问题档案、任务范围与风险表；随后可预览方案选择和动作身份导读的原则及短轨迹，了解普通程序、单次模型、固定流程和动态Agent的差别。预览不要求实现这些方案，不等于完成选型实验或学习了后置数据库与工具合同。

完整固定交付流程、动态循环、评分器、强制安全与服务经济性属于专业深读。不能为了把它们放在入口，省略实现、减少异常分支或撤销正式先修。

## 专业深读

顺序为：学习入口与基础诊断 → 问题发现 → 任务验收 → 信任边界 → 外部API → 模型候选 → 方案选择 → 动作身份 → 检索证据 → 写工具 → 持久恢复 → 固定端到端流程 → 完整动态循环 → 版本评价 → 完整MVP决策 → 强制安全 → 发布回退 → 性能成本 → 独立交付复盘。

前置选型只解释控制权和复杂度是否必要；写工具之前的身份导读只建立不同ID与调度/效果的语义。工具和存储组件具备后，固定流程才连接候选保存、准确批准、发送、未知核对与完成；动态循环再引入观察驱动的下一步与完整恢复骨架。因此，不再要求先读完整循环才能实现写工具，也不再把固定交付代码塞在选型开篇。

问题发现前置，是为了从真实工作决定研究什么；完整MVP决策在评价之后，是为了让正式方案选择有可检验的比较、护栏和停止条件。MVP章先冻结范围与试验计划，费用或负载的实际结论在性能成本阶段补齐，不能以缺失测量支持经济优势。

## 从0到1实作阶段

| 阶段 | 使用内容 | 必须留下的产物 | 进入下一阶段时检查什么 | 缺口与回退 |
| --- | --- | --- | --- | --- |
| 起点与预备 | 学习入口、基础预备 | 小程序、诊断输入输出、断言失败和环境修改记录 | 是否能解释真实控制路径与失败位置，是否可按步骤复现 | 解释器/路径回预备环境节；类型/JSON/函数/断言回对应练习 |
| 问题与限制 | 问题发现、任务验收、信任边界 | 真实问题档案或明确构造练习、现有替代、价值假设、任务范围、风险表 | 观察与解释是否分开；反例是否保留；成功/等待/未知是否分别定义；授权来自哪里 | 无问题证据回发现；指标不对应任务回验收；数据被当授权回信任 |
| 教学工程可行性 | API、模型候选、选型、身份、检索、工具、恢复、固定流程、动态循环 | 教学夹具下可判错组件、同一任务的固定与动态方案、授权及中断轨迹 | 事实对象与版本一致；候选不冒充完成；写后未知保持原动作；可解释增复杂度的条件 | 引用缺证回检索；身份/重复动作回导读和工具；中断事实丢失回恢复 |
| 评价与真实MVP决定 | 完整评价、MVP决策；反读问题档案 | 冻结比较条件、开发回归与独立保留安排、MVP合同、ADR、协作说明 | 各方案任务和机会是否相同；未知与失败是否保留；现有替代是否可能已经足够 | 比较不公平回评价；主负担与假设不符回发现；范围不能验证假设回MVP |
| 自己的MVP实现与边界 | 早先组件与流程、完整强制安全 | 自己场景的实现、数据/工具授权、四通道投影、准确批准与拒绝正反例 | 真实敏感读取和外部写入前是否已建立强制边界并取得相应授权；正常功能是否也成立 | 关键权限失败先暂停相关真实路径，回信任/安全；保留已发生和未决效果，不伪造无副作用 |
| 交付与真实使用 | 发布回退、完整MVP的反馈安排 | 版本与依赖、兼容配置、维护复现、真实采用与退出反馈 | 非作者能否复现；在途任务是否保持；用户负担与接收者返工是否都记录 | 版本状态不兼容回恢复/发布；采用障碍与目标问题不符回发现/MVP |
| 经济比较与迭代 | 性能成本、评价、反馈安排 | 全任务分母、费用与未知项、延迟负载、质量护栏、原失败与回归复验 | 缓存/模型/并发是否在相同条件下改善；是否转移人工负担或损害质量安全 | 未知账单不填实际数；删失败分母回成本/评价；改进无收益回假设或停止扩范围 |
| 独立作品与迁移 | 交付复盘 | 可复现证据包、真实使用与行业比较边界、非作者未知任务、改进复验 | 独立者能否从版本与原始证据复核结论；职业与先进性是否有相应真实证据 | 只会公开例题回独立未知任务；来源/比较不足补真实证据；失败未复验不关闭 |

“教学工程可行性”阶段使用教材构造夹具和安全替身，使学习者掌握机制；它不证明自己真实产品的问题有价值。完整MVP决定之后，再将同一机制迁移到真实问题。实际外部调用、业务写入、联系参与者和正式发布依实际权限执行，教材作业本身不代替操作授权。

表中检查是既有产物与量规的应用指向，不是新认证门槛。任务正确性、可靠性、安全、评价、运营和沟通仍按原量规评阅；原量规是未由行业专家校准的教学草案。产品八门槛、先进性比较和职业综合交付的标准不因章节调整变更。独立评阅者安排未见材料并保存其证据，公开参考分析只能作开发材料。

## 每次产出的复盘

每阶段记录目标、产物版本、原始证据、在当前范围内的结论、差距、原因、改进行动、责任人、复验方法与实际结果。无证据写未知，有反证写失败；“已改代码”或“已写报告”不能关闭问题。改进须同时重现原失败、正常回归和与能力主张相关的未知条件，旧版本的结论不能直接授予新产物。

评价/安全导读使这些意识在实现前出现，完整评估器与强制边界仍在组件后学习。真人专业评阅、真实学习者迁移、行业可比实验、收费接口与生产运行的证据由相应实际活动产生，不由目录、章节数或离线测试次数替代。
