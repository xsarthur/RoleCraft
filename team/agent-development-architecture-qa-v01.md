## 1. 目的与独立性

新增岗位需要能把用户目标、模型/规则推理、检索、工具、持久状态和评价组成可恢复的 Agent 系统。验收的重点是架构蓝图能否被另一位工程师按冻结版本重建，并且在模型、工具、检索、进程和版本发生故障时保护权限、数据和用户预期。

架构岗位的交付与相邻岗位分开：

| 责任 | 架构蓝图交付 | 不由本验收代替 |
|---|---|---|
| Agent 开发工程师（候选 `AGDEV`，正式 `role_id` 待产品经理冻结） | 运行时边界、编排/状态模型、组件接口、工具权限与副作用分类、降级、观测、评估和回滚设计 | 模型供应商实现、账户/数据库实现、前端页面、教材正文、检索语料编写 |
| AI生成工程师（`AI`） | 模型适配器、结构化生成、调用预算与模型失败实现 | 架构岗位的独立结论 |
| 后端数据工程师（`BE`） | 持久任务、账户权限、迁移与数据恢复实现 | 架构岗位的独立结论 |
| 内容检索工程师（`RETR`） | 版本化索引、召回排序、出处只读接口 | 架构岗位的独立结论 |
| 软件工程师（`FE`） | 客户端状态与接口消费 | 架构岗位的独立结论 |
| 测试工程师（`QA`） | 冻结夹具、独立复现、缺陷和复验记录 | 不补写蓝图、不降低门槛、不自行关闭缺陷 |

本文件中 `AGDEV` 只是便于测试矩阵引用的候选别名。正式蓝图必须声明稳定 `role_id`、责任边界和接收岗位；若最终 ID 不同，需在冻结记录中映射，不能产生第二个岗位或把 `FE`、`AI`、`BE`、`RETR` 的职责合并到新岗。

## 2. 验收输入与冻结要求

执行前由项目经理收齐以下输入并保存版本/哈希；缺任一项，相关检查只能记为 `insufficient_evidence`：

1. 架构蓝图正文、组件图、数据流/信任边界图、时序图和状态机，含版本号、日期、作者、变更说明。
2. 责任与交接矩阵：每个组件、接口、工具、数据表、指标和运行手册的 DRI、接收岗位、权限范围和非目标。
3. 接口合同：请求/响应 JSON Schema 或等价类型定义、错误码、超时/取消语义、相关 ID、版本兼容和未知状态。
4. 工具注册表：工具参数、只读/写入/外部副作用等级、批准条件、租户/资源范围、幂等键、查询/撤销能力和审计字段。
5. 状态与持久化说明：状态枚举、合法迁移、事件/快照格式、重启恢复、并发推进权、重复投递和迁移/回滚策略。
6. 模型与检索模式合同：规则降级、本机离线模型、真实 API 模式（如有）的区别；模型不可用、部分输出、预算耗尽和来源冲突的返回语义。
7. 观测与评估规格：事件字段、相关 ID、日志/指标/追踪保留期与脱敏、质量分母、失败分类、成本/延迟口径、数据集版本和门槛责任人。
8. 发布与回滚包：构建摘要、依赖锁定、配置变更、迁移步骤、旧版本兼容、停止领取/排空/恢复/回滚顺序和演练命令。

测试保存收到版本，不用后续改稿覆盖首份输入。旧教材、旧应用 QA、用户数据库和历史报告不自动成为本蓝图的通过证据。

## 3. 结论枚举与阻断规则

每个验收 ID 使用 `pass`、`pass_with_limitations`、`fail` 或 `insufficient_evidence`。静态图、作者自查、接口文件存在、一次成功演示或测试数量不能单独形成 `pass`。

- **P0**：越权或秘密泄露、未授权外部副作用、数据破坏/不可恢复、伪造成功/来源/回滚、无法停止的循环。未关闭即整体 `fail`。
- **P1**：核心接口不兼容、状态重复推进或丢失、模型不可用时错误承诺、检索错版本/无出处、无法重建决定或无法安全回滚。未关闭不得交付。
- **P2**：可观测字段缺失、边界记录不完整、评估分母/版本不足、文档步骤不可复现但不直接造成副作用。必须有责任人和复验日期。
- **P3**：表达或便利性问题，可排期；不能删除首轮失败记录。

本轮当前结论为 `not_assessed`：下表是待执行方案，不含任何运行哈希、HTTP 收据、故障注入结果、模型调用或生产证据。

## 7. 状态恢复、幂等和进程故障（R）

在临时数据库和确定性工具替身中注入崩溃点，至少覆盖每个事务边界：响应持久化前/后、意图提交前/后、发送前/中/后、结果落账前/后、完成前/后、迁移中和回滚中。

通过条件：重启后不丢失已确认事实；同一模型响应至多生成同一逻辑意图；未决外部效果不被当作无效果；恢复不能绕过当前权限/批准/预算；旧工作者不能继续推进新代次；原失败和重试关系可追溯。

|---|---|---|---|
| `ARC-R-01` | 正常完成后立即重启 | 恢复读取最终状态，不重复调用模型/工具；重复结果事件不重复结算 | `not_assessed` |
| `ARC-R-02` | 响应持久化后、计划提交前崩溃 | 恢复消费同一响应，最多创建同一计划/动作；参数指纹和版本不变 | `not_assessed` |
| `ARC-R-03` | 网络发送前/后崩溃与超时 | 分别保留“未证明发送”和“效果未知”；按原操作 ID 查询/等待，禁止盲目新建 | `not_assessed` |
| `ARC-R-04` | 重复 HTTP、并发 worker、旧租约 | 任务推进权/代次使旧 worker 拒绝；同一逻辑动作的业务效果不重复 | `not_assessed` |

| ID | 变体 | 预期行为 | 当前 |
|---|---|---|---|
| `ARC-M-01` | 无模型配置/密钥 | 返回受控 `unavailable` 或产品约定的只读规则路径；不发外网、不输出秘密、不显示“已生成” | `not_assessed` |
| `ARC-M-02` | 模型超时/5xx/限流 | 有界等待和单一重试责任；给出可见状态、`retryable` 理由和预算消耗；不重复副作用 | `not_assessed` |
| `ARC-M-03` | 部分/格式错误输出 | schema 校验失败即拒绝或进入修复/人工核验；保留原始响应，不把截断内容当完整答案 | `not_assessed` |
| `ARC-M-04` | 模型建议越权工具/提示注入 | 运行时按工具合同拒绝，模型不能改变用户身份、教材版本、批准或系统策略 | `not_assessed` |

## 9. 检索出处和版本绑定（P）

以当前冻结 v12 教材/索引的脱敏副本和已知术语、语义、否定、多意图、无匹配夹具测试；检索工程师提供候选召回与排序细节，Agent 架构岗位负责把出处约束接入运行时合同。

必须断言：

1. 每个推荐目标能回到稳定 `unit_id`/`section_id`、源文件路径、教材版本和源 SHA-256；摘录是该版本原文，不能用相似章节替换。
2. 索引/教材版本失配、源撤回、哈希改变或定位失效时拒绝展示为已核对，进入 `source_mismatch`/`unavailable` 或要求重建索引。
3. 无匹配、歧义、否定、混合意图和职业无关问题分别返回合同规定状态；不得编造章节、答案、引用或“已审核”身份。
4. 模型提议只能作为候选，目标、摘录、版本和小节链接必须由程序只读校验；引用不等于答案质量、学习效果或职业认证。
5. 缓存键绑定用户可读范围、教材/索引版本、查询约束和有效期；返回前再次核权限、撤回和哈希；不能缓存批准或副作用。

|---|---|---|---|
| `ARC-P-01` | 正常命中与定位 | 查询、候选、首选、摘录、源哈希、定位和实际原文逐项比对 | `not_assessed` |
| `ARC-P-02` | 版本/哈希冲突 | 拒绝旧或错源，保留冲突原因；不降级成无依据答案 | `not_assessed` |
| `ARC-P-03` | 无匹配/歧义/多意图/否定 | 各状态和澄清问题准确，结果集不混入无关小节 | `not_assessed` |
| `ARC-P-04` | 缓存和权限变化 | 权限、版本、撤回变化后不返回旧越权内容；失效缓存可解释 | `not_assessed` |

## 10. 观测、评价和运行证据（O/E）

### 10.1 观测可重建决定

每个 run/attempt 的最小事件应包含：`trace_id`、`run_id`、`attempt_id`、用户/租户的不可逆标识、架构/接口/模型/索引/提示/工具版本、输入摘要（不含秘密）、状态迁移、候选来源 ID、批准/幂等引用、预算/耗时、错误分类、重试次数、最终状态和证据链接。日志默认脱敏并可按保留期清理；不能记录原始密钥或不必要的私有正文。

观测夹具检查：正常完成、拒绝、无匹配、模型不可用、工具超时、未知效果、恢复和回滚均能按相关 ID 重建“哪一步做了什么决定、依据哪个版本、谁有权限”。健康检查不能代替业务成功；成功响应不能掩盖来源失配、未知效果或预算超支。

### 10.2 评估有分母且可复现

评估规格至少分别报告：任务完成率（分母含失败/未知）、安全拒绝正确率、出处定位正确率、无匹配/歧义处理、重复业务效果率、恢复成功率、失败/未知率、p50/p95 观察等待与业务完成时长、模型/工具尝试数、确认/未决成本和缓存命中。数据集、判定规则、模型/索引/提示/工具版本和环境必须绑定；不得把样本量、命中率或静态 schema 检查直接推成用户价值、职业胜任或行业先进。

| ID | 检查 | 通过证据 | 当前 |
|---|---|---|---|

## 11. 版本发布与回滚（V）

发布包必须同时绑定应用构建、架构合同、接口 schema、提示/模型配置、检索索引、工具注册表、数据库 schema/迁移、评估集和观测 dashboard 版本。旧运行记录和未决外部效果不能因回滚被删除或重置。

| ID | 场景 | 预期行为 | 当前 |
|---|---|---|---|
| `ARC-V-01` | 预发布合同/配置变更 | 静态兼容检查和隔离回归先于领取新任务；失败停止扩展，不混用旧/新来源 | `not_assessed` |
| `ARC-V-02` | 回滚客户端/运行时 | 新请求路由到旧稳定版本；已有任务按兼容协议继续、暂停核对或安全移交 | `not_assessed` |

## 12. 证据包与执行顺序

QA 执行时使用以下顺序，避免用静态文件替代运行证据：

1. **冻结（G0）**：收齐输入版本、哈希、责任矩阵、环境、夹具和授权；登记旧版本与非目标。
2. **静态（G1）**：完成 `ARC-S-*`，输出组件/边界/状态/版本问题清单。
3. **合同（G2）**：运行 schema、错误、兼容和检索出处 fixtures；完成 `ARC-C-*`、`ARC-P-*`。
4. **权限/故障（G3）**：在无网络、临时数据、工具替身和可控进程中执行 `ARC-T-*`、`ARC-R-*`、`ARC-M-*`。
5. **观测/评价（G4）**：回放 trace，独立重算指标，核脱敏和分母；完成 `ARC-O-*`、`ARC-E-*`。
6. **回滚（G5）**：隔离演练发布、停止领取、排空、恢复和回退；完成 `ARC-V-*`。
7. **复验与报告**：责任岗位修复后按“原例 → 受影响回归 → 一个留出变体”复验；保留首次失败、版本、哈希和未测项。

每个 `EvidenceCard` 至少包含：`acceptance_id`、架构/接口/工具/索引/数据版本与哈希、fixture、环境、命令或 UI 路径、预期状态、原始输出、实际状态、物理请求数/业务效果数（适用时）、缺陷严重级别、修复和复验版本、独立结论、限制和下一步。作者自查与 QA 结论分栏保存。
