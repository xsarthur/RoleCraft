# c01 选型控制权视觉稿交接 v0.1

## 交付物

- `c01-selection-control-map-v01.svg`：1600×1120 静态 SVG，适合教材页面或学习工作台的审阅稿。
- 目标：把“先冻结共同条件 → 判断谁选下一步 → 对照四种方案 → 用共同证据决定升级”变成一张可扫读的图。

## 设计说明

四张方案卡保留原表的四列信息，但把每行改为同一阅读顺序：

1. 方案名称与控制权主体；
2. 同一缺陷任务中的可用实现；
3. 应放弃或升级的条件；
4. 底部标出控制形态，帮助读者形成连续光谱，而不是把“Agent”理解成人数标签。

顶部先放共同条件，避免读者把不同输入、模型、权限或预算下的结果误看成架构优势。底部再放统一记录项，强调尚无实测排名，升级必须依赖同条件证据。

## 文字替代

先冻结任务目标、输入材料、允许资源、预算/时限、停止规则和验收条件。然后判断下一步由谁选择：普通程序由代码选路径；单次模型只在已组好的材料上生成一次候选；固定 workflow 由代码选分支、模型完成指定节点；动态 Agent 由模型提出调查路径，但运行时仍受授权、预算和停止规则约束。若要升级，必须记录各方案的合格结果、正确等待、错误完成、调用次数、用量、延迟和未知结果。材料冲突时应等待输入确认，不用更多模型投票制造业务权威。

## 来源与证据状态

- 内容来源：`sites/rolecraft/textbooks/v12/c01-selection.md`，尤其是“同一任务 四种控制权”“先固定共同任务条件”“怎样做一个公平且能定位原因的比较”。
- 外部定义来源沿用教材链接：Anthropic《Building effective agents》，此图只复述教材中的架构定义，不扩展为当前框架排名或性能基准。
- 状态：`design_draft`；静态 SVG 已生成，未做浏览器排版、窄屏适配、真实学习者理解测试或产品接入验证。
- 图中没有新增教材结论；“控制形态”标签是视觉压缩，不是新的产品门槛。

## 可访问性与实现交接

- SVG 含 `title` 与 `desc`，颜色只辅助分组，关键信息同时使用文字。
- 产品与前端实现时应保留文字替代，并在窄屏将四卡改为纵向或分步查看；具体显示位置、交互方式和路线信息由产品经理与设计师共同确认。
- QA 后续应检查：四方案标签与教材逐项一致、所有升级条件可读、来源和未验证状态可见、窄屏无裁切；真实用户是否理解需单独采集。

## 限制

本稿只表达 c01 的选型关系，不替代完整 workflow、动作身份、多 Agent 交接或评估章节。它没有演示真实运行轨迹、性能数据或产品推荐算法，也不能作为职业能力认证证据。
