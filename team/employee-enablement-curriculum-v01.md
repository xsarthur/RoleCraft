# 员工能力赋能与实训路径 v0.1

日期：2026-10-14（Asia/Shanghai）  
责任岗位：课程架构师  
状态：培养规格草案，待产品经理确认当前项目案例与测试工程师确认评价执行方式  
适用范围：现有十五个岗位；不修改应用、数据库、教材正文、历史报告或八项产品门槛

## 1. 目标与边界

当前员工的主要问题不是缺少岗位名称或提示词，而是缺少从“理解任务”到“独立交付并能在失败后恢复”的连续证据。赋能路径要让每个岗位逐步做到：

1. 能说明自己负责的决定、输入、输出和禁止越界的事项。
2. 能在受控练习中完成本领域工件，并给出版本、来源、未知项和验收条件。
3. 能把工件交给下一岗位，接收对方的拒收、追问和返修意见。
4. 能在陌生变体、异常状态和不完整证据下作出可解释的取舍。
5. 能复盘一次失败，区分说明不足、判断错误、实现缺陷、证据不足和外部条件未满足。

本路径不授职业认证、就业结论或行业先进结论。完成阅读、练习数量、代理会话次数、自评正确率和教材完稿都只能证明接触或局部准备，不能单独证明胜任。真实用户、真人专家、生产运行、市场基线和成本证据仍由相应岗位另行取得。

## 2. 共同能力模型

每个岗位按六个维度、四个层级记录；不以综合平均分掩盖关键维度的缺口。

### 2.1 六个维度

| 维度 | 需要观察的行为 | 最小证据 |
|---|---|---|
| 领域判断 | 能识别本岗的目标、约束、风险和不可替代的专业决定 | 一份带理由、反例和未知项的决定记录 |
| 工件执行 | 能按合同产出本岗交付物，不把草稿、建议和完成混写 | 可重建工件、版本和变更记录 |
| 证据与版本 | 能区分事实、推断、合成夹具、待验证项及来源版本 | 证据台账或来源绑定，含哈希/时间/范围 |
| 交接与边界 | 能写清接收方、输入、状态、验收条件和拒收条件 | 一份被接收或有理由拒收的交接包 |
| 失败与恢复 | 能识别超时、冲突、无匹配、权限不足、效果未知等状态并选择安全路径 | 异常演练轨迹、恢复或升级记录 |
| 复盘与改进 | 能用新证据修正判断，保留旧结论并说明差异 | 复盘表、返修前后对照和复验结果 |

### 2.2 四个层级

| 层级 | 可观察标准 | 允许的工作范围 | 晋级所需证据 |
|---|---|---|---|
| L0 认识 | 能复述岗位边界、主要概念、输入输出和常见风险 | 只能在示例和明确步骤下操作 | 口头/书面边界检查 + 术语反例解释 |
| L1 受指导 | 能按模板完成单一、低风险任务，发现明显缺项并求助 | 合成资料、冻结版本、单岗位任务 | 2 次不同夹具工件均通过领域作者检查；交接包字段齐全 |
| L2 独立交付 | 能从任务契约到交付、复验、返修独立闭环 | 有限真实约束或隔离本地数据；可拒绝不满足的前置条件 | 1 个端到端小项目 + 1 个陌生变体；接收方签收或有证据拒收；失败演练通过 |
| L3 复杂协作 | 能在冲突目标、跨岗位依赖和不完整信息下做取舍并带领交接 | 跨岗项目、多个版本、风险或成本权衡 | 独立项目评审、跨岗返修记录、一次帮助他人复盘；仍不等同真人专家资格 |

判定用“达标/部分达标/未达标/未测”逐维记录。关键风险维度（证据与版本、失败与恢复、交接与边界）为阻断项，不能用其它维度的高分抵销。

## 3. 共同核心课程（全员先修）

课程不是长篇阅读清单，而是“短读本—小练习—受控工件—交接—返修”的单元。每单元必须绑定一个可检查产物。

| 单元 | 核心问题 | 练习产物 | 通过信号 |
|---|---|---|---|
| C0 角色与授权 | 我负责什么，哪些决定必须交给别岗？ | 角色责任图、禁止越界清单 | 能从三个边界反例指出责任人和下一步 |
| C1 任务与验收 | 如何把模糊诉求变成可验证任务？ | 任务契约、成功/失败/未知状态表 | 输入、版本、目标、范围、停止条件齐全 |
| C2 证据与来源 | 什么是事实、推断、合成资料和未验证主张？ | 证据台账、来源绑定、主张—证据矩阵 | 不能支持的句子被标为未知或待核 |
| C3 版本、权限与安全 | 怎样避免串版本、跨租户、越权和隐私泄露？ | 版本/权限检查清单、最小披露包 | 能拒绝错误版本或不满足权限的任务 |
| C4 工件与交接 | 怎样让下一岗位能重建、验收和拒收？ | 交接包、接收确认、拒收及补件记录 | 接收方不需口头补齐关键上下文 |
| C5 失败、恢复与复盘 | 失败时怎样保留事实并安全恢复？ | 失败轨迹、状态机、复盘与返修差异 | 区分失败、未运行、效果未知和最终成功 |

共同核心建议用 2 周完成，但每位员工在 C0–C5 未达到 L1 前不能独立接跨岗生产样式任务。

## 4. 十五岗能力矩阵与实训工件

以下为岗位的 L1–L2 主路径。各岗仍需完成共同核心；表中“陌生变体”是独立能力的最低测试，不是新的产品功能承诺。

| 岗位 | L1 受指导练习 | L2 独立交付工件 | 必测陌生变体与交接对象 |
|---|---|---|---|
| 项目经理 | 将一项请求拆成目标、依赖、责任、状态和复验任务 | 项目任务板、风险/阻塞登记、版本复盘与最终状态报告 | 依赖延迟或失败记录；交给各责任岗并收回证据，不替专业岗验收 |
| 产品经理 | 把用户诉求转为范围、用户流程、门槛和验收条件 | 需求/验收合同、版本差异说明、八门槛证据计划 | 需求冲突、低置信度或无用户证据；交课程、设计、工程和QA |
| 课程架构师 | 将目标拆为先修、知识点、练习和能力证据 | 能力矩阵、课程路线、练习规格、评价量规 | 学员基础差异或课程缺口；交教材研发、内容审校、实训评估 |
| 设计师 | 用视觉稿表达任务、状态、步骤和反馈 | 信息架构、交互/视觉稿、可访问性与响应式交接包 | 无文字或弱视力场景、错误和效果未知状态；交产品与软件工程师 |
| 软件工程师 | 按冻结合同实现一个前端流程并写开发自检 | 可运行客户端、状态/接口消费说明、变更和自检记录 | 接口延迟、无数据、版本不匹配；交QA，不能自行关闭验收缺陷 |
| 测试工程师 | 根据门槛和反例编写测试例并保存证据 | 独立测试报告、复现步骤、缺陷、复验及残余风险 | 题意歧义、异常恢复、用户价值或内容正确性；将缺陷交责任岗 |
| 教材研发员 | 按课程规格解释机制、权衡、案例、反例和练习 | 一篇完整正文、来源/版本绑定、练习参考分析和返修稿 | 读者先修不足、反例推翻原解；交内容审校和课程架构师 |
| AI 生成工程师 | 在隔离夹具中处理提示、结构化输出、失败和来源绑定 | 模型服务契约、生成流程、超时/失败处理、调用证据 | 无配置、预算不足、部分输出或来源冲突；交软件/后端/QA |
| 后端数据工程师 | 实现账户/任务/版本的最小隔离读写 | 数据模型、迁移/恢复方案、权限与持久任务验收包 | 重启恢复、重复请求、旧版本读回；交AI生成/前端/QA |
| 用户研究员 | 设计中立任务和记录模板，区分行为与解释 | 招募/同意材料、研究记录、证据综合和待验证假设 | 方便样本偏差、无法录屏或敏感数据；交产品与实训评估 |
| 竞品研究员 | 在冻结可比条件下记录公开样本和版本 | 可比矩阵、来源、实测/未测边界、差异假设 | 样本不可比、营销声明缺实测；交产品和课程架构师 |
| 实训评估员 | 用量规给合成作品指出证据和缺口 | 作品评估、陌生任务观察、评分理由、一致性记录 | 学员只会复述教材但不会迁移；交课程与产品，不能替学员完成 |
| 运营分析员 | 区分估算、实测、账单、工时和质量分母 | 成本/延迟/质量表、预算情景、对账差异 | 价格/用量缺失、失败调用、维护成本；交产品与工程/QA |
| 内容审校员 | 独立核论断、机制、来源、案例边界 | 审校报告、问题分级、返修复核和真人专家待核项 | 作者答辩或新版本改动；交教材研发和课程架构，不改正文代写 |
| 内容检索工程师 | 构建版本化索引、词法/语义候选和来源校验 | 索引构建、排序/过滤说明、引用定位、只读接口证据 | 术语歧义、否定、多意图、无匹配；交前端/QA，不能编教材答案 |

L2 工件必须包含：任务 ID、输入版本、允许资源、输出主张、逐项证据、缺项与未知、实际消耗、状态、接收方、验收结果。工件只在隔离数据和授权范围内使用；任何真实外部调用、发布或付费动作另行授权。

## 5. 学习—练习—项目—复盘闭环

每个岗位至少完成三轮闭环，难度逐轮提升：

### 第一轮：可复算基础（L0→L1）

使用固定合成夹具和冻结版本。学习者先写任务契约，再完成一个小工件，按同一清单自查，交给相邻岗位做接收/拒收。重点不是速度，而是边界、证据和可重建性。

### 第二轮：受限端到端（L1→L2）

由项目经理给出一个真实形状但隔离的数据包，例如“学习工作台内容检索迭代”。产品、课程、设计、检索、前后端、AI生成和QA按合同接力；研究、竞品、运营和实训岗提供证据包。每岗只有一个写入所有者，异常状态必须保留原记录。

### 第三轮：陌生任务与失败演练（L2→L3）

移除步骤模板，改变一个关键条件：版本冲突、无匹配、模型不可用、权限不足、预算减半、用户目标含糊、交接方拒收或效果未知。学习者须先保护用户/数据，再说明能做什么、不能做什么、何时升级；随后由独立评审员复核，不由作者自审。

### 每轮固定复盘格式

1. 目标与门槛：当时要决定什么，成功、失败和未知如何定义。
2. 轨迹：按时间列出输入、判断、工件、交接、异常和实际结果。
3. 首次偏差：最先发生的错误是理解、证据、合同、实现还是外部条件？
4. 修复：谁负责改动，改动版本是什么，哪些旧结论仍有效？
5. 复验：同条件回归、受影响范围、陌生变体和未测项。
6. 下一步：明确责任人、截止条件和阻塞，不用“已复盘”关闭缺陷。

## 6. 十二周推进建议

| 周次 | 集体重点 | 个人交付 | 退出条件 |
|---|---|---|---|
| 0 | 基线诊断 | 角色边界、证据读写、失败识别诊断 | 每人有 L0 基线和补学项；不以分数做职业结论 |
| 1–2 | C0–C5 共同核心 | 6 个小工件、一次拒收/补件 | 全员达到 L1 前置；关键安全维度未达标者补练 |
| 3–4 | 岗位专长练习 | 岗位表中的 L1 工件各 2 份 | 相邻岗位接收一次；内容/工程/QA等需独立检查 |
| 5–7 | 受限端到端项目 | 版本化交接链、项目记录、异常轨迹 | 每个角色形成可追溯交付，缺陷回到责任岗返修 |
| 8 | 跨岗接口周 | 至少两次反向交接（接收方提出变更） | 交接双方对输入、版本、状态、验收签收一致 |
| 9 | 故障与成本演练 | 无匹配、超时、权限、版本冲突、预算变化五选三 | 有安全停止、升级、恢复或明确未恢复证据 |
| 10 | 陌生任务 | 不给步骤模板的个人任务 | 实训评估员按量规观察，不能查同题答案代做 |
| 11 | 返修与复验 | 返修稿、差异、回归和残余风险 | 原问题关闭与仍未验证项分开记录 |
| 12 | 能力复盘与下一周期 | 个人证据包、岗位负责人评语、补学计划 | 做“可独立接单/需指导/暂不接单”决定，不颁泛化认证 |

周期可按岗位拆成小组并行，但同一交付物只能有一个写入责任人；项目经理只协调依赖和状态，不代写专业产物或独立验收。

## 7. 交接训练合同

所有跨岗位练习都使用同一交接包，避免“说过了”成为隐性依赖：

```text
handoff_id / task_id
发送岗位 / 接收岗位 / 唯一写入所有者
目标与不做范围
输入资料、来源、版本、哈希与允许资源
当前状态（含失败、未知、未运行）
输出工件与每项主张的证据
验收条件、拒收条件、风险与待核问题
实际消耗（时间、调用、成本；未测则写未测）
接收确认或拒收理由
返修版本、复验方法与残余缺口
```

建议安排下列接口实验：

- 产品经理→课程架构师/设计师：同一需求分别写学习目标和可操作界面，不得偷偷扩大范围。
- 课程架构师→教材研发员/实训评估员：把能力目标转成正文、练习和评分证据；评估员可拒绝无法观察的标准。
- 设计师→软件工程师：交状态、焦点、错误、响应式和无障碍证据；工程师反馈可行性但不改产品目标。
- AI生成工程师/检索工程师→后端数据/软件工程师：交模型、来源、版本、错误和只读接口合同；不得把候选答案当已核实内容。
- 后端数据/软件工程师→测试工程师：交可运行版本、配置、隔离数据和已知限制；测试员独立复现和报缺陷。
- 用户研究员/竞品研究员/运营分析员→产品经理：只交证据、比较条件、估算或实测边界，不替产品作范围决定。
- 实训评估员/内容审校员→课程架构师/教材研发员：交缺口、反例和复验请求，不代作者补写或自审闭环。
- 测试工程师→项目经理/责任岗：报告结果、复现和残余风险；项目经理分派返修，责任岗修复后再由测试复验。

交接练习至少包含一次“接收方拒收”与一次“发送方补件”，让员工练会停止、追问和留下证据。

## 8. 证据包与独立评价

每位员工的能力档案由项目经理维护索引，专业内容由对应岗位产生，独立评价由测试工程师或实训评估员执行。档案最小字段：岗位、层级、任务版本、工件链接、观察者、反例、结论、未测项、返修状态、下一任务。员工可申诉评价，但不得删除原始失败记录。

评价分三层：

1. **形成性检查**：作者或教练指出缺项，只用于继续练习。
2. **独立交付检查**：相邻责任岗按交接合同确认是否可接收；不能证明职业能力的泛化结论。
3. **陌生任务评估**：实训评估员观察过程和作品，测试工程师核版本/运行/反例，内容审校员核技术论证；三者均可给出“未测”。

“教材已读”“模板已填”“旧题答对”“代理执行成功”不替代第三层证据。若岗位是内容审校或测试岗位，也必须由别的相应专业人员核其产物，防止自审。

## 9. 复盘门槛与下一步

首次落地应由项目经理选择一个隔离教学项目，邀请产品经理冻结目标与验收，课程架构师维护本路径，测试工程师确认观测方式。第一周期只判断“能力是否获得可观察证据”，不宣称十五岗已经胜任。每轮结束需报告：已完成的岗位层级、实际证据、未通过项、原因、责任人、返修和复验日期，以及八项产品门槛中哪些仍为 `insufficient` 或 `not_met`。

本规格下一步需要三项输入：

- 产品经理确认首个教学项目的用户目标、范围和八门槛映射；
- 各专业岗位给出一项真实形状但可隔离的陌生任务与不应越过的授权边界；
