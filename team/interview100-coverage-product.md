# 100道 Agent 面试题：教材可解答性产品判定口径

日期：2026-10-11。责任：产品经理。范围：本次聊天所列固定100题与v10独立教材；本文件不提供逐题审计结论、不修改教材或应用、不增加或改变原八门槛。

## 目标与输入

用户问“仅这100道题，有多少能通过我们的教材解答？如果不能解答又怎么能够帮助我们的用户成功入行”。本轮先测量教材对这100题的回答支持程度，并据现有产品标准说明入行支持与效果证据的缺口。100题的市场代表性、企业真题身份或统计热度并未由本轮确认，因此覆盖率只能外推到这个固定题集。

输入为本次聊天100题、`textbooks/v10/README.md`及其20篇正文、`team/product-gates.json`。正文充分性由课程领域作映射、由独立QA检查，不由产品岗自行替代审计。

## 冻结分类规则

逐题以完整问法评估，不拆成若干子问后扩大总题数。100为固定分母。

| 分类 | 判定条件 |
| --- | --- |
| 充分支持 | 仅凭v10正文，能组织出覆盖本题全部实质子问的回答；回答所需机制、取舍、实现或验证方法有具体正文依据，技术专有题须含其专属概念。必须提供篇目、段落或行号定位。 |
| 部分支持 | 正文能支持一个或多个实质子问，但关键机制、方案对比、具体框架/协议契约、操作方法或必要证据缺失，须靠外部学习或实践补足。 |
| 未覆盖 | 没有可建立实质回答的正文内容；只有术语、链接、目录或泛化原则也属未覆盖。 |

补充执行约束：

- 只计算正文已经教到的内容，不以“有这个章节标题”证明覆盖，不因评审者懂相关知识而补写教材没有的桥接论证。
- 外链全文、项目应用代码、检索服务、历史审计、其他教材版本均不能补分。正文内实际解释可以计入；只指向外部材料不计充分。
- 通用状态机、重试或权限原则不能自动覆盖LangGraph、MCP、A2A的专属对象、契约与语义。
- Q10、Q99等要求“真实项目/实际故障”的题目，即使教材完整教授陈述和取证方法，也不能替用户生成个人经历；仅凭教材最多部分支持，另记“方法支持”和“真实个人证据缺失”。不能为了提高充分率将原题改成假设案例。
- 题目若同时要求定义、差异和选择依据，缺任何决定性子问则部分；允许跨章组合，但每个必要连接须由正文支持。
- 当前版本敏感的协议或框架题，如正文未注明可核实版本，不推定其足以回答当前版本行为。
- “充分支持”只表示可建立回答，不证明读者已经学会、答对、能现场操作或能拿到录用。

结果必须分别报告：充分数量/100、部分数量/100、未覆盖数量/100。充分+部分只能称“有一定支持”，不能称“能解答率”。三类总和必须为100；计数应由逐题表生成。争议题按较保守类别暂记并显式保留原因，独立复核后再更新。

## 对入行承诺的产品判断

教材是入行支持的一部分，不能把教材完成、面试题覆盖或本地工程自检当成入行成功。若关键知识只能答一部分，当前资料便不足以独立完成这份题集的准备；这属于教学覆盖缺口，应明确承认，不能用“面试不重要”规避。即使100题全部可回答，也仍需真实编程、调试、项目解释、陌生任务迁移和用人方评价，不能推出就业效果。

目前原八门槛未因本轮变化。`teaching_quality`要求能力—章节—练习—作品关联、示例验证及专业复核；`learner_creation`要求真实学习者MVP、运行测试、目标用户验证和独立作品评审；`user_value`要求预定义指标及真实用户验证。文稿覆盖检查不能单独关闭其中任何一项，也不改变已记录的整体`not_met`状态。不得新造一个“达到若干题就能入行”的阈值或录用率。

## 缺口改进行动与唯一领域责任

本轮只交评估，以下是待据逐题审计排优先级的交接，不代表已完成补写或实践。

| 责任岗位 | 下一步产物 | 复验方法 |
| --- | --- | --- |
| 产品经理 | 明确目标岗位、经验级别、使用场景与准备范围；把逐题缺口关联现有培养目标 | 检查范围、门槛和证据类型没有被覆盖率偷换；不虚设录用阈值 |
| 课程架构师 | 基于逐题缺口维护能力—章节—练习—作品映射，区分核心机制与版本化生态内容 | 检查实质子问有对应学习目标及可评价产物 |
| 教材研发员 | 按批准规格补充不足内容、实现例和练习 | 内容审校逐论断独立核验，不以作者自评关闭 |
| 内容审校员 | 核对概念、框架版本、协议契约及技术深度 | 逐题重新判定正文是否独立足以作答并列残余限制 |
| 测试工程师 | 复核固定100题分类及新增示例实际行为 | 原缺题、边界与失败例复验；只报告实际运行范围 |
| 实训评估员 | 按既定量规评价真实学习者独立实现、故障诊断、陌生任务及项目陈述 | 保存真实作品和评价记录，禁止AI模拟学员替代 |
| 用户研究员 | 收集目标学习者的学习困难、准备过程及实际求职反馈 | 区分自述、已核事实与因果未知，不伪造访谈或招聘结果 |
| 竞品研究员 | 校验目标岗位需求、公开题型及同条件课程/产品基线 | 记录来源日期、岗位层级、比较场景与未知项 |
| 项目经理 | 登记缺口、安排依赖与独立复验，向用户报告改进是否完成 | 新稿和新评估逐轮绑定版本，不继承旧结论 |
