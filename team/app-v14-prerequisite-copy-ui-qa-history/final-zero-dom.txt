    - heading "认识 Agent 工程" [level=1]
    - paragraph: Agent 是一种围绕目标、依据新观察选择下一步，并通过工具与环境交互的软件系统。本书讨论基于大语言模型的 Agent：模型解释当前信息，提出下一步调查或候选结果；运行 Agent 的应用程序（下文称宿主程序）限定允许范围，决定能否执行，记录实际观察，再根据完成条件继续、等待或结束。它的价值来自把语言理解接到可核对的任务过程。
    - paragraph: 例如，排查一次构建失败时，先读到的日志可能决定下一步该看依赖配置还是某个调用者；第一轮材料不足以写出整条路径。Agent 可以帮助选择下一处调查对象，但读取权限、调查预算和结果核对仍由应用掌握。模型提出“创建工单”，只是一项提议；准确批准和确认工单存在分别需要自己的依据。
    - paragraph:
      - text: “Agent”在不同产品中有不同用法。本书采用控制路径的区分：固定工作流由代码预列步骤与合法分支，动态 Agent 让模型根据新观察提议业务路径。这与 Anthropic 的架构定义一致；本文进一步采用宿主准入与事实记录的工程约束。这里仅以该文支持概念区分与最小足够方案原则。

    - paragraph: 多 Agent 是可选的组织方式。可独立调查的子问题可能适合分工，但要加总预算、统一资料版本、处理交接失败，并保留唯一写入所有者。把一项任务交给多个模型，不会自动产生独立事实或更高正确率。只读任务也无需为配齐组件而增加写工具；短时、可重做的任务未必需要长期持久平台。
