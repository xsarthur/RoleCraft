# 精选面试题、通用流程与按范围组卷：课程架构交接

版本：`interview-general-training-v03-curriculum`  
日期：2026-10-16（Asia/Shanghai）  
责任岗位：课程架构师  
交接对象：产品经理、教材研发员、内容审校员、内容检索工程师、软件工程师、AI 生成工程师、后端数据工程师、测试工程师、实训评估员

## 1. 本轮要解决的问题

面试准备需要三种不同的训练入口：

1. **精选面试题**：给用户一组经过题目身份、岗位、题型和来源核对的代表性题目，用户可以直接回答、录音、查看追问和回到教材；
2. **通用面试流程**：训练自我介绍、理解与澄清、结构化回答、处理追问、向面试方提问、结束与复盘等跨题能力；
3. **按范围组卷**：用户先指定教材范围、题型、难度、数量或时间，再从已发布题目中组成一次可复现的练习卷。

三者的学习目的不同，不能用一个“全部题目”页面或一套总分混在一起：精选题解决“先练哪些代表性问题”，通用流程解决“如何进行面试对话”，按范围组卷解决“围绕我选择的边界做一次有记录的集中练习”。组卷结果是训练材料，不是招聘方正式试卷、能力认证或录用预测。

本文件只交付课程范围、题型组合建议和文章/题目/试卷的来源绑定边界，不修改教材正文、题库内容、应用代码、账户数据或历史报告。示例比例是训练建议，产品与实训评估岗位仍需按目标岗位、用户时间和真实证据调整；不得把比例当作行业统一标准。

## 2. 三种入口的共同学习原则

每次训练至少保留以下身份：

| 身份 | 必须回答的问题 | 不能被替代的证据 |
| --- | --- | --- |
| 文章 | 这篇材料解释哪个通用流程或领域机制？适用于什么条件？ | 当前正文、来源状态、版本和文章审校状态 |
| 面试题 | 用户要回答什么？需要哪些内容、事实或推理证据？ | 题目 ID/版本、题型、量规、来源映射和追问 |
| 试卷 | 为什么选择这些题？题目顺序、范围和组合能否重建？ | 题目快照、选择规则、随机种子（如有）、组卷时间和版本 |
| 用户回答 | 用户实际说了什么，哪些是事实、假设、未知或团队成果？ | 原始转写/文字、用户修订、时间和自评 |
| AI反馈 | 哪些观察来自转写或绑定来源，哪些仍未知？ | 观察证据、来源指针、不确定性和分析模式 |

课程完成、精选题做完、试卷得分或 AI 反馈条数都不能自动推导职业胜任、录用概率、真人专家认可或真实学习效果。陌生题、真实项目和专业评阅需要由实训评估员、用户研究员及相应领域专家另行提供证据。

## 3. 内容范围总表

### 3.1 通用面试流程专项训练（跨职业）

通用流程沿用 `interview-general-flow-curriculum-v0.1` 与 `interview-general-training-v02-curriculum` 的六阶段结构。正式文章目录可继续使用 GFT-01 至 GFT-10，但本轮需把它们作为一个独立内容集合，而不是精选题的前置长说明。

| 能力域 | 正式训练内容 | 最小练习产物 | 不应承诺 |
| --- | --- | --- | --- |
| 面试地图与目标 | 开场、澄清、回答、追问、反问、收尾各自要完成的信息交换 | 能标出一段对话的环节和证据缺口 | 任何公司都按此顺序进行 |
| 自我介绍 | 当前定位、相关事实、岗位连接、深入入口；30/60/90 秒压缩与展开 | 三个时长版本、事实清单、一次追问重答 | “万能自我介绍”或必然加分话术 |
| 理解与澄清 | 复述目标、识别会改变决策的未知、优先提问、声明假设 | 一个信息充分题、一个缺信息题、一个含糊题 | 提问越多越专业 |
| 结构化回答 | 概念、技术设计、项目/行为、排障题的不同骨架 | 题型判断、结构选择理由和一段回答 | 一个模板覆盖所有题型 |
| 追问与不确定性 | 证据追问、约束变化、反例、无精确事实时的诚实表达 | 原答、追问、修正版及未知记录 | 用猜测填补缺失事实 |
| 向面试方提问 | 成功标准、当前挑战、协作、质量、反馈和流程；按对方身份筛选 | 8 个问题池、每轮选择 2–4 个并说明原因 | 某问题必然改变录用结果 |
| 结束与复盘 | 回扣相关点、确认后续、记录可观察缺口、安排重练与迁移 | 30 秒收尾、三条事实/一条未知/一条动作 | 复盘完成即代表面试通过 |

通用流程文章可以链接到题目练习，但不应被当作题目答案的技术来源。文章中的“示例回答”必须标记为教学构造；用户没有提供经历时，只能提供事实填写框、假设练习和核对问题。

### 3.2 精选面试题

精选题是课程架构和产品岗位共同维护的稳定入口，重点是“代表性、可解释的覆盖和可练习性”，不是根据没有证据的热度排序。每一题必须属于当前职业、当前题库版本和一个明确题型，且至少绑定一个教材小节，或明确标注为已批准的通用流程建议。只有待核来源的候选题不能进入正式精选集。

Agent 开发者样例建议覆盖下列题型；其他职业应由产品经理和课程架构师重新确认，不直接复制比例：

| 题型 | 训练目的 | Agent 样例范围 |
| --- | --- | --- |
| 基础概念 | 判断能否定义对象、说明边界并给出小例子 | Agent、工具调用、上下文、记忆、RAG、规划 |
| 技术设计 | 判断能否从目标/约束推导组件、状态、权限、失败和验证 | 可靠性、评估、安全、权限、成本、幂等、恢复 |
| 项目表达 | 判断能否说明真实问题、本人贡献、方案取舍、验证和结果 | 项目背景、失败经验、证据与迭代 |
| 场景追问 | 判断能否在故障、资料过期、任务中断或不可信输出下保持边界 | 工具失败、数据过期、恢复、人工升级 |
| 通用表达 | 判断能否进行自我介绍、澄清、反问和收尾 | 从通用流程文章派生练习，不替代领域题 |

精选题集合至少需要有一条“通用表达”到通用流程文章的练习链接，但精选题答案仍保留题目自己的 `questionId`、`questionVersion` 和量规。通用流程文章不得通过链接自动成为领域技术答案。

### 3.3 按范围组卷

组卷允许用户从已发布范围中选择：

- 职业与教材/题库版本；
- 一个或多个单元、小节或知识点；
- 题型（基础概念、技术设计、项目表达、场景追问、通用表达）；
- 难度（基础、中等、进阶）；
- 题量或总练习时间；
- 是否包含追问、语音回答或文字回答。

组卷不允许用户把一篇未审校文章、一个自然语言关键词或一段模型生成内容直接当作正式题源。若范围只有文章而没有已发布题目，系统应显示“当前范围无可组卷题目”，提供阅读或申请扩充的入口，不生成看似正式的题目。

组卷结果应保存：范围快照、筛选条件、入选题目的 ID/版本、顺序、选择原因、题型与难度、组卷时间、随机种子（如使用随机排序）和未满足的条件。用户修改范围后，应创建新试卷版本，不能覆盖旧试卷的题目身份或回答记录。

## 4. 试卷题型组合建议

以下是课程训练组合，用来帮助产品提供快捷选项。它们不是任何公司的考试标准，也不用于计算录用分数。若筛选范围内没有某一题型，系统应保留缺口并解释原因，不用重复其他题型冒充覆盖。

### 4.1 快速口述练习（约 10–15 分钟）

适合第一次进入面试准备或时间很短的用户：

1. 自我介绍或通用流程题 1 题；
2. 基础概念 1 题；
3. 技术设计或场景追问 1 题；
4. 一个固定追问或用户自选追问。

目标是完成一次“开场—回答—追问—复盘”，不是覆盖全部知识点。若用户选择完全技术范围，系统可以说明通用流程题未加入，并保留独立专项入口。

### 4.2 标准练习卷（约 25–35 分钟）

建议 6 题左右，顺序先易后难或按用户选择：

- 通用流程：1 题（自我介绍、澄清、反问或收尾四选一）；
- 基础概念：2 题，尽量来自不同小节；
- 技术设计：1–2 题，至少有一题要求取舍或失败处理；
- 项目表达：1 题，必须允许用户标记“真实经历/学习项目/假设”；
- 场景追问：1 题，要求在条件变化后重答。

如果总时长不足，按题目预计耗时裁剪，不通过减少用户思考时间制造“完成”。每道题的预计耗时只是计划依据，不能当作表现评分。

### 4.3 综合模拟卷（约 45–60 分钟）

建议 8–10 题，覆盖一次完整口头流程：

1. 自我介绍 1 题；
2. 澄清 1 题；
3. 基础概念 2 题；
4. 技术设计 2 题（至少一题包含权限、可靠性、成本或评估中的真实约束）；
5. 项目/行为 1–2 题；
6. 场景追问 1–2 题；
7. 向面试方提问或结束复盘 1 题，可与其他题合并为同一流程任务但要单独记录。

综合卷的顺序不应使用户误解为真实公司流程。页面要明确这是教学模拟，面试方身份、时间和追问均为本次训练设定。

### 4.4 按范围自定义卷

自定义卷优先遵守用户明确选择的范围，不强行补齐快捷组合。例如用户只选“RAG 与检索”时，可以组成“基础概念 + 技术设计 + 场景追问”，并显示通用流程未覆盖；用户只选“项目表达”时，重点放在项目/行为变体和追问，不能因题型比例不足而偷偷加入无关技术题。

组卷器应显示三类计数：

- **可用题目**：满足职业、版本、范围、题型和发布状态的题目；
- **选中题目**：实际进入本卷的题目；
- **缺口**：用户选择但当前没有可用题目的题型/小节/难度。

缺口是课程和题库建设信号，不应被静默填平。重复题目只有在用户明确允许复习重复，或题目版本/追问不同且关系已标记时才可出现。

## 5. 文章、题目与试卷的来源绑定边界

### 5.1 文章来源身份

文章必须保存并在详情页显示以下之一：

| `sourceStatus` | 含义 | 可用于精选题/组卷吗？ |
| --- | --- | --- |
| `textbook_bound` | 已绑定当前版本教材的具体单元/小节，引用范围可定位 | 可作为学习来源；不能自动成为题目答案，需题目映射 |
| `general_guidance` | 课程架构批准的通用流程建议，尚未绑定某职业教材 | 可作为通用流程学习和练习来源；不能证明技术事实或行业标准 |
| `external_reference` | 已登记的公开可靠资料，版本/查询日期/主张范围明确 | 可支持明确主张；需内容审校，不能用链接存在代替审校 |
| `user_provided_fact` | 用户提供的简历、项目或岗位信息 | 只能作为该用户的练习上下文；不可进入公共题库或教材索引 |
| `unverified` | 来源、版本、适用条件或内容身份尚未核对 | 不得显示为正式答案依据或组卷来源 |

`contentStatus` 另行记录 `curriculum_spec`、`draft_unreviewed`、`content_reviewed`、`qa_verified`；来源身份和生产/测试状态不得混用。例如 `general_guidance + content_reviewed` 仍是通用建议，不会自动变成教材事实；`textbook_bound + draft_unreviewed` 也不能显示为已审校内容。

### 5.2 面试题来源身份

每道题保留自己的题目身份，不因改写或组卷改变原题 ID：

| `questionSourceType` | 适用说明 | 绑定要求 |
| --- | --- | --- |
| `curated_original` | 团队按课程规格编写并纳入精选集的题目 | 题面、题型、难度、量规、版本和至少一个来源映射齐全 |
| `textbook_derived` | 根据当前教材某小节派生的练习题 | 记录教材版本/小节、派生关系、作者和独立审校状态；不把题面当教材原文 |
| `market_sample` | 公开岗位/面试样本，用于研究或经许可改写 | 保留原样本身份、来源和改写关系；未经许可不可复制受限内容 |
| `user_variant` | 针对用户提供岗位或项目生成的私有变体 | 仅存在于用户练习空间，不进入公共精选集或公共索引 |
| `generated_unreviewed` | 模型或规则生成但尚未独立审校的候选题 | 只能作为草稿/候选，不得进入正式精选集或正式组卷 |

题目可以链接多篇文章，但每个链接要标明关系：`explains_concept`（解释概念）、`supports_structure`（提供通用回答结构）、`gives_example`（教学示例）、`provides_boundary`（提供边界/失败）或 `practice_followup`（练习后续）。文章链接不等于题目答案已经被文章证明；内容审校员仍需逐题检查题面、参考回答、追问和来源范围。

### 5.3 试卷来源与可复现性

试卷是派生集合，不能把试卷标题或推荐标签当作新来源。试卷至少保存：

```json
{
  "paperId": "paper-…",
  "paperVersion": "…",
  "careerId": "agent-developer",
  "contentVersion": "textbook-v12",
  "questionBankVersion": "…",
  "scope": {"unitIds": [], "sectionIds": [], "knowledgePointIds": []},
  "filters": {"types": [], "difficulties": [], "count": 0, "timeLimitMin": null},
  "items": [{"questionId": "…", "questionVersion": "…", "position": 1}],
  "selectionRule": "curated|range_filter|seeded_random|manual",
  "randomSeed": null,
  "sourceRefs": [],
  "gaps": [],
  "createdAt": "…"
}
```

`seeded_random` 只能在候选集合和排序规则固定时使用；随机种子不是来源，也不能替代题目版本。题库、教材或文章更新后，旧试卷继续保留收到时的版本快照；新建试卷才读取新版本。若某题被下线或来源失配，旧回答记录不能静默改绑新题，应显示失效状态并提供人工处理/重新组卷。

## 6. 训练与来源的负面边界

以下行为不允许：

- 用文章数量、精选题完成数或一次试卷得分生成“面试通过概率”；
- 用没有真实频次或来源的题目显示“高频”“热门”“必考”；
- 把通用流程建议写成某家公司真实流程、招聘规则或行业统一标准；
- 从用户简历、录音或私有项目生成公共题目、公共教材摘录或他人可见索引；
- 用模型自动生成但未审校的题目、答案或追问进入精选集/正式卷；
- 用题目相似度把未绑定的小节、无关文章或过期版本显示为精确来源；
- 把“题目来自教材”扩展成“用户掌握了教材”；
- 以口音、语速、停顿、性别、情绪或声音特征推断专业能力、人格或录用结果；
- 在没有题目量规、可靠转写或版本匹配时生成确定性技术结论；
- 通过重复同一题、缩短时间或隐藏缺口提高表面完成率。

## 7. 交付与独立验收分工

### 课程架构师

维护三种入口的能力范围、题型组合建议、文章/题目关系和先修；不编写客户端或独立 QA 报告。本文件只给结构建议，不关闭题库、用户效果或职业能力门槛。

### 产品经理

确定用户可选的范围、时间、题量和快捷试卷规格；将“可用题目/选中题目/缺口”作为产品可见状态；不把课程比例写成录用评分标准。

### 教材研发员与内容审校员

作者按文章规格和题目交接补正文/参考解析；审校独立核每篇文章、每道题、每个追问与来源范围，分开记录通用建议、教材事实、外部资料、用户事实和未知。题库答案修订不能覆盖旧题、旧审校或历史试卷身份。

### 内容检索工程师

维护版本化文章/小节/题目索引和只读来源接口；检索推荐只能返回已发布身份和绑定范围，遇到无匹配、歧义、版本失效或私有内容时返回诚实状态。不能编教材、改题目量规或替内容审校。

### 软件工程师、AI 生成工程师、后端数据工程师

客户端消费既定题目/文章/试卷合同；AI 只分析当前题面、用户回答和已核来源；后端保存版本快照、试卷项、用户私有记录和删除边界。三岗不能把示例或模型草稿写入公共精选集，也不应访问无授权的真实用户资料。

### 测试工程师与实训评估员

测试精选题、通用文章、按范围组卷的入口、来源标签、版本冻结、缺口状态、刷新/后退和错误降级；实训评估员使用陌生题和真实作品检查迁移，区分自动反馈、自评、专业评阅和实际面试结果。测试通过不能推导内容专业正确或用户能力提升。

| --- | --- | --- |
| GTT-01 | 精选题、通用流程、按范围组卷是三个可区分入口/模式，页面文案不混淆其目的 | 信息架构与隔离操作记录 |
| GTT-02 | 通用流程六阶段和 GFT-01–10 文章身份清楚，文章不是题目答案的隐式来源 | 目录、文章元数据与链接关系 |
| GTT-03 | 精选题每题有职业、版本、题型、量规和来源映射，未审校题不进入正式精选集 | 题目清单与内容审校记录 |
| GTT-04 | 快速、标准、综合和自定义卷的题型建议可解释，缺题型时显示缺口而非静默替换 | 组卷规则、缺口样例与页面证据 |
| GTT-05 | 试卷保留范围快照、题目版本、顺序、选择规则、随机种子和创建时间，可重建本次题目 | 试卷数据快照与重复读取对照 |
| GTT-06 | 文章来源身份、内容审校状态、题目来源身份和试卷派生身份分开存储/展示 | 元数据检查与界面抽查 |
| GTT-07 | 用户私有事实、录音和岗位变体不进入公共文章/题目/索引 | 隔离数据与索引检查 |
| GTT-08 | 无匹配、歧义、来源失配、版本过期和模型不可用时不编造来源/答案，保留诚实降级 | 五类反例 HTTP/UI 证据 |
| GTT-09 | 文章阅读、题目回答、试卷练习、AI反馈和真实能力评估分别记录，不能以完成率替代能力结论 | 数据合同与复盘记录 |
| GTT-10 | 当前版本独立内容审校、客户端 QA、用户研究、真人专家和实训评估状态分别复盘 | 责任岗位报告与版本绑定 |
