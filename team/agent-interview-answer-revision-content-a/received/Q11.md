# Q11 · ReAct 如何组织推理、行动与观察？它与一次性生成计划有什么不同？

版本：interview-answers-v1 / Q11-r1。本文为完整参考解析；案例和验证方案除特别注明外均为教学构造，未在本次写作中执行。

ReAct 将推理依据、行动和环境观察交错起来：根据已有信息提出下一步行动，取得工具观察，再修正理解和行动。它不是先写一份长计划后照单执行，也不是要求展示模型私有思维；工程记录可以只保留可审查的决策理由、工具参数和实际观察。模型负责提出候选，权限与执行仍由宿主控制。

## 走完一条取证轨迹

以下是构造的退款缺陷调查，目标是形成有证据说明，当前只知道报告 R71：

| 当前观察 | 可审查决策依据 | 行动与新增观察 |
| --- | --- | --- |
| 报告说 `refund(7)` 预期True、实际False | 先核实现，不能直接认定测试正确 | 读取允许修订的退款函数，发现返回 `days < 7` |
| 实现与报告的第7天断言不一致 | 不一致已知，但哪边应改仍缺业务依据 | 读取报告关联的退款规则 |
| 规则未标生效版本，另有一份相反文本 | 不能确定哪份适用于本任务 | 保存冲突、请求规则负责人确认，停止创建确定根因工单 |

若第三步得到可信有效规则，模型才可据此形成候选，并由验收核主张和引用。观察改变了“读哪里”和“能得出多强的结论”，这就是反馈的作用。

## 与一次性计划的差别

一次性生成“读报告→读代码→修复代码”可能暗含规则已知、允许修改等错误前提。若执行器无条件沿原计划推进，第二步后的证据冲突会变成后续错误。Plan-and-Execute 可以在失效点重新规划，因此区别不应说成“计划永不改变”；区别在于初始承诺的控制粒度和重新规划的位置。ReAct通常每轮只承诺一个或少数下一步，更适合路径逐步揭示；它也可能短视、耗费更多调用或被无关观察带偏。

验证时把规则材料从完整换为冲突，检查轨迹是否从生成结论变为补证/等待；把工具结果替换为相同内容，检查是否停止无效重复。若每次只是“再想一遍”而没有新证据、假设未改变，则多轮不是有效ReAct。与固定路径基线比较完整证据率、错误完成、轮次和成本，才能判断交错行动是否值得。
