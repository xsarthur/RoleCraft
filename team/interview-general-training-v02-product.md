# 通用面试专项训练产品交接 v0.2

责任岗位：产品经理  
日期：2026-10-16（Asia/Shanghai）  
状态：产品范围与验收合同；待课程架构、设计、客户端、内容检索和测试岗位交接  
前一版：`interview-general-flow-product.md`（v0.1，作为历史范围保留）

## 1. 本轮调整结论

用户反馈确认两件事：

1. 通用面试流程是可选的专项训练，不应在面试题列表/题目上方占据大面积首屏；
2. 专项训练除了提供练习入口，还要让用户在同一学习路径中阅读自我介绍、澄清、结构化回答、追问、向面试方提问和复盘等主题的文章。

因此 v0.2 采用“双入口、双层级”结构：

```text
面试准备首页
├─ 题目练习（默认主路径：题目 → 回答 → AI反馈 → 重答）
└─ 通用面试专项训练（轻量入口，不展开六阶段内容）
   ├─ 训练首页：六个阶段的概览与选择
   ├─ 练习场：语音/文字回答、转写、反馈、重答
   └─ 学习文章：按主题阅读、来源定位、读后练习
```

原 v0.1 的六阶段教学内容、语音状态和建议质量边界继续有效，但不再直接嵌入面试题首页的大面板。v0.2 只改变信息架构、入口和文章学习范围，不重新定义通用流程内容，也不改变题目练习的主路径。

## 2. 产品目标与非目标

### 2.1 目标

- 让用户在进入面试题练习时，首先看到当前题目和回答动作；
- 让用户能明确找到“通用面试专项训练”，并在训练、阅读、口述实践之间往返；
- 把高质量的通用建议拆成可学习的文章，而不是只在一个长面板内堆叠说明；
- 文章、练习建议和反馈都标明来源身份、适用情境和未验证项；
- 用户可以从任一文章或阶段直接进入相应练习，不要求先完成六阶段全流程。

### 2.2 非目标

本版本不授予真实面试通过率预测、录用判断、职业认证、真人专家认可或真实学习效果结论；不自动生成公司内部流程，不替用户编造经历、数字、项目结果或问题答案；不因新增文章而改变原题库、冻结教材、账户数据或历史审计身份。文章接入只读的现有教材/内容索引；新增或改写正式教材需课程架构与教材研发岗位另行交接。

## 3. 面试准备首页改版范围

### 3.1 默认首屏

默认首屏只呈现当前面试题主任务：题目、题型、开始回答、口述/文字切换、最近一次练习状态，以及一个紧凑的专项训练入口。专项入口不得展开六阶段正文、文章列表或大段建议。

专项入口为横向或窄卡片，至少包含：

- 标签：`专项训练`；
- 一句话说明：`练习自我介绍、澄清、追问和向面试方提问`；
- 当前学习状态（未开始/进行中/上次练习时间）；
- 一个主按钮：`进入专项训练`；
- 一个次链接：`先读文章`。

首屏入口的面积、视觉权重和题目主卡相邻但低于当前题目主操作；不得出现完整六阶段时间线、长篇介绍或文章全文。窄屏下入口可置于题目主操作下方，但必须在一次滚动内可见。

### 3.2 与题目练习的隔离

- 进入专项训练不会改变当前题目、回答草稿或题目完成状态；
- 从专项训练返回题目时，保留题目草稿和播放/录音状态（若当前浏览器仍允许）；
- 专项训练的练习尝试、文章阅读进度和题目回答记录分开标识；
- 题目详情页可提供小型“相关通用环节”链接，例如“这道行为题可练：结构化回答”，但不得在题目上方展开通用流程面板；
- 旧 v0.1 的六阶段内容不再作为题目首页的嵌入区域，旧原型截图/报告保留为历史记录，不作为新版视觉验收证据。

## 4. 专项训练入口与训练首页

### 4.1 入口位置

至少提供以下可达入口：

1. 面试准备首页的紧凑卡片：`进入专项训练`；
2. 面试准备导航/次级导航中的独立项：`专项训练`；
3. 题目详情的相关环节链接：进入指定阶段，带上题型上下文但不把题目答案改写成通用建议。

入口名称应保持一致。不得使用容易与题库完成率混淆的名称，例如“流程考试”“通用题库”或“能力评分”。

### 4.2 专项训练首页信息架构

页面按以下顺序组织：

1. **页面标题与范围说明**：说明这是可选的通用表达训练；静态建议和个性化 AI 分析分开标识；
2. **继续上次练习**：若有未完成阶段，显示阶段名称、上次动作和继续按钮；无记录则显示从任意阶段开始；
3. **六阶段选择区**：六张等权或分组卡片，仅显示阶段名、完成任务、预计练习形式和文章数，不展开所有说明；
4. **推荐学习文章**：依据用户最近选择/薄弱环节（若用户未授权读取记录则使用通用排序）显示 3–5 张文章卡；
5. **全部文章入口**：按主题浏览、搜索和筛选；
6. **诚实边界**：明确“通用建议不代表某家公司流程，也不替代真实面试反馈”。

六阶段为：自我介绍、理解与澄清、结构化回答、处理追问、向面试方提问、结束与复盘。阶段卡的“练习”进入专项练习页，“阅读”进入文章列表并预筛对应主题；不要求用户按 1→6 顺序完成。

## 5. 专项练习页信息架构

专项练习页一次只聚焦一个阶段，避免重新形成大而全的面板。结构如下：

1. 阶段标题、当前任务和返回专项首页；
2. **本次目标**：最多三条可观察目标；
3. **练习模式**：口述回答/文字回答；口述沿用 `ready → recording → transcript → analyzing → feedback → retry`；
4. **参考提示**：折叠式“查看结构/示例/常见失误”，默认不遮挡录音或文字输入；
5. **提交与反馈**：先确认转写，再分析；反馈区分流程、内容和表达三层；
6. **下一步**：重答、查看相关文章、换阶段、返回题目。

文章阅读不与录音反馈争夺主操作。练习页只显示 1–2 条相关文章入口，完整文章列表在独立学习页。

## 6. 学习文章中心

### 6.1 文章范围

首版文章围绕六个专项主题组织，每个主题至少可提供一篇正式可读文章或明确显示“当前无已绑定文章”：

| 主题 | 文章学习重点 | 练习连接 |
| --- | --- | --- |
| 自我介绍 | 60–120 秒的定位、经历证据、岗位匹配和过渡；删去履历罗列与空泛形容词 | 口述自我介绍、结构检查、重录比较 |
| 理解与澄清 | 复述问题、识别题型、询问会改变方案的约束、声明假设 | 澄清问题卡、信息不足场景 |
| 结构化回答 | 概念、项目/行为、系统设计、排障题的不同组织方式及时间取舍 | 选择题型骨架后作答 |
| 处理追问 | 证据追问、约束变化、反例、不知道精确事实时的诚实回应 | 分支追问、重答 |
| 向面试方提问 | 用问题了解成功标准、当前问题、协作、反馈、边界和后续流程 | 选择/改写 2–3 个问题并口述 |
| 结束与复盘 | 总结匹配点、确认后续、记录未答好内容并形成下一次动作 | 结束语练习、复盘卡 |

文章可以是教材中已存在的分节、经课程架构批准的专项补充文章或已审校的通用建议。未经内容审校/版本绑定的草稿不可显示为正式学习材料。

### 6.2 文章列表页

列表页提供：

- 主题筛选；
- 文章类型筛选（基础说明、示例拆解、误区与边界、练习指南）；
- 阅读状态（未开始、阅读中、已读）；
- 搜索标题/小节/关键词；
- “适合何时读”标签（开始专项前、练习前、反馈后、复盘时）。

文章卡至少显示：标题、主题、阅读时长估计、适用阶段、摘要、来源状态（教材绑定/通用建议/待核对）、版本和主操作（阅读/继续阅读/去练习）。阅读时长是估计值，不是学习成效承诺。

### 6.3 文章详情页

文章详情页需要有：

- 标题、主题、适用面试阶段/题型；
- 正文及必要的示例、反例、边界和练习动作；
- 来源卡：教材版本、章节/小节、原文定位或“通用建议/未绑定教材”；
- `适用条件`、`不确定性/待确认`和`下一步练习`；
- `开始练习`按钮与返回文章列表；
- 用户可以标记“稍后阅读”、隐藏文章或删除本次阅读记录。

文章内容不应以“必然加分”“标准答案”“面试官一定喜欢”等表述呈现；示例中的经历、数字和结果必须明确标为教学构造，不能让用户误以为是自己的事实。

## 7. 推荐与来源合同

文章推荐沿用现有版本化内容检索能力，至少携带：

- `contentVersion` / `corpusVersion`；
- 文章或分节 ID、标题、摘要和可定位链接；
- 原文摘录或明确的文章正文来源；
- `sourceStatus`：`textbook_bound`、`general_guidance`、`unverified`；
- `applicableContext`：阶段、题型、轮次和假设；
- `nextAction`：可在当前会话完成的阅读或练习动作；
- `uncertainty[]`：未提供信息、争议或待用户确认项。

无匹配、歧义、版本失效或检索不可用时，显示相应状态并提供改写/浏览全部文章/重试；不得生成不存在的文章或来源。用户未授权读取练习记录时，不得用薄弱环节或历史答案进行个性化排序。

## 8. 验收条件

| ID | 验收条件 | 证据 |
| --- | --- | --- |
| IGT-01 | 面试准备首页首屏以题目练习为主，专项训练仅显示紧凑入口，不展开六阶段正文/文章全文 | 760px 与窄屏渲染截图、DOM 结构和手动检查 |
| IGT-02 | 用户可从首页、次级导航和题目详情进入专项训练；入口名称一致 | 隔离浏览器三条路径点击记录 |
| IGT-03 | 进入专项训练不改变题目草稿、题目状态或题目回答记录 | 隔离会话前后数据对照 |
| IGT-04 | 专项训练首页显示继续上次、六阶段选择、推荐文章和全部文章入口；可从任一阶段开始 | 新用户、已有进度和删除进度三种场景 |
| IGT-05 | 阶段练习页一次聚焦一个阶段，口述/文字、转写确认、反馈和重答可用；文章不遮挡主操作 | 六阶段中至少自我介绍与提问阶段完整操作，其他阶段导航覆盖 |
| IGT-06 | 文章中心按六主题提供列表、筛选、搜索、阅读状态和练习跳转 | 每主题至少一张绑定卡；无文章主题显示诚实空状态 |
| IGT-07 | 文章卡与详情显示标题、主题、适用阶段、摘要、阅读估计、来源状态、版本和下一步 | 字段检查与来源逐项核对 |
| IGT-08 | 文章详情展示正文、示例/边界、来源定位、适用条件、不确定性和练习入口 | 至少抽查自我介绍、向面试方提问两篇正文 |
| IGT-09 | 文章推荐按用户已授权的情境/阶段排序；未授权记录时使用通用排序并标识 | 授权/未授权两组请求与 UI 快照 |
| IGT-10 | 无匹配、未绑定、版本失效、检索不可用和文章缺失状态不编造来源或正文 | 五类反例 HTTP/UI 记录 |
| IGT-11 | 专项训练和文章阅读记录与题目回答记录分开，可继续、删除和返回；刷新/后退不覆盖旧尝试 | 隔离数据前后对照与浏览器时序证据 |
| IGT-12 | 桌面与窄屏下首屏主任务突出、入口可见、阅读和练习可达；键盘/屏幕阅读器能识别入口、阶段和来源状态 | 渲染、键盘焦点、`aria-live`/名称证据 |
| IGT-13 | 文案不声称必然加分、录用概率、公司内部流程或职业认证；教学构造案例有身份标记 | 内容抽查清单与独立审校记录 |
| IGT-14 | 题目详情的相关环节链接只传递题型上下文，不把通用建议写入题目答案或覆盖来源 | 题目→专项→返回路径及数据对照 |

本合同只授专项入口、训练页和文章学习体验的实现范围；不关闭真实 ASR/AI 分析、真实用户价值、行业比较、专家审核、学习效果或生产经济性的既有门槛。

## 9. 岗位交接与复盘要求

- **产品经理**：维护入口名称、范围、验收样例和版本合同；不编写文章正文或客户端实现。
- **课程架构师**：确认六主题文章的能力目标、先修、正文去向和练习映射；指出职业特定部分。
- **教材研发员/内容审校员**：分别负责新增正文与独立论证/来源检查；未经审校的草稿不得显示为正式文章。
- **设计师**：先交“轻量入口、专项首页、阶段练习页、文章列表/详情”的视觉稿；用视觉层级表达主任务与可选学习，文字只补必要说明。
- **软件工程师**：实现页面状态和现有检索/语音合同消费，不自行重写教材或改变题库范围。
- **内容检索工程师**：维护文章/分节索引、来源绑定、状态和只读接口；不改文章正文。
- **测试工程师**：独立执行 IGT-01–14，分别报告首屏层级、文章内容/来源、状态隔离、可访问性和真实语音能力。
- **项目经理**：记录实际岗位、证据、缺口、责任人、复验方法和 R16（本版本）达标复盘；不能以入口实现或文章数量推断面试效果。

产品自查：本文件只新增 v0.2 信息架构、文章学习范围和验收合同，未编辑客户端代码、教材正文、账户数据或历史报告，未授权付费调用、上传、发布或外部联系。
