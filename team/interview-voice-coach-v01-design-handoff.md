# 语音面试教练 v0.1 设计交接

岗位：设计师；日期：2026-10-15（Asia/Shanghai）。

这份交接把“进入面试题后，用户可以先录音，再确认转写并获得带出处的 AI 反馈”表达成可点击原型的视觉合同。它是静态设计提案和交互状态定义，不是运行截图、真实录音、真实 AI 结果或职业能力认证。配套视觉稿：[interview-voice-coach-v01-board.svg](interview-voice-coach-v01-board.svg)。

## 用户在画面上应立即看懂什么

进入一题后，主路径只有四步：**看题 → 说回答 → 核对转写 → 根据反馈重答**。当前动作由中央主卡片承担；右侧只放练习进度、当前题目量规和已核验的教材来源。录音和分析状态用位置、边框、图标和短标签共同表达，不能只靠颜色或动画。

### 桌面布局（≥ 960px）

```text
┌────────────────────────────────────────────────────────────────────────┐
│ 面试准备 / 语音练习       Q017 · 工程设计 · 预计 2 分钟     退出练习      │
├──────────────────────────────────────┬─────────────────────────────────┤
│ 当前题目（主体，约 2/3）               │ 练习上下文（约 1/3）              │
│ 题目 + 题型/难度标签                   │ 第 3 / 5 题                       │
│                                      │ 回答量规：机制、取舍、证据         │
│ 录音 / 转写 / AI反馈主状态卡           │ 教材来源：v12 · 小节链接           │
│                                      │ 状态说明与删除入口                │
│ [主操作] [重录/改用文字]               │                                 │
└──────────────────────────────────────┴─────────────────────────────────┘
```

右栏在桌面保持稳定宽度，避免分析结果出现时主卡片跳动。来源卡只显示已经通过题目版本和教材版本校验的链接；没有来源时显示“未绑定教材”，不放相似但未经核对的章节。

### 窄屏布局（≤ 760px）

按同一顺序变成单列：题目 → 主状态卡 → 反馈或转写 → 量规/来源折叠卡。主操作放在底部粘性栏，宽度足够触控；右栏内容不能被隐藏，只能移到主卡片下方或折叠。≤ 390px 时标题允许两行，录音波形改为横向短条，不出现横向滚动。

## 四个核心状态

| 状态 | 视觉主语义 | 主操作 | 必须显示 | 不得暗示 |
|---|---|---|---|---|
| `ready` 待录音 | 麦克风轮廓 + “可开始录音”标签；静止边框 | **开始录音** | 麦克风权限、建议时长、改用文字 | 已经录到内容 |
| `recording` 录音中 | 红色圆点、计时器、实时波形、`录音中`徽记；红色之外再用文字/图标 | **停止录音**；次要暂停 | 已用时长、取消/重录 | 波形高低代表回答质量 |
| `transcript` 转写待确认 | 文档图标 + “请核对转写”；可编辑文本，低置信词带下划线/说明 | **确认并分析**；重录 | 原始转写与可编辑版本分开、播放 | AI 已理解或已评分 |
| `feedback` 分析反馈 | 分块反馈卡：内容、证据、表达；来源徽记和分析模式 | **再录一次**；查看教材原文 | 优点、缺口、一个重答动作、追问、不确定项 | 录用概率、人格/情绪/口音判断 |

反馈卡的总顺序固定为：**先说观察到的内容，再说缺口，再给一个动作**。表达指标（时长、近似词/分钟、停顿、填充词）和技术内容评价分开，避免用户把“说得快”理解成“技术正确”。

## 点击路径与异常状态

1. `ready` → 用户点击“开始录音” → 首次显示系统麦克风权限。拒绝权限时保留“改用文字回答”，就地显示原因和“重试权限”。
2. `recording` → 点击“停止录音” → 进入 `transcript`。点击“重录”丢弃当前临时音频前，给出同一处的撤销机会；不写入普通日志。
3. `transcript` → 用户可编辑转写 → 点击“确认并分析” → 显示 `analyzing` 等待条，保留“继续阅读题目”和“取消分析”。
4. 分析完成 → `feedback`。点击“再录一次”创建新尝试，旧转写和反馈仍可折叠查看，不能被覆盖成“已改进”。

需画进原型的降级状态：

- **无声/噪声过高**：显示可观察原因和重录建议，不产生技术结论。
- **转写低置信**：允许编辑；在分析前要求用户确认，不把猜测词当原话。
- **分析服务等待或不可用**：显示当前模式（如“本地规则 / 未配置分析服务”），保留转写和文字练习，不显示假的 AI 反馈。
- **来源失配或无匹配**：反馈可继续给通用表达建议，但明确“未绑定教材”，不显示章节名称。
- **超出时长/格式不支持**：在停止或上传前就地说明限制与下一步。

## 视觉语言与可访问性

- 背景使用暖灰 `#F7F5F0`，正文 `#2F2C25`，主操作深棕 `#72562B`；录音状态用 `#A33A35`，等待用 `#80691A`，来源用青绿 `#2A5B56`。每个颜色同时配短标签、形状或图标。
- 所有按钮触控区域至少 44×44px；焦点环 2px 且不被卡片裁切。键盘顺序按题目、主卡片、次操作、来源走；空格/回车可操作按钮。
- `录音中`、`转写已生成`、`分析完成/不可用` 使用 `aria-live="polite"`；计时器不每秒播报，只在状态改变时播报。暂停、停止和删除都有可读名称。
- 波形是状态提示而不是数据图表，提供文字替代：“录音中，已录制 00:37”。减少动画时仍显示静态录音徽记和计时。
- 反馈标题采用真正的层级标题；技术缺口和表达观察不只由红/绿区分。转写编辑区支持放大字号、换行和屏幕阅读器逐段阅读。

## 演示数据与边界

视觉稿中的 `Q017`、`00:37`、转写句子、指标和“教材 v12”均应带“演示数据 / 非真实录音 / 非实时 AI”徽记。演示不得把预写反馈写成用户实际结果；不得在原型里展示个人声音、真实用户记录、供应商名称、付费调用成功或录用分数。真实实现时，音频、原始转写、编辑后转写、反馈和删除动作分别记录，默认不进入 `localStorage` 或教材检索索引。

## 软件工程交接字段（仅定义，不实现）

客户端至少需要稳定表达 `ready | recording | transcript | analyzing | feedback | partial | unavailable`，并在每个状态保存 `attemptId`、`questionId + questionVersion`、`contentVersion`、`analysisMode`、`providerCalled`、`bindingStatus` 和 `uncertainty[]`。状态切换不能用空白卡片代替；发生错误时保留可用的转写或本地计时数据。
