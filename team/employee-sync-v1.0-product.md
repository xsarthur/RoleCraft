# Rolecraft 1.0 全员同步产品简报

- **日期**：2026-10-16（Asia/Shanghai）
- **发布口径**：`rolecraft-1.0` 本地候选
- **产品岗位状态**：`scope_frozen_for_implementation; implementation_delivered; qa_insufficient`
- **当前实现基线**：`local-workbench-0.15-p0`
- **本简报责任**：产品经理
- **用途**：给产品、设计、课程、教材、检索、客户端、后端、测试、用户研究、实训评估和运营岗位同步同一范围、优先级、验收边界与证据限制。

本简报不替代产品合同、设计稿、课程规格、工程交接或独立 QA；它把这些交接收敛为本轮开发的共同入口。所有岗位继续保留各自领域的历史记录和失败证据，不以本文件覆盖旧报告。

## 1. 当前共识与证据边界

1.0 的产品目标是让学习者从一个明确的当前任务开始，阅读版本绑定的 Agent 教材，按自然语言定位有出处的小节，完成至少一个练习并提交可追溯作品证据，再获得明确的反馈状态和下一步。主流程固定为：

**确认当前任务 → 阅读/检索 → 完成练习 → 提交作品证据 → 获得反馈状态 → 复盘并选择下一步。**

当前已收到的实现包括：当前任务卡与主 CTA、题库/复习/自评入口、项目证据状态槽、问教材结果字段和 `rolecraft-1.0` 发布字段。课程岗位已交 `V1-PILOT-P01-MVP-001`（v12 `p01-mvp`）练习合同；设计岗位已交五入口信息架构、问教材七态、证据状态槽及响应式/无障碍交接；后端岗位已交发布身份响应头和兼容字段。

这些交付仍不能证明浏览器主流程、真实 HTTP、练习提交恢复、用户理解、真人评审、真实学习效果、生产可靠性或成本经济性。最新独立 QA 只运行四个 `node --check` 和短静态断言，V1-01～V1-08 为 `insufficient`，V1-09 在静态/运输范围为 `pass`；本轮没有启动服务、浏览器、正式数据库或外部/付费模型。

## 2. 1.0 不可改变的产品合同

### 必须交付

- **一个当前任务入口**：首页只有一个主任务卡和一个主要 CTA，区分未开始、进行中、已中断和本任务已浏览四态；状态是流程事实，不是能力等级。
- **职业确认边界**：只探索 `published` 职业；候选、React 等多义澄清、目录外、不可用、取消、确认和版本冲突均要有真实状态。只有确认后才改变当前职业，不把推荐当确认。
- **有出处的学习检索**：每个肯定结果必须包含意图、候选小节、连续原文摘录、教材/索引/语料版本、`unitId`、`sectionId`、来源路径与 `sourceSha256`、推荐理由、不确定性、实际 `engineMode` 和恢复动作。
- **练习—作品—反馈最小闭环**：至少接通 `V1-PILOT-P01-MVP-001`；保留草稿、提交、证据、反馈状态和回源小节，分开显示 `self_report`、`ai_suggestion`、`professional_review`、`human_review`。
- **题库、复习、自评可发现**：一次点击可达，页面不能再显示“后续开放”；题库保持固定100题、市场补充14题和历史集合身份；复习只读本人当前版本 `weak` 题；自评只抽当前版本已访问知识点，且明确是本人自评。
- **版本与来源一致**：页面、健康接口、静态资源、教材索引、题库、练习数据和构建清单共享 `releaseVersion=rolecraft-1.0`。`agent-system-v0.12`、`workbenchVersion=local-workbench-0.11`、旧 `PRODUCT_VERSION=local-mvp-0.4` 只能作为兼容/历史字段。
- **视觉优先和可恢复**：当前任务、步骤关系、状态、问教材七态、版本徽章和证据槽优先用布局/图形/边界表达；抽屉不能遮挡正文、保存或提交，关闭后焦点回到触发控件。

### 明确不在1.0承诺

跨设备账户同步、完整七阶段产品创造闭环、真实模型供应商调用、外部协议/沙箱/OAuth/MCP/A2A、生产恢复与成本账单、公网部署、真人学习者/专家证据、就业/认证/行业领先承诺均延期到1.1或另行授权。默认本地检索或规则降级，`providerCalled=false`；不上传、不发布、不触碰正式账户或数据库。

## 3. 立即开发顺序（按产品优先级）

### P0-1：冻结并验证当前任务主路径

- **目标**：首次、已有记录、已中断、已浏览四态各只有一个可理解的下一步；刷新、后退、关闭问教材、换职业后不串职业/版本。
- **客户端责任**：实现当前任务卡、状态恢复、主 CTA 和任务完成后的下一步；不新增能力等级字段。
- **设计责任**：交付四态视觉和焦点/窄屏示意；主 CTA 与目录、路线、问教材保持明显层级差。
- **QA证据**：当前源浏览器操作、截图、刷新/后退/中断状态记录；静态分支不能单独关闭 V1-01。

### P0-2：完成职业确认与内容检索真实链路

- **目标**：候选/澄清/无匹配/不可用/取消/确认/版本冲突可恢复，检索卡逐字段回链教材来源。
- **检索与后端责任**：绑定当前 v12 corpus、index、source hash 和 `releaseVersion`；迟到响应、来源失配、规则降级不可生成旧答案或无出处答案。
- **客户端责任**：按设计提供抽屉上下文、三层结果卡、重试/改写/目录入口和焦点恢复。
- **QA证据**：临时账户/临时端口固定反例的请求、响应、页面卡、来源 hash、状态截图；不能用此前 `127.0.0.1:47231` 的 health/catalog 运输收据代替学习查询证据。

### P0-3：接通 P01-MVP 练习—作品—反馈

- **目标**：学习者能从当前任务进入 `p01-mvp`，查看输入/先修/产出/失败路径，保存草稿，提交作品包，看到“已提交/待独立复验/发现问题/证据不足”等状态，并能回到正文来源。
- **课程/实训责任**：保持 `V1-PILOT-P01-MVP-001`、正文 SHA `deb98fa616e7d670108c86eca3b2a137e1183cf69bc3a5f5799a0b08f19b57d9`、七项完成条件和七条失败路径；不把构造 fixture 写成真实用户反馈。
- **客户端/后端责任**：每次修订生成新 `submission_id`，带 `practice_id`、`source_sha256`、`evidence_refs`；不覆盖旧提交或把自述转成通过。
- **QA证据**：隔离 fixture 的提交、失败、刷新、恢复、回源和版本 hash 收据；未取得学习者或真人评审时保持 `not_run`/`未开始`/`证据不足`。

### P0-4：统一1.0发布身份并完成受影响资源清单

- **目标**：页面、脚本、接口、教材索引、题库、练习数据和构建清单能互相核对同一发布身份。
- **后端/检索/客户端责任**：公开 `rolecraft-1.0`；保留旧兼容字段但在 UI/报告中单独标明；当前教材和历史 v10/v12 使用不同只读徽章。
- **QA证据**：发布清单、每项 hash、`health/catalog/recommend` 响应头/JSON、页面徽章和题库/索引版本逐项绑定；不得把局部响应头通过扩大为全链路通过。

### P0-5：完成视觉和可访问性实际复验

- **目标**：问教材打开/关闭、加载、无匹配、歧义、失败、规则降级、有依据七态均可理解、可恢复且不遮挡正文/提交。
- **设计/客户端责任**：按 `design-v1.0-learning-workbench.md` 实现状态图形+短文案、`aria-expanded/controls`、焦点返回、状态播报和安全区留白。
- **QA证据**：1280/768/390/375/320 CSS px、200% 缩放、键盘、读屏、灰度和软键盘记录；源码有 `aria-*` 不能代替实际运行证据。

### P1（1.0后排队）

诊断结果驱动的路线调整、产品创造七阶段全闭环、跨设备同步/冲突、用户价值埋点和运营成本基线需单独产品合同、数据/安全设计与研究证据后再排期，不得挤占上述P0或伪装成1.0能力。

## 6. 发布和沟通禁语

对内外统一称呼为“`rolecraft-1.0` 本地候选，限定范围开发中/待独立复验”。不得称“正式生产版、已认证、已证明胜任、已获得用户认可、行业领先、真实模型已接入、可稳定公网服务”。若服务未启动或公网不可达，入口和报告要明确“仅本地”；若检索无依据、规则降级或版本失配，界面必须保留真实状态和恢复动作。

产品范围与跨岗位交接已完成，工程实现已收到；当前1.0仍为**本地候选，限定范围可用但独立 QA 证据不足，整体 `not_met`**。下一次项目收口必须以当前版本重新取得 V1-01～V1-08 的真实 HTTP/浏览器/可访问性/提交恢复证据，V1-09继续作为边界检查；在此之前不能把本轮开发任务结束写成1.0通过，也不能改变原八门槛状态。
