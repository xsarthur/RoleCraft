# 员工成长体系 v1.1 改进方案（课程架构草案）

日期：2026-10-16  
责任岗位：课程架构师  
状态：`draft_for_pm_review`  
适用：十五个岗位；不改变既有岗位职责、历史证据或已冻结合同。

## 1. 改进目标

v1.0 的规格完整，但把大量精力放在字段、收据和逐项人工确认上，尚未形成高频、低人工、以真实工作责任为中心的学习闭环。v1.1 将训练单位从“完成一套诊断”改成“在工作中解决一个问题并产生可复用证据”，把自动化用于准备、检查、反馈、复验和调度，把人工集中在边界、异常、里程碑和晋级判断。

本草案不把自动检查、阅读、报告、一次成功或代理生成内容当作学习者能力；不允许代理替学习者作答，不允许系统自动填写本人声明或接收签收。

## 2. v1.0 中需要修正的部分

| 现有做法 | 问题 | v1.1 修正 |
|---|---|---|
| 先完成长篇 D0，再进入工作 | 学习者等待时间长，诊断与岗位工作脱节 | 用一个短诊断任务建立基线，随后立即进入岗位沙箱 |
| 每个字段都要求人工逐项确认 | 负责人被收据管理占用 | 系统自动校验字段、哈希、版本、运行和差异；仅异常进入人工队列 |
| L3 主要靠“两个周期+最差案例” | 责任、影响和迁移标准仍不够具体 | 增加两种情境连续交付、系统性改进、教会他人和影响证据 |
| L4 依赖“真实用户/专家/生产反馈链”但缺少路径 | 很难启动，容易长期停在规格层 | 分成产品创造、领域标准、带教复用三个可观察结果，按岗位选择有效证据 |
| 练习按岗位各自设计，复用不足 | 每个岗位重复建设夹具和记录 | 建立通用任务模板、自动收据和岗位适配参数 |
| 自动返修概念含糊 | 容易替学习者修改作品，破坏归属 | 自动系统只给反馈、生成候选提示和重跑；学习者提交修复版本 |
| “签收”成为每项任务的硬阻塞 | 低风险任务也等待人工 | 沙箱任务由系统记录接收状态；只有跨岗、真实任务和晋级里程碑需要接收方确认 |

## 3. 新的训练闭环

```
岗位诊断
→ 推荐具体教材小节和先修
→ 发放可重置沙箱
→ 学习者执行并提交原始收据
→ 自动检查与带出处反馈
→ 学习者提交修复版本
→ 自动复验原例和受影响范围
→ 非作者冻结留出题
→ 形成 EvidenceCard 和能力快照
→ 异常队列/里程碑人工复核
```

系统自动完成：

- 按能力缺口推荐版本化教材小节并保存出处；
- 创建、重置和清理沙箱；
- 检查结构、来源、权限、测试、日志、哈希和证据完整性；
- 保留首失败、返修差异、回归结果和未测范围；
- 生成补学、间隔复习和下一任务；
- 对重复失败、风险越界、来源冲突和低证据质量生成异常摘要。

人工保留：

- 初次确定岗位、权限、数据、验收边界；
- 涉及真实数据、隐私、安全、外部写入、生产和费用；
- 来源冲突、歧义、严重缺陷或连续失败；
- 发布课程版本和练习模板；
- 未知任务、真实作品、晋级、生产授权和职业能力判断；
- 抽样复核自动评估是否误放行。

## 4. 统一产物和证据账本

每个训练单元自动生成一份任务包，学习者必须亲自提交执行产物：

- 任务合同、岗位和目标层级；
- 教材来源、版本、定位和先修；
- 沙箱/真实形状/内部真实模式；
- 输入、夹具、环境、命令、输出、错误和哈希；
- 首失败、修复差异、原例回归、受影响回归；
- 非作者留出任务及学习者选择；
- 事实、来源、假设、推断、未知和停止动作；
- 学习者声明、匿名 `learner_id` 和时间；
- 接收方交接与独立复核状态。

系统可以聚合和校验这些字段，不能代填 `signed_by_learner`、`learner_statement`、`learner_id` 或接收方签收。缺失归属时自动标记 `pending_learner_execution`，不得把 QA 派生文件改标为本人证据。

## 5. L0–L4 新门槛

### L0：可受训

学习者能说明唯一责任、权限、禁止事项和停止条件，并完成一次低风险沙箱观察。自动检查证据完整性；人工只处理边界错误。输出：D0 基线、补学路线、风险标签。

### L1：受指导贡献

学习者在两个不相同的沙箱中完成小任务，处理一个故障和一次交接。输出：两个任务包、首失败与返修、一个短留出、独立 QA。不得把模板填完写成 L1。

### L2：独立交付

学习者在真实形状的隔离任务中独立完成，处理一次失败恢复和一个非作者留出变体，向接收方交付可复现包。输出：真实形状任务、运行轨迹、恢复证据、交接签收和独立 QA。真实外部系统、生产和费用仍分别取证。

### L3：稳健负责

必须同时满足：

1. **两种情境**：两个不同周期、不同约束或不同协作对象的任务连续交付；
2. **迁移**：至少一个非作者冻结的关键变化（版本、权限、资源、数据形状、工具或用户目标）；
3. **失败恢复**：学习者定位根因，选择停止、降级、回滚或修复，并完成受影响回归；
4. **系统改进**：把重复失败转为夹具、检查器、流程或标准改进，且改进由独立 QA 验证；
5. **责任与影响**：能说明取舍、风险、依赖、交付影响和未验证范围；
6. **复用**：另一名员工能从交接包重建产物或按方法完成相似任务。

L3 产物：两份任务 EvidenceCard、迁移卡、最差案例复验、系统改进记录、复用记录、能力快照和独立评估。L3 不要求永久认证或行业专家背书。

### L4：产品创造与领域带教

L4 需在 L3 基础上证明一个可复用的领域结果：

- 提出来自真实问题或明确业务约束的可证伪假设；
- 以可比版本、场景和测量方法验证方案；
- 产生真实反馈、生产结果、同行/专家评审或等价外部证据；
- 迭代一次以上，并记录未达到的目标；
- 建立可复用标准、模板、工具或课程；
- 带教另一名员工重建方法，并由独立评估者核对其结果。

L4 证据按岗位适配：产品经理看用户价值和决策影响，AI 工程师看生成服务质量/成本/可靠性，QA 看缺陷逃逸和评估体系，课程架构师看学习迁移和评估一致性等。没有外部或真实工作证据只能保持 L3。

## 6. 岗位适配规则

所有岗位使用同一任务包和证据字段，仅替换三项：

- 领域核心机制与教材小节；
- 真实问题形状和可观察结果；
- 独立复核人及接收方。

例如 AI 生成工程师的 L3 任务可比较来源冲突与资源受限两种情境；软件工程师可比较接口版本漂移与恢复刷新；产品经理可比较用户目标变化与预算约束；内容检索工程师可比较术语歧义与无匹配迁移。岗位合同仍由对应责任岗位维护，课程架构不代写专业实现。

## 7. 低人工试点

先选一个低风险岗位，使用两类可重置沙箱：

- 正常任务：完成岗位产物并绑定来源；
- 边界任务：注入歧义、缺失、冲突或资源限制，要求停止或澄清。

试点只统计：

- 学习者实际操作分钟数；
- 系统自动闭环率；
- 重复失败率；
- 留出迁移率；
- 误放行率；
- 证据完整率；
- 人工复核分钟数；
- 复验耗时。

首周由负责人一次设定边界和验收合同；日常只接收异常摘要；每周查看汇总；L1、L2、L3、L4各做一次里程碑复核。试点稳定前不扩展到真实数据、外部写入或生产授权。

## 8. 自动化边界和状态

自动系统可判定：格式、哈希、版本、来源定位、命令可复现、预设测试、错误码、差异和证据缺失。

自动系统不可单独判定：学习者是否真正理解、未知任务判断、真实用户价值、职业能力、行业先进性、生产风险或 L3/L4 晋级。

统一状态：

- `planned`、`in_progress`、`pass`、`pass_with_limitations`、`fail`、`insufficient_evidence`、`not_assessed`；
- `pending_learner_execution`：缺本人归属或声明；
- `pending_receiver`：需要接收方确认；
- `human_review_required`：异常或里程碑人工复核。

## 9. 实施顺序

1. PM 冻结试点岗位和两类沙箱合同；
2. 课程架构师把 v10/v12 小节映射到能力缺口；
3. 工程岗位实现任务包、重置、自动检查和异常队列；
4. 学习者本人执行第一批任务；
5. QA 独立验证原例、故障、修复、回归和留出；
6. 连续两周期后评估 L3 条件；
7. 具备真实问题、可比测量、外部反馈和带教复用后评估 L4。

本草案只改变未来训练设计；既有 AI D0-03、产品经理和软件工程师合同、历史 QA 和未达标状态继续保留，不因新方案自动升级。

## 10. 课程架构自查

本草案覆盖工作中学习、自动化边界、两情境迁移、系统性改进、教会他人、可观察责任/影响和低人工参与。尚未证明任何岗位已达到 L1、L2、L3 或 L4；需要 PM 评审、试点任务合同、学习者本人收据和独立 QA 后再执行。
