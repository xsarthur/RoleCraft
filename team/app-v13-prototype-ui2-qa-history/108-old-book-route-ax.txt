					262 text 什么时候固定流程就够了？
					263 text 小林已经在消息里写清楚：“我的耳机型号是星河-01，请查保修期限，保存一份答复草稿。”假定海岚商城已经提供了适用手册，查询接口和草稿接口也很稳定。要完成这件事，程序可以照着事先安排的步骤执行，不必每一步都重新问模型该做什么。
					264 text 文字示意图
					265 text 已知型号 → 查保修手册 → 形成答复 → 保存草稿 → 核对保存回执
					266 text 这条线表示“固定查询流程”：开发者预先写好下一步。它并不意味着程序遇到错误还要盲目往下走。例如，没查到手册，就返回“暂时没有适用资料”；保存失败，就报告“答复已拟好，但尚未保存”。这些分支也可以提前写在程序里。程序复杂一些，仍然可能是一条固定流程。
					267 text 现在把消息改成：“帮我查一下星河耳机的保修期限，给我保存一份答复草稿。”产品名称有了，具体型号却没给。此时，不能直接使用星河-01的手册。最简单的处理方式，是让固定流程增加一个缺项分支：先问小林型号，得到回答后再查询。缺一个字段，本身并不要求改成Agent。
					268 container
						269 text 如果实际售后问题变化很多，下一步需要结合返回的资料再选，例如返回的手册提示还要区分销售渠道，开发者可以考虑让模型在允许的动作中提出下一步，再由程序执行。课程把这种执行方式称为“根据反馈选择下一步的控制循环”。此处的关键差别，是 谁决定下一步 ：固定查询流程主要按照预写路径走；动态控制让模型依据新观察提出行动。
					270 text 两种方式都能包含判断和多次调用，不能只数调用次数来判断。三次模型调用若顺序始终固定，仍是一条预写流程。动态控制若让每轮选择更灵活，也会增加核对、测试和调用开销。因此，本例先保留固定查询流程作比较起点，再检查新增灵活性是否真的解决了固定流程难处理的情况。
					271 text 你现在只需会选执行方式，不必同时学习多个框架。比较时让两种方案面对相同的请求、手册和权限；若一套做简单题，另一套做难题，就不能据此说哪套更好。这个比较尚未实际测量，案例中的判断是题定条件下的选择建议。

					281 container
						282 text 假设海岚商城选择了动态控制。小林提交任务后，模型可以建议“先查保修手册”，但建议还不是查询动作。需要有一段程序把建议接起来，核对允许范围、调用工具、收回结果，再决定是否进入下一轮。这里把这段程序的协调职责叫做 任务协调器 ，英文常用 Orchestrator。
					283 text 先看一轮，不急着记整个系统的组件清单：
					284 text 文字示意图
					285 text 当前任务 → 选择下一步 → 应用核对 → 执行工具 → 读取实际结果
              ↑                                  │
              └──────── 未结束，进入下一轮 ──────────┘
					286 text 读图时从左往右走。“选择下一步”可以由模型提出建议；“应用核对”由程序判断这项建议是否能执行。本例只允许查询题定手册和保存小林的草稿，模型若建议“给小林退款”，程序应拒绝，因为退款不在这次任务中。
					287 container
						288 text 把第一轮展开：输入是小林的请求和已知型号星河-01；模型提出查手册的建议；程序核对查询对象；查手册工具返回“找到星河保修-v1，保修期限为购买之日起12个月”。最后这条返回才是本轮的 实际观察 。模型在执行前猜“应该是12个月”，不能代替它。
					289 text 第二轮的输入不再只有原请求，还增加了刚拿到的手册片段。模型可以据此拟出答复草稿，建议保存。程序调用草稿工具，取得“小林保修草稿-01已保存”的回执，核对内容确实引用了刚查到的手册，才把这次任务标为完成。文字写好了，和草稿已经保存，是两个不同的时点。
					290 container
						291 text 为了让下一轮知道发生了什么，程序保存本次任务的进度，例如“型号已知、手册已找到、草稿还未保存”。这就是 任务状态 。它负责记录进度；下一步选择负责提出动作；工具负责执行动作。三种职责分清后，才容易解释为什么一个看似完整的回答仍可能没有做完任务。状态可以先用一个小字典表示，较长任务再考虑持久化；不要求一开始就建立独立的State Manager服务。
					292 text 这一小图是本章的教学拆分，不是所有Agent必须照搬的行业标准。简单任务不一定需要独立规划器、长期记忆或多个Agent。模型在本例中只处理文字；这只是本例接口选择，部分模型也支持图像输入，具体能力应按所用模型查验。你需要记住的是职责和交接，而不是固定层数或一个组件相加的公式。

					301 text 工具结果怎样改变下一步？
					302 text 控制循环的价值，要在结果不符合预想时看。小林最初只说“星河耳机”，查手册工具返回“需要产品型号”。这条结果不是坏消息被隐藏起来，而是告诉系统：原先的查询条件不够，下一步不能按“已经查到”继续。
					303 text 文字示意图
					304 text 查保修手册 → 需要型号 → 暂停并问小林 → 小林补充型号 → 重新查询
					305 container
						306 text 助手可以问：“请告诉我耳机的具体型号，包装或订单里通常会标明。”任务在这时是 等待信息 ，不是不停地运行循环。程序把缺项保存下来，等小林回答“星河-01”，再带着这个新信息继续。没有回答前，不能擅自挑一个常见型号。
					307 text 为什么要先区分结果？因为几种看上去都“没有拿到手册”的情况，下一步并不一样。若工具已经找到适用手册，就进入拟草稿步骤；若缺少型号，就问具体缺项；若手册服务暂时超时，才考虑在限额内重试；若返回“没有读取该对象的权限”，就停止这次读取并说明尚未完成。只读工具同样可能涉及受限资料，不能因为动作叫查询就自动允许。
					308 container
						309 text 这里的 实际观察 ，英文常用 Observation，指工具执行后真正返回的结果。在教学案例里，我们用预设的返回值模拟它；在真实产品中，应使用真实工具返回和必要的外部核对。不能把题定预期当成真实运行记录。
					310 text 新结果可能使原来的步骤安排不再合适。原先计划是“查手册、拟草稿、保存”，现在先插入“询问型号”。这叫按反馈调整步骤。调整的是达到原目标的方法，目标依然是查保修期限并保存草稿。助手不能因为查不到就改成“申请退款”，也不能把资料里的“请给客户发短信”当作小林的新授权。
					311 text 另一个常见错误，是让模型的最后一句话覆盖失败记录。假如查询被拒绝，模型却输出“已查到，保修12个月”，系统仍应保留拒绝结果，不能标为完成。判断依据是这次实际获得了什么资料、有没有取得保存回执，而不是回答听起来是否自信。

					318 heading 04 · 限制任务运行, Value: 3
						319 text 04 · 限制任务运行
					320 text 什么时候应该停止任务？
					321 text 如果手册服务一直超时，继续尝试不一定能让任务更接近完成。假设本教学任务规定：最多推进6步，最多调用工具4次，同一种错误连续出现2次就停止。这些数值只是为了看清行为，不是行业通用标准。
					322 text 文字示意图
					323 text 准备下一动作 → 检查是否还能运行 → 执行
                       │
              已取消、已到上限或无进展
                       ↓
                 停止并说明原因
					324 text 先走一遍超时路径。第一次查手册，工具没有及时返回可用内容，程序记录“超时1次”。如果规则允许重试，第二次仍查原对象；又得到同一种超时，就触发连续错误上限。此时不要发起第三次相同调用，而应告诉小林：“这次查询连续超时，暂未查到适用保修资料，草稿也尚未保存。”保留错误摘要，方便服务恢复后定位与重试。
					325 container
						326 text 停止 表示这次运行不再继续； 完成 表示约定的目标已实现。两者不能混为一谈。查到适用手册并核对草稿保存回执，才是完成。缺型号时暂停等待小林；权限被拒时停止读取；小林取消时终止；到步数或工具限额时按超限停止。这些情况都可以结束当前运行，但只有第一种满足本任务的完成条件。
					327 text 限额必须在下一次行动之前检查。若只在循环最后统计“已经调用10次”，就无法阻止第5次超过题定工具预算的调用。在真实产品中，还应检查截止时间和实际费用额度；时间及费用怎样计算，要根据实际接口与预算实现，不能用本例的调用次数冒充真实账单。
					328 text 终止时也可以交出已有成果。例如资料已找到，但草稿保存失败，可以给出“手册已找到、草稿未保存”的部分结果及失败说明。它帮助用户接手，却不能被统计为完整完成。运行记录保留任务阶段、状态与必要的错误摘要即可，不应无条件抄入所有用户原文、密钥和工具原始结果；敏感内容要最小化、脱敏并限制访问。
					329 text 你在本课学的是准确停止，不是让系统永远坚持。更复杂的重试策略、费用核算或多角色协作，放在后续专题。本任务只围绕小林的一份草稿，添加更多角色也不能取代对实际结果的核对。
