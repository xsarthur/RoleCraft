## 2. 统一的学习结构

每个岗位建立一条“共同基础 → 专业理论 → 受控作品 → 陌生迁移 → 跨岗产品创造”的路径。外部资料只是理论输入，不能直接产生能力结论。

1. **共同基础（C0–C5）**：职责和授权、任务与验收、证据与来源、版本/权限/安全、工件与交接、失败/恢复/复盘。
2. **专业理论包**：每个岗位至少三个理论域；每个理论域绑定一份主资料和一份补充资料，记录提供者、版本、访问日期、语言、费用、先修和适用边界。优先官方标准、大学课程、同行评审研究和维护良好的官方文档，再使用高质量书籍或行业课程。
3. **理论核验**：用 3–5 个机制问题、一个反例和一个取舍问题核对“读懂了什么”。只做阅读记录、课程完成或自动测验不能升阶。
4. **岗位作品**：把理论转成可交付工件，使用现有 `EvidenceCard`/练习合同，至少包含版本、来源、正常/边界/失败、交接和复验。
5. **陌生迁移**：非作者改变一个关键条件（目标、数据、权限、版本、资源、协作方或证据缺失），观察能否解释、停止、升级或修复。
6. **产品创造**：按七阶段产品创造路线连接真实问题、已有方案、差异假设、实现、可比评估、内部反馈和迭代；没有真实证据时维持 `not_assessed`。

### Agent 工程岗位的首个资料路径

`AI` 岗位以 `textbooks/v12/` 为项目内主干，按“Agent 定义与适用需求 → Python/模型基础 → 任务验收/信任边界 → 结构化输出/工具 → 检索 → 持久恢复 → 评价/安全 → 运行交付/成本”顺序学习；再补一门经版本核验的外部 Agent 课程（例如用户提到的吴恩达/DeepLearning.AI Agent 课程），并把外部课程中的演示与本项目的离线夹具、真实模型调用和生产证据分开。外部课程完成不等于本项目生成服务通过。

## 4. 专业资料卡合同

课程架构师只接收满足下列字段的资料卡，未填字段标记 `insufficient_evidence`，不直接进入正式先修：

```text
resource_id / role_id / title / provider / resource_type
url / canonical_url / source_version / accessed_at / language
cost_and_access / prerequisites / estimated_effort
theory_domains / learning_objectives / textbook_or_task_mapping
authority_reason / maintenance_or_publication_date
known_limits / disputed_or_version_sensitive_claims
theory_check / required_artifact / transfer_case / reviewer / status
```

`resource_type` 可为 `official_standard`、`university_course`、`peer_reviewed_paper`、`official_docs`、`professional_book`、`industry_course` 或 `reference_only`。每个岗位首轮目标是至少一份可公开访问的主资料和一份互补资料，主资料覆盖核心理论，互补资料用于案例、实践或反例；付费资源可以列为可选，但不能成为唯一先修。资源要记录访问日期和版本，链接失效、课程改版或 API 变化时重新复核。

## 5. 验收证据

资料目录配置和实际学习效果分开验收。

### 5.1 目录配置（可由 QA 静态核验）

- 十五个 `role_id` 均有理论域、主资料、互补资料、先修、学习产出和独立复核人。
- 每个 URL 可访问或明确标记付费/登录/区域限制，版本和访问日期可追溯。
- 资料卡有来源类型、权威性理由、适用边界、维护日期和已知限制；没有营销文案替代依据。
- 每个理论域至少映射一个练习或岗位作品；已有 v10/v12 正文的复用位置写明，不把阅读当通过。
- 资源卡、教材、岗位章程和练习合同的版本变更保留旧记录；不静默替换来源。

### 5.2 学习与能力（必须另行执行）

- 理论核验通过：能解释机制、假设、取舍和一个反例，并正确标注未知。
- 作品通过：按合同交付岗位工件，含版本、来源、正常/边界/失败和交接证据。
- 迁移通过：在非作者冻结的陌生变体中独立判断、停止、升级、修复或说明无法完成。
- 交接通过：接收岗位可复现、签收或有据拒收；独立 QA 保留首失败、返修和回归。
- 真实用户、真人专家、生产成本和行业比较若未取得，持续标记 `not_assessed`，不能由课程完成率替代。

## 6. 当前缺口、责任与下一步

1. **资料缺口**：十五岗尚无统一、版本化、可核验的专业资料目录。责任：课程架构师组织，资源研究员搜集，内容审校员核来源。
2. **等级口径缺口**：七维/L0–L4 与六维/L0–L3 并存。责任：产品经理冻结映射，QA 核合同和报告使用同一口径。
3. **岗位记忆缺口**：核心长期 `ROLE/MEMORY` 目前只覆盖部分岗位，新增七岗需要在用户确认后按同一 schema 建档；入组证据不能直接当长期专业知识。
4. **先修映射缺口**：只有 Agent 工程有 v10/v12 详细教材，其他岗位需要把外部理论资料映射到岗位工件和未知任务，而不是把 Agent 术语机械复制过去。
5. **资源质量缺口**：尚未定义链接失效、版本漂移、付费/登录限制、语言可及性和资料争议的复验节奏。责任：课程架构师制定资料卡，QA 复核访问与字段，项目经理维护状态。
6. **效果证据缺口**：目前没有十五岗 D0 诊断、理论核验、陌生迁移、真实内部反馈或真人专家复核；当前只能报告 `training_specification_ready_not_assessed`。

建议执行顺序：先由课程架构师建立 15 行资料卡清单并保留当前版本；产品经理确定首个隔离训练项目和口径映射；岗位责任人从每行选择理论主资料和互补资料；教材研发员/内容审校员将资料转成可读的理论摘要、反例和练习交接；测试工程师先做目录静态 QA，再冻结 D0 诊断和陌生任务；最后由实训评估员按作品和迁移证据判断成长状态。该顺序不把“找到了资料”写成“岗位已经学会”，也不改变现有应用或教材冻结记录。

## 7. 课程架构自查

本建议稿只读复盘了现有培养规格、岗位档案、v10/v12 教材和入组证据目录，并提出资料卡及十五岗理论主题；没有执行外部课程、没有给任何岗位授予等级，也没有修改应用/教材/数据库。结论：`met_within_architecture_scope`; 资料目录、学习者结果、真人专家意见和真实产品效果仍为 `not_assessed`。
