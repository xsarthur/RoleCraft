# 用户研究员 · user_value 专项执行材料

日期：2026-10-10；研究方案 v1，输入为 prototype-0.3。交接产品经理，独立复核交测试工程师。门槛及既有审计不变：**用户价值仍证据不足，真实研究未执行**。

## 甄别与访谈

先询问学习目的、近一次学习行为、编程/模型调用经历、已做作品和可展示证据。零基础组与有基础组分别记录，具体纳入条件及样本安排由产品经理确认；不按自称能力直接分组。剔除与目标职业无关者；团队成员、熟人及主动报名者的来源单列，避免当作代表人群。

访谈依次问：①最近一次想学习或制作 Agent 是什么情境？②具体用了什么方法，能否展示记录？③哪一步停住，当时如何处理？④实际投入多少时间或资源，哪些结果有用或无用？⑤完成后怎么判断自己能独立做产品？⑥现有方式有哪些已经满足的需求？先问过去行为，再展示原型；不问“这个先进平台是否有帮助”，不将未来使用意愿算实际价值。追问反例：不需要本网站的情况、选择已有方案的原因。

## 观察任务与依赖

阶段 A 是需求验证：参与者展示一次真实学习/制作过程，研究员记录目标、操作、困难及已有解决办法。随后用静态原型寻找适合自己的学习起点、找到练习和达标证据。说明原型没有真实生成；仅观察理解与查找，不评定学习成效。

阶段 B 是实际系统试点：必须先有可用生成服务、已核对课程、数据记录和测试验收，并由产品经理冻结试点目标与阈值。使用同一目标任务、规定帮助条件，观察起始测评、学习、独立产物、目标用户验证及再次完成未知任务；作品独立评分交实训评估员。研究员不提示答案，所有帮助记录，研究中断与未完成不得从结果中消失。

## 试点前冻结表（产品经理填写）

研究 ID／协议版本／目标人群与分组／要验证的问题与假设／招募来源及样本依据／比较对象与版本／任务及帮助条件／主指标定义与计算口径／基线与目标阈值／观察窗口／成功、失败及不足规则／异常、退出与缺失处理／负面指标／复验条件。可选指标候选包括独立任务完成、产物可运行、时间投入、错误和求助；不由研究员设通过值，不以满意度替代作品或行为。

## 非诱导证据记录模板

每条记录：研究 ID、匿名参与者 ID、分组依据、同意范围、时间、系统/协议/任务版本、原始记录位置、原话或可见行为、对应操作/产物、完成与帮助情况、错误/退出原因、研究员解释、竞争解释、待核对项。原话与解释分栏；没有记录填“缺失”，不补造回答。分析同时保留支持、反对、失败与未知，报告每组实际参与及缺失情况，说明样本来源和适用范围。

记录前取得参与及录制同意，分别确认使用和保存期限；不同意录制可使用获准笔记，退出记录范围和处理结果。去除非必要身份信息，原始证据受控保存，报告使用匿名 ID；原始记录、分析和修改历史保持可追溯，不覆盖旧版结论。
