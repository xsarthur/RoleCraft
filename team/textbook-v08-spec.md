### 主夹具冻结与局部变体

同一 `repo@8e12/test-report-71` 不得在不同章指向不同测试事实。本轮统一：可信租户 `tenant-dev`，可写项目 `refund-maintenance`；源路径 `src/refund.py`，完整文件为 `def refund(days):\n    return days < 7\n`；失败断言 `test_refund_day_7` 输入 `days=7`，报告 expected=True、actual=False。源片段引用ID `repo@8e12:src/refund.py:1-2`，失败记录引用ID `report-71:failure-1`。这是报告给定事实，不能据此虚构真实业务退款规则或根因已证实。

权限/缺证/旧版本/并发等可作为同一主夹具的 case 变体，但要带独立 `case_id`、明确改变哪些输入、批准或权限。新增测试/源文件内容应给新的对象ID；若改为 parser 等其他案例家族，就换 repo/report ID并说明与主案例关系，不能复用 `test-report-71`。v0.7未固定具体失败文件，可直接兼容本主夹具，原文不改。源内容哈希由给定完整UTF-8内容计算，不编造；模型看到的片段可以无末尾换行，但引用完整文件哈希仍来自源读取结果。

- 保留 `read_source`、`read_test_report`、`create_issue` 工具意义。源代码和测试日志是数据，不是权限或系统指令。若需增加检索层或模型适配接口，明确它是内部组件，不任意扩充本轮业务动作。
- `principal/tenant_id/project` 的可用范围由可信宿主身份及策略派生。具体租户可用 `team-runtime` 与 `team-secret` 表达授权对照，不用A/B代号；模型参数不能改可信身份。
- `tool_call_id` 是本次模型调用协议关联；`action_id` 是持久逻辑意图；`attempt_id` 是一次发送尝试；`intent_hash` 绑定不可变参数；同一唯一 `effect_slot` 同指纹可复用原动作，不同指纹冲突。v0.7相同词不可在别章变成别种语义。
- `status` 是调度进度；`effect_resolution` 是外部效果核对；`READY + UNRESOLVED`可能共存。未知效果不是已失败且未写入；恢复先核对，不能先让模型重新造一条副作用。
- 写前持久意图、发送前记录未决、结果和状态事务提交；本地事务/租约/栅栏不保证远端恰好一次。本章可以用隔离临时存储/无网络替身演示，但不把它的原子性扩展到真实外部服务。
- 审批绑定准确动作、对象、正文/证据指纹、工具版本和期限；本地单次消费用于新意图与原动作合法核对重发必须区分，v0.7的恢复许可沿用原键/原参数。取消停止新工作，迟到成功仍要核对效果。

### f01 · 实现可复现、可判错的外部 API 边界

正文路径：`textbooks/v08/f01.md`。

唯一核心问题：**怎样把类型不可信、网络会失败的外部请求，变成可校验、可判错、可复现的小服务？**

原先修：无。原能力域：software。创造阶段：mvp。

原目标保持：
- `f01-o1`：实现输入校验、异常处理与 API 请求。
- `f01-o2`：使用 Git、依赖锁定和测试复现服务。

知识点去向（能力保留，正文自由组织）：
- `f01-k01` 输入类型与非法输入 → 输入边界与类型/语义校验。
- `f01-k02` HTTP请求与失败分类 → HTTP 状态、网络失败与解析分层。
- `f01-k03` 依赖与版本复现 → 可复现运行与依赖/Git 交接。
- `f01-k04` 测试断言与变更记录 → 测试断言、固定夹具与变更追踪。

主线机制：
- 请求进入时的类型、长度、编码与语义校验；错误分类必须保持调用事实，不把 timeout 当 not_found。
- 不可变修订的读取请求/响应结构、成功和业务错误、连接失败/超时的不同返回。
- 依赖和运行时版本、Git 提交、测试输入和断言构成他人复现链；配置不把秘密写入样例。

必要实现：
- 定义 ReadSourceRequest/ReadSourceResult 与可观察错误码，principal 不从请求正文接受。
- 给出小而完整的请求处理或客户端实现：正常输入、拒绝非法输入、非成功 HTTP、解析错误、超时，不用 catch-all 静默默认成功。
- 给出固定夹具的测试断言、运行命令和环境交接；选可运行代码须说明版本/依赖，未运行如实标注。

必须分析的失效条件：
- 列表当路径、空或超长输入、修订缺失被默认成最新、403 被重试、超时被伪造读到资料。
- 另一环境启动失败：定位运行时/锁定依赖/配置/工作目录，不能只补一张成功截图。

必须给出条件判断的取舍：
- 请求失败向上层抛异常或归一化为结果联合类型的边界；超时和自动重试的前提，只读不等同无限重试。
- 标准库小示例与依赖库客户端的成本；锁版本和允许版本范围如何影响复现。

练习与参考分析：先修补非法类型/超时误判，再独立实现接口与固定断言，最后改变字段/修订/环境定位兼容问题。参考分析解释错误应在哪层产生，交接缺哪类证据。

产物及验证保留：命令行或 API 服务；有效与非法输入测试；环境和提交记录。原验证约束：陌生环境启动；解释至少一种异常路径。这些是学习者提交/检查要求，本轮正文没有学习者执行证据。

本章交接边界：f01 没有原模块先修。附独立且可操作的基础补学入口，覆盖变量/函数/列表字典、JSON、命令行、请求响应和断言；给诊断任务与参考分析，未通过者不能靠自报基础跳过。不要把专业主线改写为长篇科普。

### f02 · 把模型响应变成可验收的候选结果

正文路径：`textbooks/v08/f02.md`。

唯一核心问题：**怎样在响应可能拒绝、截断、结构合法但业务错误时，可靠接收一次模型调用的候选结果？**

原目标保持：
- `f02-o1`：完成真实模型调用及结构与业务双重校验。

知识点去向（能力保留，正文自由组织）：

- `f02-k02` 结构与业务双重校验 → 结构合法与业务有效的双重校验。
- `f02-k03` 可信指令与外部资料 → 指令/用户/工具资料的信任分层。
- `f02-k04` 上下文预算与缺信息 → 上下文预算、压缩不变量与缺信息处理。

主线机制：

- 结构校验和业务校验分别负责语法契约、对象归属/修订/证据支持，后者不被 schema 替代。

- 定义 ModelRequest、ModelOutcome（complete/refused/incomplete/protocol_error/transport_error）、Candidate 与 ValidationVerdict。

- 实际 API 示例只有核当前官方资料及版本后才能采用；允许自定义接口但不能冒充 SDK。给真实调用所需配置、执行作业和记录方法，不执行付费模型调用。

- 完整 JSON 的 repo/修订归属错误、引用片段不足支持根因、模型返回半响应被 parse 后接受。
- 压缩丢掉关键例外/审批/已执行动作；外部源文件自称系统指令；超限后无界追加重试。

必须给出条件判断的取舍：
- 完整上下文与证据投影的准确性/成本/审计取舍；结构输出与后验解析均仍需业务检验。
- 单次响应失败重试、请求澄清和拒绝的判定，重试计数和预算不重置。

练习与参考分析：给完整、截断、拒绝、对象错位和缺证夹具进行归一化；独立接供应商适配记录实际响应状态与用量；迁移到更长报告时证明必要事实仍在上下文。公开答案不算保留测试。

产物及验证保留：请求与响应示例；缺失信息处理；超时和成本记录。原验证约束：校验格式合法但业务无效的数据；解释上下文截断风险。这些是学习者提交/检查要求，本轮正文没有学习者执行证据。

本章交接边界：原 f02-o1 是真实模型调用，不因本轮无配置/预算降低成离线替身即达成。教材解释实现与练习方法；作者正文未实际调用必须明说，真实调用证据仍待学习者或授权运行产生。

### c01 · 按任务不确定性选择最小可行方案

正文路径：`textbooks/v08/c01-solution-selection.md`。

唯一核心问题：**怎样证明缺陷分析任务需要动态 Agent，而不是普通程序、单次模型、固定 workflow 或额外协作 Agent？**

原先修：f02。原能力域：model-context, tools-state。创造阶段：baseline, mvp。

原目标保持：
- `c01-o1`：按任务不确定性选择固定流程或动态决策。
- `c01-o2`：根据工具反馈决策并设置停止预算。

知识点去向（能力保留，正文自由组织）：
- `c01-k01` 单次调用与工作流基线 → 单次/普通程序/workflow 可比基线。
- `c01-k02` 动态循环与复杂度取舍 → 动态控制判定与复杂度选择。
- `c01-k03` 行动观察与重规划 → v07 的反馈/验收拒绝/再规划，补篇只给选型关联。
- `c01-k04` 停止预算与协作边界 → v07 的预算/停止；补篇的单/多 Agent 协作合同与代价。

主线机制：
- 判断标准是控制权和新观察是否改变下一行动，不数模型调用次数。
- 同一 TaskContract 和完成语义下比较普通程序、单次模型、固定 workflow、单 Agent；单/多 Agent 只在交接可带来实质收益时展开。
- 材料齐备、缺证需要动态读取、证据冲突需澄清是可区分的输入条件；方案复杂化须有可比收益证据。

必要实现：
- 定义统一 TaskContract/InputSnapshot/TaskResult（accepted/needs_input/blocked/failed）以保持各基线可比。
- 给固定流程完整决策骨架：校核快照/证据→分析→业务校验→审批等待→创建/核对→验收；失败/缺证/无批准分支不能跳过。
- 动态执行机制直接衔接 v07，不重复编一套不同动作身份；比较实验固定材料、权限、验收、资源和模型配置，给记录格式不造成绩。
- 多 Agent 分工契约说明证据版本、任务产物、唯一写所有者、总预算、失败交接/取消；不允许多个角色各自建单。

必须分析的失效条件：
- 固定 workflow 缺明确分支却声称任意适应；给动态方案更多资料或预算造成伪优势。
- 第二位 Agent 接过已过期快照、没有验证来源就放大错误、双写槽位、只算主 Agent 成本。

必须给出条件判断的取舍：
- 固定路径测试/延迟/维护代价与动态循环适应/不确定性；何种新增任务分布证据足以升级。
- 单 Agent 与多 Agent 的上下文隔离/专业分工收益对照交接丢失、协调延迟、总成本、误差放大；给明确放弃条件。

练习与参考分析：在三类给定任务条件下选择方案并指出反例；独立设计同条件基线实验；迁移增加角色时给失败交接和唯一写所有者，解释是否值得。

产物及验证保留：两种方案比较；执行轨迹与停止说明。原验证约束：正常、工具失败和预算耗尽场景；说明复杂度与效果取舍。这些是学习者提交/检查要求，本轮正文没有学习者执行证据。

本章交接边界：这是原 c01 的补篇，不替代或修改 v07。它补足 v07 §12 未详细承担的可比基线实施及角色协作判断。原 c01-o1 由本补篇主讲，c01-o2 由 v07 主讲，二者共同组成一个原模块。

### c02 · 构造可追溯且符合权限的检索证据包

正文路径：`textbooks/v08/c02.md`。

唯一核心问题：**怎样把仓库和测试资料检索结果变成符合修订、权限与支持范围的证据包，使回答有据或明确无据？**

原先修：f02。原能力域：retrieval-data, model-context。创造阶段：baseline, mvp。

原目标保持：
- `c02-o1`：记录数据来源、版本与访问范围。
- `c02-o2`：比较检索策略并验证引用与无答案行为。

知识点去向（能力保留，正文自由组织）：
- `c02-k01` 文档版本与可读范围 → 文档/索引版本和可信查询范围。
- `c02-k02` 片段与证据归属 → 片段 provenance 与引用支持边界。
- `c02-k03` 词法与语义检索比较 → 精确/词法/语义或混合的可比检索。
- `c02-k04` 冲突和无答案 → 冲突、过期、无答案与无权限的不同决策。

主线机制：
- 文档摄取、不可变版本、分块、权限元数据和索引发布版本共同决定可检索集合。
- 检索命中和证据支持不同；citation 指到内容哈希/修订/位置并校核对主张的实际支持。

知识点去向（能力保留，正文自由组织）：
- `e05-k01` 任务成本与单位 → 每任务/每成功任务成本和成本组成。
- `e05-k02` 延迟分布与失败分母 → 延迟分布、尾部、失败分母和删失。
- `e05-k03` 缓存与模型选择比较 → 版本/权限安全缓存及模型选择比较。
- `e05-k04` 并发预算与资源取舍 → 并发、限流、预算与资源约束。

主线机制：
- 成本单位是任务或成功任务：模型、工具、失败/重试和必要人工均需说明统计范围。
- 用户端到端延迟、排队、执行各层分布；成功/取消/超时/未决的分母与删失状态不能混算。
- 缓存键的身份/权限/资料/模型/tool版本与失效，routing和并发改动都受质量及安全护栏。

必要实现：
- 定义 Workload、TrialAccounting、LatencyObservation 与 PerformanceComparison，给任务成本/成功任务成本/吞吐/延迟口径。
- 给冻结工作负载、预热与冷缓存、重复测量、总预算、失败类别和质量指标共同汇总的实验路径。
- 缓存 lookup/验证/失效/拒绝复用逻辑，或受预算/限流的调度机制至少一个讲到关键实现；不能只列优化名称。

必须分析的失效条件：
- 只看模型单价、失败成本出分母、成功p95被当全任务体验、只展示最优一次。
- 新修订命中旧缓存、跨租户缓存、并发放大限流与重试、路由便宜模型破坏引用或审批质量。

必须给出条件判断的取舍：
- 同步/异步/并发与排队/限流代价，吞吐和尾延迟不是同指标；预算公平性与资源预留。
- 缓存命中率/正确性、模型路由/质量和维护代价；没有实测价格/负载不给数字结论。

练习与参考分析：纠正分母/预算遗漏报告；独立比较至少两种合理路径且记录相同质量护栏；迁移旧缓存与高突发负载解释收益何时失效。所有演算数据必须标虚构非账单。

产物及验证保留：负载条件；p50/p95 延迟、成功率与成本报告；优化前后比较。原验证约束：注明模型、样本、重复次数与限制；不得只展示最优单次结果。这些是学习者提交/检查要求，本轮正文没有学习者执行证据。

### p01 · 把真实问题证据转成可证伪的 MVP 契约

正文路径：`textbooks/v08/p01.md`。

唯一核心问题：**怎样从目标用户的真实任务与替代方案出发，决定值得实现的 Agent MVP，并用契约和架构决策解释取舍？**

原先修：c01, e02。原能力域：product-collaboration, software。创造阶段：discover, hypothesis, mvp, usage, iterate。

原目标保持：
- `p01-o1`：把用户问题映射为可衡量的技术任务。
- `p01-o2`：通过架构评审和文档解释取舍。

知识点去向（能力保留，正文自由组织）：
- `p01-k01` 真实问题与作者假设 → 真实问题、观察/解释/假设的证据链。
- `p01-k02` 行业基线与差异假设 → 行业替代基线与可证伪差异假设。
- `p01-k03` MVP范围与架构决策 → MVP任务范围、ADR和架构评审。
- `p01-k04` 协作交接与用户反馈 → 业务/技术交接、真实采用反馈与修订。

主线机制：
- 用户原话/行为、研究解释和作者假设分开；问题真实不自动说明应做Agent。
- 代表性人工/普通程序/单次模型/行业方案基线，冻结对象/版本/任务/资源，提出可被结果推翻的差异假设。
- MVP只实现检验假设所需路径，技术与业务文档指向同一任务/指标/边界；评审反馈改变版本。

必要实现：
- 定义 ProblemEvidence、AlternativeBaseline、ValueHypothesis、TaskContract、AcceptancePlan 与 ArchitectureDecision。
- 给从观察→假设→事前主指标/护栏/停止条件→最小任务范围→架构取舍→真实使用观察的推导实例；虚构材料不能伪装访谈。
- 架构评审输入、决策理由/反例/拒绝项和复现/使用/维护文档结构写成可用示例，非空表。

必须分析的失效条件：
- 自己故事冒充用户证据、对照宣传而非运行、假设不可证伪、选择框架先于问题。
- 用户不用但只改UI、无反证渠道、非作者无法复现、工程指标达成却真实工作负担增加。

必须给出条件判断的取舍：
- 访谈/观察/试用与受控比较的证据强度不同；小试点不能授市场因果或领先。
- 普通程序/固定 workflow/MVP 单Agent在交付复杂度和验证能力的选择；针对技术与业务受众保持事实一致。

练习与参考分析：修一份无证据问题和不可证伪假设；独立取得真实问题/替代证据并冻结MVP契约与ADR；迁移负面使用反馈修改假设或停止，不以模拟受访者冒充真实研究。

产物及验证保留：场景和任务标准；架构决策与评审修改；使用与维护文档。原验证约束：非作者根据文档复现；向技术和业务受众解释同一方案。这些是学习者提交/检查要求，本轮正文没有学习者执行证据。

本章交接边界：保留从0到1七阶段：发现/行业基线/差异假设/MVP/质量经济评价/真实使用/迭代。p01讲决策链，e02/e05承接评价，p02承接完整交付；真实证据待学习者取得，不给模板填假用户数据。

### p02 · 用可复现作品证据完成交付判定与复盘

正文路径：`textbooks/v08/p02.md`。

唯一核心问题：**怎样让独立评阅者根据可复现作品、真实使用和迁移证据作出有限交付结论，并验证一次改进确实关闭了原失败？**

原先修：e01, e03, e04, e05, p01。原能力域：software, model-context, retrieval-data, tools-state, eval-safety, operations, product-collaboration。创造阶段：usage, iterate。

原目标保持：
- `p02-o1`：整合证据并完成外部评审。
- `p02-o2`：用失败分析改进并迁移到未知任务。

知识点去向（能力保留，正文自由组织）：
- `p02-k01` 作品证据与外部评审 → 可复现作品证据与外部专业评审。
- `p02-k02` 真实使用与比较局限 → 真实使用、可比先进性和小样本局限。
- `p02-k03` 失败复盘与二次验证 → 失败归因、改进、原例复验及回归。
- `p02-k04` 未知任务与能力边界 → 非作者未知任务迁移及有限能力结论。

主线机制：
- 一个证据包把目标/版本/运行/业务结果/基线/反馈/成本/安全/专业评审关联，报告不是证据本身。
- 作品任务达标、职业能力和行业先进分别判定；先进性须代表性方案、可比条件、真实价值和独立专业证据。
- 失败→可检验原因假设→单次改动→相同条件复验+回归+未知任务迁移；原问题不因新报告自动关闭。

必要实现：
- 定义 DeliveryBundle、EvidenceIndex、GateVerdict、IssueRecord/RetestRecord 与 IndependentTask。
- 给可复现工件入口/环境/夹具/结果绑定及评阅流程，结论可为任务通过/失败/证据不足；未知任务由非作者安排。
- 完整复盘例子包含失败事实、竞争原因假设、干预选择、原例复验、回归、新任务和残留边界；题定结果明确非运行。

必须分析的失效条件：
- 启动成功但无业务回执、无网络替身当真实工具、两人满意当领先、原报告复用为新版本审核。
- 公开解答当未知迁移、只修提示不复测、修一项安全回归、无法重现被包装为通过。

必须给出条件判断的取舍：
- 交付速度与证据充分性；接受有限场景任务与拒绝过宽认证的不同结论。
- 自动评判/外部专业/真实学习与市场证据不能相互顶替；未获评审时保留待审而非猜评分。

练习与参考分析：审一份缺证交付包并登记开放缺口；独立交付可部署作品及真实比较/使用/外部审查记录；非作者给新资料/约束安排未知任务，二次验证并解释当前边界。参考方案是评阅思路，不代学员产证据。

产物及验证保留：可部署作品；完整评价报告；复盘与二次验证；独立任务答辩。原验证约束：按项目量规评审；保留案例与修改任务；说明当前适用边界。这些是学习者提交/检查要求，本轮正文没有学习者执行证据。

本章交接边界：原量规与产品八门槛均不改。教材演算/AI审校/任务完成不产生职业认证。p02必须明确何时是失败、何时只是证据不足，不能为当前教材项目写虚构通过案例。
