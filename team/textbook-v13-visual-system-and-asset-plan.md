# Agent 教材 v13 视觉系统与配图资产计划

设计岗位交接；2026-10-16（Asia/Shanghai）；版本 `v13-visual-system-1`。

## 目的与范围

本计划把 v12 Agent 教材的视觉经验整理为可复用的编辑、产品、设计、开发和测试交接规则。目标是让读者更快看出对象、顺序、控制权、证据和失败边界，减少长篇连续文字的阅读负担。它只规定视觉输入和资产规格，不自行决定课程顺序、路线状态、产品范围或功能门槛；产品经理确认产品语义，课程架构师确认教学来源，设计师负责画面，开发负责渲染，测试负责独立复验。

不修改 v12 正文和应用代码。下表中的“计划”不是已完成资产；已存在的 v13 图稿需继续标注版本、来源和验证状态。

## 统一视觉语法

### 颜色角色

| 语义 | 主色建议 | 非颜色编码 | 使用限制 |
|---|---|---|---|
| 输入/事实/来源 | 靛蓝 `#3157A6` | 圆角矩形、来源标签 | 表示材料，不表示可信结论 |
| 控制/决策 | 紫 `#6B4FA1` | 菱形或决策框 | 只表示谁作决定 |
| 运行/处理中 | 琥珀 `#B87500` | 虚线边框、时钟/等待标签 | 不表示成功 |
| 证据/已核对 | 绿色 `#287A52` | 勾选徽记、实线边框 | 仅用于有绑定证据的状态 |
| 风险/需处理 | 红 `#B23A3A` | 警示图标、粗边框 | 不用作装饰，不与成功只靠颜色区分 |
| 未知/未验证 | 灰 `#667085` | 斜线填充、`未验证`文字 | 不可写成失败或成功 |

同一套图内保持颜色含义一致；任何关键关系至少同时用文字、位置、形状或线型表达。正文颜色只用于标题条、侧卡和状态徽记，避免大面积高饱和背景。灰度、色盲和低亮度环境下仍须能读出关系。

### 连接、节点和文字

- 连线从节点留白区出发，箭头尖端落在边界，不穿过标题、正文、图例或状态标签；跨区关系改用绕行、编号或分段。
- 节点按最长已确认文案预留内边距；文字变长、字体放大或窄屏时改为纵向卡片，不压缩到不可读。
- 每张图都有标题、短文字替代和图例；文字替代描述“谁通过什么关系到达什么结论”，不能只写“见图”。
- 图内真实运行、教学构造、伪代码和未验证状态分开标注。

### 章节节奏与数量

每个单元最多配置：**1 张开篇定位图 + 2 张中段解释图 + 1 张练习/复盘卡**。普通单元建议开篇 1 张、中段 1 张；只有机制转折或多状态章节才使用第二张中段图。连续两张图之间至少有一个解释段或练习提示，避免把文章变成图册。长代码超过 10 行默认折叠，折叠摘要须说明用途、语言、行数、输入/输出和验证状态；折叠是跨端功能，须走产品、设计、开发、测试合同。

## 图形类型选择

| 图形 | 适合回答的问题 | 典型章节 |
|---|---|---|
| 流程图 | 下一步由谁决定、分支何时发生 | 选型、固定流程、发现、MVP |
| 时序图 | 事件先后、提交点、等待和恢复 | 控制循环、持久状态、运行时、API |
| 边界图 | 哪些数据/权限可以跨越哪条边界 | 信任、权限、沙箱、工具、写入 |
| 对照卡 | 方案差异、收益、代价、升级条件 | 选型、规划策略、评估、成本 |
| 证据链 | 结论如何绑定来源、实验和作品 | 任务验收、检索、评估、交付 |
| 状态卡 | 当前状态、允许动作、未知和失败 | 控制循环、图编排、长任务、回退 |
| 结构/生命周期图 | 对象从创建到更新、过期、恢复 | 记忆、检索摄取、版本发布 |

## 跨岗位交接与验收

- **课程架构师**：确认图表达的能力目标、先修关系和章节来源；不得借图新增课程门槛。
- **产品经理**：确认图是否表达产品已有对象、流程和状态；决定是否进入产品功能或仅为教材静态图。
- **教材研发员**：提供图前后的解释任务、关键文案、代码摘要和证据状态；长代码按跨端折叠合同标注。
- **设计师**：绘制源文件、文字替代、颜色角色、响应式变体和箭头避让说明。
- **软件工程师**：若进入工作台，实现图片、折叠、锚点和降级；不把静态示意当真实运行状态。
- **测试工程师**：独立检查实际渲染、箭头与文字重叠、字体回退、窄屏、键盘/读屏、灰度和状态辨识。
- **项目经理**：维护版本、依赖、责任、复验和未验证项；不替岗位做产品或设计决策。

每张图的最小验收记录包含：`目标读者`、`要回答的问题`、`绑定章节`、`状态来源`、`颜色/形状图例`、`文字替代`、`桌面/760px/窄屏预览`、`长文和长标签检查`、`未验证项`。没有实际渲染和独立复验，不写成已通过。

## 可迁移的编辑经验

1. **先画关系再补解释**：如果一段文字描述了顺序、边界、状态或比较，优先判断是否能用流程、时序、边界或对照卡表达。
2. **图服务于一个阅读任务**：每张图只回答一个主要问题；标题用结论或动作，不用抽象装饰名。
3. **中段图承担转折**：图放在机制改变、失败分支、证据交接或练习开始前，不能只在文章开头放一张总览图。
4. **视觉不能掩盖证据缺口**：示意图、伪代码、真实运行和未验证状态必须分开；颜色和勾选不能制造“已通过”印象。
5. **彩色与可读性一起验收**：颜色有语义并有形状/文字重复编码；先看灰阶、窄屏和放大，再看美观。
6. **编辑与产品边界分开**：编辑提供教学关系和素材，产品决定功能范围，设计决定表达，开发实现，测试复验。编辑不能自行决定路线图显示内容或把静态图变成应用功能。
7. **保留可观察证据**：每个视觉资产都有版本、来源、状态、预览和复验记录；真人反馈单独记录，不能从图稿通过推断学习效果。

本计划服务后续任何职业教材：替换单元主题、证据和案例即可复用颜色角色、图形选择、箭头避让、文字替代、窄屏和跨岗位交接规则。职业领域的事实、案例和验收标准仍由对应课程与产品岗位确认。
