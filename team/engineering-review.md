# 软件工程师 · 技术审查与实现交接

日期：2026-10-10。唯一责任领域：软件实现与技术方案。输入：工作区 `AGENTS.md`、项目 `README.md`、产品／课程／设计审查，以及 `dist/index.html`、`dist/app.js`、`dist/styles.css`。

本轮仅阅读源码与提出实现建议，没有修改应用、执行开发自检或独立验收、访问浏览器、调用模型、核验外部资料或发布网站。以下技术方案尚未实现，也不代表产品范围已获确认；未选择付费模型或服务。

## 1. 当前软件事实

| 部分 | 源码可见事实 | 实际边界 |
| --- | --- | --- |
| 应用形态 | 3 个静态文件；原生 HTML、CSS、JavaScript；README 使用本地静态 HTTP 服务启动 | 项目目录中没有后端、数据库、模型适配器或生成 worker |
| 教材与来源 | `app.js` 内嵌 8 个章节对象、2 个项目对象、3 个官方参考链接 | 教材为固定内容；来源日期是固定标签，没有逐条核验或版本快照 |
| 路线 | `route()` 根据自报基础选择固定章节；目标主要改变文案；工时按固定章节时间累加 | 没有能力诊断或根据学习证据调整内容的逻辑 |
| 学习记录 | `rolecraft-v1` 的 localStorage 保存 profile、passed、checks、notes、lastLesson；加载时校验部分字段，备注最多 12000 字符 | 当前浏览器与来源内保存；没有账户、跨设备同步、版本化学习证据或评审记录 |
| 导航与输出 | 5 个 hash 页面；切换用 `history.replaceState`；按模板写入 `innerHTML`；代码及作品备注经过 HTML 转义；Blob 导出 Markdown | URL 未定位教材版本和章节；导出是计划文本，不是完整备份／恢复功能 |
| 网络与执行 | 应用脚本没有模型请求或资料检索调用；CSS 引入外部字体；来源链接可打开外部网页 | 没有代码执行、自动批改、作品接收或专家审核功能 |

源码观察的工程关注点（未作为已复现缺陷）：

- `storageAvailable` 在读取／保存失败后置为 false，后续保存成功未恢复；目前状态提示与真实最近写入结果可能不一致。保存提示也主要是短暂 toast，应按设计交接改为就地、持久且准确的状态。
- `checks` 与 `notes` 只做对象级检查，项目检查项没有完整的 ID／范围清理，进度按数组长度计算。未来服务端契约应验证已知项目、检查项及字段大小，不能直接信任导入或客户端数据。
- `passed` 记录只关联章节 ID，未关联教材版本。重新生成或更新课程后不能直接把此数组视为新版通过，更不能视为职业能力证据。
- 大部分静态正文目前直接插入模板。未来接入模型、来源或用户文本时，必须使用受控结构和安全渲染；当前针对代码与备注的转义不能代表全链路已处理动态内容。

### 独立 QA 缺陷输入

项目经理转交的测试工程师执行摘要为：22 项逻辑检查中有 5 项失败，涉及历史导航、异常存储导致导出报错、重复／越界记录及保存恢复状态。这属于独立 QA 的缺陷输入；本工程岗位尚未读取完整复现证据或复核，不将该摘要称为自己的测试结果。正式缺陷编号、环境、步骤和预期结果以测试工程师报告为准。

建议下一阶段先由工程师复核并修复原型可靠性，再开始真实生成：恢复正确导航历史；为载入／导出的 notes、checks 等数据补齐类型和范围校验；清理重复及越界记录；让最近保存成功／失败状态准确恢复。修复范围对应产品与设计交接，工程师完成开发自检后交给测试工程师独立复测，不自行关闭验收结论。本轮未修改代码。

## 2. 最小实现的模块建议

依据产品经理的“一个真实章节＋一个作品”的 MVP 建议，采用可观察的固定生成流程。首个主题、教学正文、诊断及评审门槛由课程责任人提供；工程岗位只实现数据与执行机制。

| 模块 | 建议职责 | 前置输入 |
| --- | --- | --- |
| 学习前端 | 档案、路线、任务状态、章节阅读、版本查看、作品提交与反馈展示 | 产品流程、设计状态规范 |
| 应用 API | 登录会话、账户隔离、输入校验、学习记录、任务创建、作品与评审读取 | 账户／评审角色及访问规则 |
| 教学目录 | 读取不可变能力标准版本、先修关联、章节模板、练习及评分量规 | 课程团队结构化教学契约 |
| 受控资料层 | 保存允许的来源、检索／收集时间、原文位置、版本和片段快照；生成只引用本次提供的片段 | 课程团队允许来源与引用标准 |
| 生成 worker | 持久化阶段执行、模型调用、结构校验、引用关联、恢复及预算记录 | 已确认单章生成模板与模型接入授权／配置 |
| 审核与版本 | 分别记录事实核对、示例运行、教学审核、专家审核及发布门槛 | 有资格的审核人、门槛及审核流程 |
| 作品与反馈 | 保存用户提交的链接、运行证据和说明；保存带评分依据的 AI 建议及人工评审 | 项目任务、量规版本、反馈规则 |

首期可用一个应用服务、一套事务存储与一个独立 worker。生成任务通过数据库任务表及租约领取运行，暂不必引入多代理框架、向量库或独立队列产品；这些是实现建议，需结合部署约束最终确定。长时模型调用不占用浏览器请求，前端通过任务查询恢复状态。若后续使用专用队列，业务任务记录仍须持久化，不能只依赖队列消息。

资料层首期可接收课程责任人核对后的官方资料快照，或接入范围受限的收集器；两种来源应明确标注，不能把手动导入称为自动联网核验。检索日期使用实际收集时间；原文发布日期未知时保存未知值，不补造日期。

## 3. 数据与接口契约建议

所有 ID、枚举、字段大小、关联及权限在服务端验证；用户身份来自会话。客户端不能指定其他用户 ID、审核通过状态或发布结果。

| 数据对象 | 最小字段／关系 |
| --- | --- |
| 用户与档案 | user_id、基础／目标／时间、profile_version、updated_at；自报字段与诊断证据分开 |
| 能力标准／章节模板 | occupation_id、standard_version、competency_id、prerequisite_ids、chapter_template_version、目标、练习及量规版本 |
| 资料与片段 | source_id、source_version、URL、标题、published_at／updated_at（可未知）、retrieved_at、适用环境、内容哈希；snippet_id 与原文定位、快照 |
| 生成任务／尝试／事件 | job_id、user_id、输入快照、标准／模板／资料／提示模板版本、idempotency_key、status；attempt_id、阶段检查点、租约、次数、时间与错误；有序事件 |
| 章节版本 | chapter_id、chapter_version_id、parent_version_id、job_id、attempt_id、内容哈希、结构化正文、学习目标、先修、练习、引用主张与片段映射、变更摘要 |
| 审核证据 | chapter_version_id、审核类型、实际执行者／角色、范围、结果、证据引用、环境／工具版本、时间及未解决项 |
| 学习记录 | user_id、chapter_version_id、记录类型、练习／概念题结果、时间；概念通过与能力评审分表或分类型 |
| 作品／评审 | submission_id、user_id、项目／量规版本、目标能力、作品链接及证据快照；review_id、提交版本、评分项、理由与证据、评审来源类型、结论 |

建议接口（路径为待实现契约，不是现有 API）：

- `GET /api/me`、`GET /api/profile`、`PUT /api/profile`：读取／更新档案，更新携带版本号以检测并发覆盖；登录／退出流程在账户方案确定后细化。
- `GET /api/occupations/agent-developer/standards`、`GET /api/learning-plan`：读取标准与路线依据。诊断接口及题目规则待产品、课程交接后定义。
- `POST /api/generation-jobs`：提交章节主题、档案版本及标准版本，携带幂等键；返回 `202`、job_id 与状态地址。不得立即返回虚构教材或把静态样例作为成功产物。
- `GET /api/generation-jobs/{job_id}`：返回真实阶段、更新时间、attempt_id、可读产物、错误代码及是否可重试；首期可用轮询，不估造完成百分比。
- `POST /api/generation-jobs/{job_id}/retries`：新增尝试及事件，保留原尝试与旧产物；如改用新档案／资料／模板，建立关联的新任务，避免输入含义悄然变化。
- `GET /api/chapters/{chapter_id}/versions/{version_id}`：返回固定版本及独立审核字段，旧版本可回看。
- `PUT /api/learning-records/{record_id}`：服务端校验记录关联和所属账户，按版本处理保存；重复提交不重复计数。
- `POST /api/submissions`、`GET /api/submissions/{submission_id}`：保存版本化作品证据及反馈；链接首期作为用户提交证据，不自动抓取或执行任意仓库。
- `POST /api/chapters/{chapter_id}/versions/{version_id}/reviews`、`POST .../publication`：仅授权审核／发布身份可执行，服务端检查完整证据和相应权限。发布权限与来源门槛需由项目经理协调产品／课程确认。

API 错误统一返回 request_id、稳定 error_code、用户可理解的 message、retryable；完整服务错误仅在受控日志内保存。模型凭据只在服务端配置，不写入前端、课程、导出或用户可见日志。

localStorage 迁移需显式显示来源与导入范围：可将已有自报档案、概念结果与备注导入当前账户并标为“原型本地记录”。不自动提升为诊断、正式作品或能力评审；保留原本地副本，并将旧课程明确映射为原型 v0.1，而非套到新生成版本。具体导入是否纳入首期由产品经理确定。

## 4. 生成任务、失败与版本处理

建议单章流水线：冻结输入及版本 → 加载／收集受控资料片段 → 按教学模板规划本章 → 生成结构化章节草稿 → 校验结构及引用位置 → 保存草稿与独立核验记录 → 等待对应审核 → 达到门槛后发布固定版本。

“引用 ID 存在”只说明关联成立，不证明原文支持论断；自动检查可提出待复核意见，事实支持判断按课程标准记录。示例运行若未安排实际受控执行，状态必须是“未执行”；伪代码记录类型并按课程规则使用“不适用”。专家审核只能由符合要求的实际评审者执行，模型自检存为 AI 检查。

执行状态建议为 `queued → running → succeeded / failed`，中断可记录 `interrupted` 并经租约恢复。同一章的生成成功仅表示草稿已保存；事实核对、示例运行、教学／专家审核各自有独立状态与证据，发布状态另外记录 `draft / published / superseded`。整本教材的部分完成由每章实际状态汇总，不将一个章节完成表述为全书完成。

| 异常 | 建议行为 |
| --- | --- |
| 断网、模型超时、限流或临时错误 | 有次数、时间与费用上限的退避重试；持久化尝试和阶段，不丢失已保存产物 |
| 资料不足、引用不支持或章节结构不合法 | 保存问题与草稿；按规则有限修复或进入待处理。资料不足须补齐输入，不通过盲目重复调用宣称解决 |
| 凭据／配置错误、预算耗尽 | 停止并返回可理解原因；由相应责任人处理，不能无限自动重试 |
| worker 进程终止 | 租约过期后领取检查点；版本保存有唯一约束和事务，重复 worker 不能保存重复章节或覆盖新版 |
| 保存成功但响应中断 | 按幂等键返回已保存任务／结果；模型外部请求可能再次发生，不能承诺外部调用恰好一次，记录可能的重复费用 |
| 用户重复点击或并发提交 | 按账户＋幂等键去重；同键不同输入拒绝；状态查询恢复同一任务 |
| 审核未通过或来源过期 | 保留意见、原版及学习记录；新增修订版或复核标记，不改写原来审查历史 |
| 学习保存冲突或失败 | UI 保留未保存输入并持久提示；按记录版本处理冲突，不静默覆盖另一设备记录 |

模型输出和远程资料始终作为数据处理：限制结构、长度、资源链接协议与来源范围；生成文本采用安全 Markdown／结构化渲染，禁用原始脚本和事件属性，不让检索文本驱动后台动作。来源收集器若后续实现，限制目的域、重定向、响应大小／超时并拒绝内网目的地址。首期不运行任意用户代码；受控教学示例测试也需先有工程执行环境与记录，不能伪造运行结果。

内容版本不可变：编辑正文、引用或运行示例产生新版，与原版和变更摘要关联；审核只适用于它检查的内容版本。学习记录和作品证据绑定原章／量规版本，未来迁移由产品与课程提供明确规则。技术上分别记录标准、教材、来源、提示模板、模型标识、应用版本及实际生成时间，支持追踪；记录这些信息也不能保证模型结果可完全复现。

## 6. 交给测试工程师的技术验证点（待执行）

1. 先按当前版本独立验证路线、测验、本地记录和导出，不把原型结果当成后端、生成或课程质量验收。
2. 未来 API 覆盖未登录、跨账户读取／修改任务、章节私有产物、学习记录和作品；客户端伪造用户／评审字段不能改变服务端权限或结果。
3. 用同键同输入重复创建任务、同键不同输入及并发请求，验证一个持久任务和可追踪尝试，不重复计数或覆盖版本。
4. 注入模型超时、限流、错误结构、资料不足与无效引用，核对实际失败阶段、重试上限、费用记录、草稿保留和页面状态；真实接入单独核对服务调用证据。
5. 在任务领取后、产物写入前后中断 worker，验证租约恢复、检查点和事务一致性；重复进程不重复发布，不丢失旧产物。
6. 分别检查生成、事实核对、示例运行、教学审核、专家审核和发布状态；缺失真实执行／评审证据时不能显示通过。伪代码和未执行代码无测试通过标记。
7. 检查章—能力—引用片段—来源快照—示例／审核证据—练习量规的版本关联；新版引用或正文不能沿用失效审核，旧学习结果不自动变为新版通过。
8. 两设备保存、刷新和服务重启后恢复记录；覆盖存储失败、冲突和无效 localStorage 资料，输入保留且失败提示持续；原型导入保持来源身份。
9. 在模型正文、来源、备注和作品链接注入 HTML／脚本／危险 URL，检查安全渲染及日志／导出无凭据；若实施来源抓取，再验证域名、重定向和内网限制。
10. 按设计交接独立测试键盘、读屏、焦点、导航历史、版本／章节链接、缩放和移动布局；按课程交接区分概念通过、自查、AI 建议和人工能力判断。

这些是工程交接要求，尚未执行，也不是测试通过结论。软件工程师负责后续实现与开发自检；独立验收由测试工程师完成，教学及专业正确性由课程责任人和实际评审者核查。
