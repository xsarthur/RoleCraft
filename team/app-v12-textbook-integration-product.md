## 版本与兼容交接

继续使用原本地入口和公开只读内容接口；工程岗交接新的客户端/检索版本、实际 corpus hash、30 源文件绑定及实际向量构建身份。API 输入当前 `corpusVersion` 为 `textbook-v12`，返回沿用现有状态、理由、准确原文、source path/hash、unit/section 和定位合同。明确选择概念降级时也使用当前 v12 公开正文，诚实显示实际模式；本轮默认 HTTP 语义模式须有本机实际推理证据，无需外部收费模型调用。

旧用户记录原来按单元 ID 保存，旧键名或无版本字段不能自动变成 v12 记录。软件工程师选择独立新版存储或逐条保留版本的兼容方案；均须保留旧值并允许查看/导出原记录。旧项目自述仍为自述，不能因为教材增加章节获得审核。

旧链接分两类处理：明确带旧版本的链接或由旧记录生成的链接，应保持历史内容身份或显示清楚的历史/升级入口；原无版本 `#learn/agent/<unitId>/<sectionId>` 可作为当前阅读入口兼容，但必须显示当前 v12 身份。若原小节已变、目标缺失或无法可靠对应，提示旧位置及可选当前章/历史入口，不静默映到其他章节。对正文一致的保留单元可有据对应新版位置，不声称其新 hash 就是旧源。具体版本路由由前端与检索岗冻结并交 QA，不由产品岗编造技术路径。

## 有限必要复验

QA 使用收到基线和冻结 v12 输入，保留实际实现版本及真实观察。结构与来源可逐项机械核对 30 单元；浏览器与查询只覆盖本次新增和必要受影响场景，不重审全书技术质量，不重跑旧教学代码，不重新统计原面试题/学习效果。

证据分层记录：30 单元结构/全文/链接目标/图文件/先修与源绑定属于静态检查；catalog、当前正文接口、实际 BGE 推荐及失配拒绝属于服务/HTTP 检查；图可读与放大、推荐卡点击、页面定位/刷新/后退、旧记录查看及实际导出属于真实 UI 检查。同一场景可分别记录这些子结果。若浏览器通道不可用，相关真实 UI 项保持未验证/证据不足，静态或 HTTP 通过不代替实际点击、存储交互或视觉通过，产品要求不降低。
