# 职造当前产品复盘与优化机会

日期：2026-10-15（Asia/Shanghai）  
责任岗位：产品经理  
复盘范围：当前本地学习工作台 `local-workbench-0.14-dialog-detail` 及已接入的 v10/v12 教材、内容检索能力。本文只做产品判断与需求交接，不代表实现或独立测试已通过。

## 1. 产品目的与当前应交付的价值

职造的产品目的，是帮助学习者从理解一个职业问题开始，沿着可解释的学习路径获得知识、练习和作品证据，最后能够独立完成真实 Agent 工程任务并复盘改进。产品同时服务两类结果：一是形成可验证的岗位能力，二是训练从问题、用户证据、方案比较到 MVP 和迭代的产品创造能力。

当前可交付价值集中在“阅读经过版本绑定的教材、按自然语言找到相关小节、保存学习与项目自述记录”。它还不能证明学习者已经掌握能力、作品达到岗位标准、产品具备行业优势或能够稳定生产运行。产品界面和推荐结果应持续把“教材支持”“本人自述”“AI 建议”“专业/真人评审”分开表达。

## 3. 核心流程复盘

建议把主流程收敛为：**确定当前任务 → 阅读/检索 → 完成练习 → 提交作品证据 → 获得反馈 → 复盘并选择下一步**。当前页面存在顶部导航、阶段卡、章节目录和固定检索助手多入口并列的情况，用户可能先看到工具而不清楚当前任务。每个页面都应有一个明确的主行动，其他入口作为次级操作。

检索流程必须形成闭环：表达问题 → 显示检索范围和教材版本 → 返回候选小节与原文 → 说明推荐理由和不确定性 → 一键打开原文 → 记录是否解决。歧义、零结果、服务失败和规则降级都要给可恢复动作，不能显示空白或把无结果解释成用户没有能力。

学习流程必须把“读过”与“会做”分开：章节阅读后引导一个可观察练习，再要求提交运行证据、设计说明或作品链接；系统只记录提交状态，专业评价由对应岗位完成。版本更新时应显示变更摘要，并允许回看旧版本与旧提交。

## 4. 优先优化机会

### P0：建立单一“继续学习/当前任务”入口

**证据：**&#x8BBE;计复盘已指出入口分散，当前有阶段卡、目录、检索助手等并列入口。  
**产品假设：**&#x82E5;首页只突出当前章节、目标、预计时长和唯一主按钮，首次进入及已有记录用户更容易开始下一步。  
**需求：**&#x65E0;记录显示起点选择；有记录显示当前任务、未完成原因和“继续学习”；完成后显示下一任务与可选复盘。  
**验收：**&#x9996;次、已有记录、任务完成、任务中断四态各只有一个主行动；产品埋点记录主行动点击、到达章节和中断位置。用户研究再验证“5秒内说出下一步”。

### P0：把检索助手变成有上下文的可追溯工具

**证据：**&#x68C0;索已能返回原文和来源，但当前固定底部入口可能遮挡阅读；设计复盘要求章节上下文、理由、版本和可关闭状态。  
**产品假设：**&#x5728;当前章节上下文中检索，能减少无关候选和重复输入。  
**需求：**&#x62BD;屉/对话层显示当前章节与教材版本；结果卡必须包含原文摘录、来源小节、推荐理由、歧义/置信状态、打开原文和复制；保留查询历史及“未解决”反馈。  
**验收：**&#x96F6;结果给出改写建议；歧义先让用户选择；失败提供重试或明确规则降级；任何结果不能没有版本和原文定位。

### P0：建立“练习—作品—反馈”最小闭环

**证据：**&#x5F53;前项目档案和作品记录是本人自述，不能证明能力；原八门槛的 learner_creation 仍证据不足。  
**产品假设：**&#x6BCF;个关键单元配一个可提交产物和明确评分项，才能把阅读转为可验证证据。  
**需求：**&#x8BFE;程单元声明产出类型、输入、完成条件、运行/截图/日志证据和评分维度；提交状态区分草稿、自述、AI建议、专业评审、真人评审。  
**验收：**&#x4EFB;一评分结论都能回链到提交证据和课程版本；缺证据时不得显示“已掌握/通过”；版本升级不覆盖旧提交。

### P1：用诊断结果调整路线，而不是只依赖自报

**证据：**&#x73B0;有起点主要来自用户自选/自报；v12 教材补齐了能力内容，但未形成学习者验证。  
**产品假设：**&#x77ED;诊断加练习证据可减少过难或过浅的路线推荐。  
**需求：**&#x5C06;档案字段标为“自报”，将诊断、练习和评审结果标为“已验证”；路线推荐显示依据、可跳过条件和补学入口。  
**验收：**&#x81EA;报不能自动变成掌握；用户可查看、更正或拒绝路线建议；推荐变化保留版本和原因。

### P1：把产品创造路线前置为可执行任务

**证据：**&#x5DF2;有七阶段路线和八门槛，但当前完整用户/竞品/成本证据不足，路线仍偏说明。  
**产品假设：**&#x6BCF;阶段有明确提交物和进入条件，学习者更可能完成真实产品验证。  
**需求：**&#x9636;段任务模板固定问题证据、方案基线、差异假设、MVP、测试、用户反馈、成本和迭代字段；允许附来源、样本、日期、版本和指标。  
**验收：**&#x9636;段未完成时不能显示“已达标”；比较缺少同任务/同资源/同评分方法时标记证据不足；每次迭代生成可追溯复盘记录。

### P1：形成跨设备、可恢复的学习记录边界

**证据：**&#x5F53;前记录主要在浏览器本地，刷新和来源变化可能隔离；README 明确未承诺账户同步。  
**产品假设：**&#x5B66;习者在不同设备恢复进度是持续学习的必要条件。  
**需求：**&#x5728;授权后引入账户同步、冲突处理、导出与删除；明确哪些内容属于个人记录、作品证据和系统审计。  
**验收：**&#x540C;一账户跨设备恢复章节、查询、提交和版本；不同账户不可读取；网络失败时保留本地草稿并提示同步状态。该项需后端与安全设计交接后再实施。

### P2：建立可量化的用户价值与运营度量

**证据：**&#x76EE;前没有真实学习者、留存、完成率、检索解决率、作品通过率或成本账单。  
**产品假设：**&#x6CA1;有统一指标，无法判断优化是否提升学习结果。  
**需求：**&#x5148;定义事件和隐私边界：首次完成当前任务、检索后打开原文、练习提交、证据补齐、复盘完成、用户反馈；按版本和来源记录，不把点击量当能力达成。  
**验收：**&#x6BCF;个指标有定义、分母、版本、采样范围和缺失处理；先用试点用户获得基线，再设改进目标。运营成本由运营分析员提供真实账单。

## 5. 暂不应承诺的结果

在用户研究、真人专业评审、真实外部运行和公平竞品实测完成前，产品文案不得承诺就业、职业认证、行业领先、自动生成可靠教材或自动证明学习者胜任。局部 QA 通过只说明指定范围的行为可复现。

## 6. 下一轮产品验收合同

下一版本应由产品经理冻结以下内容后再实现：

1. 一个主任务入口及四种任务状态；
2. 检索结果字段：意图、候选、原文、来源、版本、理由、不确定性、可恢复动作；
3. 至少一个单元的练习—作品—反馈合同及评分字段；
4. 自报、系统验证、AI 建议、专业/真人评审四类证据状态；
5. 产品创造阶段的提交物和进入条件；
6. 试点用户研究问题、指标定义和证据留存方式。

测试工程师应按当前版本重新核对以上合同；不得继承历史 QA。任何未验证项标记为 `insufficient` 或 `not_met`，并登记责任岗位、复验方法和版本。

## 7. 产品领域自查

已完成：目标、用户价值、核心流程、范围边界、优化优先级、证据/假设区分和可执行验收条件。  
未完成：真实用户访谈与试点、行业公平比较、作品独立评审、生产运行及实际成本。上述事项需由用户研究、竞品研究、实训评估、工程、运营和测试岗位分别交付，不能由本产品复盘替代。

## 8. 当前版本关键矛盾：已有题库能力与主路径不可见

**事实证据。** 当前 `dist/learning-experience-v13.js` 已实现 `questionPage()`、`reviewPage()` 和 `checkPage()`：题库支持固定 100 题与市场补充 14 题筛选，复习支持按本人标注的未掌握题逐题回顾，检验支持从已访问知识点抽题并明确“仅作本人自评”。但同一文件的 `page(view)` 仍把 `questions`、`review`、`check` 三个视图统一返回“配套题目 · 该模块将在后续开放”，并提示当前只能通过教材阅读、收藏和笔记学习。由此形成产品矛盾：能力和数据已存在，用户主路径却看不到题库、复习和检验，无法完成“阅读—练习—复习—自评”的闭环。当前主导航也未将三入口作为可发现的学习动作，入口只能依赖隐藏路由或后续接线。

**版本与交付证据。** `team/qa-review-current.md` 记录 QA-CR-02：v15 登录实现文档、客户端 `local-workbench-0.14-dialog-detail` 声明和历史 `app.js` 的 `local-workbench-0.14` 常量存在版本身份漂移。QA-CR-01 同时记录公网部署不可达：`http://111.231.8.78` 首页及三个内容 API 均无 HTTP 响应。因而即使题库入口接通，也不能把本地实现描述成公网可用服务；版本不一致还会使题目、教材和学习记录难以判断是否属于同一发布批次。

**产品优先级。**

1. **P0：恢复题库—复习—检验的可发现闭环。** 将三入口放入学习主导航或“当前任务”区域；题库页、复习页和检验页应调用已有实现，不显示“后续开放”。入口文案要明确：题库用于查缺，复习只处理本人标记的未掌握题，检验只生成当前版知识点的自评，不授予专业认证。
2. **P0：先统一发布身份，再扩大入口。** 页面、静态脚本、教材数据、健康接口和构建清单必须使用同一发布版本与内容版本。历史版本入口继续标明历史身份；当前题目标注题库版本、教材版本和来源哈希。版本未统一前不得把新入口标成正式生产能力。
3. **P0：明确部署状态和本地/公网边界。** QA-CR-01 关闭前，产品文案应显示本地可用或部署不可达状态，不承诺公网访问。若要面向试点用户，必须先完成外部 80/443、健康接口、目录和推荐接口的可达性复验，再由 QA 按线上版本重新验收。

**产品验收条件。**

- 首页/学习主导航能在一次点击内到达题库、复习和检验；三页均渲染实际页面，不再出现“该模块将在后续开放”。
- 题库显示 100 固定题 + 14 市场补充题的当前题组身份和教材来源；题目详情能回到对应知识点与原文。
- 复习只读取当前版本且本人标记为 `weak` 的题；“仍未掌握/已掌握”操作会保留时间、题目版本和自评性质，并支持结束与返回。
- 检验只抽取当前版已访问知识点对应题目，排除需真实经历题并显示题数不足；结果明确为本次自评，不改变专业审核或能力认证状态。
- 页面、`/api/health`、教材数据、题库数据和静态资源的版本字符串、内容哈希及发布日期一致；旧版本深链仍显示历史身份。
- QA-CR-01：公网首页、`/api/health`、`/api/content/catalog`、`/api/content/recommend` 从外部网络获得明确 HTTP 响应；若暂不部署，所有入口和文案均明确“仅本地”。
- 产品验收必须由测试工程师在统一版本冻结后重新执行；通过本地页面或源码存在不能代替线上可达性、浏览器主路径和真实用户理解证据。
