# UI/UX 教材与产品训练：视觉美与和谐产品合同 v0.1

产品经理；2026-10-15（Asia/Shanghai）。

## 1. 变更目的与判断

用户提出：教材有大量逻辑性内容，也应增加让作品“视觉美、和谐”的训练；视觉的好坏是设计的核心竞争力。

本文件把这项判断转成产品范围和可验收证据。这里的“美”不是个人偏好或装饰数量，“和谐”也不是把所有页面做成同一种模板。产品合同把视觉质量定义为：在已经确认的用户、任务、品牌/场景和约束下，界面中的层级、节奏、比例、色彩、字体、形状、图像、动效（如有）和文字语气形成有意图、可辨认、可复用、适合场景的整体；它同时要保住可读性、可访问性、任务完成和状态诚实。

视觉美与和谐是产品体验的竞争维度，不能由“功能能用”自动推断，也不能由一张漂亮的封面或 AI 生成图证明。视觉质量训练须与问题证据、任务成功、信任、可访问性、工程约束和迭代证据一起交付。

本合同只增加教材与产品训练的质量目标，不改原课程能力 ID、八项产品门槛、冻结正文、账户数据或现有应用功能范围。

## 2. 适用对象与版本边界

### 2.1 适用对象

- UI/UX 产品设计、AI 产品体验和产品创造学习者；
- 需要从“逻辑正确”进阶到“清楚、协调、有辨识度”的学习任务；
- 教材中的视觉案例、作品练习、设计批评、工程交接和作品集证据；
- 以后涉及教材阅读工作台的视觉表达时，作为产品与设计交接的附加条件。

### 2.2 首批课程映射（只定义产品接收范围）

课程架构师在不改变既有单元 ID、先修和量规的前提下，核对下列既有能力的视觉证据是否出现：

| 既有能力/单元 | 本合同要补的产品证据 |
|---|---|
| C05 UI 视觉与可访问性、`10-visual-interface` | 视觉诊断、构图/层级/节奏取舍、可访问性与审美冲突的处理 |
| C06 设计系统与跨端、`12-design-system` | Token、组件变体、间距/字体/色彩/形状的一致性和例外治理 |
| C07 AI 产品交互、`15–17` AI 专题 | 等待、候选、低置信、拒答、恢复和人工接管状态的视觉语义与情绪控制 |
| C08 原型与可用性评估、`13`、`18` | 对照版本、任务观察、视觉问题归因和返修证据 |
| C10 工程交付与协作、`20–21` | 视觉规则、状态、资源和降级方式可交给工程复现 |
| C11 信任/隐私/包容 | 视觉美不能掩盖风险、权限、来源、错误或不确定性 |
| C13 0→1 产品创造、`23–25` | 由问题和差异化假设产生视觉方向，并用证据判断是否值得继续 |

映射是接收与核对清单，不是新教材正文，也不把每个单元强行改成“视觉课”。课程架构师仍负责能力去向和教学顺序，教材研发员负责正文，设计师负责视觉交接，内容审校员核论断，测试工程师独立核证据。

## 3. 用户场景

### VH-U01 从“能用”提升到“看起来有意图”

学习者已有一个功能正确但拥挤、无重点的页面。学习者需要指出用户第一眼应看到什么、哪些内容应退后、怎样用比例、留白、对齐和节奏形成主次，并交付修改前后对照。验收关注能否解释每个视觉决定服务的任务和约束，而非只说“更高级”。

### VH-U02 诊断不和谐的界面

页面的字体、颜色、圆角、图标、间距或插图各自好看，但组合后显得吵杂。学习者需要建立视觉问题清单，按影响分级，区分结构性问题（层级、网格、节奏）与表面偏好（个人喜欢的颜色/风格），再选择一次修订范围。验收关注问题是否可定位、可复现、可回退。

### VH-U03 在视觉吸引力与任务清楚之间取舍

产品 brief 要求有品牌记忆点，同时包含表单、来源、异常和下一步动作。学习者需要提出至少两个方向，说明哪一项视觉强调会损害读写、对比度、状态辨认或任务成功，并保留必要的文字、操作标签和错误原因。验收不接受以“美观”压过可用性或事实边界。

### VH-U04 让 AI/Agent 的不确定性看起来稳定而诚实

界面存在等待、候选、低置信、拒答、来源冲突、重试和人工接管。学习者需要让这些状态在视觉上有秩序、不过度制造焦虑，也不把候选结果装成已确认事实。验收关注状态间的形状/位置/层级差异、用户可见的控制点和错误恢复路径。

### VH-U05 设计系统中的和谐与例外

学习者为多页面或多组件建立小型视觉系统。需要证明颜色、字体、间距、圆角、阴影、图标和插图有共同规则，并说明何时允许例外、例外如何命名、如何在窄屏或高对比模式下降级。验收关注跨页面关系和可复用规则，不接受只展示一张孤立海报。

### VH-U06 响应式、国际化和内容变长后的视觉稳定

学习者需处理桌面、约 760px 和窄屏，以及较长标题、翻译、缺图、弱网和动态数据。验收关注主次关系、行长、裁切、折行、留白和状态表达在不同条件下仍成立；不以缩小字体、横向滚动或删掉必要信息作为唯一修复。

### VH-U07 对作品进行可证据化的视觉批评

学习者在同伴或面试场景展示作品，能够从目标、输入、视觉假设、方案、反例、观察和迭代讲清楚“为什么这样做”。验收要求保留被否决方向、来源/版本和未知项，不以自述的“审美很好”作为结果。

### VH-U08 0→1 产品的视觉差异化假设

学习者面对真实场景的问题、已有替代方案和资源约束，提出一个可验证的视觉方向。验收关注视觉方向是否由用户/业务/场景证据支持，是否能在小范围实现并与可比方案比较；不把一张概念图当成市场优势证明。

## 4. 产品定义：什么算“美”和“和谐”

交付中应分别标记以下维度，不能用单一审美分数相互抵销：

| 维度 | 可观察含义 | 反例信号 |
|---|---|---|
| 意图与适配 | 视觉方向能回指用户、任务、品牌语气、平台和内容约束 | 仅引用流行风格、个人偏好或 AI 提示词 |
| 层级与节奏 | 首要任务、次要信息、操作和反馈有稳定权重；重复间距/对齐/比例有规律 | 每个元素都抢焦点、间距随机、重点靠大红字补救 |
| 视觉一致性 | 字体、色彩、形状、图标、插图、动效和文案语气形成可复用语法 | 每屏单独“做得漂亮”，跨页像不同产品 |
| 适度对比与记忆点 | 有清晰的焦点、品牌识别或情绪，但对比服务任务和场景 | 高饱和/强阴影/装饰堆叠造成噪声或遮挡 |
| 状态诚实 | 正常、等待、空、错误、拒答、来源和恢复的视觉差异真实表达状态 | 以动效、颜色或大插画掩盖未知/失败 |
| 可读与可访问 | 对比度、字号、焦点、键盘/读屏顺序、非颜色编码和响应式均可核 | 灰度/色觉差异/窄屏即失去关系 |
| 可实现与可维护 | 规则能被工程实现、复用和回归，资源/字体/动效有明确边界 | 只交渲染图、无状态/尺寸/降级说明 |
| 可验证与可迭代 | 视觉判断有基线、反例、观察和修改依据 | 把自评、点赞或一次展示写成用户效果 |

“和谐”允许有意的对比、留白和局部破格；验收看整体关系和用途，不要求所有元素同质或没有个性。

## 5. 必交作品证据包

下列是产品训练的接收物，不限定工具。缺少任一关键证据时，应标 `insufficient_evidence`，不能用最终截图补齐全过程：

| 证据包 | 最小内容 | 可核问题 |
|---|---|---|
| E-VH-01 视觉 brief | 用户/任务、场景、品牌或情绪目标、内容/技术/可访问性约束、不做清单 | 视觉方向服务什么问题？哪些要求不能牺牲？ |
| E-VH-02 基线与诊断 | 原始版本、视觉问题标注、问题影响和优先级、待验证假设 | 问题能否在原稿定位，而非事后编理由？ |
| E-VH-03 方案对照 | 至少两个视觉方向或一次明确的前后版本，对每项说明取舍与否决原因 | 选择是否由任务和证据，而不是偏好决定？ |
| E-VH-04 和谐规则表 | 字体/字号层级、间距/网格、色彩语义、形状/图标、图像/动效边界、例外规则 | 规则能否在第二个页面或组件复用？ |
| E-VH-05 状态与响应式板 | 正常、加载/等待、空、错误/拒答、恢复/结果；桌面、约 760px、窄屏和内容变长至少一组 | 视觉关系在状态和尺寸变化后是否仍成立？ |
| E-VH-06 可访问性与降级记录 | 对比度/非颜色编码/键盘焦点/读屏名称或等价检查；高对比、灰度、缺图/字体回退的结果 | 美观是否以可访问性为代价？未知处是否标明？ |
| E-VH-07 批评与迭代 | 批评记录、被否决方向、修改前后、观察或测试输入、剩余问题 | 哪个证据促成了哪次改变？ |
| E-VH-08 工程/内容交接 | 组件/Token/状态/资源/断点/文本长度/来源和版本；无法实现处的降级方案 | 他岗能否复现并知道哪些仍未验证？ |

### 5.1 示例作品（用于训练夹具与作品集，不代表真实客户结果）

产品经理可为课程提供以下示例类型，必须标注“教学构造/未运行/待验证”状态：

1. **客服知识助手结果页**：对照“候选答案、来源冲突、拒答转人工”三种状态；重点证明视觉层级、信任和状态诚实。
2. **移动端任务表单**：同一任务在桌面、约 760px 和窄屏的前后对照；重点证明留白、折行、焦点和错误恢复。
3. **小型设计系统页**：按钮、卡片、表单、消息和空态的 Token/变体矩阵；重点证明规则复用和例外治理。
4. **有品牌记忆点的 0→1 首页**：同一 brief 的两个方向及裁决记录；重点证明差异化假设来自场景、竞品和可验证任务，而非“好看”宣言。
5. **视觉批评记录**：一张“各部分都漂亮但整体不和谐”的构造页面，学习者标出层级、网格、节奏和语气冲突，提交一次小范围修订。

示例只作为结构和反例夹具；不能称为真实业务上线、真实用户偏好、行业先进作品或学习者能力认证。

## 6. 验收合同

### 6.1 产品与教材训练范围验收

| ID | 条件 | 证据与责任 |
|---|---|---|
| VH-P01 | 每项视觉方向绑定已确认的用户/任务/场景/约束，且有不做清单 | brief 与来源；产品经理冻结，课程架构师核映射 |
| VH-P02 | 学习者能从基线标出至少一项层级/节奏/比例/一致性问题，并说明影响与优先级 | 标注稿、问题台账；教材研发员交付，内容审校员核论断 |
| VH-P03 | 至少有两个方向或一个保留失败版本的前后对照，选择理由可回指证据 | 版本差异和裁决记录；设计师交接，QA核版本完整 |
| VH-P04 | 视觉规则在第二个页面/组件/状态中可复用，例外有命名和理由 | Token/变体/示例；设计师交接，工程岗评估可实现性 |
| VH-P05 | 关键状态和任务层级可通过位置、形状、边界、文字等多种线索辨认，不只靠颜色/动效 | 状态板、文字替代、键盘/读屏路径；QA独立核 |
| VH-P06 | 桌面、约760px、窄屏、内容变长/缺图/字体回退的视觉关系可读，无关键裁切或无替代的横向滚动 | 实际渲染预览与操作记录；设计师自查，测试工程师独立复验 |
| VH-P07 | 可访问性、信任、来源、错误和未验证状态未被审美处理隐藏；必要文字、操作标签和恢复动作仍在 | 反例清单和修订差异；内容审校/QA核 |
| VH-P08 | 作品能说明“问题—视觉假设—方案—观察/测试—修改—未知”，自评不替代用户证据 | 作品证据链；产品经理核范围，用户研究员后续核真人理解 |
| VH-P09 | 工程/内容接收方能依据交接包复现规则或明确拒收原因；不可实现处有降级方案 | 交接记录、版本/资源/状态字段；接收岗与QA共同核 |

### 6.2 可选的真实理解与产品效果证据

VH-P01～09只证明限定训练工件和视觉表达具备可检查条件。若要声称用户理解、偏好、信任、任务成功或市场竞争力，必须另由用户研究、测试、竞品研究和运营岗位取得真实证据，明确样本、版本、场景、测量方法和未知结果；本合同不预设一个审美分数替代这些证据。

## 7. 与既有标准和岗位交接的兼容规则

1. **与 `DESIGN_COMMUNICATION_STANDARD.md` 兼容。** VF-P01～05 继续有效；视觉美是与任务清楚、状态诚实和可访问性并列的产品质量维度，不替换当前位置、目标、顺序、状态和结果的语义。颜色仍只是补充；箭头/连线不得盖字；图例、对比度、窄屏、文字替代和实际渲染检查仍是前置条件。
2. **与 `ui-visual-first-product.md` 兼容。** 视觉稿仍须先表达意图，但不因减少文字、增加插图或动效而删掉教材正文、题面、出处、错误原因、无障碍名称和能力边界。状态、等待、无结果、不可用和来源失配继续按原合同区分。
3. **与 `design-rule-update-v02.md` 兼容。** 有语义的色彩和布局质量门槛是本合同的基础；本合同把它们扩展为教材/作品训练中的诊断、方案和复现证据，不把任何具体颜色、风格或路线图固定成应用功能。
4. **与 UI/UX 课程规格兼容。** 视觉训练服务 C05/C06/C07/C08/C10/C11/C13；不删减研究、任务流、AI 不确定性、工程交付和评估目标，不把 UI/UX 教材改成 AIGC 视觉生产课程。
5. **与责任分工兼容。** 产品经理维护范围和验收；课程架构师维护能力去向；设计师提供可审阅视觉稿和视觉规则；教材研发员写正文、案例和练习；内容审校员核概念/来源/边界；软件工程师实现已批准交接；测试工程师独立检查渲染、交互、响应式、可访问性和证据；用户研究员核真实理解。任何岗位不能以自查关闭他岗门槛。
6. **与版本和历史记录兼容。** 新视觉工件、稿件、应用实现和QA均创建当前版本记录；不覆盖冻结教材、旧设计报告、历史失败或旧结论。视觉工件的示意、实际运行、未运行、模拟和真实用户证据分开标记。

## 8. 不纳入本轮

- 不重写完整 UI/UX 教材正文，不改变 26 单元、原能力 ID、正式先修、原量规或现有产品门槛；
- 不指定品牌、配色、字体、插画风格、设计工具、模型或单一审美流派；
- 不恢复或新增应用导航、题库、课程工具区、账户字段、下载/发布、外部上传或付费模型调用；
- 不把教材构造案例、静态视觉稿、AI 生成图、作者自评或点赞当成真实用户喜欢、用户理解、可用性通过、就业能力或行业先进性；
- 不替代真实用户研究、真人视觉/行业专家审核、浏览器/辅助技术/工程运行验证、竞品实测、学员未知任务和运营经济分析；
- 不承诺“美观越强越好”，不以审美掩盖可访问性、隐私、来源、错误、权限、延迟、成本或任务失败；
- 不把本合同中的示例作品当作现有应用已实现或完整产品已达标。

## 9. 实施顺序与独立复验

1. 产品经理冻结受影响课程单元、作品类型、证据字段和本合同版本；
2. 课程架构师确认既有能力映射与先修，不写实现方案；
3. 设计师交可审阅的基线/方案对照、状态板、响应式预览和视觉规则；
4. 教材研发员按已确认规格补正文、案例、练习和参考解析；内容审校员独立核论断、来源、边界与图文一致；
5. 若接入应用，软件工程师按批准设计交接实现，内容检索/数据岗位只在接口或版本受影响时参与；
6. 测试工程师先冻结输入、版本、环境和原始失败，再独立复验 VH-P01～09 及受影响旧合同；缺陷返修后必须重跑原例和受影响变体；
7. 用户研究员另行取得真实用户理解/审美偏好/任务结果证据；产品经理在复盘中分开报告“训练工件通过”“限定界面通过”“真实用户和完整产品证据”。
