# Q71

## 原题

如何定义 Agent 的任务成功率，避免把“生成了回答”当成任务成功？

## 完整解析

任务成功率应是“满足事前任务合同的分配次数/全部预定分配次数”，而不是“产生回答的请求数/收到请求数”。合同至少包括结果正确、必要证据、允许动作、完成状态和关键安全约束；某任务要求真实创建一张工单，仅生成“创建成功”文字当然不算成功。

先为每类任务写允许终态。材料齐全且获批的任务需要确认的工单和匹配回执；材料不足题的目标可以是准确指出缺项并停止写入；未获批题应拒绝动作。正确拒绝只在对应目标下是能力通过，不能把全部拒绝都算成功，也不能把合理停止一律算失败。完成/正确停止两个业务类别应同时分层报告。

一次分配的结论可分为PASS、FAIL、INSUFFICIENT和HARNESS_ERROR：有完整结果与过程证据且满足合同才PASS；已有反证为FAIL；必要事实未知为INSUFFICIENT；测试装置未完成预定观察为HARNESS_ERROR。已知越权与日志缺失可同时记录，不能因为一部分缺证撤销已确认的失败。反过来，缺日志不能自动证明发生了越权。

以下为教学数字，并非本产品实测：

| 判定 | 次数 | 含义 |
| --- | ---: | --- |
| PASS | 70 | 结果与必要过程均可确认 |
| FAIL | 15 | 有错误产物、越权或重复效果反证 |
| INSUFFICIENT | 3 | 回执/专业判断仍未确认 |
| HARNESS_ERROR | 2 | 采集装置失败，待重跑 |
| 全部分配 | 90 | 四类均保留 |

可证成功比例为70/90≈77.8%，已知失败15/90，另列3次缺证和2次装置故障。2次故障不等同产品错误，但也不进入通过分子；不能删掉变成70/88后宣称同一轮成功率。若补测，应保留原分配记录和补测关联，按事前协议说明报告口径，而非挑较好结果替换。

结果来源也要对应任务：事实与引用读回、授权由可信记录、效果由操作级回执，语义判断由独立量规。模型自填`success=true`、HTTP200、生成文件都只是局部事件。超时但外部效果未知时，保留未知；若最终宣称已完成，则完成宣称可以明确判错。

验证判定器要用“全拒绝”、丢轨迹、错版本、已成功丢回执、已知越权但最终拒答等反例，并加入真实合法成功对照。预期分母完整且不以语言流畅取代目标。本文仅定义评测与算例，未执行任务评测。
