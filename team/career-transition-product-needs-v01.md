# 求职者与转行者产品支持需求 v0.1

日期：2026-10-16（Asia/Shanghai）  
责任岗位：产品经理  
状态：需求分析，待课程、设计、用户研究、实训评估与测试岗位交接

## 产品判断

求职者缺的通常不是更多阅读页，而是从“我是否应该转、要转到什么岗位”走到“我能拿出什么证据、怎样获得面试、入职后怎样交付”的连续支持。当前学习工作台已经有 Agent 开发课程路线、题库与自评、教材检索、项目自述记录和本地导出；这些产物能支持学习与记录，不能单独证明岗位胜任、录用概率或行业先进性。本需求补齐五个阶段的连接层，保留当前单职业 Agent 开发范围，不恢复职业广场或自动替用户选择职业。

所有阶段都采用以下证据状态：`本人自述`、`学习/练习产物`、`可复现作品`、`独立评阅`、`真实工作反馈`、`未知`。应用不得把阅读完成、自评正确、AI 草稿或静态页面升级为职业认证。

## 一、转行决策

### 场景与痛点

| 场景 | 主要痛点 |
| --- | --- |
| 有原行业经验，但不知道哪些经验能迁移到 Agent 开发 | 职位名称相近而实际工作不同，用户难以区分相邻岗位、级别和日常交付 |
| 想辞职转行，但时间、收入、地域和家庭约束不同 | 课程路线默认理想条件，缺少机会成本、试错预算和停止条件 |
| 看到招聘要求后不知道是“暂时不会”还是“岗位不匹配” | 学习目录与目标职位要求没有一一对应，缺口容易被泛化成继续学习 |
| 想先做小实验再决定是否全职投入 | 没有低成本的真实问题、桥接项目和可复盘的 go/no-go 判断 |

### 功能机会

1. **目标岗位卡**：记录岗位变体、级别、工作内容、地点/工作方式、收入下限、可投入时长和不可接受条件。允许同时保存 1–3 个候选目标，不给出单一“最适合”结论。
2. **岗位要求快照与证据差距表**：用户粘贴或手动录入职位描述，保存来源、日期和版本；把要求映射到当前课程、项目和已有经历，区分必须项、可在岗学习项和未知项。
3. **迁移能力地图**：把旧行业的真实经历映射为问题发现、交付、数据/工程、沟通和复盘等可验证能力；每个映射必须保留原经历与证据链接，不自动改写成 Agent 经验。
4. **小型转行实验**：为 1–2 周的桥接任务设定问题、时间预算、学习目标、实际交付物、反馈人和继续/暂停条件。教材中的教学构造只能作为练习，不得当作市场验证。
5. **决策账本**：保存选择、假设、证据、风险、替代路径和复盘日期；允许保留“暂不转行”或“先做邻近岗位”的结果。

### 可观察验收条件

| ID | 验收条件 |
| --- | --- |
| CT-DEC-01 | 用户可保存至少一个目标岗位卡及约束，重新打开仍能看到版本、日期和来源；空白约束不被系统补写。 |
| CT-DEC-02 | 对每条岗位要求，界面明确显示已映射证据、缺口或未知；没有证据时不能显示“匹配”或“适合”。 |
| CT-DEC-03 | 用户可创建一个有时间预算、实际输入、产出、反馈人、停止条件的桥接实验；未提交结果时状态保持“待验证”。 |
| CT-DEC-04 | 调整目标岗位不会覆盖旧决策和旧证据；导出文件保留来源、版本与未确认项。 |
| CT-DEC-05 | 任何市场或薪酬信息都显示来源和采集日期；没有可核来源时显示“未知”，不显示“热门”“成功率”或保证性建议。 |

## 二、求职准备

### 场景与痛点

| 场景 | 主要痛点 |
| --- | --- |
| 有明确目标但只剩 2–8 周准备时间 | 不知道先补哪项能力，容易把时间耗在泛读或重复题目 |
| 会做练习但讲不清方案、取舍和失败 | 面试表达与工程作品脱节，答案变成背诵模板 |
| 转行者需要解释过去经历与新岗位的关系 | 简历和自我介绍容易夸大或掩盖可迁移经验、缺口和学习计划 |
| 需要同时准备技术题、场景题和项目追问 | 现有题库有题目与参考分析，但缺少按目标、时间和薄弱点编排的准备合同 |

### 功能机会

1. **目标驱动准备计划**：在现有课程、题库、项目记录和教材检索之上，按岗位要求、准备天数和每日分钟数生成可调整清单；每项任务回链到实际章节、题目或项目，不显示总体“掌握率”。
2. **面试练习工作流**：沿用 `interview-prep-v1` 的基础/工程设计/项目表达/场景追问四类题型，加入思考区、用户答案、参考分析、追问、自评和复习日期；不自动给答案打对错分。
3. **转行叙事编辑器**：用“过去做过什么—为什么转—目标岗位需要什么—已有证据—仍缺什么—下一步如何补”组织自我介绍、项目介绍和行为题答案。每个事实可回指经历或作品。
4. **准备材料版本管理**：简历、项目简介和面试答案按目标岗位复制为版本，显示差异和未验证主张；只生成草稿，不自动投递。
5. **真人练习入口**：预留同伴/导师/面试官反馈字段和预约信息；AI 反馈只能标为辅助建议，不能冒充招聘方或行业专家评价。

### 可观察验收条件

| ID | 验收条件 |
| --- | --- |
| CT-PRE-01 | 准备计划的每项任务至少有目标岗位要求、对应课程/题目/作品入口、预计时长和完成证据；调整天数不删除已完成历史。 |
| CT-PRE-02 | 用户答案、参考分析、追问和自评状态分开保存；系统不以自评或阅读访问生成“通过”“胜任”结论。 |
| CT-PRE-03 | 转行叙事中每个经历主张可回指用户输入的事实或作品；缺失事实显示待补，不生成个人经历。 |
| CT-PRE-04 | 材料导出前列出未验证主张、引用来源与目标岗位版本；用户未确认时不能标为已发送。 |
| CT-PRE-05 | 题目无可信频次、公司真题或行业反馈时，界面不显示“必考”“高通过率”等标签。 |

## 三、能力证明

### 场景与痛点

| 场景 | 主要痛点 |
| --- | --- |
| 课程学完但没有可信作品 | 阅读和自评无法让招聘方判断真实实现、取舍和边界 |
| 有项目但说不清个人贡献 | 团队项目、平台能力和个人代码混在一起，面试追问容易失真 |
| 作品能跑但别人无法复现 | 缺依赖、版本、输入、失败路径、测量和限制，截图不能证明交付 |
| 没有真实用户或生产数据 | 容易用教学构造或模型生成数字冒充业务结果，或因没有数据完全放弃展示 |
| 需要独立评阅或陌生任务 | 自审只能证明准备过，不能证明迁移到未见问题 |

### 功能机会

1. **作品证据包**：按“真实问题/用户—已有方案—差异假设—方案选择—实现版本—失败与修复—可比评价—反馈—下一版”收集材料，复用 v12 `n10/e02/p02` 的证据链。
2. **个人贡献与边界表**：分别记录本人完成、团队完成、平台提供和未完成部分；支持面试口述与项目 README 两种视图。
3. **可复现交付包**：记录源码/文档版本、依赖、运行入口、输入夹具、预期、实际输出、失败日志、环境和已知限制；安全示例与真实数据分开标识。
4. **独立复核与陌生任务**：邀请授权的同伴/导师/测试员按固定量规复核；保存评阅人、条件、意见和复验结果。未实际执行时显示待验证。
5. **证据账本与公开包**：将目标岗位要求连接到具体工件和来源，按用户选择导出脱敏版本；缺口和负结果保留，不强行形成漂亮故事。

### 可观察验收条件

| ID | 验收条件 |
| --- | --- |
| CT-EVD-01 | 作品草稿必须区分真实问题、教学构造、合成数据和真实反馈；缺项显示“未知/待补”，不允许自动补数字或经历。 |
| CT-EVD-02 | 每个能力主张至少可链接一个工件、版本和验证状态；只有学习记录或自评时，状态不能升级为“独立复核”或“真实工作反馈”。 |
| CT-EVD-03 | 导出的可复现包包含版本、依赖、入口、输入、预期/实际结果和限制；另一位执行者未实际运行时不能显示“已复现”。 |
| CT-EVD-04 | 评阅意见与作者自评分开存储；修复后保留首个失败、修复版本和复验结果，不覆盖历史。 |
| CT-EVD-05 | 公开或分享前有脱敏检查和用户确认；企业代码、客户数据、密钥、内部指标不能进入公开作品包。 |

## 四、求职执行

### 场景与痛点

| 场景 | 主要痛点 |
| --- | --- |
| 面对多个职位，逐一改简历和项目描述 | 要求、证据和材料版本容易错配，重复劳动也易造成夸大 |
| 申请后忘记跟进，无法知道哪个环节出了问题 | 邮件、内推、面试、作业和拒信分散在不同工具，反馈没有沉淀 |
| 想联系招聘方或前同事但担心隐私 | 自动发信或批量投递可能越权，个人资料和雇主资料有泄露风险 |
| 得到 offer 后难以比较岗位质量 | 只看薪资，忽略职责范围、成长、团队支持、地点、风险和转行成本 |

### 功能机会

1. **申请管线**：记录公司/岗位、来源、要求快照、申请日期、当前状态、下一动作、截止时间、联系人和拒绝/反馈原因；支持用户自定义状态。
2. **职位描述到证据映射**：把 JD 要求与能力账本、作品和准备任务连接；解析不确定的条款明确标为待人工确认。
3. **材料定制与差异审阅**：从已确认事实生成简历/项目介绍草稿，突出目标岗位差异；所有新增主张需要用户逐项确认并标注来源。
4. **跟进与面试记录**：提醒下一动作，保存面试问题、用户回答、面试官反馈和复盘；外部发送仍需用户明确操作。
5. **Offer 比较表**：按岗位职责、级别、薪资结构、地点、学习支持、试用期、风险和个人约束比较；涉及法律/税务的字段引导用户咨询专业人士，不给确定性结论。
6. **投递数据摘要**：只用用户完整记录计算申请数、面试数、响应时间和阶段转化；缺少分母时显示数据不足，不推断录用概率或因果。

### 可观察验收条件

| ID | 验收条件 |
| --- | --- |
| CT-APP-01 | 每个申请有稳定 ID、职位描述来源/日期、材料版本和状态变更记录；刷新、导出后不丢历史。 |
| CT-APP-02 | JD 解析会显示原文片段、解析结果和不确定项；未确认的要求不能静默变成用户技能。 |
| CT-APP-03 | 任何生成材料都突出新增或修改内容，并标出无证据主张；用户确认前不提供“已投递/已发送”状态。 |
| CT-APP-04 | 用户可记录跟进和拒绝原因，但系统不自动联系第三方、不代投、不发送短信/邮件；未来外部动作需另行授权和独立验收。 |
| CT-APP-05 | 统计只基于实际记录并显示样本量、时间范围和缺失字段；不显示保证性匹配分数、薪资预测或录用概率。 |
| CT-APP-06 | 简历、作品和联系人等敏感数据可本地导出、删除或标记不分享；分享前必须有明确范围和确认。 |

## 五、入职后支持

### 场景与痛点

| 场景 | 主要痛点 |
| --- | --- |
| 转行后第一次承担真实交付 | 课程任务与团队流程、权限、代码库和业务目标之间存在断层 |
| 想在试用期证明价值 | 没有把目标、交付、反馈和影响串起来的记录方式，容易只记任务不记证据 |
| 遇到事故或需求变化 | 缺少安全复盘、求助路径和在职学习的最小下一步 |
| 想把在岗经验更新为作品 | 可能泄露公司机密、客户数据或未经授权的指标，无法安全脱敏 |

### 功能机会

1. **30/60/90 天入职计划**：将岗位期望拆成认识业务、获得权限、完成小交付、获取反馈和复盘；每项有负责人、截止时间和可观察证据。
2. **工作证据与决策日志**：记录任务目标、约束、方案、批准、实现、结果、反馈和下一步；支持与学习路线的双向回链。
3. **反馈转学习任务**：将经理/同伴反馈标为来源和敏感等级，生成下一项课程、练习或请教清单；不把模型建议冒充绩效评价。
4. **安全复盘模板**：保留时间线、观测、假设、排除项、修复、回归和未知效果；鼓励保留失败，不要求虚构正向结果。
5. **脱敏作品导出**：只导出经用户确认的结构、匿名化数据和可公开代码；保留“不可公开”标记和原始私有记录。
6. **岗位不匹配与下一步**：记录实际职责与原目标差异，支持继续适应、换相邻岗位或暂停的决策复盘，不自动判断离职或成功。

### 可观察验收条件

| ID | 验收条件 |
| --- | --- |
| CT-ONB-01 | 入职计划每项包含目标、负责人/协作者、期限、证据和当前状态；未获得公司确认时显示待确认。 |
| CT-ONB-02 | 工作记录按来源区分本人、经理、同伴、客户和系统数据，并保存日期与敏感等级；不能把个人笔记改写为绩效结论。 |
| CT-ONB-03 | 事故复盘保留原始失败、修复版本、回归条件和未知效果；缺数据时显示未知，不生成影响数字。 |
| CT-ONB-04 | 学习路线可从经用户确认的反馈创建任务，但旧工作记录和旧教材版本不被覆盖；反馈删除或撤回后状态可追溯。 |
| CT-ONB-05 | 公开作品导出有字段级脱敏预览和用户确认；密钥、客户资料、内部仓库路径和未授权指标被阻止或明确警告。 |

## 跨阶段底层能力

- **证据与版本**：所有岗位要求、作品、答案、简历、申请和反馈都有来源、版本、日期及状态；“未知”是一等状态。
- **隐私与授权**：本地优先，简历/作品/雇主资料分开存储；任何分享、外部发送、上传或模型调用须单独授权、可撤回和可审计。
- **真实人与机器边界**：AI 可做整理、检索和草稿；真人招聘反馈、专家复核、实际工作表现和真实用户反馈分别记录。
- **低压力可持续计划**：支持暂停、调整时间、跳过和分阶段复盘，不用连续打卡或总完成率制造“已准备好”的错觉。
- **无障碍与可达性**：关键状态有文字、键盘等价入口和可导出文本；移动端能完成查看、记录和导出，不把图表作为唯一证据。

## 版本优先级

### P0：在现有单职业工作台上补连接

目标岗位卡、要求快照/证据差距表、桥接实验、作品证据包、独立复核字段、面试准备计划和本地申请管线。复用现有课程、题库、检索和项目记录；不接外部投递、不自动发信、不新增付费模型调用。

### P1：提高求职执行与反馈闭环

JD 解析与材料差异审阅、同伴/导师评阅、跟进提醒、拒绝反馈归因、Offer 比较和本地统计。任何动态市场结论都必须带可追溯来源和时间范围。

### P2：入职与真实市场证据

30/60/90 天计划、敏感资料脱敏作品、真实招聘方/导师反馈、经授权的外部同步和跨岗位路线。P2 需要用户研究、内容/专业审核、数据权限与独立 QA 的新交接，不能由教材完成度替代。

## 不能由本需求宣布的结果

以上功能通过只能证明相应记录、映射、准备或复核流程在限定范围可用；不能宣称学员已经胜任、提高录用概率、获得职业认证、完成真实转行、达到行业先进或证明产品经济性。上述结论分别需要真实学习者作品、独立评估、招聘/入职反馈、行业可比条件和运营数据。
