## A. 当前任务卡：四种事实状态

首页首屏只能突出一个当前任务卡，卡内固定提供：当前职业快照、当前阶段/篇章、任务目标、预期动作、作品/证据提示、当前教材/版本身份、状态短标签和一个主 CTA。目录、路线图、工程全景、问教材和低频工具保持次级权重。卡片不能以阅读次数、百分比或颜色推导能力。

实现时沿用产品合同的四态名称和事实边界：

| 产品状态 | 必须可见的视觉事实 | 唯一主 CTA | 交互边界 |
| --- | --- | --- | --- |
| **未开始** | 没有有效的当前版本阅读足迹；明确真实起点/首篇 | `开始学习` | 不显示已掌握、完成率或就业承诺；点击后写入相应阅读起点并进入当前篇 |
| **进行中** | 当前职业、当前篇章/小节和最近合法位置 | `继续学习` | 刷新、后退或关闭问教材后仍保留当前职业和位置；不把阅读事实变成能力结论 |
| **已中断** | 明确的中断位置或失败原因；未完成动作保留 | `恢复任务` 或 `查看原因`（只能有一个主 CTA） | 不能把中断画成失败等级或已完成；恢复前允许用户查看真实原因 |
| **本任务已浏览** | 当前任务浏览动作已经完成；若有提交，单独显示提交/反馈事实 | `回顾` 或 `提交证据`（依据当前真实动作择一） | 浏览不等于练习完成、作品通过或掌握；不得自动写专业评审状态 |

四态必须满足：

1. 状态用形状、边界、短标签和文字重复编码，颜色只做辅助；灰度下仍能区分。
2. 首次进入、已有记录、中断、已浏览各只有一个清晰下一步；不要并列两个同权重主按钮。
3. 换职业、换教材版本、刷新、后退、关闭问教材时重新核对职业快照和版本，不能把旧职业/旧版本记录呈现为当前任务。
4. 已浏览状态若没有练习合同或作品证据，应显示真实的“尚未提供练习/证据”或“待提交”空态，不显示“已完成”。
5. 当前任务卡的状态词与路线阶段状态共用事实语义，但不自行创造路线字段。阶段的 `未开始 / 阅读中 / 已提交证据 / 待独立验证` 只在课程数据提供时显示。

## B. 问教材：入口、抽屉和状态

### 入口和容器

- 收起态是正文外、不遮挡内容的右下角 `查教材` 胶囊；它是跨页辅助入口，不是第六个主导航。
- 桌面打开为锚定触发入口的侧抽屉或内嵌面板；抽屉内部独立滚动，正文、保存、分页和练习提交仍可见并可聚焦。
- `≤760px` 打开为接近全屏的底部工作表；保留安全区，输入、发送、关闭和结果操作不能被软键盘遮挡。
- 打开/收起不得清空输入、查询主题、当前阅读上下文、查询历史、结果滚动位置或焦点；`useCurrentContext` 默认关闭，只有用户主动开启才发送当前章节位置。
- 关闭后焦点回到 `查教材` 触发控件；迟到结果不能夺走焦点或覆盖新查询。

### 视觉层级

结果卡固定按三层呈现：

1. **推荐去哪里**：篇章/小节标题与唯一主按钮 `阅读这一节`。
2. **为什么匹配**：一句匹配理由、限制和不确定性。
3. **原文依据**：默认折叠的连续摘录、教材版本、来源路径、定位与 `sourceSha256`。

肯定结果卡应把以下身份放在卡内可见或一步展开可见的位置：`textbookVersionId`、`contentVersion`、`corpusHash`、`indexVersion`、`unitId`、`sectionId`、来源路径、`sourceSha256`、实际 `engineMode`。推荐、原文依据和能力结论不能混成“已解决”或“已掌握”。

### 状态呈现和恢复动作

客户端不能将后端状态压缩为“有/无结果”。每种状态都同时使用图形、短标签、边界和真实动作；颜色不是唯一编码。

| 状态 | 视觉表达 | 必须保留/提供的动作 |
| --- | --- | --- |
| `pending` | 进度形状 + `正在查找教材依据`；保留当前正文 | 可收起继续阅读；防止同请求重复提交 |
| `recommended` | 结果卡三层结构；显示版本/小节徽章 | `阅读这一节`、`查看出处`、`复制引用` |
| `needs_clarification` | 单一澄清问题；候选做成完整按钮 | 选择候选后继续；无结构化选项时要求补充表达 |
| `no_match` | 说明当前教材没有足够依据；使用空态图形 | 2–3 个改写 chip、课程目录入口；保留原输入 |
| `related_uncovered` | 相关但当前教材未覆盖的状态标签 | 目录入口或改写；不得回退到相邻旧答案 |
| `unrelated` | 说明问题与当前职业教材无关 | 清除/改写提示；不能自动套用当前章节 |
| `unavailable` | 服务/职业内容不可用的边界状态 | `重试`、课程目录或换职业；不能伪装成无匹配 |
| `invalid_input` | 输入附近的短错误提示 | 保留可编辑输入，说明可接受表达 |
| `stale_version` | 版本失配徽章和刷新提示 | `刷新来源`/重试；不显示旧摘录为当前结果 |
| `anchor_unavailable` | 来源定位不可用的明确状态 | 返回篇章/目录或重试；不得给无锚点的确定性引用 |

规则降级必须在结果附近明确显示 `当前使用规则检索`，并继续提供版本和原文校验；不能称为联网生成、通用语义模型或外部模型。服务故障不能伪装成 `no_match`。输入、主题、历史和滚动位置在状态切换后可恢复。

## C. 练习、作品和证据状态槽

工作台和记录页将学习事实、作品事实和评价来源并列显示，至少保留以下五个来源槽：

- `本人自述`：学习者输入的目标、方案、差距和改进；
- `运行证据`：日志、截图、测试记录或链接是否实际存在；
- `AI 建议`：机器建议，不能作为审核；
- `专业评审`：对应专业岗位独立核对；
- `真人评审`：只有真实专家证据存在时才显示已发生。

作品流程状态沿用合同：`未开始`、`draft`、`已提交`、`待独立复验`、`复验发现问题`、`证据不足`。来源槽和流程状态分开显示，不能把“自述已填”渲染为“专业评审通过”。状态卡建议采用相同宽度、图标+文字和事实短句，例如：

| 来源槽 | 有事实时 | 无事实时 |
| --- | --- | --- |
| 本人自述 | `本人自述 · 已填写` | `本人自述 · 未开始` |
| 运行证据 | `运行证据 · 已提供` | `运行证据 · 未提供` |
| AI 建议 | `AI 建议 · 已生成（机器建议）` | `AI 建议 · 未生成` |
| 专业评审 | `专业评审 · 待独立复验/已发现问题` | `专业评审 · 未开始` |
| 真人评审 | `真人评审 · 已记录`（必须有真人记录） | `真人评审 · 未验证` |

保存、提交、失败和导出反馈紧邻对应控件，并保留提交版本、职业快照、教材/练习版本和来源链接。版本升级不能覆盖旧提交。缺证据时不得显示 `已掌握`、`已通过`、`可录用` 或百分比能力结论；没有练习合同的单元显示真实的“尚未提供练习/证据”。

## D. 响应式实现清单

实现与 QA 均按 CSS viewport 记录，不以设备名称代替尺寸：

| 视口/场景 | 设计必须保持的关系 | 失败条件 |
| --- | --- | --- |
| `≥1280px` | 侧栏、单一任务卡、路线/目录、正文 `680–740px`、先修右栏层级清楚；问教材不挡正文/保存 | 抽屉覆盖正文末段，先修被 sticky 裁掉，主 CTA 与探索入口同权重 |
| `1024/768px` | 阅读切单列，先修在正文前；题库筛选不挤压题面；路线节点可读 | 横向滚动、关键先修被折叠到文末、题面被筛选器遮挡 |
| `390/375px` | 侧栏折为导航菜单；当前任务 CTA 仍唯一；问教材为工作表，输入/发送/关闭/结果均可见 | 固定面板遮挡提交，标题或来源被截断，打开后不能回到触发点 |
| `320px` | 长中文标题、题面、版本、来源和先修自然换行；代码/表格只在自身容器横滚 | 整页横向滚动、操作按钮溢出、hash 或来源被裁剪 |
| 软键盘/安全区 | 输入字号至少 `16px`；发送、收起、错误恢复和保存不被键盘/安全区遮挡 | 键盘打开后无法提交/关闭，焦点跳出工作表 |
| `200%` 缩放/长内容 | 任务、证据、版本和错误状态仍可读；焦点可见；无信息只靠 hover | 文案裁切、按钮重叠、长 hash 破坏布局、主路径必须依赖 hover/动画 |

正文、先修、代码块、表格和教学图必须各自可读；代码/表格在局部容器滚动，整页保持无横向滚动。图片放大对话框要有标题、关闭、`Esc` 和返回触发点。

## E. 键盘、焦点和读屏验收

这些是客户端实现和测试工程师的共同验收接口；本设计交接不把静态 `aria-*` 属性当运行通过证据。

| 编号 | 实现检查 | 独立运行证据 |
| --- | --- | --- |
| `DV1-A11Y-01` | 主导航、路线、目录、题库、记录、设置、正文均可键盘到达；当前入口有 `aria-current`；页面切换把焦点移到新标题 | QA 键盘逐步记录和截图 |
| `DV1-A11Y-02` | `查教材` 有可理解名称；打开/收起有 `aria-expanded`、`aria-controls`；`Esc`/收起返回触发点；迟到结果不抢焦点 | QA 打开、收起、查询、迟到响应操作记录 |
| `DV1-A11Y-03` | `pending`、无匹配、澄清、失败、保存状态用 `role=status`/`role=alert` 播报；长摘录不自动朗读 | QA 读屏录屏/文字记录 |
| `DV1-A11Y-04` | 状态有图形+文字；图标按钮有稳定名称；焦点环清楚；链接、按钮、`details/summary` 语义正确 | QA 灰度、键盘和读屏证据 |
| `DV1-A11Y-05` | 长中文、长 hash、代码、表格在 200% 缩放下不裁切；主流程不依赖 hover 或动画 | QA 200% 截图和键盘操作记录 |
| `DV1-A11Y-06` | 工作表/抽屉有合理焦点范围；打开时焦点到输入或标题，关闭时还给触发按钮；正文末端、保存、提交仍可聚焦 | QA 使用键盘 Tab 顺序记录 |

读屏文案必须说清当前职业、当前任务、版本、状态和恢复动作；不要把原文摘录、hash 或多余内部字段作为连续播报。图标不能单独承担“失败/等待/已提交/未验证”的意义。

## F. 给各岗位的同步边界

- **客户端软件工程师**：按本文件 A～E 和 `design-v1.0-learning-workbench.md` 实现视觉层级、状态分支、抽屉/工作表、焦点恢复与响应式；消费产品和后端真实字段，不自行增加章节、先修或能力状态。完成后交付可运行版本和变更清单给 QA。
- **AI 生成/内容检索岗位**：只提供产品合同所需的意图、候选、小节、摘录、版本、理由、不确定性、`engineMode` 和恢复状态；无依据时返回明确状态，不能给设计层补造答案。检索状态显示必须与本文件 B 的状态映射一致。
- **后端数据工程师**：保持职业快照、教材/索引版本、练习提交版本和历史记录的真实边界；不以进程内状态让前端伪装跨重启恢复，不修改正式用户记录。
- **课程架构师/教材研发员**：提供试点单元的输入、产出、完成条件和证据合同；未提供的单元让界面显示真实空态，不要求设计创造内容或评价。
- **测试工程师**：当前源冻结后独立执行 V1-01～V1-09，重点复验四态、问教材全部状态、证据分层、版本失配、320/375/390/768/1024/1280、200% 缩放、键盘/读屏/软键盘。旧 QA 的局部通过不能继承到 1.0。
- **项目经理**：同步记录每项实现/复验状态、责任人、证据和缺口；本文件完成不等于 1.0 通过，完整产品仍按原八门槛维护。

## 当前设计结论

设计交接足以作为 1.0 客户端实现的视觉/交互输入：主路径、四态任务卡、问教材状态、证据层级、版本身份和无障碍/响应式条件均已落盘。当前 QA 结论仍是 `insufficient`，V1-01～V1-08 尚未有当前源的真实浏览器/HTTP 证据，V1-09 只有限定的本地静态/运输通过。下一步应由客户端按清单实现，随后由测试岗位独立复验并记录缺陷；不能把 SVG、源码分支、静态断言或本同步文件当成运行通过、真人理解、学习效果、职业认证或完整产品达标证据。
