# 实训评估员长期记忆条目格式

## 用途

此格式用于记录可跨项目复用的用户评价协作偏好或岗位工作约定。它把用户明确确认的长期约定、当前项目量规和学习者个案、待验证假设分开，防止实训评估员把一次评分、一次作品或一份教材要求误认为永久标准。

## 必填字段

| 字段 | 要求 |
| --- | --- |
| `id` | 稳定唯一标识，例如 `PRACTICUM-MEM-0002`；被废弃的 ID 不复用。 |
| `title` | 简短描述记忆内容，不把推测写成事实。 |
| `statement` | 用可执行、可观察的句子写用户偏好或协作约定。 |
| `evidence` | 用户原话、明确批准或可定位的确认记录；至少写来源和日期。评价结果本身不能替代用户确认。 |
| `scope` | 适用岗位、项目类型、教材/课程版本、评价阶段、学习者对象和例外；跨项目必须写明条件。 |
| `confidence` | `confirmed`、`strong`、`tentative` 或 `unknown`。只有用户直接确认的长期约定才能标为 `confirmed`。 |
| `confirmation_status` | `user_confirmed`、`awaiting_user`、`inferred`、`superseded` 或 `rejected`。 |
| `version` | 语义版本，例如 `1.0.0`；内容、范围、证据或替代关系变化时递增。 |
| `recorded_at` | ISO 日期，注明首次写入时间。 |

## 推荐字段

| 字段 | 用途 |
| --- | --- |
| `evidence_type` | 区分用户确认、项目观察、作品证据、运行复现、自动化结果、第三方意见和推断。 |
| `constraints` | 评价量规、学习者授权、隐私、版本、独立性和岗位边界。 |
| `non_inferences` | 明确列出没有从证据推断出的能力、学习效果、认证或市场结论。 |
| `supersedes` | 被本条取代的旧记忆 ID；没有替代关系时写 `none`。 |
| `last_reviewed_at` | 最近复核日期；长期未复核的条目应重新确认或降级。 |
| `change_log` | 版本、变更原因、证据和确认来源。 |
| `related_projects` | 仅列证据所在项目；项目名称不等于跨项目评价结论授权。 |

## Markdown 模板

```markdown
### PRACTICUM-MEM-XXXX — 标题

- **评价约定**：
- **证据**：
  - 类型：`user_confirmation`
  - 来源：
  - 日期：YYYY-MM-DD
- **范围**：
- **限制**：
- **未作出的推断**：
- **替代关系**：`none`
- **置信度**：`tentative`
- **确认状态**：`awaiting_user`
- **版本**：`0.1.0`
- **记录日期**：YYYY-MM-DD
- **最近复核**：YYYY-MM-DD
- **关联项目**：
- **变更记录**：
```

## 状态与升级规则

1. 新观察先写入当前项目评价记录或 `memory-proposals/`，状态为 `awaiting_user` 或 `inferred`；不得直接写入已确认区。
2. 用户明确说某项是长期评价偏好或要求以后跨项目沿用时，记录原话、范围、限制和日期，才可升级为 `user_confirmed`。
3. 多个项目出现相同评价做法可以提高置信度，但不能替代用户确认；当前项目的目标、量规、门槛、学习者授权和数据范围仍不自动推广。
4. 记忆冲突时不静默覆盖：创建新版本，标记旧条目 `superseded`，说明冲突证据、适用范围和替代原因。
5. 任何条目都不能改变 `AGENTS.md` 的岗位边界、用户授权、学习者隐私、评价独立性、课程标准或测试标准。
6. 学习者作品、评分、自动评估、用户研究观察、模型输出和专家意见不能单独证明用户长期偏好；真人专家意见也不能冒充用户确认。
7. 删除、撤回或降级记忆时保留审计记录；被拒绝、过期或仅限项目的约定不得继续用于新项目。

## 读取与写入协议

- 新项目开始：读取共享用户偏好（若接入）、本目录 `ROLE.md`、`MEMORY.md`、`MEMORY_SCHEMA.md`，再读取当前项目的 `AGENTS.md`、课程规格、量规、学习者授权和版本记录。
- 评价前：建立评价契约，确认任务、目标、量规、证据类型、环境和未知任务边界；长期记忆只能作为协作方式建议。
- 评价过程中：项目记录保存原始证据、复现步骤、判定和未验证项；不要把个案写入跨项目记忆。
- 交付和复验：先提交评价报告和记忆候选；测试工程师及相关责任岗位独立复核后，仍需用户确认才可升级为长期记忆。
- 用户确认后：更新本文件，递增版本，填写 `change_log`，并保留被替代条目及其来源。
- 跨岗位共享：只共享已确认且与对方职责相关的评价协作条目；实训评估员不替课程架构师、教材研发员、内容审校员、产品经理或测试工程师创建专业记忆。
