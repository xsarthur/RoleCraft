岗位：测试工程师  
适用版本：教材 v13 试读稿及其后续接入的学习阅读器  
状态：测试合同，未执行，不代表客户端已经实现

## 1. 目的与职责边界

长代码默认收起会改变正文阅读、定位、键盘操作和读屏行为，因此属于产品、设计、客户端开发、教材编辑和 QA 的共同交接项。编辑只提供代码块的教学元数据和必要内容；产品确认功能范围和状态语义；设计确认控件、色彩、间距及窄屏表达；开发实现渲染和交互；QA 按本合同独立核验。任何一方的静态自查、源码存在或 Markdown 写法都不能代替实际阅读器验收。

本合同只验代码块折叠功能及其与正文、图示的关系，不验代码正确性、模型调用、账户数据、教材整体达标或真人学习效果。

## 2. 受测内容与固定定义

首批受测文件：

- `textbooks/v13/02-task-acceptance.md`：25 行 YAML 教学示例，当前标注“默认展开/收起”语义的基准样本。
- `textbooks/v13/03-trust-boundary.md`：正文含短代码/伪代码及中段视觉卡，作为短代码和图文混排样本。
- `textbooks/v13/c01-control-loop.md`：多段超过 10 行的 TypeScript/Python 伪代码，作为长代码、多个代码块和深阅读样本。

行数按代码围栏内的逻辑换行计数，不按屏幕自动换行计数；空行按展示行计数。代码块标题、语言标记、说明文字和折叠控件不计入阈值。超过 10 行必须有展开/收起控件，默认收起；10 行及以下不强制折叠，默认完整可见，除非产品另有明确合同。

“收起”只隐藏代码内容，不删除标题、用途、行数、运行状态、关键输入/输出和必要结论。示例代码没有运行时，必须保留“未运行”等状态。折叠状态是当前阅读界面的临时状态，不得被写成学习掌握、完成或能力认证。

## 3. 独立验收条件

| ID | 范围 | 通过条件 | 失败示例 |
| --- | --- | --- | --- |
| CC-01 | 长代码阈值 | 11、25、50 行代码均出现清楚的展开/收起控件，首次进入默认收起 | 25 行代码直接铺满正文，或 10 行代码被错误隐藏 |
| CC-02 | 行数判定 | 逻辑行数与编辑元数据显示一致；自动换行不改变阈值 | 窄屏一行折成三行后被误判为长代码 |
| CC-03 | 短代码 | 1、5、10 行代码默认完整可读，不出现无意义的折叠层 | 短代码被默认收起，读者必须多一次操作才能看到定义 |
| CC-04 | 默认状态 | 刷新、首次打开、从目录进入和从检索结果定位时，长代码均按合同默认收起 | 页面记住上一次展开状态并造成下一篇长代码默认展开，或首次进入自动滚到代码内部 |
| CC-05 | 展开/收起 | 鼠标、触摸、键盘均可切换；按钮文字、箭头/图标和 `aria-expanded` 与实际状态一致；重复操作无跳变 | 只改变图标不改变内容，或点击后控件失去焦点且无法再次收起 |
| CC-06 | 锚点与定位 | 深链接到代码标题/代码块时能定位到真实标题；必要时自动打开目标代码并将焦点放到控件或代码块，不把正文截在不可见区域 | 链接落在收起代码中间但用户看不到目标，或定位后焦点落到页面顶部 |
| CC-07 | 刷新与返回 | 展开后刷新、浏览器后退/前进、从章节目录返回，章节、代码块和阅读位置语义正确；不产生跨章节串状态 | A 章展开导致 B 章同 ID 代码也展开，或返回后跳到首页 |
| CC-08 | 键盘 | Tab 可到达控件，Enter/Space 可切换，焦点环清楚；折叠后焦点仍在控件，继续 Tab 顺序合理 | 只能鼠标点击；Space 滚动页面但不能切换；焦点进入隐藏代码内部 |
| CC-09 | 读屏与文字替代 | 控件有可理解名称，读屏能知道代码标题、行数、展开状态和“未运行”等状态；隐藏内容不在收起态重复朗读 | 只有“按钮”“展开”无上下文，或收起后读屏仍朗读整段代码却视觉不可见 |
| CC-10 | 图文混排 | 代码前后的教学图、图注、Mermaid 降级说明和段落顺序不被折叠破坏；箭头、图例和代码控件互不覆盖 | 展开代码覆盖中段视觉卡，收起后图注贴到错误章节，或出现双重滚动条 |
| CC-11 | 窄屏 | 320/375/390/760px 等目标宽度下，控件可见可操作；代码容器可独立横向滚动，正文和整页不横溢；收起态不保留空白高墙 | 代码横向滚动带动整页，按钮被裁切，或展开后遮住图和末尾练习 |
| CC-12 | 视觉与色彩 | 控件、代码背景和状态色符合设计稿；对比度足够，颜色不是唯一状态依据；展开/收起箭头不覆盖文字 | 箭头穿过标题，依赖颜色才能区分状态，暗色代码背景导致文字不可读 |
| CC-13 | 代码高亮 | 语言标记、高亮、等宽字体和复制/下载（若产品提供）在展开与收起前后一致；高亮失败仍显示纯文本 | 收起再展开丢失高亮，代码被当成正文换行，或复制得到隐藏说明文字 |
| CC-14 | 多块连续阅读 | 同一章节多个长代码块可独立展开；展开一个不会误展开全部；连续展开不会破坏章节标题、图和练习的阅读顺序 | 使用同一个全局开关造成全部代码同时打开，或第二块覆盖第一块 |
| CC-15 | 内容完整性 | 展开后代码首尾、空行、缩进、标点、行数和正文源一致；收起不改变源文、锚点或链接 | 展开时截断最后几行、丢缩进，或把收起作为删除代码的替代 |
| CC-16 | 失败和退化 | JavaScript 不可用、CSS 未加载、旧浏览器或导出 Markdown 时，代码仍可读；控件失效时不隐藏关键代码 | 无脚本时 `<details>` 内容永久不可见，或错误状态只剩一个无意义按钮 |

所有条件均须在真实渲染页面核验。Markdown 源码、DOM 属性或单元测试只能作为辅助证据。

### 4.2 交互与设备矩阵

每个样本至少在桌面鼠标、桌面全键盘、触摸窄屏和读屏模式各执行一次。目标尺寸至少包括约 1280px、760px、390px 和 320px；若产品合同另有目标尺寸，以产品/设计冻结值为准并记录版本。记录浏览器、字体、缩放比例和是否启用 JavaScript。

### 4.3 锚点、刷新与混排步骤

1. 从章节目录、检索结果和正文内链接分别进入长代码标题。
2. 验证默认收起、标题可见、来源/未运行状态可见。
3. 展开，记录代码首行、末行、焦点、滚动位置和图示位置。
4. 收起，再刷新；执行后退/前进；再从另一章节进入相同类型代码。
5. 在代码前后各有一张图或图注的章节中重复步骤，确认不覆盖、不重排、不丢失降级文字。

## 5. 证据与缺陷记录

每个测试结果至少保存：教材版本与源文件 SHA、页面 URL/章节锚点、代码块标题和逻辑行数、浏览器/视口/字体、操作路径、默认/展开/收起截图或 DOM 可见状态、键盘/读屏观察、是否影响图文混排、结果 `pass` / `fail` / `insufficient`。

缺陷须注明责任领域：

- 行数、标题、运行状态或示例语义：教材编辑/课程架构师交接；
- 控件名称、色彩、间距、图文层级：产品/设计交接；
- 渲染、状态、锚点、键盘、读屏和退化：客户端开发交接；
- 缺陷复现、证据和复验：测试工程师负责。

一次“已加 `<details>`”或“源码检查通过”不能关闭缺陷。修复后须按原失败步骤复验，保留首失败证据；任何默认状态、阈值或可访问性语义变化都要更新产品、设计、开发和编辑交接版本。
