# 教材标准：生产级 Agent 应用工程

版本：教学草案 v0.2；日期：2026-10-10；正式行业评审未完成。

## 职业对标

培养目标是形成领先企业所需的工程、协作与持续改进能力。已访问 Anthropic 的 [Applied AI Engineer, Startups 公开岗位](https://job-boards.greenhouse.io/anthropic/jobs/5432575008)：列出 Python、生产 LLM 应用、上下文、Agent 架构、评估、部署与技术协作。该岗位还有经验和客户顾问要求，不能把课程完成等同于满足全部招聘条件。

技术参考分别是 [Agent 模式与取舍](https://www.anthropic.com/engineering/building-effective-agents)、[状态与持久化](https://docs.langchain.com/oss/python/langgraph/overview)、[Agent 评估方法](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)。四页访问日期均为 2026-10-10。前者是公开企业岗位描述，后三者是官方技术能力参考；本课程的模块、练习和评分是教学推导，不代表企业认可或录用保证。模式文章提醒工具生态已变化，具体 API 仍需核对版本。

## 层次与覆盖

学习分四层：基础层掌握编程、接口、测试与模型调用；核心层独立完成上下文组织、检索、Agent 决策和工具动作；工程层验证状态恢复、评估、安全、部署和性能成本；职业交付层完成业务任务、协作评审、答辩与复盘。跳级必须依据作品或诊断证据，不凭自报从业身份。

“广”定义为七域覆盖：软件工程、模型上下文、检索数据、工具状态、评估安全、部署成本、产品协作。每域至少有一个模块、一个产物和一种评价方式，覆盖率应为 7/7。当前规划 12 个模块，八个短教材仍是示例，不能称为整套教材完成。

## 清晰与精度规则

“清晰”：100% 模块列出 2—4 个可观察目标、先修、深度、交付证据和验证方法。每章按职业任务与边界、目标先修、原理取舍、完整案例、示例环境、分层练习、验证反馈、来源审核、复盘迁移九项组织，案例和代码应直接服务目标。

“精”：每章聚焦一个主要任务，注明适用边界与常见误区；提供至少一个完整案例及正常、边界、失败三类验证。练习分脚手架、独立实现、迁移三类，给出提交物、参考解法和反馈依据。质量按证据衡量，不按字数、工具数量或生成篇幅衡量。

关键事实需定位到原文并记录资料和技术版本、访问日期及未知信息。可运行示例需有依赖、输入、预期结果与执行记录；伪代码明确标记。事实核对、示例测试、教学审核和专家审核分别记录。任何未执行的审核不能显示通过；AI 自检不能标为专家审核。

## 证据与评价

采用 0—3 分教学量规：0 无证据或关键错误；1 依赖脚手架且证据不全；2 独立完成约定任务并可复现；3 在未知任务和异常下复现，能解释并改进。分别评价正确性、可靠性、安全、评估证据、运行维护和沟通协作。

草案门槛为适用维度至少 2 分，安全关键检查不得失败；这是待行业评审校准的教学规则。综合交付需要非作者复现、独立保留案例及专业评审。概念题、项目勾选或一张截图均不能认证职业能力。学习工时在真实学员数据形成前只作参考。

## 复盘产出

每模块至少分析一项失败或限制，每项目至少完成一次改进和二次验证。复盘记录：原目标与标准、实际成果和证据、差距分类、原因假设与未知、改进取舍、相同条件复测、回归结果、新任务迁移、遗留问题。允许指出无改进或负面结果，不能只写心得或自信评价。

课程复盘应区分缺乏知识、任务表述不清、示例失效和练习难度不匹配，再更新受影响章节及版本。现阶段已完成来源页面核验和教学草案；完整教材、真实模型生成、示例全量运行、专家评审与学习效果验证仍待执行。
