# 从 Agent 教材沉淀的可迁移编辑经验

版本：v01（2026-10-16）  
责任岗位：课程架构师  
用途：为后续职业教材提供编辑、设计、产品、开发和测试的共同参考。本文提炼 Agent 教材 v13 的方法，不把 Agent 专属术语强行复制到其他职业。

## 1. 先区分通用规则与 Agent 专属规则

### 可迁移的通用规则

这些规则适用于任何需要解释复杂工作、工具或判断的职业教材：

- **先回答读者要解决的问题**：开头给结论、适用条件和边界，避免用行业背景拖延核心判断。
- **固定同一案例和对象**：跨段落保持角色、任务、输入、产物和状态名称，避免 A/B 代号漂移。
- **把文字转成可观察关系**：在责任、时序、状态、方案差异或证据链适合时使用流程图、状态卡、时间线、对照表、作品模板或示例界面。
- **少量、带任务的视觉材料**：图前提出读者问题，图中保持字段/方向一致，图后回到正文；图为理解服务，不以插图数量评分。
- **稳定而克制地用色**：色彩区分层级、风险或证据状态，同时使用文字、形状和图例；颜色不能单独承担含义，需检查对比度和灰度阅读。
- **降低连续阅读负担**：长段落拆成有逻辑的短段、列表、表格或卡片；保留完整推理，不能用视觉排版掩盖缺失机制。
- **代码默认可控地展开**：超过产品约定阈值的代码默认收起；摘要说明用途、版本、行数和关键分支，静态/无脚本场景仍可理解。
- **把练习做成证据**：基础练习重建机制，迁移练习改变条件，综合练习交付能被他人复现的作品；不以背定义或自评代替能力证据。
- **明确证据状态**：区分事实来源、教学构造、作者自查、独立审校、实际运行、真人反馈和未知项。
- **跨端同步呈现变更**：内容新增图、代码折叠或状态徽章若改变程序行为，产品、设计、开发、测试和编辑共同确认，不由编辑单方面决定。
- **用职责链交付**：课程架构负责能力/先修，作者写正文，设计决定视觉表达，产品决定产品行为，开发实现，审校核论证，测试独立验证，项目经理协调记录。
- **保留失败和复验**：每个核心技能都要有正常、失败/拒绝、未知或停止路径，以及修复后如何复验的说明。

### Agent 专属规则

以下内容来自 Agent 工程的机制，不应原样移植到没有相应对象的职业教材：

- Agent 的控制循环、动作账本、提议/调度/发送/效果身份。
- 模型响应的结构闸门、工具调用、MCP、A2A、检索、重排和多 Agent 控制权。
- 任务状态、上下文、长期记忆、计划 DAG、重规划、checkpoint、事件流和远端副作用。
- 代码沙箱、提示注入、权限来源传播、审批绑定、去重、补偿、熔断和模型服务成本。
- Agent 特有的“模型提议不等于执行授权”“本地取消不等于远端撤销”“检索召回不等于事实支持”等边界句式。

迁移时只保留背后的教学原则。例如，Agent 的“动作账本”可以转化为医疗教材的处置记录或财务教材的审批记录，但字段、风险和证据必须重新由领域岗位定义；不能把 Agent 的状态名、风险阈值或工具协议当成通用答案。

## 2. 可迁移的章节编辑框架

后续职业教材可采用以下检查顺序，由课程架构师按领域改写：

1. 本章解决哪个真实工作问题？读者做完要作出什么判断或交付什么作品？
2. 需要哪些先修？哪些读者可以跳过，哪些缺口必须补学？
3. 贯穿案例的角色、输入、产物、责任人和成功条件是什么？
4. 哪些关系用文字难以快速看懂，适合做图、表、流程、时间线或示例界面？
5. 正常路径、反例、拒绝/异常、未知和停止如何发生？各自的观察证据是什么？
6. 至少有哪两个真实可用的替代方案？选择、放弃和复验条件是什么？
7. 练习如何从机制理解递进到跨场景迁移和作品交付？
8. 哪些是来源事实、教学构造、建议、未运行示例、用户反馈或未知？
9. 需要哪些跨端功能同步？是否涉及产品入口、交互、代码折叠、无障碍、数据或测试？
10. 本轮完成后，什么仍需真人学习者、行业专家、真实工作或生产证据确认？

## 3. 通用视觉与代码交接模板

每篇交给设计师和产品/开发的附件至少写明：

| 项目 | 必填内容 |
|---|---|
| 理解任务 | 读者看完应回答的一个具体问题 |
| 视觉材料 | 文件、类型、邻近段落、对象/关系、是否构造示例 |
| 文字替代 | 无图或低带宽阅读仍能获得的关键关系 |
| 色彩语义 | 每种色彩表达什么；对应的文字/形状替代 |
| 代码折叠 | 行数、折叠摘要、必须在摘要外保留的输入/输出/分支 |
| 产品影响 | 是否需要组件、深链、阅读状态、版本或降级支持 |
| 设计验收 | 布局、连线、对比度、窄屏、键盘和读屏关注点 |
| 测试证据 | 实际打开/渲染/交互/链接检查的版本、输入和结果 |
| 未验证项 | 浏览器、外部服务、真人理解或专家判断等缺口 |

这份模板提供交接信息，不预先决定产品路线图、界面状态或行业标准；具体行为仍由产品和设计岗位确认。

## 4. 迁移时的常见错误

- 把 Agent 专属流程图直接换名后用于另一职业，导致对象、责任或风险不成立。
- 以“多放图”替代对案例、边界和失败机制的解释。
- 只在开篇放一张总图，正文中段仍是无法定位的连续文字；或插入没有阅读任务的装饰图。
- 用颜色表达通过/失败/权限，却没有文字、图形或图例，造成灰度和无障碍误读。
- 编辑先决定界面路线图、阅读状态或交互行为，再要求产品和开发照做。
- 代码折叠只看前端展示，没有同步产品阈值、设计控件、开发降级和 QA 反例。
- 把作者自查、AI 审校、阅读完成、模拟练习或一位真人反馈写成职业胜任、用户普遍理解或行业先进。
- 章节完成后丢失旧版本、失败记录和未验证项，无法判断改动真正改善了什么。

## 5. 交接与复盘要求

每个新职业启动时，课程架构师应先写领域能力/先修和“可迁移规则适用项”；产品经理和设计师确认产品呈现与视觉入口；作者提交正文、图文任务和练习；审校与测试按当前版本独立复验。项目经理在复盘中同时写明目标、实际证据、差距、责任人、复验方法和状态。

Agent 教材 v13 的反馈说明：真实读者能直接指出连续文字、图示时机、箭头覆盖文字和折叠功能的跨端影响。这类反馈是一个读者的原始证据，适合改变编辑合同和验证问题，不能直接外推到所有职业或所有用户。迁移到其他教材时，应重新取得该职业读者、专家和真实作品证据。

本文是编辑参考，不是任何职业的课程正文、产品需求、设计稿、代码实现或独立质量结论。
