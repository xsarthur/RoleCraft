# 课程架构师 · 教学领域审查与交接

审查日期：2026-10-10。输入：项目 `README.md`、`dist/app.js` 的八个教材示例、八道概念题及两个实践项目。本轮只审查本地材料，未联网核验来源、运行示例或进行专家审核；以下能力矩阵是待专业评审的教学草案，不是行业认证标准。

## 当前覆盖与缺口

现有内容覆盖编程基础、模型调用、Agent 循环、工具契约、检索、状态恢复、评估和部署；章节有目标、案例、练习和概念反馈。两个项目分别训练有据回答和可恢复的业务动作，适合作为后续教学骨架。

实际正文较短，属于教材样例，尚不足以独立支撑入行培养。基础章节列出 Python、HTTP、Git 和测试，但正文主要展示函数输入校验；模型章节使用静态字典，未演示真实模型请求；Agent 循环明确为伪代码；检索和部署章节主要是流程与清单。完整环境、可运行项目、练习分层、参考解法、常见误区和反馈机制仍待补充。

还缺少可观察的入学诊断、能力先修依赖、模型与方案选择比较、检索策略实验、工具鉴权与对抗输入训练、线上故障诊断、持续维护及团队协作证据。现有预约案例与基础章姓名校验代码未完全对应，需课程责任人统一教学目标。此处是内容缺口，不决定产品实施顺序。

## 教材生成与发布审核标准

1. **来源与版本**：每个关键知识主张对应支持它的原文位置，记录资料标题、发布/更新日期（未知则注明）、检索日期、SDK/框架版本及适用条件。官方来源链接不等于已证明整章正确；引用广泛的方法文章不能替代具体 API 和工程行为依据。
2. **事实与适用性**：区分事实、教学简化、经验建议和待验证判断；核验术语、接口、限制及相互冲突的资料。现有“核对于 2026.10.10”只见日期标签，本轮未见逐条核验记录，需补证据。
3. **可运行示例**：明确示例代码或伪代码；运行型内容提供依赖版本、环境、输入、预期输出、错误路径和测试记录。不得将伪代码标为测试通过。各章节目标与例题、代码和练习保持对应。
4. **教学设计**：列出目标能力、先修要求、分层练习、参考解法和常见误区；练习能产生矩阵要求的证据。新手版需更多脚手架，进阶版需独立取舍和未知案例，而非只删掉基础章节。
5. **教学及专家审核**：课程架构师审查目标与练习一致性；有相关实践经验的评审者审查专业正确性与任务质量。记录评审者、范围、结论和遗留问题；AI 自检不能标为专家审核。
6. **可追踪发布**：关联“职业能力—章节—来源—示例测试—练习—评价量规”，按教材版本保留审核记录。分别标记已生成、事实核对、示例测试、教学审核和专家审核状态；内容修改后重新检查受影响证据。

## 测验与工时估计的限制

八章各一道三选一题，只能提供有限的概念反馈；允许重复作答，答对后保留通过状态，不测代码实现、迁移应用或持久掌握。界面进度是概念题通过比例，项目检查项是自查，均无独立能力评审。

按代码中的固定值计算，零基础路线 128 小时、开发者路线 104 小时、从业者路线 80 小时；周数只是总时长除以每周时间后向上取整。未见学习者样本或耗时测量，不能据此承诺掌握程度、就业或交付周期。自报身份不能充分支持跳过基础；从业者从评估开始需确认工具、模型与工程先修。后续应记录阅读、练习、项目和返工用时，并依据真实学习证据调整范围。

## 向其他岗位交接

- **产品经理**：将职业培养目标转成可验证的学习结果；明确诊断、作品提交、反馈和专业评审的范围。保留原型、生成、审核和能力评价的不同含义；由产品经理确定产品范围。
- **设计师**：在阅读和项目流程中呈现先修要求、示例/伪代码、审核状态及评价依据；将概念进度、自查记录与评审结果分别表达。具体交互和视觉由设计师负责。
- **软件工程师**：接收能力 ID、章节版本、来源记录、样例类型、练习产物与评价量规等教学数据契约；提供生成和核验状态的证据记录。实现方案由工程师制定。
- **测试工程师**：检验内容状态标签与实际记录一致、关联可追踪、伪代码无运行承诺、概念题与自查不产生能力认证。专业事实和专家评价转交课程责任人及专业评审者，功能测试通过不能替代教学效果验证。

本轮交付为内容审查与教学交接草案，未修改原型、补写正式教材或完成职业能力认证。
