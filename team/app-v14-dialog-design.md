# v14 对话短答：设计交接

设计师；2026-10-12（Asia/Shanghai）。只读依据：`app-v14-dialog-product.md`、收到的 `dist/learning-experience-v13.js/.css`、`dist/learning-workbench.js/.css` 底部检索面板。未执行浏览器渲染，布局及真实键盘/移动端表现待测试员核对。本交接只规定当前底部面板的呈现与交互，不新增导航，不修改教材或产品门槛。

## 最小落地

保留现有固定底部输入栏及可收起面板，入口标签改为“问教材”，提交按钮改为“发送”。面板标题“Agent 学习问答”，副说明“根据 v12 教材简答，并提供原文入口”。不将本地语义检索、提取短答称为联网生成或专家答疑。输入提示“描述 Agent 开发、学习或项目中的问题”；该提示是表达引导，不替代实际职业范围判断。

面板内从上至下：标题与“收起”；紧凑上下文条；已提交问题；简答或状态提示；1–3 个来源入口。最近查询保留折叠区域，但排在当前结果后，避免首先看到旧结果。新结果不自动展开已经收起的面板。

简答采用自然段/句列，1–3 句，每句末有明确“来源 1”等引用标记；标记是页内定位到对应来源卡的真实链接。不要用课程标题拼接充当回答，也不将长摘录置于短答之前。混合请求在简答前用一行说明“本次只回答 Agent 学习相关部分”，并显示服务核定的排除范围，不扩写被过滤问题。

来源卡采用一列，显示“来源 1 · 第 N 篇 / 章节名称”、小节标题及主要入口“阅读这一节 →”。每卡默认折叠“展开教材原文”；展开后显示对应连续原文，不重新生成解释。另用折叠“查看出处”放教材版本、源文件与 SHA256。普通视图不暴露检索分数、岗位、门槛或审计术语。入口使用已核对的 `href`，不能自行用标题推导位置。

## 五种服务状态

| 服务状态 | 当前问题下的呈现 | 入口与下一步 |
| --- | --- | --- |
| `answered` | “教材简答”，显示有出处的 1–3 句；如服务实际使用有限上下文，显示“结合上一个问题：主题”或“结合当前阅读：章 / 节” | 1–3 来源卡；可编辑输入继续问；清除会话主题后独立提问 |
| `related_uncovered` | “当前教材未找到足够依据回答这个职业问题”，展示服务的简短说明；不得标为“无关”或显示旧答 | 保留输入，可补充问题背景；仅显示合同允许且经核对的辅助入口，不硬凑推荐 |
| `unrelated` | “这里只回答 Agent 职业学习相关问题。请换一个学习或项目问题。” | 不显示来源卡、不回答无关内容；保留输入供改写 |
| `needs_clarification` | “请补充你指的含义”，随后给出服务核定的澄清项/问题 | 若合同有明确选项，使用文字按钮；点击应提交完整澄清表达，不仅改选中样式；若无结构化选项，不自造选项，保留输入请补充 |
| `unavailable` | “暂时无法完成这次问答”，附具体可理解的服务提示；来源核对失败同样不能显示可用答 | “重试本题”使用该次提交的问题与上下文；可以修改后“发送”新题；没有有效来源不显示旧卡 |

`invalid_input` 是输入校验反馈，独立于上述五种结果：空问题提示先描述问题，超长提示长度限制，输入保持可编辑，不归入无关。结果为空的界面不要留下“推荐阅读”空标题。规则降级如发生，使用小字“当前使用规则检索”，真实本地语义运行才显示对应方式；标签不保证语义判断可靠。

## 提交、追问与结果生命周期

1. Enter 发送，Shift+Enter 换行，中文输入法候选确认不触发发送；按钮永远提供等价操作。等待时输入仍可编辑和发送不同问题，发送同一个尚在等待的问题可防重复提交。
2. 发送时冻结问题和本次上下文，清除结果区的上一题回答/来源，显示“正在理解问题并查教材，可收起继续学习”；输入草稿随后变化不改变这次任务身份。完成后展示提交原文，避免回答与新草稿混淆。
3. 收起不取消任务，用户继续阅读。完成后只更新底部轻提示“本题已完成，展开查看”，不自动展开、不滚动阅读页、不移动输入/阅读焦点。再次展开保留该题结果与必要的面板滚动位置。
4. 新发送、重试、选择历史问题、清除问答主题均更新当前任务身份。旧任务迟到答、错误及 finally 更新不得覆盖当前题、停止当前等待指示或插入当前来源；取消网络请求只是辅助，任务身份核对仍必需。
5. 短追问仅结合上一条已验证职业问答主题及合法阅读/题面上下文。上下文条明示实际使用来源，并提供“清除问答主题”和现有“清除章节上下文”。新主题优先；无可验证上下文的“它有什么缺点”显示澄清。无关追问不得因先前职业题自动放行。
6. 点击来源收起面板并定位该节，采用既有章节路由/返回机制。短答不能代替教材内容。刷新/返回后缓存必须重新核版本和出处，再呈现历史结果；历史结果加“本会话此前问题”标识，不装成新题已完成。

## 可访问性及小屏

面板继续采用非模态区域，`aria-label` 对应“Agent 学习问答”，不锁定阅读页、不做焦点陷阱。展开/收起按钮具有 `aria-expanded`、`aria-controls` 及可理解名称；显式展开可把焦点留在输入，收起/Escape 后回到仍存在的输入或展开按钮。请求完成只用一个 `role=status`/polite 提示结果状态，避免长回答和全部来源同时自动朗读；结果区等待加 `aria-busy`。输入错误使用 `aria-invalid` 并绑定文字说明，不能只靠红色。

所有正文、问题、摘录、服务提示当纯文本呈现；来源仅使用验证通过的当前教材链接。来源卡及原文折叠使用真实 `a`、`details/summary`，键盘可达、聚焦框清楚。引用标记的可访问名称为“来源 1：小节名称”，原文折叠名称包含来源编号。状态与来源不只靠颜色区分，延续现有白底、棕金强调色与正文对比。

桌面延续当前 840px 最大面板及约 60vh 高度；面板内部结果区滚动，标题、上下文和底部输入保持可见。760px 及以下来源一列，输入/发送/展开均保留至少 44px 操作面积；textarea 使用 16px 字号避免小屏自动缩放，允许有限多行但不顶掉结果区。小屏面板用 `dvh` 和安全区控制上限，键盘打开后仍能看到输入与收起；长章节名、问题、hash 换行，不挤出视口。不要在短答与来源中新增横向滚动，原教材代码块的既有横向阅读保留。真实 375px/760px、键盘和长文布局由 QA 验证，不以本说明替代。

## 领域自查与交接

本稿覆盖五状态、短答与引用/入口层级、澄清和有限追问、等待收起及迟到保护、输入/键盘/移动端，均对应冻结产品合同；未自定产品通过条件。PM 交接的具体服务使用 `POST /api/content/dialog`，保留原 `/api/content/recommend` 兼容。请求沿既有问题/当前页字段，短追问仅传 `previousContext {unitId,sectionId,corpusVersion,sourceSha256}`，不发送任意历史聊天文本。前端保存经校验的 `dialog.context` canonical 主题作为本会话下一次指代上下文；无法核对不使用。

响应 `dialog.sentences[{text,citationIds}]` 对应句末引用，`dialog.citations[{id,...原result字段,quote,offset}]` 对应来源卡与原文；只显示当前教材核对通过的最多三项。`scope.relatedSegments/filteredSegments/contextUsed` 供本次范围/上下文提示，`message` 供五状态短提示。不得从旧顶层 `no_match` 直接推为职业无关；优先消费 `dialog.status`。澄清服务若无结构化选项，只显示其 message 并由用户补充。

前端工程师负责底部面板及交互；检索工程师提供可验证状态、句子、引用、澄清和上下文信息；QA 独立核 DV14 原条件与真实 UI。当前交付仅设计交接，浏览器表现、用户理解、职业学习效果及完整产品目标仍未由本稿验证。
