# v12 课程架构复盘与非文字教学优化交接（r2）

日期：2026-10-15（Asia/Shanghai）  
岗位：课程架构师  
状态：`reviewed_with_actionable_gaps`  
范围：`textbooks/v12/` 当前 30 个阅读单元、`team/textbook-v12-curriculum.md/.json` 课程规格，以及本轮设计师、内容审校员和产品复盘。  
边界：本报告只做课程架构和教学交接，不改教材正文、合订本、应用代码、数据库、题库、用户记录或历史 QA 结论。

## 复盘判断

v12 已把原 20 单元扩展为 30 单元，学习顺序、正式先修、10 个新增专题、练习、作品和执行边界均有记录；原 12 个模块、24 个目标、48 个知识点也已在课程数据中保留。当前影响读者理解的主要问题，是关键教学关系仍要靠读者从长段落、表格和代码中自行拼接：

- 读者不知道自己处在“概要、深读、实作、补学、待复验”的哪一种学习状态。
- 读者能看到术语定义，却难在同一张图上追踪输入、状态、动作、观察、证据和结局。
- 固定流程、单次模型、动态 Agent、多 Agent 的适用条件和新增负担分散在不同章节，选择依据不易比较。
- 练习和作品要求写得具体，但“什么算证据、哪里仍未知、怎样交给独立接收者”缺少可填写的统一载体。
- 代码示例、构造夹具、策略模型、真实外部系统和未验证主张的关系已有文字说明，读者仍容易把模拟运行误解为生产能力。

因此下一版应优先补充**可复用的关系表达**，而不是在每章继续堆叠解释段落。非文字材料要服务于一个教学动作：让学习者能判断下一步、观察状态变化、比较方案、注入失败、提交证据，并由独立者复验。图、流程、交互和模板都必须回指当前正文与课程数据，不能另造一套隐含课程。

## 不可变的课程骨架

下一轮任何视觉稿、交互或模板均须以以下清单为约束：

| 项目 | 当前基线 | 复盘要求 |
| --- | --- | --- |
| 阅读单元 | 30 个，顺序以 `assembly-manifest.json` 和 `textbook-v12-curriculum.md` 为准 | 不删、不合并、不改变正式先修；允许增加导览、跨章索引和补学入口 |
| 原课程模块 | 12 个 | 每个模块保留原 `moduleId`、原标题、目标文本和知识点归属；新增专题只能补子能力 |
| 原课程目标 | 24 个 | 视觉/交互必须标注目标 ID 的来源和对应作品，不把“看过图”计为目标达成 |
| 原知识点 | 48 个 | 每个知识点仍须有正文真实定位、练习或作品去向；不能以节点数量替代语义覆盖 |
| 新增专题 | n01–n10 共 10 个 | 保留问题、机制、正常/失败轨迹、作品和运行边界；不把新增专题改写成必用框架清单 |
| 实作路径 | 问题证据→任务验收→信任边界→组件→评价/MVP→安全→交付→独立作品与迭代 | 视觉路线可提供分支和回看，但不能制造“完成阅读=职业能力”或未经授权的解锁门槛 |
| 证据状态 | 自述、构造夹具、本地运行、外部契约、真人/用户证据分别记录 | 所有徽标、进度和图例必须显示证据性质；不得以颜色或进度环暗示认证 |

建议维护一份机器可校验的“关系账本”：每个图、交互和模板登记 `artifact_id`、覆盖单元、覆盖模块/目标/知识点 ID、输入数据来源、正文锚点、责任岗位、验收记录和证据状态。关系账本是教学导航的派生索引，不能替换原课程 JSON，也不能反向修改原门槛。

## 优先级 A：必须先建立的四种教学关系

### A1. 路线与先修关系：30 单元学习路线状态图

**覆盖**：`00-learning-route.md`、`README.md`、全部 30 单元的 `prerequisites`；重点支撑 01、p01、02、03、c01、e01、e02、p01、p02 等原模块的学习阶段关系。

**表达方式**：以五个阶段泳道呈现“诊断与问题、边界与候选、固定/动态运行、安全与交付、独立作品”。每个单元卡片显示编号、标题、概要/深读/实作入口、正式先修、可选补学、当前证据状态。正式先修使用实线，可选补学使用虚线，回看使用回环箭头；不把所有单元画成单一路径锁。

**必须保留的课程语义**：`n01` 是基础补学与应用先修；`c01-selection` 早于完整控制循环；规划、检索、图编排、协作后置；安全在首次生成代码前成为强制前置；`p02` 是综合作品和独立复验出口。路线图不能把选读的 ANN 参数、A2A、推理服务或多 Agent 画成所有项目必经节点。

**验收条件**：

1. 30 张卡片与 `assembly-manifest.json` 一一对应，标题和文件链接可定位真实正文。
2. 每条正式先修箭头均能回指课程 JSON 的 `prerequisites`，不存在图上新增的隐含门槛。
3. 任取基础不足、已有开发基础、已有 Agent 项目三种起点，学习者能在 2 分钟内找到下一单元、补学入口和应交产物。
4. 图例同时用形状、文字和线型表达状态；无障碍文本顺序与结构化列表完整。

**责任**：课程架构师维护拓扑和 ID；设计师交视觉稿；软件工程师/内容检索工程师接入导航数据；QA 核对 30 单元、先修和链接。

### A2. 运行因果关系：统一“输入→状态→动作→观察→判定”轨迹模板

**覆盖**：`02-task-acceptance`、`03-trust-boundary`、`c01-control-primer`、`c01-fixed-workflow`、`c01-control-loop`、`e01`、`n06`、`n09`，并与原 `agent-runtime-loop` 图保持同一语义。

**表达方式**：每个案例使用同一张五列轨迹图或可逐步播放的时序卡。至少画出两条泳道：模型/组件提议，宿主/业务准入。末端统一显示“完成、等待、拒绝、效果未知”四种结局；恢复路径从事实记录回到核验，不从未知直接跳到成功。每一帧显示 `task_id`、版本、权限、预算、证据和副作用状态。

**必须覆盖的反例**：正常读取后完成、权限拒绝、超时效果未知、重复提议被去重、恢复前重新核对外部效果。对于图编排和长任务，再加入节点重入、迟到结果和补偿失败；不得用动画速度或循环次数暗示能力提升。

**验收条件**：

1. 学习者仅看轨迹可指出第一次写入闸门、效果未知点、禁止重复发送点和恢复核对点。
2. 每条轨迹的输入、观察和结局均可在章节构造事实或示例夹具中找到，未知效果明确标记。
3. 同一事件在 `c01-control-loop`、`e01`、`n06`、`n09` 中使用相同形状/字段含义，不能一章把“提议”画成已执行。
4. QA 能以静态 JSON 夹具复验正常、拒绝、未知、恢复四轨迹，不把图稿存在当运行证据。

**责任**：课程架构师定义字段和结局语义；教材研发员填案例；设计师制作模板；QA 提供反例夹具并独立核对；客户端岗位只负责展示和状态绑定。

### A3. 方案条件关系：最小方案选择对照画布

**覆盖**：`c01-selection`、`c01-fixed-workflow`、`c01-control-loop`、`n03`、`n07`，关联原 `c01-o1/o2`、`p01-o1` 与对应知识点。

**表达方式**：同一任务并排比较普通程序、单次模型、固定流程、受控动态循环、多 Agent 五种方案。每张方案卡固定显示：变化来自哪里、谁拥有控制权、需要哪些观察、预算/延迟/恢复负担、最小证据和何时不应升级。增加“同任务失败轨迹切换”，让读者看到模型次数增加并不等于问题被解决。

**至少两组对照实验**：

- 稳定材料、可枚举分支的任务：固定流程与动态循环的质量、成本、等待和故障对比。
- 需要新观察改变调查方向的任务：固定流程漏分支与动态循环新增证据的对比；预算不足、没有业务权威或没有效果回执时必须展示停止/未知。

**验收条件**：

1. 读者能根据任务变化来源和证据条件选出最小足够方案，并说明升级所需的新证据。
2. 多 Agent 卡片不使用“更高级”等等级暗示；能明确指出并行性、权限、交接和成本的新增负担。
3. 对照实验记录固定输入、预算、模型/规则版本、成功定义和失败原例；没有真实模型调用时显式标为策略夹具。
4. 原 `c01-o1/o2` 和 `n03` 的机制仍可在正文定位；画布不替代完整解释。

**责任**：课程架构师负责比较维度和判定条件；教材研发员写实验说明；设计师制作画布；运营分析员提供成本字段规范；QA 核对同条件和边界。

### A4. 作品证据关系：从问题到独立复验的证据包模板

**覆盖**：`p01-discovery`、`02-task-acceptance`、`p01-mvp`、`n10`、`p02`，并回接全部模块的作品输出。

**表达方式**：提供可复制的证据包模板和链路图：问题证据→现有方案→差异假设→任务合同→实现版本→失败轨迹→修复回归→独立接手→迭代决定。每个节点有字段、来源类型、日期、版本、责任人、未决项和“未验证/已运行/待真人复核”状态。另给一份小型完整样例和一份缺证样例，展示接收者如何拒收或要求补证。

**必须形成的模板**：任务合同、来源/版本清单、轨迹记录、失败复现单、实验矩阵、ADR/取舍记录、技术移交包、复验记录。模板字段不应要求学习者填写未经实际取得的用户访谈、真实账单或专家意见。

**验收条件**：

1. 每个新增专题的 `W-N01` 至 `W-N10` 和原 20 单元作品要求都能映射到证据包节点，不能只覆盖新专题。
2. 无来源的判断不能显示为“已验证”；自述、教材引用、本人作品、真人复核四类状态互不混淆。
3. 未参与实现的接收者能依据模板复现一个小型构造任务，并指出缺失证据；模板完成不自动授予职业能力结论。
4. `p02` 交付能分别输出作品结论、学习者能力证据、行业优势证据三条出口，不能互相替代。

**责任**：课程架构师定义字段与映射；教材研发员提供样例；实训评估员定义接收者任务；QA 进行盲接收复验；产品经理决定工作台的展示范围。

## 优先级 B：按专题增加的非文字材料

| 教学关系 | 主要单元 | 建议材料 | 最低验收 |
| --- | --- | --- | --- |
| 错误发生在哪一层 | `f01`、`f02`、`n04`、`n05` | 协议/结构/业务/效果四层失败分诊卡；HTTP 200、合法 JSON、召回为空、引用失效的并排案例 | 学习者能指出下一项核对，不把上一层症状当根因 |
| 记忆、权限和任务切换 | `n02`、`03` | 记忆生命周期时间线、作用域泳道、撤销失效传播图、双任务歧义交互 | 能从图中判断哪些记录可读、哪些批准不能继承，并能拒绝歧义动作 |
| 检索摄取到答案 | `c02`、`n05` | 小语料对照实验包：Flat/HNSW/IVF、重排、改写开关；recall、nDCG、延迟、费用和漏召回样例面板 | 能解释指标变好但证据边界变差的一次结果；混版/权限收回不漏入 |
| 计划和反思 | `n03` | 固定流程/ReAct/Plan-and-Execute/证据反思四轨迹对照；DAG 重规划交互 | 能指出首个失效节点、停止理由和不能用空泛反思替代证据的原因 |
| 工具与协议 | `n04`、`c03` | 工具目录筛选器、MCP 往返时序、过期令牌/版本不兼容拒绝卡 | 能区分模型提议、协议连接和执行授权；拒绝层可定位 |
| 图编排与协作 | `n06`、`n07` | 状态字段/Reducer 交互图、父子图边界、交接信封正常/拒收/过期泳道 | 能指出私有状态、共享证据、迟到结果和唯一写入责任 |
| 安全与执行 | `e03`、`n08` | 宿主→准入→隔离器→收割器→业务核验剖面图；策略 YAML 与拒绝回执对照 | 能判断哪个层强制 CPU/网络/挂载限制，并说出模拟策略不能证明 OS 隔离 |
| 长任务与运行维护 | `e01`、`e04`、`e05`、`n09` | 补偿账本、熔断状态机、检查点/租约时间线、内存增长曲线 | 能区分未知效果、补偿失败、服务故障和业务拒绝；不把单次 RSS 下降当修复 |
| 跨场景评价与移交 | `e02`、`n10`、`p02` | first divergence 轨迹查看器、消融矩阵、跨语失败对照、接手者批注 | 能定位首错层并完成一次独立复现；真实用户/专家缺失保持待验证 |

这些材料应优先使用同一视觉词典：实线表示已发生事实，虚线表示候选或待验证，锁表示权限闸门，空心节点表示缺证，菱形表示判定，红色之外还必须有文字或形状说明。每个交互都提供静态打印版和结构化文本版，避免学习内容只能在浏览器中获得。

## 优先级 C：持续治理与内容维护

1. **来源卡**：每个关键外部论断标注来源类别、版本/访问日期、支持主张、未支持范围和本地是否运行；内容审校员维护，课程架构师检查是否影响目标解释。
2. **示例状态徽章**：统一显示可执行/已运行、策略模型、伪代码、外部依赖未调用、最近验证日期；不能用单一绿色表示通过。
3. **章节三屏导览**：每章固定显示“要解决的问题、要交出的证据、失败时先看哪里”，只抽取已有目标、练习和作品，不增加隐含目标。
4. **关系账本与变更检查**：每次新增图或模板运行 ID 覆盖检查、链接检查、无障碍文本检查和保护文件起止对照；新增材料不能覆盖历史正文或旧 QA。

## 分阶段实施顺序与复验合同

### 阶段 1：课程架构与视觉规格

课程架构师冻结路线图字段、轨迹字段、方案比较维度、证据包 schema 和 30/24/48 映射表；设计师据此制作两张静态稿：路线状态图、输入—状态—动作—观察—判定轨迹图。交付只进入 `team/` 规格与候选资源，不改正文和客户端。

阶段验收：课程架构师逐项核 30 单元、原 12 模块、24 目标、48 知识点；内容审校员核图中主张都能回指正文；QA 核图例、无障碍文本和四类反例。

### 阶段 2：专题材料和模板

教材研发员按不重叠批次补章节导览、对照案例、交互夹具说明和模板样例；检索、安全、运营等岗位只对各自字段和证据边界提供交接。所有新增文本和图稿仍需回指原单元，不把模板字段变成新目标。

阶段验收：每个新增专题至少一条正常轨迹、一条关键失败轨迹、一个作品模板；原 20 单元至少接入路线、轨迹或证据包中的一个共享组件；无法取得真实运行/用户/专家证据的节点保持未验证。

### 阶段 3：产品呈现与独立测试

软件工程师把已经冻结的关系数据接入学习工作台；客户端只消费版本化只读数据。内容检索工程师为图、模板和章节来源提供只读定位；产品经理确认入口和状态，不改变题库范围或产品门槛。QA 使用固定夹具验证链接、状态、歧义、空结果、无权限和窄屏/键盘路径。

阶段验收：学习者任务测试能完成“找到下一步、解释一次失败、选择方案、提交证据包”四个动作；QA 报告区分静态绑定、浏览器行为、内容正确性和真实学习效果；真人学习者、行业专家、生产经济和用户价值仍需各领域证据，不能由交互通过推断。

## 课程岗位交接与责任边界

## 当前结论与未验证项
