# Agent 全部面试参考答案返修：产品范围与验收合同

责任岗位：产品经理。日期：2026-10-14（Asia/Shanghai）。版本：1.0。

用户明确要求“将所有题进行返修”。本轮目标是让用户获得经过逐题编辑、独立内容审校和测试验证的完整参考解析，不以检查报告替代答案。执行沿用 [参考答案最低质量标准](ANSWER_QUALITY_STANDARD.md) 的 AQS-01–08；不新设字数、栏目数、代码数量、通过率或行业先进阈值。产品岗只定义范围和判据，不编写答案、修改应用或代替测试。

## 新答案与交接合同

本岗已确认 `textbooks/interview-answers-v1/` 在接单时未占用。本轮新答案在该目录交付，建议 `answers/Q1.md`、`answers/M101.md`、`answers/P01.md` 等逐题文件，并有 README 阅读入口及 manifest。课程架构师可按学习体验安排主题导航，但每个ID必须能直接定位完整答案，不能只有目录或整章链接。正文内容自然组织，不套八栏模板。

三位作者分别独占 `author-a.json`、`author-b.json`、`author-c.json`，不得共同修改总文件；数据工程整合岗唯一写入 `manifest.json`。每份作者manifest使用 `schemaVersion=1`、`answerSetVersion=interview-answers-v1`、`author`、`assignedIds` 与 `items`。逐题正文必须包含完整原题面、完整解析与参考出处，元信息放manifest。字段和路径以同名JSON合同为准，字段存在不代表内容合格：

| 字段 | 约定 |
| --- | --- |
| `id` / `collection` | 保持Q、M、P命名空间及100/14/10分组 |
| `question` / `sourceId` | 原题面完整保留；P保留原q映射及原追问 |
| `answerPath` / `answerVersion` / `answerSha256` | 当前逐题正文、明确版本及最终字节哈希；返修后重算并重新绑定 |
| `sourceBindings` | 本地来源路径、教材/材料版本、哈希、小节、行范围及支持的主张；外部新增事实另附一手URL及查核日期/必要版本 |
| `personalEvidenceRequired` | 经历题保留true；示例明确为教学假设/虚构，不写成学习者或作者亲历 |
| `authorSelfCheck` | AQS-01–08各项适用性、正文位置与理由；不适用不能掩盖本题关键机制 |
| `reviewReferences` / `qaReferences` | 指向独立岗位报告；作者不得自己写独立通过结论 |
| `priorDefectReferences` | 关联前轮原始缺陷/反例，记录当前如何修复或为何无需改动 |

正文优先回答本题及所有子问，讲清会改变理解或决策的相关机制，连接实施/判断路径、完整案例、关键失败分支、适用条件、取舍、检验方法和来源。引用应支持邻近主张；不能把截断摘录、多条互不连接的段落或让用户自行拼接整章视为完整答案。复习摘要/口述提纲可以另存，但完整解析必须存在且可直接访问。

现有文本准确且完整时允许复用。新增/变化的版本敏感技术事实须独立查核一手资料；查不到则缩小主张或明确未证实，不能为凑全而编造。伪代码、执行计划、实际运行、外部互操作及真人效果逐项分开。无必要时不要求概念题编写代码，也不要求每题完整生产实现。

## 验收分层

1. **逐题静态内容**：内容审校员和QA均须读当前题面与完整答案，按AQS语义核查，覆盖原具体缺陷和能推翻错误解释的反例；不能凭字段、字数、关键词、链接存在或旧19题结论通过。关键机制、子问、来源或边界未满足时退回责任编辑。
2. **必要的有限执行**：QA按该题实际承诺选择安全隔离的最小验证，记录环境、输入、预期、实际与输出。概念题可用静态反例；可执行主张需区分未运行和实际运行。复用旧测试程序也必须说明本轮实际执行范围，不能让运行通过弥补读者看不到的解析。
3. **当前交付与展示**：正式题数据、原型十题引用当前批准答案时，版本、ID、题面、来源、全文和状态一致。验证全文不被三条/定长截断；本地文件、导航、深链接、刷新和当前原型显示按实际检查记录。验证失败交工程岗，不让作者修应用。
4. **真人与完整产品**：真实读者理解、面试表现、职业胜任、用户认可、真人专家及行业先进/生产经济性不由前三层自动推出，仍按原门槛和实际证据独立判定。

逐题最终状态为 `met_within_reviewed_scope`、`not_met` 或 `insufficient`，待处理时用 `pending`；每个通过状态必须说明范围和限制。124题全称通过的条件是124份当前答案全部完成适用检查且无开放的关键缺陷/必要缺证；部分批次通过不能代表全部。三个集合单列分母和结论。若静态通过而展示未验，应直接写“正文限定范围通过，展示未验”，不能称全部交付完成。

## 应用交接边界

用户授权返修现有答案，实施时将批准后的完整答案供现有正式数据和原型参考展示消费，由软件工程师负责最小内容接入；不得为了接入擅自重新开放当前延期的 questions/review/check 模块、扩大产品功能或改变用户记录。原型十题可更新答案内容和来源指向；布局/入口调整若超出必要内容可读性，另向设计岗交接。正式题库数据须保留327条原始来源证据，可增加独立完整解析引用，不能把完整解析冒充教材原文摘录。没有当前审校通过的答案不能在界面标为已审校。

不改冻结v12教材、旧审计、原题ID/题意、账户数据库、用户笔记或学习状态；不调用付费模型、不上传发布、不外部联系。线上发布未获授权。工程接入先消费审核版本，最后QA对实际产物及其引用重新验证；作者文件与应用派生包不能各自悄悄变化。

## 分工与复验

课程架构师给教学组织/逐题路线和整合合同；教材研发员按不重叠题号撰写完整正文、自查和逐题缺陷修复说明。内容审校员只读独立核机制/事实/来源/边界，QA只读独立核逐题内容/反例/必要执行与交付。软件工程师独占所分配客户端/派生接入路径。PM维护任务、版本和问题流转，不写正文、应用或测试报告。

每次返修都记录原缺陷、责任人、改变位置、当前版本与原反例/受影响范围复验。允许审校与QA对未变文本纠正误判，但须说明依据并保留旧判断，不把判断纠正记成作者修复。新发现的问题同样进入闭环；没有完整复验的批次不能标最终完成。
