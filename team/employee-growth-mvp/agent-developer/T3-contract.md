# T3 · 超时、缺证与权限冲突的停止升级合同

合同版本：`T3-v1.0`  
合同状态：`scoped`（尚未执行）  
周期：`agent-developer-mvp-20261015`  
唯一责任岗位：`agent-developer`（`AGDEV`）  
独立复核岗位：`qa-engineer`  
升级接收：项目经理、产品经理；按原因抄送相应接口责任岗位  

## 1. 用户问题、目标和边界

**使用者与触发**：Agent 运行中可能遇到工具超时、检索/模型来源缺证或请求超出当前权限。若它继续重试、猜测或越权，用户会看到无法追溯的结果并可能产生副作用。

**任务目标**：在本地隔离环境中建立并回放三类阻断的停止、澄清、降级和升级策略：超时、缺证、权限冲突。每次阻断都必须有明确状态、停止原因、保护动作、所需权限/证据和升级对象。

**价值假设（待验证）**：Agent 能把“暂时不可完成”诚实地变成可复核的停止或升级事件，后续责任岗位才有机会安全修复；这不等于所有异常或生产事故已覆盖。

## 2. 范围与不做项

### 范围（本合同允许做）

1. 为 T1/T2 共用的运行事件增加阻断分类：`timeout`、`evidence_missing`、`permission_conflict`（具体枚举可在合同升版时扩展）。
2. 对三类本地确定性故障分别实现或演示最大等待/步数、证据核对、权限前置检查、停止状态和升级交接。
3. 保存不猜测、不重复副作用的失败轨迹，并交付 QA 可独立回放的最小夹具、停止条件和留出变体。

### 不做项

- 不修改账户/权限数据库、生产策略、教材索引、模型供应商、客户端提示或其他岗位的修复产物；
- 不把超时无限重试，不用“模型说有来源”填补缺证，不用用户输入自行授予权限；
- 不执行真实网络、付费调用、账户写入、不可逆工具或外部消息；
- 不删除首次失败，不把“已停止”写成“任务成功”，不由责任岗位替 QA 关闭缺陷。

## 3. 输入、环境和证据

- **超时夹具**：确定性工具 stub 在合同阈值内不返回；预期进入 `timeout`/`stopped`，不得继续调用。
- **缺证夹具**：候选缺少来源版本、章节定位或原文摘要之一；预期进入 `evidence_missing`，请求补件或升级，不生成结论。
- **权限冲突夹具**：工具声明需要合同外权限或用户身份不匹配；预期在调用前进入 `permission_conflict`，不触发工具。
- **环境**：本地临时目录，默认 Node `24.16.0`，网络关闭，使用合成数据和无副作用 stub；日志只写必要摘要。
- **证据**：阻断前最后事件、停止/升级事件、状态与原因、未执行的动作、升级目标、输入/夹具哈希、首次失败、返修和复验。未实际运行项标 `not_assessed`。

## 4. Delivery 轨道与可观察验收

交付状态初始为 `not_started`。完成后由 QA 独立复核，结论只能是 `passed`、`failed` 或 `insufficient`。

- **`AC-T3-D1` 超时停止**：超时夹具在约定阈值/最大步数内只产生一次受控等待，随后进入 `timeout` 或 `stopped`；事件包含 `run_id`、工具、尝试次数、停止原因和下一步，不继续重试。
- **`AC-T3-D2` 缺证停止**：缺少来源版本/定位/原文任一必填证据时，Agent 进入 `evidence_missing`，指出缺什么、向谁补件或升级，不猜测、不拼接旧版本来源。
- **`AC-T3-D3` 权限冲突前置阻断**：工具所需权限超出合同或身份不匹配时，在工具调用前进入 `permission_conflict`，记录所需权限、当前授权范围和升级对象；工具调用计数为 0，不能靠重试绕过。
- **`AC-T3-D4` 保护和可观测**：三类阻断均不写账户/生产数据、不发外部消息、不泄露密钥；事件顺序可由 QA 回放，状态与停止原因不依赖人工猜测。
- **`AC-T3-D5` 交接和责任**：每条阻断交接包列出未完成动作、责任岗位、升级条件、复验命令和残余风险；不得把 QA 未复核的停止策略宣称为稳健能力。

## 5. Growth 轨道与独立证据

**本周期唯一成长目标**：面对一个未提前给出步骤的异常输入，能先识别是超时、缺证还是权限冲突，选择停止/澄清/升级，保留证据并让 QA 在留出变体中复现。

- 执行前基线：知道“失败要停”但尚未证明能按不同根因选择不同保护动作；以 T1/T2 事件和 D0 记录为基线。
- 目标情境：三类故障各一条，QA 只改变发生顺序、字段缺失位置或权限名称作留出变体。
- 成长证据：逐类策略、运行轨迹、升级交接、首次失败与返修、QA 原例/留出复核；自我说明或课程阅读不单独计入。
- 预期状态：`emerging` 或 `independent_candidate`；没有连续周期和外部证据时保持 `unverified`/局限。
- 不能推出：全面安全性、真实生产事故处理能力、权限系统正确性、职业认证或行业先进性。

## 6. 风险、停止和升级

任何一次继续调用已超时工具、缺证仍输出事实、权限冲突仍执行工具、产生真实副作用、版本/夹具不可复现、日志泄露敏感数据，均为阻断风险：立即停止并将任务标为 `failed` 或 `insufficient`，通知项目经理、产品经理和 QA；权限问题另通知后端数据工程师，来源问题另通知内容检索工程师。

本合同没有外部预算和生产授权。风险责任人是 `agent-developer`；产品经理决定是否需要升版/重新定界，项目经理维护状态和交接，QA 保留独立结论。修复前不得推广到下一岗位或更高能力级别。

## 7. 独立复核和复验

QA 依次执行：

1. 独立运行超时夹具，确认阈值、停止和不重复调用；
2. 独立运行缺证夹具，确认缺失字段、澄清/升级和不猜测；
3. 独立运行权限冲突夹具，确认调用前阻断和升级对象；
4. 运行一个未提前给出步骤的留出变体（改变异常顺序或缺失字段位置），检查分类、保护动作和事件完整性；
5. 返修时先按原三例复验，再跑受影响回归，保留首轮失败和未测范围。

如无法证明停止发生在副作用之前，或不能从日志确认未执行动作，QA 结论为 `insufficient`；不能只凭静态状态图关闭安全缺口。
