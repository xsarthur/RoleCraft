## 目的和证据边界

这份 D0 只确定 Agent 开发工程师的学习起点和补学顺序，不授予岗位能力、产品权限、职业认证或 L1。诊断需要冻结题目和夹具后，由学习者独立作答；本文件先保存题目、预期证据和待采集字段，不能把已有架构蓝图、岗位契约、静态 QA 方案或运行时演示当成个人能力证据。缺少学习者原始回答、实际产物、环境与独立复核时，结论保持 `insufficient_evidence`。

现有资料仅作为诊断输入边界：`team/agent-development-engineer-product-v01.md`（岗位契约）、`team/agent-development-architecture-v01.md`（架构蓝图）、`team/agent-development-architecture-qa-v01.md`（独立验收方案）和 `team/agent-runtime-v01-qa.md`（运行时验收）。这些文件说明岗位门槛，不能证明某位学习者已经掌握门槛。

## 起点、阻断和补学结论

- **暂定起点：`L0`（准备与边界）**。这是“尚未执行 D0”的证据状态，不是对个人能力的负面判断。L0 只允许阅读、观察和无副作用沙箱；不得独立交付 Agent 运行时。
- **L1：`insufficient_evidence`，尚未达到候选条件**。至少需要两个不同、可重建的沙箱工件，七维均有初步证据，独立复核无 P1；本文件目前没有这些产物。
- **阻断风险**：边界/权限/来源/副作用/恢复判断均未观察；真实模型、外部工具、真实账户、数据库迁移、上传、发布和付费调用在 D0 禁止。
- **统一补学顺序**：共同基础（合同、证据、版本、风险、交接）→ D0-01/D0-02 → D0-03 正常/无匹配 → D0-04 失败与恢复 → D0-05 迁移；每一步保留原例失败和独立复验。
- **不能推出的结论**：不能由岗位资料阅读、架构文件存在、运行时历史 QA、诊断文件完成或未来一次正常演示推出 L1/L2/L3、真实模型质量、用户价值、专家认可、生产可靠性或行业先进性。
