## 设计意图与正文绑定

### 02 任务合同

图按 `目标与输入 → 边界 → 三类证据 → 结局` 阅读。蓝色表示共同前提，灰色表示资源边界，黄色表示完成证据，底部用绿色、橙色、紫色和红色区分完成、缺证停止、缺批准等待和效果未知。内容来自 `v12/02-task-acceptance.md` 的 YAML 合同和四种结局；图不创造新的评分门槛。

短文字替代：任务合同图：先固定目标和输入，再限制读写边界，用产物、过程和效果证据判断完成；缺证、缺批准或效果未知时停止或等待。

### 03 信任边界

图按 `事实资料 → 可信身份 → 准入检查 → 业务效果` 横向阅读。灰色表示事实来源，黄色表示身份范围，绿色表示运行时准入，紫色表示允许的业务效果；红色虚线示例表示越权文本在边界处拒绝或等待。内容来自 `v12/03-trust-boundary.md` 的来源权限表和提示注入示例。

短文字替代：信任边界图：源文件、报告和模型只能提供事实或建议；可信身份、对象范围与准确批准经过准入检查后才允许读取或写入，越权指令被阻断。

### c01 控制循环

图将模型区和运行时区分开：`观察 → 提议 → 准入 → 动作 → 效果/未知`。紫色虚线回路表示效果未知时带着原身份核对；红色分支表示拒绝或等待时不发送。底部链条保留 `tool_call_id / action_id / attempt_id / operation_id` 的不同职责。内容来自 `v12/c01-control-primer.md` 与 `c01-control-loop.md`，不表示任何供应商 SDK 字段。

短文字替代：控制循环图：运行时接收观察，模型提出候选，准入检查决定执行、拒绝或等待，执行器记录尝试，效果可能确认、无效果或未知；未知状态回到核对，不能直接重发。

## 共同视觉规则

- 色彩有语义且同时配合标题、位置和文字标签；颜色不是唯一状态表达。
- 所有箭头均位于节点之间的留白或外围回路，未穿过标题、节点和说明文字。
- 节点内保留足够内边距；长句拆成两行，避免把箭头终点放在文字基线。
- 每张图包含来源和未验证状态；未声称浏览器渲染、窄屏适配、真实服务回执或真人理解已完成。
- 红色只表达阻断、未知或需要等待，不表达“模型错误”这一未经证据确认的结论。
- 图示是教材辅助表达，不能替代产品验收、权限实现或能力认证。
