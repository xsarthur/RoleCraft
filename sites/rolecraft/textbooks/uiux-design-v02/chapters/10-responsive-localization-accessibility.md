# 10 在设备、语言与能力变化时保持同一个任务

响应式与可访问性不是把桌面缩小或最后补标签，而是保持同一任务的身份、信息、控制与反馈。在澄明，宽屏能同时看列表、草稿和订单；窄屏必须顺序阅读，但仍要核对R-81的订单、CNY 268.00、版本与后果。放大、长译文、RTL、键盘与辅助技术会同时改变空间和操作，不能各做一张孤立样稿便宣布完成。

## 断点从内容失效处选择

教学桌面布局有列表、工作区和事实栏。如果可用宽度不足以让工作区保留约48个拉丁字符的参考阅读宽度，硬保三栏会缩小字号和按钮。这里的48字符只是本方案的排版起点，需字体和任务验证，不是规范要求。我们先收起低频侧导航，再让列表成为可返回入口，最后把事实栏移到当前任务的核对段落，而不是直接隐藏它。

| 条件 | 布局变化 | 必须保留 |
| --- | --- | --- |
| 宽屏连续处理 | 列表/正文/事实三域同屏 | 当前项、来源和订单的对应 |
| 中等宽度 | 列表可收起，事实跟随正文 | 返回列表后原筛选与位置 |
| 390 CSS px | 单列：身份→消息→草稿→依据→订单/退款→动作 | 所有决定字段和来源入口 |
| 320 CSS px等价宽度 | 关键字段整组换行，按钮竖排，操作区随文档流 | 无二维滚动才能读完整句和操作 |

![390与320宽度下按任务重排的教学图](../assets/04-responsive-390-320.svg)

图里的390/320是静态布局提案，不是浏览器缩放报告。[WCAG 2.2的1.4.10重排](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)要求一般垂直内容在等价320 CSS px宽度下不丢内容功能且无双向滚动；1280宽度放大400%是等价情形之一。确需二维结构的图表、数据表等有例外，但不自动豁免整页、单元格或外围操作。200%截图不能代替这项检查。

## 表格与卡片是任务取舍，不是大小屏固定配方

客服逐条回复时，单列卡片容易保留阅读顺序；财务比较多笔退款时，表格的列对齐有价值。后一种可保留必要横向滚动区域，给可见行头、滚动提示和逐项详情，外围按钮仍重排。不能给整页设横向滚动，只因为内部有一张表。若卡片化后无法比较同币种金额，也应承认它损失了横向比较能力，再选择固定比较摘要或返回桌面分析流程，而非称所有体验完全相同。

## 本地化保护的是业务含义

T-1042来自美国站，但R-81的金额为CNY人民币教学结算。列表可有简写，进入核对必须显式显示`CNY 268.00（人民币，教学结算）`。语言为英文并不意味着交易美元；界面时区也不决定原始交易时区。日期使用无歧义形式，如“2026-10-14 09:30 UTC+08:00（显示时区）”，并保留原事件时间标识；不使用可被解释为月/日或日/月的`10/11`。

英文长标签“Approve R-81 revision 4 after reviewing the current request”不可通过裁成“Approve...”丢失对象。更合适的是短动作“Approve R-81 v4”，把条件放在同一确认区的完整说明。中文、英文都遵守动作+对象关系，不逐字复制导致句法奇怪。

RTL布局用逻辑起点/终点安排标签与控件，但ID、金额代码和数字可能仍以LTR显示。设计交接明确把`R-81`、`O-7819`、`CNY 268.00`作为隔离的可读片段，不能简单镜像字符。箭头只有在表示前进/返回关系时跟随阅读方向；播放、勾和品牌标记不因界面方向自动翻转。实际双向文本行为必须在真实字体与浏览器中检查。

### 一个长文本与跨日反例

许然在英文RTL环境核R-81，说明变成长句，时间在当地已跨日。旧设计将金额限制一行、币种浮在另一端、固定底栏盖住理由；用户只能看见268.00和Confirm。修复先让金额币种成为不可误解的一组，再允许块级换行；批准版本贴近标题；说明按自然语言方向显示，ID隔离；操作区进入文档流。跨日不把排序中的“昨天”当凭据，展开原时间和显示时区。复验输入要同时改变语言、长度、宽度和时区，不能分别通过后推断组合也通过。

## 键盘序列是可交付的操作设计

下表定义教学确认弹层的焦点合同，不代表已实现。APG的[模态对话框模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)规定焦点进入对话框、Tab在其中循环、Escape关闭及关闭后的合理回焦；复杂内容适合先聚焦标题或静态说明。只有视觉遮罩而无真实行为，不能标为模态。

| 事件 | 焦点/语义输出 | 页面保留的事实 |
| --- | --- | --- |
| 键盘激活R-81审批入口 | 焦点到标题“批准R-81 v4”或低风险“返回检查”；对话框有可感知名称 | 原触发工单与列表位置 |
| 读摘要 | 顺序为订单→金额币种→理由→政策版本→批准后果 | 不把全部摘要压成一串难导航标签 |
| Tab/Shift+Tab | 在可操作控件中顺序循环，可见焦点 | 不让背景按钮仍可操作 |
| 金额校验失败 | 错误摘要可读，定位对应字段并关联错误说明 | 保留用户输入，不清空整表 |
| 关闭/Escape | 关闭本地检查，回触发入口 | 不撤销已发送或已批准事实 |
| 原入口消失 | 回到工单列表标题/合理邻项并说明变化 | 不把焦点丢到文档根部 |

### 名称、角色、状态不能只存在于画面上

“查看P-07@v3来源”需要明确名称和链接/按钮角色，展开来源时状态要可感知；“当前工单T-1042”应有程序可辨的当前状态；禁用的发回复按钮旁要解释“第3句依据不足”。不要把每个可见文字都重复放进无障碍名称，否则会冗长甚至冲突；也不应靠`aria-label`覆盖一个含义不同的可见标签。设计提供语义意图，工程按实现选择原生元素与必要属性，再由独立测试核对。

## 目标、焦点、文本间距的具体条件

当前默认控件高44px、密集控件36px，是教学设计选择。[WCAG 2.2的2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)AA基线为指针目标至少24×24 CSS px，并有间距、等价控件、行内、用户代理和必要性例外。不能把“图标24px”当命中区域24px，也不能因满足最低值就推断触控舒适。

[2.4.11焦点不被完全遮挡](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)要求获得焦点的控件不被作者内容完全遮住。我们的更强设计目标是控件和焦点环都清楚可见，因此固定底栏、聊天浮层与顶部通知要一起检查；给了焦点色仍可能被遮挡。

[1.4.12文本间距](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html)检查用户设置行高1.5倍、段后2倍、字距0.12倍、词距0.16倍字体大小时不丢内容或功能，按语言适用性处理；它不要求设计默认就使用这些值。固定高按钮、卡片或错误条最容易截字。避免只测英文短标签，含中文段落和混排金额也要检查实际结果。

等待、查询结果和批量摘要可采用适当的非抢焦点状态通知；不要对每个流式字符都报警。错误需要紧迫时才用更强提醒。连续播报会掩盖当前阅读，与完全不播报一样损伤任务。[4.1.3状态消息](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)支持程序可感知的状态，但不会替我们决定哪些句子值得打断用户。

## 实际验证应如何记录

静态稿可查字段、顺序、颜色冗余、长度、版式；浏览器可查重排、真实命中区、Tab和遮挡；辅助技术可查名称角色状态、通知与阅读顺序；真实使用者可揭示策略、负担和理解。记录必须分层，不写一个“无障碍通过”覆盖所有。

具体执行单应含：实现版本、浏览器/OS/辅助技术版本、显示缩放与视口、语言/方向、任务输入、按键轨迹、实际读出/可见结果、缺陷及复验。比如“打开审批→Tab至返回检查→Shift+Tab→Escape→回T-1042”，保存实际发生的顺序；当前书内只是预期合同，不能填写通过。

## 分层练习与完整参考分析

**基础：** 状态只靠绿/橙，来源只在hover出现，怎么改？参考：状态加准确文字和形状，来源给常驻可聚焦入口；鼠标hover、键盘focus、触屏激活都有等价取得方式；信息不是仅移到标题属性。静态稿可核这些入口是否存在，行为仍需实现验证。

**迁移：** 将R-81改为RTL英文长文本、320px、当地跨日。参考：保留tenant/工单/版本在上方，金额CNY 268.00作为LTR隔离片段；理由完整换行；日期显示带时区的绝对值；动作竖排且进入文档流；不镜像数字或危险图标。检验焦点在长说明滚动后仍可见，关闭后回原入口。

**综合：** 没有读屏环境能否交付？参考：可以交付静态语义与焦点合同、需执行的逐步脚本、已完成的浏览器检查证据，但将真实辅助技术结果保留未验证，不可称通过。优先安排关键路径真实测试，不以作者模拟朗读替代。若工程不支持正确模态，先用普通页面式确认是可行替代，需重新定义返回、标题和焦点，而不是给现有非模态容器贴`aria-modal=true`。

### 基础补学

CSS px是布局单位，不是每台屏幕上的物理点；LTR/RTL是书写方向，不等于币种或地区；无障碍名称是技术可感知的名称，不等于把所有正文重复朗读。理解这些差别后，再去选择具体属性和布局。
