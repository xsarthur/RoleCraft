## 问题及交接

严重性含义：P2 为有限场景下明显影响操作或状态可信度；P3 为较小的记录一致性问题。此分级不表示已经完成其他范围的风险审查。

### QA-01 · P2 · 页面导航覆盖历史条目

- 证据：T16；`dist/app.js:42` 的 `navigate()` 调用 `history.replaceState`。
- 隔离复现：默认上下文 → `navigate('path')` → `navigate('book')` → 检查历史调用；实际两次 replaceState、零次 pushState。
- 影响：点击主导航不会为各页面建立独立历史条目；浏览器后退无法按这两次点击回到路线和概览。此结论基于调用机制，未操作浏览器后退按钮。
- 状态：现有行为与设计师“后退／前进恢复页面”的交接建议不符；该建议尚未形成用户确认的实施范围。
- 预期依据：设计交接要求历史恢复。本次断言使用 pushState 验证现有导航能否保留条目；未来实现也可采用其他能够保留正确历史的方案，不能把必须使用某个 API 当成产品需求。
- 责任：软件工程师实现，设计师确认导航与章节链接规范，测试工程师后续在隔离浏览器复测实际历史行为。

### QA-02 · P2 · 异常已存自查记录使导出失败

- 证据：T17；加载处只校验 `checks` 外层对象，`dist/app.js:50` 导出直接使用项目值的 `.includes()`。
- 隔离复现：有效档案的模拟存储中放入 `checks: { p1: { bad: true } }` → 加载 → `projectsPage()` 可以生成页面 → `exportPlan()` 抛出 `(state.checks[p.id] || []).includes is not a function`，未创建导出 Blob。
- 影响：局部记录结构损坏时，页面容错与导出不一致，用户不能使用原型提供的导出入口保留其他正常记录。该数据不是正常 UI 路径写出的数据；这是异常记录恢复缺陷，不能描述为每次导出都会失败。
- 预期依据：原型的导出入口与保存失败提示提供记录保留路径，项目页面已经对非数组值采用空列表回退。测试预期导出采取一致的容错；该异常数据恢复要求尚非用户确认的数据迁移契约。
- 责任：软件工程师统一读取、渲染、导出的结构校验与容错；测试工程师覆盖对象、数字、字符串、缺失字段及正常记录。

### QA-03 · P2／P3 · 已存列表未去重及范围校验

- 证据：T18、T19；`dist/app.js:25` 对 `passed` 只过滤未知 ID，对 `checks` 只校验外层对象；`dist/app.js:39` 直接用数组长度计算自查进度。
- 隔离复现 A：载入 `passed: ['foundation', 'foundation']`，实际长度仍为 2，未规范化（P3）。当前路线百分比按章节成员关系计算，因此本次未出现测验进度翻倍。
- 隔离复现 B：载入 `checks: { p1: [0, 0, 1, 2, 3, 4, 99] }`，项目 HTML 输出 `7 / 5 项自查完成` 和 `width:140%`（P2）。
- 影响：损坏／旧版本记录可导致不可信自查进度。正常勾选和正常答题事件去重已通过 T06、T09，未发现正常操作会写出这些异常值。
- 预期依据：UI 使用“已通过章节”和“完成检查项”含义，正常事件明确去重；载入应维持同样的集合语义和项目检查项范围。重复 passed 的规范化是稳健性建议，未证实它造成当前百分比错误。
- 责任：软件工程师按当前章节及项目检查项范围校验、去重；产品经理确认未来版本迁移与旧记录保留规则，测试工程师检验迁移结果。

### QA-04 · P2 · 保存恢复后状态标记不复位

- 证据：T20；`dist/app.js:29` 失败时设置 `storageAvailable=false`，成功分支没有恢复 true；`dist/app.js:45` 显式保存备注依据该标记选择提示。
- 隔离复现：第一次模拟 setItem 抛出 quota exceeded → 标记 false → 解除异常 → 再次 `save()`，内存存储确实写入一次，但标记仍 false。
- 影响：后续成功保存后仍可能提示“请导出学习计划以保留记录”，与真实保存结果不符；首次损坏 JSON 设置的不可用标记也存在相同恢复问题。
- 预期依据：设计交接要求“数据恢复后更新状态”，保存成功／失败提示应与实际结果一致。测试只注入内存 setItem 异常，并未复现真实浏览器配额或隐私策略；恢复后的状态错误由当前源码分支直接证实。
- 责任：软件工程师修正成功／失败状态；设计师负责持久、就地的保存状态表达。测试工程师用暂时故障与持续故障分别复测。

## 本轮未验证

1. 未进行浏览器 DOM 实测。stub 不解析 HTML、执行布局或浏览器默认行为，不能验证 focus、dialog、事件命中、真实下载、Safari 的 file:// 存储差异、历史按钮及链接安全。
2. 未进行 320／375／768／1024／1440 像素、200% 缩放、文字对比度、触控目标、键盘、读屏或减少动态效果偏好验收。设计师提出的这些要求保持“待测”。
3. 未核验外部来源可访问性、更新日期或逐条教材主张，未运行教材示例，也未执行专业或教学效果评审。“核对于 2026.10.10”是现有文本，不是本轮验证证据。来源核对与教学内容由课程责任人处理。
4. 未验证账户、跨设备数据权限、真实生成任务、模型调用、资料检索、教材版本、作品评审、沙箱与部署；当前没有这些实现。本轮也未发送源码或发布网站。
