# 团队分派、原记忆读取和交接协议

状态：v0.3 REVIEW DRAFT；不是专业调度完成回执。唯一协调入口是原项目经理。

本轮新增读取与报告约定仅约束本任务执行代理。原项目岗位、用户自有员工、协作支持职责及归属未知分别报告；十五/十六映射不证明管理归属。归属无明确证据标 `unknown`，不写入或管理对方员工；跨团队资料只在获准范围按协作必要只读参考，不修改其身份、职责、记忆、等级或管理规则。

## 运行方式与资格

专业工作由实际可用的专业子代理或明确独立的执行/审查上下文完成，可按任务顺序调度；不要求十五/十六岗常驻或同时在线。执行标识须来自实际工具或执行者记录，缺失就填null并标记未执行。同一助手更换角色标签不算多个执行身份。

不存在专业调度能力时，PM只能完成协调材料、缺口和交接；产品/设计/工程任务保持 `blocked_runtime`，不得以角色扮演形成签收。独立QA缺失只阻塞验收，不强迫已经具备条件的专业任务停止，也不能降级为作者自验通过。

## 普通任务的完整必读闸门（2026-10-18，本地修复）

## 每次真实执行的读取顺序

1. 核对实际工程根、适用AGENTS、分支、HEAD提交和工作树；提交SHA必须来自Git，不用报告版本标签替代。
2. 读取本任务最新Owner决定和批准设计范围，再读取相应实际存在的原ROLE、MEMORY、SCHEMA及适用的共享偏好；没有成套原档案的岗位读取可核专项资料，记忆缺失单列。
3. 从core README / v12 manifest / 原SPECIALISTS名册与当前任务交接定位确实存在的原文件；资料可读不等于已取得历史记忆，不创建替代身份。
4. 完整共同必读基线之外，再读取本任务相关专项配置和证据；配置被引用、文件被读取、方法被应用是三个不同状态。
5. 回执写明实际路径、原文位置/条目、内容摘要、适用/不适用原因、提交或文件哈希；仅报路径和哈希不是理解证据。
6. 依据本目录映射承担任务，保留不做事项和冲突。原记忆不得覆盖、重置或自动晋升。

本任务执行代理使用[只读启动检查](./startup/README.md)与[来源清单](./startup/sources.json)分别报告岗位资料可读、原长期记忆缺失、固定共享方法可读、项目最新记录可读四类事实，另列自身读回引用及应用证据。本任务所需资料不能被“不适用”覆盖，共同必读基线不可被“不相关”删减，额外无关专项资料不强制通读；可核专项资料可读与原 ROLE/MEMORY/SCHEMA 缺失可以同时成立，不统一其他团队的岗位档案格式。

开工前可以记录计划应用点；只有实际产物与来源位置核对后才记录应用证据，其专业质量仍交独立 QA。仅链接、哈希或“我已读”自述不足以报接通或掌握；检查器不自造调用记录，不认证模型理解。固定方法全文或最新项目记录未取得、版本不符、必需读回证据缺项时，明确标未接通并交接，不默认通过。

## 交接和独立QA

每次交接至少包含：原责任岗；真实executor_ref；输入/版本；实际动作；产物路径/哈希；已完成/未完成；自检方法；未验证项；下一责任岗；相关独立QA状态。只写“完成”不可签收。
独立QA必须与受验作者区分，并提供自身执行来源、读取输入、具体场景、预期与实际、证据位置、版本、通过/失败/证据不足/未测和范围。代理标识不同只是最低线索，不自动证明其真正复核；无证据不能判通过。
文件字节校验、单元测试、模拟仓库写入是机械自检，不是产品、视觉、学习效果、浏览器或专业独立QA。设计稿不证明后端持久化，源码不证明浏览器运行。
