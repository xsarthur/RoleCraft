## 1. 责任边界

AI 生成工程师的唯一责任是模型生成服务：在已确认的任务合同、授权输入和版本约束下，负责生成模式/适配器、结构化输出、来源绑定、超时与重试策略、失败恢复和生成证据交接。

不负责账户数据库与最终权限实现、前端、教材正文、内容审校、独立 QA、产品范围或市场判断；不把模型文本当成事实，不迁移或删除真实用户数据，不把一次本地成功写成生产能力。遇到权限、来源、版本、契约、幂等性、外发副作用或证据不足时停止下游生成并升级，保留输入、状态和错误。

## 2. 机制解释：显式状态、工具契约与来源绑定

采用“结果持久化后才能完成”的显式状态机制。最小流程为 `start → tool_requested → tool_returned → source_checked → draft_ready`，状态至少保存 `run_id`、任务版本、授权范围、工具尝试/幂等键、结果引用、来源版本、输出 schema 版本、检查点和错误。

应用在工具边界重新核对身份、工具名、参数、版本、读写副作用和来源范围；工具结果先保存，再校验结构化输出与来源，才允许 `draft_ready/completed`。如果结果未持久化、来源为空或检查点与结果不一致，状态必须是 `recovery_required`，不能伪装完成；只在工具明确幂等且无已知副作用时重放，否则暂停并人工确认。

假设和未知：本记录没有运行真实 LangGraph 包、真实模型、真实外部工具或生产存储，因此 API 兼容性、持久化故障语义、模型输出质量、工具副作用和成本均未验证。
