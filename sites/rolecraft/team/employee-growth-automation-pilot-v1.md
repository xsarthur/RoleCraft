# 员工成长自动化试点规范 v1

- `pilot_id`: `employee-growth-automation-pilot-v1`
- `status`: `specification_only_not_assessed`
- `scope`: 低风险、隔离、只读的岗位训练闭环
- `试点岗位`: 内容检索工程师（首选）；可替换为产品经理
- `试点夹具`: 两类本地沙箱：正常教材检索、歧义/无匹配/否定/来源冲突
- `不包含`: 真实用户、真实生产、外部写入、付费模型、上传发布、自动晋级

## 1. 目标

把负责人日常逐项陪跑改成规则设定、异常处理和里程碑评审。系统自动整理学习材料、练习反馈和证据包；学习者仍必须亲自执行、提交原始作品并确认修复。试点只验证流程能否减少人工操作，不宣称学习效果、岗位胜任或任何等级。

## 2. 端到端状态机

```
diagnosed
 → material_recommended
 → sandbox_issued
 → learner_running
 → learner_submitted
 → auto_checked
 → feedback_ready
 → learner_revision
 → regression_checked
 → holdout_ready
 → evidence_pack_pending_review
 → qa_review
 → milestone_review
 → closed | blocked | needs_human
```

每个状态必须记录 `run_id`、`role_id`、`exercise_version`、夹具版本和 SHA、状态进入/离开时间、操作者、输入输出路径及当前证据状态。失败不覆盖旧状态；首次失败、返修、回归和留出结果作为不可变事件追加保存。

### 状态转移条件

| 转移 | 自动动作 | 必须阻断的情况 |
|---|---|---|
| diagnosed→material_recommended | 按缺口映射推荐教材小节、版本、路径和出处 | 版本/来源无法确认 |
| material_recommended→sandbox_issued | 创建可重置本地夹具和练习合同 | 练习超出岗位范围或涉及真实数据 |
| sandbox_issued→learner_running | 发放命令、预期、停止线和收据模板 | 学习者身份或授权边界缺失 |
| learner_submitted→auto_checked | 检查结构、代码、来源、权限、日志、哈希和退出码 | 原始收据缺失、由代理生成、禁止数据被访问 |
| auto_checked→feedback_ready | 生成带出处反馈、缺陷定位和下一步 | 反馈会替学习者写答案/作品 |
| feedback_ready→learner_revision | 学习者确认后提交新版本 | 未有学习者确认或版本不可追溯 |
| regression_checked→holdout_ready | 冻结原例回归结果，发放非作者留出题 | 留出题被作者预先看到或答案泄漏 |
| evidence_pack_pending_review→qa_review | 聚合 EvidenceCard 和完整 provenance | 缺少独立复核分母 |
| qa_review→milestone_review | QA、内容/专业复核均完成 | 有未关闭 P0/P1 或关键未知未标记 |
| milestone_review→closed | 负责人作出里程碑结论 | 不得自动写成 L1/L2 |

## 3. 系统自动完成

- 根据能力缺口推荐教材的具体单元/小节，并绑定版本、路径、源 hash、推荐理由。
- 创建可重置的本地练习、正常/边界/失败输入和收据模板。
- 运行格式、结构、权限、来源绑定、测试、日志、哈希和证据完整性检查。
- 保存首失败、返修差异、原例回归、受影响回归和留出结果。
- 生成引用到原文的反馈，标出事实、假设、推断、未知、停止线和责任边界。
- 在学习者确认后安排补学、间隔复习和下一项任务。
- 聚合 EvidenceCard、环境、版本、命令和交接包。
- 仅发送异常摘要：阻断、连续失败、来源冲突、严重安全问题、里程碑待审。

系统不得自动执行外部动作、代填学习者声明、伪造签收、改写原始作品、替学习者回答未知题、把自动检查结果改成能力结论。

## 4. 学习者归属和禁止代答

以下字段只能由学习者本人提交或明确确认：

- 匿名 `learner_id`、`learner_statement`、`signed_by_learner`
- 实际命令/操作、环境、开始结束时间
- 原始回答、代码、产品合同或作品
- 首次失败及本人选择的停止/升级动作
- 返修确认和留出题提交

QA 派生文件必须标记 `derived_by=QA`。自动聚合不得把 QA 回放、静态检查、代理生成内容或历史结果改标为学习者证据。没有学习者归属时，状态为 `blocked_learner_provenance`。

## 5. 人工介入点

负责人只在以下节点介入：

1. 入组：确认岗位、权限、允许数据、验收边界和试点夹具。
2. 异常：来源冲突、歧义、连续两次失败、权限/隐私风险、P0/P1、模型或运行时不可用。
3. 版本：批准课程版本、练习模板和夹具 hash。
4. 里程碑：审阅 D0/L1/L2 候选证据，确认是否进入下一阶段。
5. 高风险动作：真实数据、外部写入、生产、上传、发布、付费调用和职业能力判断。
6. 抽样：每周抽样检查自动反馈是否误放行；抽样结果进入误放行率。

系统不因“无异常”发送逐项通知，只发送周摘要和必须决策的异常。

## 6. 两类低风险沙箱

### S1 正常检索

输入自然语言学习目标，返回教材小节、版本、source hash、片段定位和推荐理由。验收：出处可回指正文，版本一致，未生成正文外事实。

### S2 不确定与拒答

输入歧义、否定、无匹配、来源版本冲突或提示注入。验收：澄清、标记 `unknown/related_uncovered/unavailable` 或停止；不得编造答案、越权读取或调用外部服务。

两类沙箱均使用合成数据和本地只读资源；可重置、可复现、不得访问账户数据库。

## 7. 证据包最小字段

`diagnostic_id`、`exercise_id/version`、`role_id`、匿名 `learner_id`、输入/输出快照和 hash、夹具版本/hash、实际命令、环境、时间、stdout/stderr、退出码、首次失败、返修差异、回归、留出、来源映射、unknowns、停止/升级决定、QA 结果、内容/专业复核、交接包和签收状态。

证据包状态只能是 `pending`、`insufficient_evidence`、`met_with_limitations` 或 `ready_for_milestone_review`。系统不得自动写 `L1_granted` 或 `L2_granted`。

## 8. 指标与采集

每轮按岗位、练习版本和 run_id 记录：

- **人工分钟数**：负责人实际处理异常/里程碑的分钟数；不把系统运行时间算人工。
- **自动闭环率**：无需负责人介入而完成到 `evidence_pack_pending_review` 的任务数 / 启动任务数。
- **重复失败率**：同一缺陷在修复后回归或下一轮再次出现的任务数 / 有缺陷任务数。
- **留出题迁移率**：非作者留出题达到预定观察条件的任务数 / 发放留出题任务数。
- **误放行率**：自动标记可进入 QA 或里程碑、经人工抽样发现应阻断的任务数 / 抽样任务数。
- **证据完整率**：一次提交包含全部最小字段的任务数 / 学习者提交数。
- **人工介入原因分布**：按异常、版本、里程碑、高风险和抽样分类。

首轮只做基线，不设“通过”阈值。连续两轮数据后，由 PM、QA、课程架构师共同决定是否扩大范围；任何岗位能力或 L1/L2 结论仍须沿既有门槛独立判断。

## 9. 试点节奏和退出线

- 第 0 周：冻结岗位合同、两类沙箱、来源版本、字段和指标。
- 第 1 周：最多运行 5 个学习者任务；只读、隔离、无外部动作。
- 第 2 周：QA 抽样全部首失败和至少一个留出题；复盘指标和误放行。
- 退出试点条件：出现越权访问、伪造学习者归属、自动代答、误放行高风险结果、不可重现收据或连续两次来源链断裂。
- 扩大条件：连续两轮无 P0/P1、证据完整率稳定、人工介入原因可解释，且负责人明确批准扩大。扩大不等于授予能力等级。

## 10. 当前依据和限制

试点可复用现有内容检索 Agent 的版本化分节索引、来源定位和离线夹具，以及产品经理 D0 合同的学习者收据、独立 QA、交接签收要求。现有检索开发检查和历史 QA 只证明局部工程行为，不能证明真实学习效果、员工能力、真人专家认可、生产可靠性或行业先进性。本文件是自动化试点规范，状态为 `specification_only_not_assessed`，不改应用代码，不关闭现有 D0/L1/L2 缺口。
