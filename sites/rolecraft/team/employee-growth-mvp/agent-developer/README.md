# Agent 开发者两周 MVP 合同包

日期：2026-10-15（Asia/Shanghai）  
产品版本：`agent-developer-mvp-v1.0`  
状态：`scoped_not_executed`  
责任岗位：产品经理（范围、任务合同和验收条件）  
首个岗位：`agent-developer`（岗位标识 `AGDEV`）  
独立复核：`qa-engineer`  

## 1. 目的和结果边界

这是一轮只针对 Agent 开发者的两周最小可执行合同包，用来观察该岗位能否在受限本地环境中：

1. 交付一个有边界、有停止条件、可回放的控制循环；
2. 将本地教材检索结果作为只读、有版本和出处的输入接入运行流程；
3. 在超时、缺证或权限冲突时停止、澄清或升级，不猜测成功、不制造来源、不越权。

每项合同只有一个唯一责任岗位：`agent-developer`。`qa-engineer` 只做独立复核、复现和缺陷记录，不代写返修。产品经理负责本合同包的范围和门槛，项目经理负责排期、交接和状态汇总；相邻岗位只能按接口合同提供输入。

本合同包只证明当前合同版本的 Delivery/Growth 证据是否形成。它不授予职业能力级别，不代表真实用户价值、真人专家认可、生产可靠性、成本可行性或行业先进性。

## 2. 共同范围和硬边界

### 允许范围

- 在本地隔离工作区设计或实现一个受限 Agent 运行时切片，并记录运行合同、事件和失败；
- 使用确定性 stub、固定本地夹具和只读教材源/检索 stub 验证控制流；
- 消费内容检索岗位交接的只读候选，核对来源和版本后再交给后续步骤；
- 记录 `run_id`、`agent_version`、输入/夹具版本、工具调用、停止原因、返修和复验。

### 明确不做

- 不调用付费模型、真实供应商、外部网络或有副作用的工具；
- 不读取、迁移、删除或写入真实账户、生产数据库、私有用户记录或密钥；
- 不改教材正文、内容索引/召回算法、客户端界面、账户权限实现或其他岗位的历史报告；
- 不把模拟响应、静态检查、一次成功演示或本地离线结果写成真实生成、用户效果或生产证据；
- 不由责任岗位给自己最终复核，不删除首次失败或用新版本覆盖旧证据。

执行产物的具体运行目录由项目经理在启动时分配。本次创建合同包不预创建运行产物，也不授权修改应用源码。

## 3. 合同和执行顺序

| ID | 任务目的 | 主要交付 | 必须暴露的情境 | 合同 |
| --- | --- | --- | --- | --- |
| `T1` | 控制循环基线 | 状态/事件合同和本地可回放的受限循环 | 正常完成、工具失败、受控重试和停止 | [T1-contract.md](./T1-contract.md) |
| `T2` | 本地教材检索与来源 | 只读检索接入、来源/版本核验和定位结果 | 正常命中、无匹配/歧义、来源版本失配 | [T2-contract.md](./T2-contract.md) |
| `T3` | 失败安全和升级 | 超时/缺证/权限冲突的停止、澄清和升级策略 | 三类阻断各自可回放，禁止猜测和越权 | [T3-contract.md](./T3-contract.md) |

先完成 `T1` 的合同复核，再执行 `T2`；`T3` 依赖前两项的事件字段，但三项仍各自独立记账、独立复核。任何范围、工具、数据或验收变化都必须升合同版本并保留旧合同与旧失败。

## 4. 本地隔离环境

- 默认运行时：Node `24.16.0`（若实际环境不同，必须在合同和交接中记录并由 QA 判断是否可复验）。
- 数据：临时目录、合成输入、脱敏副本或确定性 stub；禁止真实账户和生产数据。
- 网络：默认关闭；检索使用本地冻结教材文件或 QA 提供的只读 stub。没有网络时不得伪装为真实 API 成功。
- 模型：不需要真实模型；如需模型形状，使用可记录输入/输出的确定性替身并标注 `simulated`。
- 日志：可回放但只保留必要字段，不写入密钥、完整私有输入或不必要的账户数据。

T2 可引用执行时冻结的教材版本（例如 `sites/rolecraft/textbooks/v10/` 或 `v12/`），但必须在运行记录中保存实际文件/索引版本和哈希；当前文件存在不等于已完成检索运行。

## 5. Delivery / Growth 双轨

每项合同同时填写两条轨道：

- **Delivery**：本版本产物、运行证据、边界和 QA 复核是否满足合同验收。状态使用 `not_started`、`in_progress`、`passed`、`failed`、`insufficient`。
- **Growth**：是否有独立证据显示岗位在不同情境中学会了可观察动作。状态使用 `not_started`、`emerging`、`independent_candidate`、`stable`、`unverified`。

Delivery 通过不能推出稳定职业能力；Growth 有进步也不能覆盖交付失败。没有跨情境独立证据、真实用户/同行/专家或生产反馈时，保留局限和 `unverified`。

## 6. 独立复核、停止和复验

QA 必须拿到冻结合同、输入版本、最小复现步骤和独立夹具后复现原例，并至少使用一个不提前给出步骤的留出变体。QA 记录 `passed`、`failed` 或 `insufficient`，保留首轮失败、返修版本、原例复验、受影响回归和残余风险；QA 不修产物、不降低门槛。

出现未授权数据/应用改动、外部/付费调用、密钥泄露、无限循环、重复副作用、来源或权限无法核实、运行版本/夹具不可复现，立即停止当前任务，标为 `failed` 或 `insufficient`，通知项目经理和产品经理，并保留证据。修复后按原合同复验，不能通过改写验收、删除失败或跳过 QA 关账。

本合同包当前仅为 `scoped_not_executed`；三项任务、D0 诊断、员工能力和推广门槛均尚未执行。
