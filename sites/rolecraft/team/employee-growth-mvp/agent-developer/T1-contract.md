# T1 · 受限 Agent 控制循环合同

合同版本：`T1-v1.0`  
合同状态：`scoped`（尚未执行）  
周期：`agent-developer-mvp-20261015`  
唯一责任岗位：`agent-developer`（`AGDEV`）  
独立复核岗位：`qa-engineer`  
接收/协调：项目经理  
产品门槛负责人：产品经理  

## 1. 用户问题、目标和边界

**使用者与触发**：内部工程协作者需要把一个有明确输入和有限工具的单步任务交给 Agent，并能看到它如何进入、执行、检查、完成或停止。当前缺少一份可回放的状态/事件基线，导致“模型说完成”与真正完成无法区分。

**任务目标**：在隔离本地环境中交付一个最小单 Agent 控制循环合同和可回放切片。循环必须有显式状态、步数上限、工具错误语义、受控重试、停止原因和事件轨迹。

**价值假设（待验证）**：若状态和停止条件能被 QA 从日志复现，后续检索、超时和权限冲突就能在相同事件合同上安全接入。该假设不是用户满意或生产可靠性的结论。

## 2. 范围与不做项

### 范围（本合同允许做）

1. 冻结一个版本化运行合同，至少定义 `run_id`、`agent_version`、输入/输出、状态、事件顺序、步数上限和停止原因。
2. 在本地隔离夹具上实现或演示状态链：`received → planning → tool_call → checking → completed`，并定义 `failed`/`stopped` 的进入和退出条件。
3. 使用一个无副作用、确定性的工具 stub 验证正常路径、工具错误、最多一次受控重试和最终停止；保存原始轨迹和环境。

### 不做项

- 不接真实模型、真实工具、网络、外部写入、付费服务或生产任务；
- 不实现教材检索索引、来源真值、账户权限、持久任务、客户端显示或其他岗位接口；
- 不以多 Agent、开放式规划或无限循环增加复杂度；不把 stub 输出写成供应商成功；
- 不改变本合同的验收门槛或替 QA 给出最终结论。

## 3. 输入、环境和证据

- **输入夹具**：一个合成的有界任务、一个工具调用参数和预期结果；另备一个工具返回错误的边界夹具。QA 在复核时冻结哈希并另造留出夹具。
- **工具权限**：仅允许确定性 `echo`/等价内存 stub，无文件、网络或账户副作用。
- **运行环境**：本地临时目录，默认 Node `24.16.0`；若采用其他运行时，必须记录版本、依赖、命令和为何仍可复验。
- **证据**：运行合同、状态图/时序、输入与夹具哈希、事件日志、首次失败、返修差异和交接最小复现步骤。计划或静态推理必须标为未运行。

## 4. Delivery 轨道与可观察验收

交付状态初始为 `not_started`。责任岗位完成后转 `in_progress`/`handoff`，QA 只能给 `passed`、`failed` 或 `insufficient`。

- **`AC-T1-D1` 合同完整**：运行合同能定位版本、责任人、输入/输出、状态进入/退出、最大步数、超时占位、工具权限和停止原因；任何未定义状态不得靠日志猜测。
- **`AC-T1-D2` 正常轨迹可回放**：在冻结正常夹具上按交接命令运行，事件顺序与合同一致，产生唯一 `run_id`，在不超过 3 个 Agent 步骤内进入 `completed`，结果带输入/夹具版本。
- **`AC-T1-D3` 工具失败受控**：工具 stub 返回错误时，循环最多重试 1 次；仍失败则进入 `failed` 或 `stopped`，记录错误摘要和停止原因，不重复副作用、不伪造完成。
- **`AC-T1-D4` 日志可安全复验**：日志含状态、步骤、工具名、尝试次数和停止原因，不含密钥、完整私有输入或不必要账户数据；QA 可在独立临时目录重放而不依赖作者机器状态。
- **`AC-T1-D5` 交接可接收**：交接包列出已运行/未运行、依赖、首次失败、返修、原例复验和 QA 最小步骤；缺字段则为 `insufficient`。

## 5. Growth 轨道与独立证据

**本周期唯一成长目标**：在两个不同的本地夹具（正常夹具与工具失败夹具）中，独立解释并实现状态、停止和事件证据，提交可回放轨迹，且通过 QA 的原例和留出变体复核。

- 执行前基线：能描述控制循环术语，但尚未在本岗位合同下留下独立运行和失败恢复证据；由 D0 诊断记录确认。
- 目标情境：T1 正常路径加一条工具失败边界；QA 留出变体只改变任务输入或工具返回顺序。
- 成长证据：独立产物、run log、失败/返修差异、QA review 和未知变体结果；阅读或自评不单独计入。
- 预期状态：`emerging` 或 `independent_candidate`，不得由 T1 单次通过直接写成 `stable`。
- 不能推出：整套 Agent 能力、真实模型质量、用户满意、职业认证或生产稳定性。

## 6. 风险、停止和升级

出现无限循环、步数超限未停、工具权限扩大、重复副作用、无法生成 `run_id`、日志泄露密钥/私有数据、环境依赖作者本机状态，立即停止运行并升级项目经理、产品经理和 QA。若需要真实模型、网络、账户或外部工具，先退回 `scoped` 并另立授权/版本合同。

时间上限为本周期内一个受限切片；无付费预算、无外部网络预算。风险责任人是 `agent-developer`，门槛变更由产品经理批准，复核结论由 QA 保留。

## 7. 独立复核和复验

QA 依次执行：

1. 用冻结正常夹具复现 `AC-T1-D2`；
2. 用工具错误夹具复现 `AC-T1-D3`；
3. 用一个未提前给出步骤、只改变输入或错误顺序的留出变体检查步数上限、停止原因和日志安全；
4. 若返修，先复验原例，再跑受影响回归，并保留首次失败的证据 ID。

原例或变体无法按说明运行、版本/夹具不完整或结果只能靠人工猜测时，QA 结论为 `insufficient`，不以补写说明代替运行。
