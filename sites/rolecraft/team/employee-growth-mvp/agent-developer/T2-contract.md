# T2 · 本地教材检索与来源核验合同

合同版本：`T2-v1.0`  
合同状态：`scoped`（尚未执行）  
周期：`agent-developer-mvp-20261015`  
唯一责任岗位：`agent-developer`（`AGDEV`）  
独立复核岗位：`qa-engineer`  
检索接口提供岗位：`content-retrieval-engineer`（只提供只读合同）  
接收/协调：项目经理  

## 1. 用户问题、目标和边界

**使用者与触发**：学习者用自然语言表达一个 Agent 工程问题，例如“我想理解控制循环如何停止”。运行时需要推荐当前教材的具体小节并能定位原文；它不能把检索候选冒充成没有来源的答案。

**任务目标**：在本地隔离环境中，让 Agent 调用版本化的只读检索接口，核对候选的教材版本、索引版本、章节/小节、原文摘录和路径，再返回可定位的推荐或明确的无匹配/需澄清状态。

**价值假设（待验证）**：来源字段进入 Agent 事件轨迹后，学习者和 QA 能区分“找到教材原文”与“模型自行编写”；该假设不等于学习效果或内容正确性已被验证。

## 2. 范围与不做项

### 范围（本合同允许做）

1. 消费 `content-retrieval-engineer` 交接的只读检索请求/响应合同，保留 `query`、`content_version`、`index_version`、`section_id`、`source_path`、`excerpt`、`retrieval_status` 等字段。
2. 编排检索候选进入 T1 控制循环的后续检查：来源字段完整、版本匹配、路径在允许教材根目录内，才可形成推荐卡或交接结果。
3. 对正常命中、无匹配/歧义和来源版本失配分别产生可回放事件；失配或缺证必须停止或请求澄清，不能编造教材答案。

### 不做项

- 不创建或修改教材正文、分节索引、嵌入模型、术语词典、召回/排序算法或检索服务实现；
- 不绕过只读接口直接扫描任意路径，不接受用户输入指定其他账户、私有材料或外部 URL；
- 不修复内容审校问题、不判断教材论断是否专业正确、不实现客户端展示或账户权限；
- 不调用真实外部模型或网络，不把检索候选写成已回答用户问题。

## 3. 输入、环境和证据

- **教材源**：执行时由 QA/检索岗冻结实际版本（可选 `sites/rolecraft/textbooks/v10/` 或 `v12/`），记录文件/组装版本哈希；不得只写“当前教材”。
- **检索输入**：至少一个明确自然语言查询、一个无匹配或歧义查询、一个来源版本失配响应；响应由本地确定性 stub 或已交接的本地只读实现提供。
- **允许路径**：仅在冻结教材根目录和隔离临时目录内读取；无网络、无账户写入、无付费调用。
- **证据**：接口版本、查询/响应哈希、Agent 事件轨迹、来源定位截图或文本片段、失败和复验记录。任何缺来源或未实际打开定位的结果标为未验证。

## 4. Delivery 轨道与可观察验收

交付状态初始为 `not_started`。完成后进入 `handoff`，QA 结论只能是 `passed`、`failed` 或 `insufficient`。

- **`AC-T2-D1` 接口字段保真**：每条候选都保留检索接口的版本、章节/小节、允许路径、原文摘录和状态；Agent 不重写或省略导致无法追溯的字段。
- **`AC-T2-D2` 正常命中可定位**：对冻结的明确查询，运行轨迹返回至少一个候选，打开其 `source_path` 能定位到相同 `section_id` 和摘录；事件标明查询、索引/教材版本和 `run_id`。
- **`AC-T2-D3` 无匹配/歧义诚实停止**：检索返回无匹配或多个无法判定的候选时，Agent 返回相应状态并请求澄清/交给人工；不得生成看似教材原文的补全。
- **`AC-T2-D4` 版本失配拒绝使用**：`content_version` 或 `index_version` 与合同冻结值不一致时，Agent 拒绝该候选并记录 `source_version_conflict` 或等价停止原因，不把旧来源混入新结果。
- **`AC-T2-D5` 只读和安全**：回放只读冻结教材和 stub，不访问合同外路径、网络、账户或密钥；QA 可从事件追到实际来源和未验证项。

## 5. Growth 轨道与独立证据

**本周期唯一成长目标**：在正常命中和无匹配/版本冲突两类不同查询中，独立把用户意图路由到现有检索接口、核验来源版本并在缺证时停止，提交可定位的交接结果。

- 执行前基线：能够调用已知检索接口，但尚未证明在 Agent 编排中保留来源并处理歧义/版本失配；以 D0 与 T1 事件为基线。
- 目标情境：至少一个命中、一个歧义/无匹配，QA 再改变查询表述或来源版本作留出变体。
- 成长证据：接口交接、运行事件、来源定位、拒绝/澄清轨迹、QA 原例和留出复核；模型生成的流畅文本不算独立证据。
- 预期状态：`emerging` 或 `independent_candidate`；不能由一次命中推成 `stable`。
- 不能推出：检索召回率、教材内容专业正确性、学习者理解、用户价值或职业能力认证。

## 6. 风险、停止和升级

发生路径穿越、来源字段缺失、版本冲突仍继续输出、无匹配时猜答案、检索接口被改写、网络/付费调用或访问私有数据，立即停止当前运行，保留响应和日志，升级项目经理、产品经理、内容检索工程师与 QA。索引、教材或接口需要改变时，另开由对应责任岗位负责的合同；本合同不能借检索需求越界。

预算为零付费调用；执行时间限于本地可回放切片。风险责任人是 `agent-developer`，来源真值和索引正确性由 `content-retrieval-engineer` 交接，独立复核由 QA 给出。

## 7. 独立复核和复验

QA 依次执行：

1. 用冻结明确查询复现正常命中并打开实际来源定位；
2. 用无匹配/歧义响应检查澄清或停止，不允许补写；
3. 用版本不一致响应检查拒绝路径和事件字段；
4. 用一个未提前给出步骤的同义查询或更换候选顺序的留出变体检查来源保真；
5. 若返修，先复验原命中和原拒绝，再检查受影响事件与路径范围。

若教材/索引哈希、响应版本或实际定位缺失，QA 结论为 `insufficient`，不以候选文本或作者说明替代来源证据。
