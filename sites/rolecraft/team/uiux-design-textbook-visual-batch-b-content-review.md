## 当前交付中成立的内容

1. 四章都有独立的首要视觉入口，且图文职责基本正确。第05图表达租户—工单—订单—草稿—退款—政策的对象与边界；第06图表达固定快照、逐项结果、等待/冲突/权限/可恢复失败及恢复；第07图把界面、批准、运输、业务效果和请求身份分开；第08图表达结构线框、状态原型、视觉/实现及证据边界。正文补充定义、条件、责任、失败、恢复、禁止推断和验证边界，没有用静态箭头替代数据库、权限、幂等、外部回执或用户效果证据。
2. 四张新增 SVG 均可 XML 解析，尺寸均为 1600×1000，包含 `role="img"`、`aria-labelledby`、`title`、`desc`，图内有 `chapter_id`、`asset_id`、`source_type=教学构造`、`verification=未验证`。章节邻近记录都有相对路径、来源、短/长替代文本和 `visual_downgrade`/未验证边界。
3. 教学状态和事实边界表达诚实：第05明确对象关系不等于数据库或权限服务；第06明确动画/批量完成不等于回执和外部效果；第07明确失败不等于未知且禁止盲重发；第08明确保真度提升不扩大证据范围。教学金额、角色、批次、状态和原型任务均标为教学构造。
4. 旧章节的先修、分层练习、参考解法、基础补学和能力主线仍在。README 中第05以04为先修，第06以02/05为先修，第07以06为先修，第08以06/07为先修；四章的基础/迁移/综合题继续要求读图、改变条件、处理未知和写恢复路径。章节链接及所引用旧资产均存在；新资产未替换或删除旧练习。
5. 四张新图的身份彼此唯一，章节中的复用旧资产有局部用途和“不代表完整流程/不能拼成同一时间线”等说明，未发现把不同教学批次数字合并为同一事实的情况。

## 限制与待处理项

### BATCH-B-SRC-001（P1，待修）—README、source-index 和 assembly-manifest 漏列 Batch B 四资产

`README.md`仍只列批次A四张新图，并写“12幅静态图稿（原有8幅与批次A新增4幅）”；`source-index.md`仍只列原八张和批次A的四个绑定；`assembly-manifest.json`的 `asset_bindings`、绑定计数和审校范围也没有 `v02-batch-b-05` 至 `08`。四个 SVG 虽能从章节直接打开，索引和组装版本链无法按 `asset_id`、来源、版本和 SHA256 追溯，不能把章节存在性当作全书资产已收录。

**建议责任人：** 课程架构师维护目录/来源索引，教材研发员补章节与合订本导航，组装责任人更新 manifest，QA复核。**复验：** README/source-index列出四个文件、chapter_id、教学用途、来源/版本/教学构造/未验证和哈希；assembly-manifest加入四条资产绑定、计数与当前章节/合订本引用，并核所有路径一致。

### BATCH-B-TEXT-002（P1，待修）—新增首要资产后仍保留相互矛盾的“无专门资产”降级文字

第05章第26行仍写“没有专门对象关系资产”，第06章第27行仍写“当前没有标题级独立恢复流程资产”；这与本轮已经插入且标为核心关系图/核心恢复流程图的 Batch B SVG 相冲突，读者会把已交付首要图误认为尚未交付。第07章关于“没有独立四维叠加资产”和第08章关于“没有独立保真度选择矩阵”可以作为补充降级说明，但应明确它们是核心 SVG 之外的细分图缺口，避免与首图混淆。

**建议责任人：** 教材研发员按课程架构修正措辞，内容审校复核图—文职责；不删除仍有价值的表格/文字降级。**复验：** 每个降级块明确“缺少的补充工件”及其与首要 Batch B 资产的关系；不能再声称第05/06核心关系/恢复图不存在。

### BATCH-B-VIS-003（P2，当前范围不足）—第08核心图未完整呈现正文宣称的五个独立保真度维度

第08正文将视觉、交互、内容、数据、行为定义为五个独立维度，首图却主要呈现 A结构线框、B状态原型、C视觉/实现三个阶段，图内没有对五维逐项标注或明确映射。章节 alt 声称“五个保真度维度按待验证问题对照低、中、高成本方案”，与 SVG 可见内容不完全一致。图仍可承担“按未知升级证据”的主问题，但五维对照目前主要靠正文表格，不能把 alt 当作图中已经表达的五维证据。

**建议责任人：** 设计师/教材研发员补五维到三阶段的显式映射或收窄 alt；QA按映射复验。**复验：** 图中逐项出现五维及其信号/边界，或alt准确描述实际三阶段结构，并在正文说明五维表与首图的互补关系。

### BATCH-B-VIS-004（P1，当前范围不足）—响应式、灰度、字体回退、键盘和读屏仍无实际证据

四张图都是 1600×1000 的密集横向静态板。章节有编号/文字替代、非颜色语义和 `visual_downgrade`，但设计师自查明确未提供渲染器，尚无桌面、约760px、窄屏、灰度、大字号、缺字体、浏览器、键盘、读屏或真人理解证据；内容审校不能以 SVG 可解析替代这些检查。

**建议责任人：** 设计师提供受控预览与限制记录，测试工程师独立复验。**复验：** 逐图核桌面/约760px/窄屏、灰度/大字号/字体回退的可读性，并记录浏览器、键盘、读屏是否运行；未运行继续标 `insufficient`/`not_verified`。
