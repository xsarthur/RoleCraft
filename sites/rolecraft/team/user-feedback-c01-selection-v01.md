# 用户反馈记录：c01-selection 视觉化建议

- 记录编号：UF-C01-20261015-01
- 日期：2026-10-15
- 研究岗位：用户研究员
- 阅读对象：`sites/rolecraft/textbooks/v12/c01-selection.md`
- 样本：1 位真实参与者
- 证据：用户提供的方案对照表截图，列出“方案 / 谁选下一步 / 同一缺陷任务中的可用实现 / 应放弃或升级的条件”

## 原始反馈

> 类似这类流程的最好是能通过转化成图片的方式帮助用户理解。  
> 内容还不错，但需要避免全是大篇幅的连续文字，多配文字以外的手段帮助用户更快地理解。

## 可观察发现

1. 用户认可当前内容方向，但认为连续大段文字会拖慢理解。
2. 用户主动提供了结构化对照表作为视觉参照，说明方案差异、决策顺序、任务实现和升级条件之间的关系值得尝试视觉化。
3. 用户提出的目标是“更快地理解”，后续应关注读者能否更快找出方案差异和判断条件，而不只是检查是否增加图片。
4. “图片”是用户明确提出的方向；流程图、决策树、轨迹图、对照表等具体形式仍需编辑、课程、产品和设计按职责判断。

## 不外推声明

本次反馈仅记录一位参与者对 c01-selection 表达方式的意见，不能外推为：

- 所有读者都偏好图片、表格或流程图；
- 参与者已经理解全文、能够独立完成方案选型，或教材已达标；
- 某一种图形必然优于其他形式；
- 产品路线图、学习工作台信息架构或界面显示范围已被用户决定；
- 用户已认可职业能力、真实学习效果、真人专家审核或完整产品价值；
- 可量化的阅读耗时、清晰度提升、学习效果或转化率。

用户提供的截图是表达参照，不是产品规格、实现授权或对现有界面的改版要求。

## 后续交接问题

- 哪些关系最需要视觉化：方案对照、决策顺序、运行轨迹、失败分诊，还是升级/放弃条件？
- 加入候选图示后，读者是否能更快说出“谁选下一步”和“何时升级”？
- 图示是否会误导读者把动态 Agent 理解成默认或更高级方案？
- 文字与图示如何共同保留原有边界、来源和失败条件？
