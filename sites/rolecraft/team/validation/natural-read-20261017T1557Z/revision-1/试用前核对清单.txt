一、试用前先核对

□ 确认试用的是应用内“面试准备 → 精选面试题 → 直接练习”。对应本机服务已由负责人准备好时，上层入口为 http://127.0.0.1:4318/#interview；本文未访问该地址，也未核服务存活。独立文件 interview-voice-coach-v01-prototype.html 仍是另一份演示，不用其点击结果证明应用内录音成功。[S1:196–200/208，S10]

□ 准备 Mac 内置麦克风并核浏览器录音权限。当前代码会核对设备 ID、名称与枚举结果，明确阻断 iPhone/Continuity、蓝牙、外部或无法确认名称的设备；这会排除部分耳机、外置麦克风、Windows/手机环境。浏览器需提供 getUserMedia、MediaRecorder 和设备枚举能力，具体浏览器兼容性未实测。[S1:142–149]

□ 先核本次转写路径能否满足试用条件。浏览器 SpeechRecognition 在状态初始化和重置时默认启用，选项位于折叠的“识别设置”。当前存在同一轮取消勾选未必更新识别状态的静态冲突（见限制5），不能承诺取消勾选即可可靠关闭；重录或离开重进还会重置为启用。若本次要求仅本地转写/手输且不启动浏览器识别，当前不能仅靠该复选框保证，须等工程修复并由独立测试复验后再安排该路径。此风险尚未在浏览器复现，不表示已观察到语音外发；浏览器/系统是否外发、供应商及保留期限仍未知。分析结果 providerCalled=false 只描述本地分析，不能证明浏览器没有外发。请使用适合这种处理边界的练习内容。[S1:112/123/137/147/161/221，S4]

□ 若要试“使用本地转写”，请负责人另行确认本机 ASR 就绪；仓库支持 whisper.cpp 命令、中文模型及非 WAV 转换所需的 ffmpeg，实际安装/环境配置均未在本轮探查。模块不自动下载模型；缺命令、模型或格式转换条件会受控失败，之后可手输文字。不要仅凭 README 的历史环境描述断言本机当前有或没有模型。[S2:16–19/46–100/121–142，S3，S5:489–494]

□ 本次仅安排单题、短回答，并预期数据离页丢失。语音 blob、转写和反馈放在页面内存状态，返回、重录、切主导航、历史导航和页面离开会重置；没有这条语音流程的历史答卷保存或专用导出。面试模块配置存到 localStorage，不等于录音或回答已保存。[S1:112/147–148/190–193/213/216/228/230–231]

二、当前源码支持的操作（存在实现；本轮均未实操）

□ 从 Q1“工具调用超时”、Q17“如何界定 LLM Agent”、Q42“验证工作流无静默失败”三道 Agent 开发者演示题选择“直接练习”；题目可按 ID/标题/题型及轮次筛选。这不是完整 100/124 题语音接入。[S1:164–168/200]

□ 开始录音、请求权限时取消、暂停、继续、停止；暂停态可“放弃”。停止后用浏览器 audio 控件试听，或重新录音。无权限、不支持、设备被拒和空音频有不同状态/提示。[S1:147–153/161/213]

□ 浏览器支持且启用时，录音同时请求中文 SpeechRecognition；也有“使用本地转写”接口路径。进入可编辑的“转写校对”态后可输入/粘贴和修改文字，点击“确认并分析”。没有麦克风或录音能力时，不能据此保证本语音页仍可直接进入手输流程。[S1:120–126/138/159/161]

□ 对有限词表生成“术语纠错”建议，单条“采纳”或“一键采纳”；例如 rag→RAG、mcp→MCP、sqlite→SQLite。它是匹配替换规则，可能误改“麦克”等普通词，需本人核对；不是通用语义或上下文纠错模型。[S1:127–136/159]

□ 得到“本地规则反馈”：可观察亮点、缺失证据、下一次动作、固定追问、字数/字符数和填充词；可“修改转写后重分析”或按重答提示“重新录音回答”。默认客户端检查约束/机制/取舍/验证等关键词，不判断技术事实是否正确、口音、情绪、自信或录用结果；教材绑定默认 none，没有逐节证据引用。界面出现 completed 仅是规则流程完成。[S1:137–139/158]

□ 录音完成后可在“其他转写方式”载入测试转写，核后续页面关系。这是明确的本地 fixture；必须与自己的口述分开记，不把预写文字当 ASR 或学习效果证据。[S1:118–119/161]

三、会影响试用的限制与当前证据空缺

1. 本地 HTTP 转写容量受更小门槛限制：语音模块校验标称 25 MiB/3 分钟，但 /api/voice/transcribe 先调用通用 JSON body()，整个请求超过 128 KiB 即拒绝；音频 base64 占用会使原始音频上界不足 96 KiB，尚需扣 JSON 包装。因此不能承诺 3 分钟浏览器录音能够提交；当前录音端也未见自动 3 分钟停止。实际可录多久依编码而变，本轮未测。[S1:126/149，S2:18–19/121–142，S5:387–390/490–494]

2. 暂停录音只调用 MediaRecorder.pause()，未同步暂停/停止 SpeechRecognition；暂停期间是否继续收字、转写是否与试听一致，要在下一轮验证。浏览器结束识别与 recorder.onstop 都会改状态，成功候选能否稳定进入可编辑校对态亦未实测。转写/分析异步响应缺少与录音同等的 requestId 校验，需核离页和重录后的旧响应隔离。[S1:123–126/138/149–152]

3. 当前页面与旧文案/报告有差异：源码里“识别设置”已折叠，实时识别区及部分标记被隐藏；精选题页仍有“不调用 ASR/AI，不上传录音”的旧说明，但本地转写会向同源服务发送音频，浏览器识别处理边界也未知。不能以这些旧文案认定全程离线或未传音频。[S1:126/155–161/200，S8:17–21]

4. 2026-10-17 既有 QA 记载语音视觉 insufficient、旧语音脚本 13 pass/2 fail、voice smoke 在第28行失败；这是历史报告，不是本轮运行。当前 CSS 已存在 h1:focus 去轮廓处理，不能据旧报告断言当前完全没有修复，也不能据该规则宣称视觉已验收。最新项目归档还记录两脚本原件及运行版本绑定未恢复；本轮在 team 文件清单也未找到这两个同名脚本。需恢复可核来源后决定回归方式，不能直接把旧断言改成通过。[S7/S8:10，S9]

5. DQ-01：同一轮取消勾选有静态状态冲突。第161行输出无值属性 data-interview-speech-consent；按其 DOM dataset 值为空字符串的语义，第221行 if(input.dataset.interviewSpeechConsent) 守卫为假，跳过对 browserSpeechOptIn 的更新。第112/147行初始/重置仍为 true，第123行启动识别函数消费该状态。因此在浏览器识别 API 可用且录音前置满足时，即便复选框外观看似取消，仍可能进入识别启动路径；不能把取消勾选作为仅本地/手输路径的可靠保证。以上为源码静态推断，本轮未浏览器复现、未观察网络或语音外发；工程修复未实施，需另行授权。A4列的是未来接受条件，不是当前通过结果。[S1:112/123/147/161/221]

四、下一轮最小验收（产品接受条件；由独立测试执行，当前均未验收）

每项保留当次 HEAD/关键源哈希、浏览器/系统/设备、实际转写路径、步骤、预期/实际和证据；分别记 pass、fail、insufficient、not_tested。使用隔离试用数据。以下只验练习流程，不授学习效果、职业能力或完整产品达标。

□ A1 入口与题目：分别从 Q1/Q17/Q42 进入，题面与 ID 一致；返回再选另一题，无上一题录音、文字、反馈混入。独立演示入口身份明确。[S1:113/164–168/200/213]

□ A2 设备和权限：允许内置麦克风能进入录音；拒绝权限、外部/未知设备、浏览器缺录音 API 各有可理解提示。请求权限时取消，之后才返回的 stream 也停止，不在后台续录。[S1:143–149/161]

□ A3 录音生命周期：开始→暂停→继续→停止→试听、暂停→放弃、停止→重录均可完成；计时/状态和音频内容一致。专门在暂停时说一句标记话，核这句话是否进入音频/转写，避免两份内容不一致。[S1:149–153]

□ A4 浏览器转写及设置：先由独立测试复现限制5的同一轮取消勾选冲突；当前不把“可关闭”列为已支持。下一轮接受条件为：用户取消勾选后，识别状态实际变为关闭，随后开始录音不调用 SpeechRecognition.start；应同时取得控件、状态和调用行为证据，不能只看勾选外观、文案或 providerCalled=false。若需工程修复，另行授权实现后按新源独立复验，未通过前不得安排依赖该开关隔离浏览器识别的路径。默认状态以及重录/返回重进的重新启用行为须明确。覆盖支持/不支持、权限拒绝、network、no-speech；失败仍可保留试听并走可用的手输/重试路径。成功 final 先返回和后返回两种顺序，都要能在停止后进入校对并确认分析，不被 captured 状态卡住。本项仍未执行，也不据识别调用与否推断已发生或未发生外部处理。[S1:112/122–124/147/149/159/161/221]

□ A5 本地转写与容量：配置就绪时用一段真实短录音核正确文字和来源；未配置/接口失败清楚提示，可手输并继续。分别核 128 KiB JSON 边界、3 分钟/25 MiB 模块边界与页面行为，文案必须匹配实际可提交范围；不把 fixture 替代真 ASR 成功。[S2/S3/S5]

□ A6 校对与术语：用含 rag、mcp、SQLite 及“麦克风”的文字；修改中文、单条和全部采纳后文字不丢、不误替换无关内容，空文字不能出成功反馈。确认后反馈确用最后一版校对文字，修改后可重新分析。[S1:127–138/159/213]

□ A7 反馈诚实性：同一回答补/删约束、机制、取舍和验证后，反馈对应变化；人工核其适用范围，不以关键词齐全认定技术正确。明确显示规则模式、ASR 来源、教材绑定及已知处理边界；录音前可获知浏览器处理未知与同源本地转写路径，纠正旧绝对“不调用/不上传”说明。[S1:137–138/158/161/200]

□ A8 退出与迟到结果：录音中返回、导航、刷新/离页均停止麦克风/识别并释放旧播放地址；转写或分析尚未返回时离开/重录/换题，迟到结果不复活旧文字、覆盖新题或更改新反馈。不把模块配置恢复当回答恢复。[S1:115–116/126/138/147–148/216/228/230–231]

□ A9 可操作性与旧失败：桌面及390px宽度走完整主流程；真实键盘 Tab/Shift+Tab 可达并有清晰焦点，程序标题焦点不产生整行异常框、重绘不抢走正在编辑的位置；取得 activeElement/AX/截图。恢复旧测试脚本/原调用版本与依赖后，由测试岗解释旧失败及当前结果，不复写历史。[S7/S8/S9]
