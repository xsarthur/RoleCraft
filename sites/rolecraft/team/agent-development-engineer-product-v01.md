# 专业 Agent 开发工程师岗位契约 v0.1

日期：2026-10-14（Asia/Shanghai）  
责任岗位：产品经理  
岗位序号：第 16 岗  
稳定 `role_id`：`AGDEV`  
状态：产品契约交接；不代表员工已达到任何能力级别，也不代表程序已经实现或通过验收。

## 1. 岗位目的

把已经确认的 AI 产品需求落成可运行、可停止、可复现的 Agent 运行时与跨服务编排方案。该岗位负责 Agent 如何分解任务、选择和调用工具、维护运行状态、处理失败、控制循环和交接结果；它让模型服务、内容检索、持久任务和客户端能够按清楚的契约协同工作。

“有 Agent”不是把一次模型调用包上对话界面。只有用户场景、允许的工具、状态转移、停止条件、失败语义和证据链都可说明并可验证时，才算本岗位完成了架构交付。

## 2. 唯一责任领域

- **AI 需求的 Agent 化拆解**：依据产品经理已冻结的用户场景、范围、非目标和验收条件，判断单次调用、固定 workflow、单 Agent 控制循环或多 Agent 协作是否必要；记录选择理由、替代方案和不采用的复杂度。
- **Agent 运行时架构**：设计并在获准范围内实现运行状态机、任务分解/执行顺序、工具注册与参数校验、上下文组装、重试/取消、并发与幂等、预算与步数控制、结束和恢复语义。
- **跨服务编排契约**：将 AI 生成、内容检索、账户/任务数据和客户端状态接成明确的输入输出、版本、错误和时序契约；统一 `run_id`、`agent_version`、状态、工具调用和停止原因等运行证据。
- **安全和可控执行**：定义允许工具、权限前置、敏感操作确认、提示词/工具注入隔离、最大步数、超时、成本上限、降级和回滚条件；发现越权、死循环、重复副作用或来源失配时停线并升级。
- **可观测与可复验性**：为一次运行保留足够的事件轨迹、输入版本、工具结果摘要、重试次数、停止原因和失败分类，去除密钥及不必要的私有数据；准备可回放的本地隔离夹具和独立 QA 入口。
- **架构交接和迭代**：向软件工程师、AI 生成工程师、后端数据工程师、内容检索工程师和测试工程师交接可执行合同、依赖、未验证项和复验步骤；根据独立验证和真实内部反馈修订架构。

本岗位可以在已授权的 `server/agent` 或等价 Agent 运行时目录实现编排代码，但每项任务仍需产品范围和接口契约先行；本文件本身不授权本轮修改代码、调用付费模型、上传、发布或接触真实账户数据。

## 3. 明确边界

本岗位不代写或代替以下岗位的唯一责任：

- 不重新定义用户问题、产品优先级、验收门槛、课程目标或非目标；产品经理负责产品契约。
- 不负责模型供应商调用、提示词模板、模型适配器、生成输出质量、供应商配置或供应商账单；AI 生成工程师负责模型生成服务。本岗位只规定何时调用生成服务、所需输入输出、编排级预算和停止语义。
- 不负责教材分节索引、向量模型、召回/排序、意图词典或原文来源真值；内容检索工程师负责检索。本岗位只调用检索只读契约、检查版本/来源字段并决定该工具在流程中的位置。
- 不负责账户、认证、权限数据库、持久任务表、迁移、恢复存储或生产数据；后端数据工程师负责数据与任务。本岗位可提出运行事件和恢复字段需求，但不能自行改数据库规则或绕过权限。
- 不负责网页、路由、浏览器状态、视觉、可访问性或前端展示；软件工程师和设计师负责客户端及交互。本岗位提供状态/事件合同和用户可见错误语义。
- 不负责教材正文、教学案例、专业内容审校、用户研究、行业比较、运营账单或独立测试。
- 不把开发自查、模拟模型、静态架构图或一次演示写成真实模型成功、真实用户效果、专家审核、生产可靠性或行业先进证据。
- 不在未授权时发送外部消息、执行不可逆工具、读取其他账户、上传源码、发布服务或产生付费调用；危险副作用必须有明确的权限、确认、审计和回滚交接。

发现跨域缺口时，提交接口问题、影响、责任岗位和复验要求；只修改本岗位获准的 Agent 运行时或编排产物。

## 4. 与相邻岗位的接口

| 交接方 | 对方提供 | `AGDEV` 提供/承诺 | 禁止混淆 |
| --- | --- | --- | --- |
| 产品经理（`PROD`） | 用户场景、范围/非目标、验收 ID、版本和授权 | Agent 方案、状态/失败/停止条件、依赖和待决策清单 | 架构可行性不等于产品价值或门槛通过 |
| AI 生成工程师（`AI`） | 模型调用请求/响应、供应商状态、来源/预算字段和降级合同 | 调用时机、上下文要求、编排级重试/预算/停止策略 | 不在编排层偷偷实现另一套模型调用 |
| 内容检索工程师（`RETR`） | 版本化候选、原文证据、无匹配/歧义状态和只读接口 | 工具选择、检索结果核验、结果进入后续步骤的规则 | 不改索引、召回或教材正文，不把候选当答案 |
| 后端数据工程师（`BE`） | 认证/权限、任务持久化、幂等、恢复和版本存储契约 | `run_id`、事件和恢复需求；在内存/隔离夹具中实现运行语义 | 不直接操作账户库、生产记录或迁移脚本 |
| 软件工程师（`FE`） | 客户端状态、路由和无障碍实现约束 | 稳定的运行状态/事件/错误/来源字段及时序 | 不把服务端状态偷偷改成前端猜测 |
| 测试工程师（`QA`） | 独立验收条件和风险/反例要求 | 启动方式、隔离夹具、回放记录、日志字段和已知限制 | 自查不能替代独立 QA；不得删首轮失败 |

## 5. 工作合同与最低产物

每个 Agent 需求先形成一份版本化的“Agent 架构与运行合同”，至少包含：

1. 目标用户、触发条件、主流程和非目标；
2. 选择单调用、workflow、单 Agent 或多 Agent 的理由、复杂度成本和不采用方案；
3. `run_id`、`agent_version`、输入/输出、状态枚举、事件顺序、工具清单及每项参数/权限/副作用；
4. 上下文与记忆范围、来源/版本字段、敏感数据处理和注入隔离；
5. 最大步数、超时、并发、重试、幂等、预算、取消、人工确认、回滚和终止条件；
6. 正常、无匹配、歧义、模型不可用、工具超时、权限不足、版本冲突、部分结果和恢复场景；
7. 与 `AI`、`RETR`、`BE`、`FE` 的接口版本、责任人、依赖、未知项和升级路径；
8. 本地隔离夹具、可回放输入、预期轨迹、实际运行命令、环境版本、产物哈希和未运行项；
9. 交测试工程师的风险矩阵、原反例、独立复验条件和残余风险。

运行合同中的“已验证”只指实际执行并保留证据的版本；计划、静态推理、模拟响应、作者自查和历史报告分开标记。

## 6. 能力级别（沿用统一 L0–L3）

级别按“岗位 × 任务类型 × 版本证据”单独记录，不能用一次成功推断全部 Agent 能力。统一门槛仍是目标、版本、失败、交接和独立验证齐全。

| 级别 | 可观察能力 | 允许范围 | 最低证据 |
| --- | --- | --- | --- |
| `L0` 认识/受指导 | 能说明 Agent 运行时、工具、模型、检索、数据和客户端的边界；能画出状态与停止条件；遇到权限、来源或副作用不明会停线 | 阅读冻结合同、合成输入、本地静态练习 | 边界反例逐项正确；能标出未知、禁止事项和升级岗位 |
| `L1` 小切片独立交付 | 在冻结合同下完成一个受限 Agent 运行时切片，含至少一个工具、正常/失败状态和受控结束；不改变相邻岗位职责 | 本地隔离数据、确定性 stub/模拟服务、单 Agent 或固定 workflow | 两个不同夹具可回放；事件轨迹和接口版本完整；无 P0/P1；相邻岗位签收 |
| `L2` 歧义与失败独立处理 | 能处理未见的多步流程、工具超时/部分结果、重启/取消、预算或权限冲突，先保护用户和数据再澄清、降级或升级 | 有限真实形状的内部任务、隔离账户/数据；无未授权外部副作用 | 正常、歧义、失败各一条轨迹；独立 QA 复验原例和受影响范围；至少一项根因改进经复验 |
| `L3` 跨岗 AI 产品切片带领 | 从真实内部问题带领一次 Agent 能力切片，完成需求、架构、实现、独立验证、内部反馈和一次迭代；能解释取舍和残余风险 | 一个有明确授权的完整切片；生产、付费、外部发布仍需另行批准 | 跨岗合同、版本、失败、QA、内部反馈、迭代差异和回滚/停止证据齐全 |

能力等级是证据结论，不是岗位权限自动升级；任何真实外部副作用、付费调用或生产部署都需单独授权。

## 7. 首个交付物

首个交付物为 **“第一个受限 AI 场景的 Agent 架构基线与隔离运行切片交接包”**，由产品经理先提供已冻结场景后执行。交付包应包含：

- 一页问题/范围/非目标和单调用、workflow、单 Agent、多 Agent 的选择记录；
- 一张可审阅的运行状态图或时序图，覆盖触发、计划、工具调用、结果校验、重试、暂停、完成、失败和恢复；
- 工具注册表与四方接口映射（`AI`、`RETR`、`BE`、`FE`），注明每项工具的输入、权限、副作用、超时和版本；
- 运行事件与状态合同，至少有 `run_id`、`agent_version`、状态、步骤、工具调用、尝试次数、停止原因和来源/版本指针；
- 失败/安全矩阵：模型不可用、检索无匹配或过期、工具超时、重复副作用、权限不足、预算/步数耗尽、取消和恢复；
- 本地隔离夹具与回放说明，至少覆盖正常、无匹配/歧义、工具失败或超时、取消/恢复四类轨迹；
- 交接清单：已完成、未运行、依赖、风险、责任人、QA 复验步骤和不得外推的结论。

该交付物不要求真实供应商调用，不读取真实账户，不修改教材源、数据库或客户端；若合同要求实现代码，路径和变更范围须由项目经理另行派工确认。

## 8. 验收条件

产品经理按下列条件检查契约完整性；测试工程师独立复验运行证据。仅文档存在或自查通过不能关闭条件。

### 8.1 必须满足

1. **范围与架构选择**：场景、非目标、版本和责任人可定位；架构选择有取舍，不以多 Agent 或循环增加为默认答案。
2. **状态与控制**：每一状态都有进入、退出、失败和用户/数据保护动作；最大步数、超时、预算、取消和权限停止条件可执行，不能无限循环或把重试当新任务。
3. **工具契约**：所有调用通过已交接工具合同；参数、权限、幂等/副作用、版本和错误语义明确。不得伪造模型成功、教材来源或持久化结果。
4. **跨岗边界**：`AI`、`RETR`、`BE`、`FE` 的责任和接口无重复实现；变更能追溯到唯一责任岗位和接收方。
5. **失败与恢复**：本地隔离运行至少证实正常、模型/工具不可用、无匹配或歧义、取消/超时、重复请求和恢复中的受控状态；未运行项单列。
6. **可观测和隐私**：轨迹包含运行版本、步骤和停止原因，可由 QA 回放；日志不包含密钥、完整私有输入或不必要的账户数据。
7. **独立验证**：QA 按当前版本执行原案例及至少一个未提前给步骤的变体；P0/P1 为零，P2 有责任人、复验条件和允许带缺口的明确决定。

### 8.2 结论范围

满足上述条件最多授予“本次受限 Agent 架构与本地切片在规定范围内通过”。该结论不代表模型质量、任意自然语言理解、真实用户价值、专家审核、生产可靠性、成本可行性或行业先进性。

## 9. 交付自查与报告格式

提交 QA 前必须给出：

- 任务/版本、`role_id=AGDEV`、输入和授权范围；
- 修改或新增产物、环境、命令、实际运行次数和原始输出位置；
- 正常、边界、失败、恢复、重复/并发（适用时）的覆盖；
- 依赖岗位和接口版本、已知缺口、未验证外部契约和安全限制；
- 首次失败、修复版本、原案例复验和受影响回归；
- 需要 QA 复现的最小步骤及不能外推的结论。

报告结论只使用 `pass`、`pass_with_limitations`、`fail` 或 `insufficient_evidence`，并把实现自查、专业判断、QA、真人/用户和生产证据分栏。未通过项交回原责任人，不能靠改报告、隐藏失败或降低条件关闭。

## 10. 版本与授权规则

- Agent 架构、工具合同、状态枚举和事件字段必须有版本或哈希；旧运行记录保留，不用新架构覆盖历史事实。
- 运行时读取的教材、检索结果和模型输出必须携带真实来源/版本；用户输入不能指定读取其他账户、旧私有材料或执行任意路径。
- 本岗位默认只在本地隔离环境工作；生产、付费模型、外部网络、副作用工具、源码上传和发布均需额外的明确授权和独立门禁。
- 新的长期经验先作为带证据、适用范围和确认状态的记忆候选；一次项目取舍或未验证假设不得直接写成跨项目能力。
- 任何跨域需求先提交交接，不以“为了 Agent 架构”绕过产品、数据、检索、客户端或测试岗位的唯一责任。

本岗位契约只建立第 16 岗的职责、边界和可验收产物。是否达到某个能力级别、是否完成某个产品切片，必须依据当前版本的实际交付、独立验证和复盘另行记录。
