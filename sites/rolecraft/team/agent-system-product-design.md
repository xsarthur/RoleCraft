# Agent 系统产品设计（输入点接入方案）

- 文档角色：产品需求与验收合同
- 版本：product-agent-system-v0.1
- 日期：2026-10-15
- 责任岗位：产品经理
- 适用范围：在现有学习工作台中，为所有允许用户输入的入口接入 Agent 能力；本版先定义“选择职业”和“输入学习内容相关问题”两处核心入口。

## 1. 产品目标与非目标

目标是让用户用自然语言表达目标、困惑或约束，由 Agent 识别意图、调用已有目录/教材检索能力、给出可解释的下一步建议，并保留用户可控的确认点。推荐必须能回到当前教材版本的具体章节/小节；无法确定时先澄清，不生成不存在的教材内容。

本版不把 Agent 变成无边界聊天机器人，不替用户作职业承诺、能力认证或就业判断，不改变账户权限、用户记录、教材正文和原八门槛，不调用未授权的付费模型或外部服务。动态教材生成仍属于后续 AI 生成工程范围，未配置时必须明确显示不可用。

## 2. 用户场景

### 2.1 选择职业入口

1. **探索型**：用户输入“我想做能把客服流程自动化的工作”，尚未知道职业名称。Agent 从受支持职业目录中提议一个或多个候选，解释依据、典型任务和差异，并要求用户确认。
2. **迁移型**：用户输入“我会 Python 后端，想转做 Agent 应用”，Agent 识别已有能力与目标差距，推荐职业及先修阅读入口；不把自述当作测评结论。
3. **约束型**：用户输入“每周只能学 5 小时、希望先做可展示项目”，Agent 将约束作为排序条件，推荐职业路径的起点和最小实作单元。
4. **歧义型**：用户只输入“React”或“做自动化”，可能是技术词或职业目标。Agent 不直接选定职业，展示候选含义并追问。
5. **不支持型**：用户输入目录外职业。Agent 明确当前支持范围，提供最接近的候选或返回人工选择，不伪造新职业页面。

### 2.2 学习内容输入入口

1. **定位型**：用户问“恢复轨迹和幂等在哪一节？” Agent 返回具体章节、小节、版本和原文摘录。
2. **解释型**：用户问“为什么要先做任务边界？” Agent 先定位相关内容，再用教材已存在的段落解释；若需要新增讲解，标记为待生成/不可用。
3. **规划型**：用户说“我想从零做一个带恢复的 Agent”，Agent 将目标拆为已存在的阅读单元、先修和实作入口，给出顺序与理由。
4. **比较型**：用户问“workflow 和多 Agent 怎么选？” Agent 返回教材中对应选型段落，并列出比较维度；没有证据的行业结论不得补写。
5. **复习型**：用户输入“我刚学完控制循环，接下来练什么？” Agent 根据当前章节和学习记录（仅在用户授权读取时）推荐下一单元；学习记录不转换成能力认证。
6. **多意图/否定型**：用户输入“不要检索章节，我想知道如何写持久任务并控制成本”。Agent 应拆分意图，排除被否定的检索建议，同时返回数据/成本相关小节。
7. **无法定位型**：用户输入含糊的“记得那个东西吗？” Agent 返回澄清选项（上下文、检索、任务事实等），不确定时不输出确定章节。

## 3. Agent 职责与意图分类

Agent 由编排层负责识别、澄清、调用和解释；领域能力由现有内容检索服务提供。职责边界如下：

- **意图识别**：判断入口（职业/学习内容）、目标动作（选择、定位、解释、规划、比较、复习）及约束（时间、基础、当前章节、否定词）。
- **候选生成**：职业入口只从产品维护的职业目录生成候选；学习入口只从当前教材 corpus 的章节/小节索引生成候选。
- **证据绑定**：每个肯定推荐绑定 `corpus_version`、教材/章节 ID、标题、原文摘录、来源 SHA（如接口提供）和可打开的 section URL。
- **澄清与排序**：候选不足或多义时提出最少必要问题；用户确认后才能提交新的检索快照。
- **反馈与恢复**：区分 `no_match`、`needs_clarification`、`unavailable`、`invalid_input`；允许重试，迟到响应不得覆盖新请求。
- **解释限制**：可总结和重排已有内容，不得把模型推断包装成教材原文、真人审核或学习成效。

建议意图枚举：

`career_discovery`、`career_confirm`、`career_compare`、`career_constraint`、`content_locate`、`content_explain`、`learning_plan`、`content_compare`、`practice_next`、`multi_intent`、`clarification`、`unsupported`。

## 4. 交互与推荐流程

### 4.1 通用流程

1. 用户在输入框提交自然语言；界面显示当前入口、可用教材版本和隐私/数据范围提示。
2. Agent 解析意图与约束，先做输入校验（空白、超长、明显敏感或外部请求）。
3. Agent 调用对应只读能力：职业目录或 v0.11 内容检索接口；不直接读私有路径或数据库。
4. 结果卡显示：结论类型、依据、候选/章节、置信提示、来源版本、下一步按钮（确认、换一个、澄清、重试）。
5. 用户确认后才写入选择或学习工作台状态；未确认的建议只保留在当前会话。
6. 用户可打开原文，返回后保留原始表达与结果快照；新查询不得覆盖旧卡。

### 4.2 选择职业流程

- 输入 → 识别目标任务/能力/约束 → 从职业目录召回 1–3 个候选 → 解释“为何匹配/仍需确认的差距” → 用户确认职业 → 建立学习入口。
- 多候选时按任务相似度、用户约束和教材覆盖度排序；显示“候选”而非“已判定”。
- 用户确认后写入当前学习会话的 `career_id` 与 `selection_source=agent_confirmed`；不修改历史账户能力字段。

### 4.3 学习内容流程

- 输入 → 解析意图与否定/多意图 → 检索 v0.11 版本化分节索引 → 对结果做来源与原文校验 → 返回章节卡/解释卡/计划卡。
- 章节卡至少包含教材版本、篇章、小节标题、原文摘录和可点击定位链接。
- 解释或规划必须先展示引用依据；超出 corpus 的内容显示“当前教材无对应内容”，可提供相邻章节或澄清选项。
- 计划卡只能组合现有单元与实作入口，不声称完成时间、职业胜任或行业先进。

## 5. 边界与失败处理

- **空白/过长/非法输入**：返回 `invalid_input`，说明可接受范围；不调用检索。
- **无匹配**：返回 `no_match`，建议改写或浏览目录；不生成虚构章节。
- **歧义**：返回 `needs_clarification`，最多给 3 个明确选项；保留原输入，用户选择后再检索。
- **检索资源/模型不可用**：返回 `unavailable` 与重试入口，不能降级为看似确定的答案。规则降级仅在产品显式标注为 `rule_fallback` 时可用。
- **否定与多意图**：按子句拆分；被否定目标不得出现在肯定推荐首位；多个合法目标分组展示。
- **版本变化**：结果卡携带 corpus/version/SHA；恢复旧卡时重新校验，版本不一致则提示刷新。
- **外部知识请求**：当前版本只回答教材和职业目录范围；需要联网或付费模型时明确不可用，不自动外呼。
- **隐私与权限**：不把未授权的账户记录、项目档案或私有文件送入 Agent；学习记录仅在用户明确授权的会话范围读取。
- **并发/迟到响应**：每次提交有 request ID；新请求到达后旧响应不得覆盖输入焦点、结果卡或确认状态。

## 6. 与 v0.11 系统衔接

- 沿用 `local-workbench-0.11` 学习工作台、`rolecraft-content-query-v11` 查询会话和现有版本化 corpus；不覆盖 v0.11 QA 与历史记录。
- 内容 Agent 通过现有公共只读检索合同取得章节候选、摘录、来源 SHA、href 和状态；前端继续负责卡片、定位、刷新、后退和复制链接。
- 选择职业是上层意图入口：确认后的 `career_id` 作为检索过滤/排序上下文，但不得改变教材源或伪造职业专属内容。
- “解释/规划”先消费已有教材段落；若未来接入真实生成服务，须单独定义生成版本、来源校验、失败处理与 QA，不借本设计关闭 `real_generation` 门槛。
- 版本、错误状态、Node 运行时支持范围和本地只读边界沿用 v0.11；任何扩展必须创建新版本产品与独立 QA 记录。

## 7. 验收条件（产品合同）

| ID | 验收条件 | 证据要求 |
|---|---|---|
| AGP-01 | 两个输入入口均能提交自然语言并显示当前入口/版本上下文 | 独立浏览器记录与请求日志 |
| AGP-02 | 职业探索可返回 1–3 个目录内候选，说明依据并等待确认 | 冻结的探索、迁移、约束、歧义样例及结果快照 |
| AGP-03 | 未确认职业不会写入正式选择或能力字段；确认后仅写入当前会话 career_id | 隔离账户/会话数据前后对照 |
| AGP-04 | 学习定位/解释/规划结果逐项绑定章节、小节、版本、摘录和 href | 原文逐字核对及点击定位证据 |
| AGP-05 | 无匹配、歧义、不可用、非法输入四种状态可区分且无虚构答案 | 四类反例的 HTTP/UI 记录 |
| AGP-06 | 否定和多意图输入按子句处理，被否定目标不首推，合法目标分组返回 | 冻结混合/否定样例及排序记录 |
| AGP-07 | 版本变化、刷新、后退和新查询不会错绑或覆盖旧结果 | corpus 变更模拟、浏览器时序证据 |
| AGP-08 | 迟到响应不会覆盖新请求；重试可恢复且输入焦点保留 | 代理延迟/并发请求证据 |
| AGP-09 | 不读取私有路径、未授权账户数据或外部服务；模型未配置时诚实标注不可用 | 边界请求与配置状态记录 |
| AGP-10 | 产品结论只授本合同范围；不将推荐当能力认证、用户满意或完整产品达标 | 独立 QA 报告中的范围声明与缺口清单 |

## 8. 后续拆分与责任

产品经理维护意图枚举、职业目录口径、验收样例和版本合同；设计师交互与可视化状态；软件工程师实现入口和状态消费；内容检索工程师维护索引、召回、引用校验及只读接口；AI 生成工程师仅在另行授权后接入生成；测试工程师按 AGP-01..10 独立复验。任何岗位不得用自己的自查替代独立验收。
