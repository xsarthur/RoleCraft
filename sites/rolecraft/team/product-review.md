# 产品经理交付：职造产品审查与 MVP 建议

日期：2026-10-10。责任领域：产品需求。输入：用户目标、AGENTS.md、README.md、dist/index.html 与 dist/app.js。本文依据文件阅读，未执行浏览器验收；MVP 为建议需求，尚未由用户确认，也未实现。

## 1. 当前原型能力（代码可见事实）

- 学习档案：三种自报基础、三种学习目标、每周 3—20 小时投入。
- 职业路线：基础决定预设章节顺序；目标改变建议文案；时间用于估算周期。目标尚未改变课程正文或评估内容，没有能力诊断。
- 教材：8 个固定章节示例，每章包含概念、场景、代码或伪代码、练习及一道概念选择题。测验通过记录在当前浏览器。
- 实践：2 个项目的自查清单、作品链接与备注记录，没有真实作品接收、自动执行或独立评审。
- 留存：浏览器本地保存档案、测验与实践记录，支持 Markdown 学习计划导出；没有账户和跨设备同步。
- 来源：3 个官方参考链接与固定核对日期。日期及链接不证明本次已核验内容，也不构成逐条教材证据。
- 导航覆盖概览、路线、教材、工坊与知识来源，页面明确声明原型边界。

## 2. 与用户目标的差距

| 用户目标 | 当前差距 | 产品需求方向 |
| --- | --- | --- |
| 自主生成职业教材 | 固定文本与规则组合，没有模型或生成任务 | 根据职业能力标准、学习档案和受控资料生成可追踪的章节 |
| 零基础到从业者都可学习 | 起点来自自报，进阶路径缺少实际能力证据 | 显示先修条件，结合练习和作品证据调整路线；证据不足时不默认跳过基础 |
| 达到行业先进水平 | 来源数量有限，无动态核对、案例执行或专业审核 | 对具体知识点记录来源版本、核对状态和审核证据，持续维护 |
| 培训成优秀人才 | 概念题与自查无法证明职业交付能力 | 以真实项目成果、明确评分条件及外部复核验证阶段能力 |

“先进水平”和“优秀人才”应转为可评估的岗位任务能力与质量指标，不能直接作为网站自动保证的结果。

## 3. 首个真实系统 MVP 建议范围

目标：让一位学习者完成“设置起点 → 获得 Agent 开发路线 → 生成并学习一个真实章节 → 完成练习 → 提交一个作品 → 获得证据明确的反馈”的闭环。

1. 只覆盖 Agent 开发者一个职业，支持零基础、已有编程基础、已有 Agent 经验三类入口；首期用档案与短诊断提供建议，明确区分自报和验证结果。
2. 采用课程架构师维护的岗位能力版本及章节结构。首期仅选一个能力主题实现真实章节生成；其余内容保留审核过的基础教材或明确标注示例，避免把单章试点称为完整教材系统。
3. 使用受控官方来源生成章节，提供学习目标、先修要求、正文、练习、支持主要技术论断的引用、版本及审核状态。新生成内容先以草稿可见，达到既定审核条件后进入正式教材。
4. 提供一个实践项目的作品链接、运行证据和评估报告提交入口；审核者按课程团队定义的标准反馈，区分 AI 初步建议和人工结论。
5. 提供最小账户、学习记录、课程版本及生成任务保存；可查看生成中、成功、失败状态，失败后重试，不丢失旧版本或已有学习记录。

首期非承诺：全职业覆盖、完整教材无人审核自动发布、固定时间就业、职业资格认证、仅凭概念题认定胜任、自动运行任意用户代码。在线代码执行可作为后续独立范围；首期通过外部运行证据与人工复核推进。

## 4. 建议验收条件（供测试工程师验证）

| 场景 | 可验收的预期行为 |
| --- | --- |
| 零基础创建路线 | 路线明确显示编程先修阶段、目标能力和学习任务；用户可查看修改起点的入口 |
| 已有基础请求跳过先修 | 页面区分自报与已有证据；尚未验证的能力有提示，用户仍能访问基础章节 |
| 从业者请求进阶路线 | 返回进阶任务及对应能力缺口说明；自报经验不会自动变成已掌握标记 |
| 成功生成首个章节 | 对受控输入得到真实模型生成内容并保存任务、档案与能力标准版本；页面展示草稿状态、先修、练习和引用，不把原型固定文本当成生成成功 |
| 引用不足或审核未通过 | 明确展示对应状态和缺失项，保留草稿，不显示已审核或行业认证标记 |
| 生成失败后重试 | 用户看到可理解的失败状态和重试入口；重试保留原任务记录、旧教材及学习记录，成功产物可追踪到对应任务 |
| 切换设备恢复学习 | 同一账户在另一浏览器恢复档案、章节版本及已保存学习记录，其他账户不可读取 |
| 提交作品并获得反馈 | 每条结论对应实际提交证据与评分项；未评审、自查、AI 建议和人工结论显示为不同状态 |
| 更新教材版本 | 新版本有变更摘要和来源信息，旧版本与原有提交证据可回看，不把旧版本完成记录直接当作新版本通过 |

以上均为未来验收要求，不是测试通过报告。具体诊断题、课程主题、评分阈值与审核门槛由课程架构师提交，再由项目经理协调确认。

## 5. 岗位交接

- 课程架构师：提交岗位任务能力矩阵、三类起点的先修规则、首个生成主题、资料与引用标准、练习及作品评估要求；教学内容和评分定义由该岗位负责。
- 设计师：依据确认后的范围设计起点、生成任务、阅读、版本、作品提交与审核反馈流程，重点表达自报／验证、草稿／审核和自查／能力证据的区别。
- 软件工程师：在需求、课程结构和设计交接完成后，给出真实生成、来源追踪、账户存储、任务恢复、版本及提交功能的实现方案；技术方案不代替产品与课程决策。
- 测试工程师：根据本报告的场景形成独立验收计划，验证状态真实性、权限、失败恢复及记录留存；发现缺陷交项目经理分派，不自行修改专业交付物。
- 项目经理：收集各岗位交付，确认首个章节与作品闭环的边界、依赖和待决事项，再安排实现。当前轮次完成产品审查不代表 MVP 完成。
