# 员工成长 L3/L4 独立 QA Gate v1.1

- `gate_id`: `EMP-GROWTH-L3-L4-QA-v1.1`
- `status`: `specification_only_not_assessed`
- `effective_scope`: 全部岗位的课程成长等级评估；不授予任何现有员工等级
- `owner`: 测试工程师（独立评估）；项目经理只协调

## 1. 证据分层

每条主张必须标注 `evidence_class`，不得跨层替代：

| 类别 | 可证明内容 | 不能证明 |
|---|---|---|
| `training` | 学习、沙箱练习、首次失败、返修、自动检查和本地复验 | 独立交付、真实用户效果、生产可靠性 |
| `delivery` | 受控真实形状任务、交接、恢复、跨情境迁移和接收结果 | 外部用户价值、行业先进性、长期生产结果 |
| `user_or_peer` | 经同意的真实用户/内部接收/同行反馈及可追溯变更 | 由单次满意度推断普遍能力 |
| `production` | 获授权生产运行、成本、质量、时延、事故与回滚 | 任何未授权环境或模拟运行 |
| `expert_review` | 具身份和范围的领域专家意见 | AI 自评、作者自审、证书自动等同专家认可 |

自动检查产生的结果只能作为 `training` 或技术收据，不得直接授予 L3/L4。

## 2. L3 稳健负责 Gate

### 必备证据包

1. **两次不同周期、不同情境的学习者本人交付**：每次均有匿名 `learner_id`、任务合同、版本/hash、环境、原始输入输出、首次失败、修复、原例回归和非作者留出结果。
2. **跨情境变化**：至少两项约束变化（版本、权限、资源、目标、数据形状或工具可用性），且学习者能说明选择、停止和升级理由。
3. **盲测留出**：QA 冻结并由非作者生成至少一个未知变体；学习者不得提前看到答案或夹具；记录提示次数、实际行为和偏差。
4. **最差案例与恢复**：最差案例须通过失败恢复、幂等/回滚/停止条件；失败不能被删除或重写。
5. **观察与追问**：独立评估者观察关键执行步骤，并对约束、机制、证据和取舍进行追问；回答必须与实际作品一致。
6. **作品集与交接**：交付包可由接收岗位在干净环境重建；接收方填写 accepted/rejected、身份、时间、版本、复跑结果和理由。
7. **问题闭环**：无未关闭 P0/P1；P2 必须有责任人、期限、影响和复验计划；返修后须完成受影响回归。
8. **教会他人**：学习者辅导另一名员工重建最小产物，记录被辅导者的独立复跑和误解点；此项不能由学习者自评替代。

### L3 通过规则

- 上述 1–8 全部满足；
- 两个情境均通过，且未知留出不是原题改名；
- 观察/追问、作品集、QA 复验、内容/领域复核、接收签收均独立完成；
- 任何匿名身份缺失、作者代答、单次成功、自动通过、无签收或缺少最差案例，结果为 `insufficient_evidence`；
- 通过只可写为 `course_level_L3_recommended`，不得改写为永久认证、专家认可或生产授权。

## 3. L4 产品创造与领域带教 Gate

L4 是额外的课程扩展评估，不由训练完成、L3 或内部自动检查自动产生。除 L3 全部证据外，必须同时具备：

1. **真实问题与用户证据**：经授权、可追溯的真实问题定义，含非目标、同意/隐私边界和基线；不得用虚构访谈或自述替代。
2. **可比评估**：明确比较对象、版本、场景、指标、样本/反例、成本和时间窗口；结果含不确定性和失败样本。
3. **迭代结果**：至少一轮依据用户/同行/专家或生产反馈的变更，保留前后差异、回归和未解决问题。
4. **外部或跨团队反馈链**：真实身份、范围、时间和反馈原文/结构化记录可核验；AI 生成评论不算外部反馈。
5. **持续可靠性**：在获授权环境有连续两次或规定窗口的结果、监控、成本、限流、回滚和事故处理证据。
6. **领域带教**：辅导至少一名他人独立完成未知任务；被辅导者的结果由第三方复核，记录迁移失败和改进。
7. **可复用资产**：形成版本化标准、夹具、检查器或课程改进，并由另一岗位在干净环境复用成功。

L4 只能输出 `course_level_L4_evidence_ready` 或 `insufficient_evidence`。它不等同于岗位职级、行业先进性、永久认证或生产批准；外部证据不足时必须保留 `not_assessed`。

## 4. 反误放行规则（硬阻断）

以下任一项触发，自动门禁必须停止并标记 `blocked`，不得由系统补全：

- `learner_id`、`signed_by_learner`、本人声明或提交 provenance 缺失；
- 代理代答、代理执行、作者自审、自动生成签收或把 QA 派生文件当原始收据；
- 只有阅读、报告、一次本地成功、证书、自动检查或旧版结论；
- 未公开留出题、未知任务、最差案例、失败和回归缺失；
- 真实数据、生产运行、外部协议、费用或用户反馈未授权/无法核验；
- QA、内容/领域复核、接收方签收中的任何一项仍为 pending；
- 版本/hash、环境、输入、输出、时间或主体不一致且未有据解释；
- P0/P1 未关闭，或 P2 没有责任人和复验日期；
- 将课程等级映射为产品等级、职业认证、专家认可或行业领先结论。

## 5. 独立评估顺序与抽样

固定顺序：冻结合同与 hash → 身份/provenance → 原例 → 首失败/停止 → 修复 → 原例回归 → 受影响回归 → QA 盲测留出 → 观察与追问 → 作品集重建 → 接收签收 → 领域/内容复核 → 结果判定。

每个岗位每个里程碑至少抽查一条完整证据链；高风险岗位或出现失败时抽查两条。抽样报告必须记录抽样框、选择规则、未抽样范围、误放行回溯和下次抽样日期。抽样通过不代表未抽样项通过。

## 6. 输出状态

允许状态：`not_assessed`、`in_progress`、`blocked`、`insufficient_evidence`、`course_level_L3_recommended`、`course_level_L4_evidence_ready`。任何 `recommended` 或 `evidence_ready` 都须附独立 QA 报告、限制、复验日期和责任人；不得自动改变员工主档等级。
