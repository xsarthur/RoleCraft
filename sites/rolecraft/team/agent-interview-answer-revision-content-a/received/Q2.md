# Q2 · 单次模型调用、固定 Workflow 和动态 Agent，分别适合什么业务条件？

版本：interview-answers-v1 / Q2-r1。本文为完整参考解析；案例和验证方案除特别注明外均为教学构造，未在本次写作中执行。

选型依据是任务的未知性在哪里，而不是步骤数量。**材料齐全、一次语义转换足够时用单次调用；路径和分支可预列时用固定 Workflow；下一处证据或行动需要依据新观察判断、路径难以合理穷举时才考虑动态 Agent。**三者都需要输入边界和结果校验，动态方案也不能绕过审批。

## 在同一缺陷处理目标下选择

先固定输入报告、可读仓库、允许动作、时间和验收条件，再比较：

- 报告、源代码和适用规则已经齐全，只需写一份说明：代码构造证据包，一次模型调用生成候选，再核对事实、引用和缺项。没有新信息可取时，多轮自主调查可能只是增加费用。
- 报告提供确定文件路径，接着读该文件和固定规则，再生成、审批、创建工单：用 Workflow。它可以有缺文件、审批拒绝、重试等分支，也可以多次调用模型；“固定”指控制结构由代码定义。
- 报告只给现象，读实现后才发现需要追某个动态注册器，再读配置才能确定下一文件：可尝试限定范围的动态只读调查，再接固定的审批和创建流程。动态部分解决取证路径，不负责给自己增加权限。

三个常见业务也可分别落位：固定字段提取先用确定性解析，无法覆盖的语义提取才用单次模型；固定审批链用 Workflow；多跳未知调查才是动态 Agent 的候选场景。

## 代价怎样进入决定

单次调用较易复现和限费，但缺材料时只能等待；Workflow 路径可审计，但分支增长会带来维护成本；Agent 能自适应补证，但可能走错路、反复搜索，调试和恢复需要记录完整轨迹。不要让 Agent 获得更多材料和预算后，把所有提升归给架构。

一个条件变化应导致重新选型：若后来发现动态注册器可由稳定配置规则解析，就可退回 Workflow；若原本一次生成的任务反复因缺证返工，可比较有界补读是否改善。按相同案例记录合格结果、正确等待、错误完成、调查次数、费用和时延；材料齐全、需动态调查和权威冲突三类分开看。若新增探索没有改善目标内结果，或引入不可接受的越权/成本，就不升级。两份同权威规则冲突需要权威澄清，任何架构都不能用模型票数制造事实。
