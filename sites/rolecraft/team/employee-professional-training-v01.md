# 十五岗位基础职业素养与 90 天训练方案 v0.1

日期：2026-10-14（Asia/Shanghai）  
责任岗位：`CURR`（课程架构师）  
协作岗位：`PM`（组织与状态）、`PROD`（训练项目范围与验收门槛）、`QA`（独立验收）、其余 `role_id`（练习工件与专业复核）  
状态：训练规格，待 `PROD` 冻结首个隔离训练项目及 `QA` 冻结评价表  
适用范围：下表定义的十五个稳定 `role_id`

## 1. 目标、边界与使用方式

这份方案把五类公开行业实践转成可以观察、练习和独立复验的工作行为。目标不是让员工背诵案例，而是让每个岗位在接单、决策、产出、交接和失败后恢复时都留下可重建的证据。

本方案只规定培养路径和证据要求，不修改网站、服务、数据库、教材正文、历史报告或原有八项产品门槛；不发起付费模型调用、外部发布、上传或外部联系。任何真实外部副作用仍需另行授权。

完成阅读、参加训练、填写模板、代理会话次数、一次成功演示或自评正确率，都不能单独证明职业胜任、就业结果、真人专家认可、真实学习效果或行业先进。训练结束只允许报告“在本方案范围内，哪些能力有独立证据、哪些仍未测或未通过”。

首轮执行顺序固定为：`PROD` 冻结训练问题和验收 ID → `CURR` 发放本方案与岗位任务 → 学员完成练习 → 专业 `role_id` 复核作品 → `QA` 独立抽查、复现和盲测 → 责任 `role_id` 返修 → `QA` 复验 → `PM` 汇总状态。`QA` 不代写正文、代码、设计或需求；作者不自审自己的最终通过结论。

## 2. 五个行业案例转成共同职业素养

下表是训练时使用的机制映射。公开材料是设计启发和组织自述，不是对其实际效果的第三方证明；每个岗位仍要用本项目证据验收。

| 案例输入 | 可迁移的工作机制 | 十五岗的可观察行为 |
|---|---|---|
| 丰田生产方式（TPS） | 标准作业、在当前环节制造质量、异常立即停止、现场确认、持续改善 | 先按任务合同和清单做小批次；发现错版本、缺输入或风险时暂停交接；保留现场事实和改进动作，不把问题推到下游 |
| Google SRE | 服务目标、错误预算、可靠性优先、无责复盘、用数据决定是否继续发布 | 将成功、失败和未知分开；高风险缺陷或错误预算耗尽时停止扩展；复盘系统逃逸点而非只责备个人 |
| Microsoft SDL | 从需求、威胁/风险建模、设计、实现、验证到响应的生命周期门禁 | 任务开始先列风险和权限；每阶段交版本、环境、反例和限制；安全、隐私、数据损坏和核心事实错误未关闭时不能交付 |
| GitLab DRI | 一个最终责任人（DRI）、咨询者和知情者分开，责任可追踪 | 每个工件指定唯一写入所有者、接收者和升级人；征求意见不等于转移责任；冲突由 `PM` 协调，不能多人共同拥有而无人负责 |
| GOV.UK 服务标准 | 从用户需要出发，简单可用、可访问，尽早并持续用真实/代表性用户测试 | 交付前说明用户任务和不做范围；设计、内容和功能都覆盖空态、错误、辅助技术和理解风险；用观察到的用户行为，不以内部感觉代替 |

### 2.1 基础职业素养十项最低标准

每项都必须通过行为和工件观察，不能用口号或平均分抵消关键缺口。

1. **目标和验收先行**：接单前能说清用户/内部场景、目标、非目标、输入输出、版本、成功/失败/未知和停止条件。
2. **唯一责任和边界**：知道自己能决定什么、必须交给谁、哪些决定需要升级；不越界改需求、代写他岗产物或自行宣布验收。
3. **标准作业可重建**：按固定步骤、冻结夹具和小批次执行，记录环境、命令/操作、输入、输出和变更，使他人能重做。
4. **证据与版本诚实**：事实、推断、模拟、静态检查、实际运行、真人反馈和未验证项分栏；来源、哈希、时间和适用范围可定位。
5. **当前环节制造质量**：交接前完成领域自查和反例检查；发现 P0/P1 或关键前置缺失时停线、拒收或升级，不把问题留给下一岗。
6. **异常与恢复**：能处理超时、无匹配、权限不足、重复请求、错版本、部分输出、取消、恢复失败等状态；保留原始失败轨迹，说明是否恢复。
7. **结构化交接**：接收方能只靠交接包重建上下文；接收方可明确签收、拒收或列补件，不以口头“说过了”作为证据。
8. **用户和可访问性**：从可完成的用户任务检验内容、界面和流程；覆盖理解、键盘/辅助技术、空态、错误和反馈状态；不把内部演示当真实用户证据。
9. **安全、隐私和最小权限**：不输出密钥、私有记录或无授权数据；权限、租户、数据保留和外部副作用不明确时停止并升级。
10. **复盘和持续改进**：缺陷记录直接原因、系统原因、逃逸门禁、修复版本、原例复验、受影响范围和残余风险；重复三次同类错误必须改流程、夹具、工具或训练。

### 2.2 阻断行为

下列任一行为出现，任务直接标记为“未通过/暂停”，不以其它优点抵销：伪造运行、来源、用户反馈或专家审核；隐瞒错版本、失败或权限问题；绕过唯一责任岗位；删除首轮失败记录或降低门槛来获得通过；在 P0/P1 未关闭时继续对外副作用；将未验证内容写成已验证结论。

## 3. 能力分级与授权

能力层级按“知识、执行、判断、交接”四维分别记录；不计算一个综合平均分。关键维度（证据/版本、失败/恢复、边界/交接）未达标，不能晋级。为与产品和独立 QA 的记录一致，本方案只使用 L0–L3；`level_A` 用 A0–A3 一一映射，A4 只作为 90 天后的导师扩展。

| 层级 | 观察标准 | 允许范围 | 最低证据 |
|---|---|---|---|
| L0 认识/受指导 | 能复述岗位职责、输入输出、禁区、十项标准和三个常见反例；按示例和逐步指导完成练习 | 只能阅读、口述和跟随示例；不独立写入真实项目 | 边界反例口试/书面解释；指出应停止或升级的位置；关键边界答错继续留在 L0 |
| L1 边界清楚的小任务独立交付 | 在冻结合同和清晰边界内，独立完成低风险单岗位小任务，主动标记缺项和求助点 | 合成或隔离数据、单岗位小工件；不得自行扩范围 | 两个不同夹具工件均可重建；每个有 EvidenceCard 和一次相邻岗位接收/拒收；无阻断行为 |
| L2 处理歧义/失败的独立交付 | 面对歧义、冲突或失败先澄清和建风险，再完成交付、恢复/升级、交接、返修和复验 | 隔离的真实形状任务、有限内部数据；可拒绝前置不满足的任务 | 一个端到端任务 + 一个陌生变体；失败演练可重放；接收方签收或有证据拒收；独立复核通过 |
| L3 一次跨岗产品切片 | 在跨岗依赖和不完整信息下完成一次产品切片，获得真实内部使用反馈，依据反馈完成一次迭代并说明限制 | 只限本项目授权的跨岗隔离环境和内部反馈；仍需按权限矩阵执行 | 跨岗切片版本、反馈原始记录、迭代差异、独立 QA/专业复核；不得把内部反馈写成外部用户或行业证据 |

`level_A` 映射为：L0=A0、L1=A1、L2=A2、L3=A3。A4 仅在本 90 天周期之后，凭两个不同场景的 L3 证据、经复验的团队改进和带教记录申请“导师扩展”，不纳入本轮基础验收。晋级是授权决定，不是永久标签；连续两轮同类缺陷、环境变更、岗位变化或证据过期，都可退回较低层级。L3/A3 也不等于真人专家、职业资格或行业先进。

### 3.1 每级通用证据包

每位员工每轮只需提交一个统一 `EvidenceCard` 索引，但必须链接完整原始证据。字段名固定，显示名称可以翻译，不能用口头说明替代缺失字段：

```text
evidence_id / checkpoint / blind_case_id / role_id / role_label / level_L / level_A
task_id / task_contract_version / acceptance_id / DRI / handoff_recipient
scenario / scope / non_goal / risk_level / authorized_tools / permission_scope
input_fixture_id / input_fixture_hash / source_versions_and_hashes
worker_session_id / reviewer_id / test_date / environment / command_or_ui_path
expected_success / expected_failure / expected_unknown / stop_condition / rollback_condition
observed_steps / duration / raw_outputs / output_artifact_hash
normal_result / boundary_result / failure_result / recovery_result / wrong_version_result
decisions_and_tradeoffs / source_and_version_bindings
handoff_status / acceptance_or_rejection_reason
counterexample_result / defect_ids / direct_cause / system_cause / escaped_gate / severity
first_failure_preserved / repair_version / retest_version / retest_method / regression_scope
conclusion / residual_unknowns / limits / next_step / evidence_links
```

`level_L` 必填 L0–L3，`level_A` 必填 A0–A3；尚无足够证据时使用结论 `insufficient_evidence`，不能猜测等级。

## 4. 稳定 role_id 别名与十五岗位分组

训练、EvidenceCard、独立测试和项目状态统一使用下表 `role_id`。中文岗位名只用于阅读；不得因简称、空格、翻译或下划线变体产生第二个岗位身份。

|---|---|---|
| `PM` | 项目经理 | 范围、依赖、状态、交接与复盘协调 |

| `QA` | 测试工程师 | 独立测试、复现、缺陷与验收证据 |

允许值固定为：`PM`, `PROD`, `CURR`, `DES`, `FE`, `QA`, `ED`, `AI`, `BE`, `UR`, `COMP`, `PRACT`, `OPS`, `REV`, `RETR`。EvidenceCard、缺陷台账、交接包和独立测试报告必须使用这些值。

训练按领域分成四个小组；QA 横跨四组但不代替任何组的专业判断。每个岗位在 **D1–30** 完成 L1 作品，在 **D31–60** 完成 L2 受限任务，在 **D61–90** 参与一次跨岗产品切片，收集真实内部反馈并迭代，形成 L3/A3 候选。A4 导师扩展另行安排。

## 5. 90 天训练节奏

每周固定节奏：周一由 `PM` 冻结本周任务合同和唯一责任人；周二至周四练习/实现；周五由相邻专业 `role_id` 复核，`QA` 抽查或实测；周末记录失败实验室和下一周补学。所有练习使用隔离数据和授权工具。

### 5.1 主节点

| 主节点 | 时间 | 目标与出口 |
|---|---|---|
| D0 | 开始前的冻结日 | QA 冻结合同、夹具、环境、角色边界和历史缺陷；完成每岗 L0/L1 基线诊断，不把基线当通过 |
| D1–30 | 第 1–4 周 | 完成共同核心和两个边界清楚的小任务；形成 L1/A1 证据，关键维度有证据且无阻断缺陷 |
| D31–60 | 第 5–8 周 | 在受限真实形状任务中处理歧义、失败和跨岗交接；形成 L2/A2 证据，原例和陌生变体均可复验 |
| D61–90 | 第 9–13 周 | 完成一次跨岗产品切片，获得真实内部反馈并完成一次迭代；具备 L3/A3 候选证据，A4 不在本周期内 |

`D0` 是训练前的独立基线节点，D1–30、D31–60、D61–90 是训练与复验主阶段。周任务如下标明归属；若阶段门未通过，后续周任务只用于补学，不得用时间经过自动晋级。

|---|---|---|---|---|
| D1–30 | 第 1 周（1–7） | 基线与角色边界 | 全员完成 L0 诊断；`PM` 建立任务/责任/版本索引；`QA` 执行 D0 基线的收尾与反馈 | 角色卡、禁区清单、三个边界反例；QA 只记录基线，不作能力结论 |

| D1–30 | 第 3 周（15–21） | 证据、版本、安全 | 研究/内容岗位做来源绑定；工程/检索岗位做版本和权限夹具；设计补无障碍输入 | 证据台账、版本哈希、最小权限包、来源—主张矩阵；QA 复核是否把模拟写成实测 |

### 5.2 各阶段的练习比例

- **0–30 天：熟悉夹具 60%、边界/失败 20%、交接 20%**，目标是从 L0 到 L1，不追求速度。
- **31–60 天：受限真实形状任务 40%、跨岗交接 30%、失败/成本/可访问性 30%**，目标是形成一个可复验 L2 样本。
- **61–90 天：陌生任务 25%、跨岗产品切片 30%、真实内部反馈与迭代 20%、独立复验 15%、复盘和带教 10%**，目标是判断是否有 L3/A3 证据，而非制造“全员通过”叙事。

## 6. 跨岗交接训练合同

所有交接使用同一模板。接收方必须先复述目标、版本、状态、验收和未知，再选择“接收 / 拒收并列补件 / 升级”。

```text
handoff_id / task_id / sender_role_id / receiver_role_id / DRI / escalation_role_id
目标、用户/内部场景、非目标、验收 ID、停止条件
输入、来源、版本、哈希、环境、权限与允许工具
输出工件及逐项证据；正常、异常、恢复、未运行、未知状态
已知限制、风险、成本/耗时、隐私与外部副作用
接收复述；接收、拒收或补件理由；返修版本与原例复验
```

90 天至少完成以下接口实验，每个接口都要有一次拒收和一次补件：

1. `PROD` → `CURR`/`DES`：同一需求分别转成学习目标和可操作流程，禁止偷偷扩大范围。
2. `CURR` → `ED`/`PRACT`：把能力目标转成正文、练习和可观察量规；`PRACT` 可拒绝不可观察标准。
3. `DES` → `FE`：交正常、空态、错误、焦点、响应式和无障碍状态；工程师反馈可行性，不改产品目标。
4. `ED` → `REV`：交正文、来源、版本、反例和未验证主张；`REV` 给缺陷，不替作者改写。
5. `AI`/`RETR` → `BE`/`FE`：交模型、来源、版本、超时、无匹配和降级合同；候选不等于核实答案。
6. `BE`/`FE` → `QA`：交可运行版本、隔离数据、配置、命令和已知限制；测试独立复现。
7. `UR`/`COMP`/`OPS` → `PROD`：交原始证据、比较条件、估算/实测边界；不替产品做范围决定。
8. `QA` → `PM`/责任 `role_id`：交复现、严重级别、残余风险和复验要求；`PM` 分派，责任岗修复。

## 7. 独立测试与验收安排

本节是给 `QA` 的执行交接；`QA` 应在首轮开始前把评分表、抽样数和严重级别冻结，并在报告中记录实际采用的版本。以下目标值是训练建议，不改变产品门槛；若 `PROD` 或 `QA` 冻结了不同口径，以已冻结口径为准并保留差异。

### 7.1 测试节奏

- **D0 基线（训练开始前）**：每岗抽取一项近期工件和一个合成反例，记录错误类型、逃逸门禁、证据完整性和环境；不把基线当作员工结论。
- **周检（第 2–12 周）**：每周每组至少一件工件由相邻专业岗复核；QA 至少独立重做一个关键反例，核版本、运行、内容/用户证据边界和交接字段。
- **阶段门（D1–30、D31–60）**：`QA` 分别出 L1/A1、L2/A2 证据状态；未通过项有责任 `role_id`、返修版本和复验日期，不以补报告关闭。
- **终评（D61–90，第 85–90 天）**：`QA` 从未参与作者任务的夹具生成盲测变体，观察过程、检查工件、复现关键行为、核独立交接和复盘；切片必须有真实内部反馈和至少一次迭代。内容岗另由非作者复核论证，`QA` 岗的产物由 `PM` 指定其他合格测试观察者核查。

### 7.2 终评通过条件（建议冻结项）

1. 十项共同标准逐项给出“达标 / 部分达标 / 未达标 / 未测”；证据、版本、失败/恢复、边界/交接四项为阻断维度。
2. P0/P1 缺陷为零；P2 必须有责任人、风险、复验日期和是否允许带缺口交付的明确决定；P3 可排期但不得删除。
3. 每人至少有两份 L1/A1 工件、一份 L2/A2 端到端工件和一份未见变体；D61–90 再有一份跨岗 L3/A3 产品切片，含真实内部反馈、迭代差异和独立复验；各项均有专业复核、独立测试或实训观察证据。
4. 训练目标值可用于比较但不单独授予能力：建议首轮接收率 ≥70%、交接字段完整率 ≥90%、重复同类缺陷相对基线下降 ≥30%；若实际样本不足，报告“未测”，不补造分母。
5. “可独立接单 / 需指导 / 暂不接单”按证据决定；不报告泛化为职业认证、就业概率、行业先进或真实用户满意。

### 7.3 缺陷与复验

缺陷至少记录：缺陷 ID、岗位、任务/版本、实际现象、预期、复现步骤、严重级别、直接原因、系统原因、逃逸门禁、责任人、修复版本、原例复验、受影响回归、残余风险。连续三次同类错误必须升级为流程、夹具、工具或训练专项；“粗心”不能作为唯一根因。

## 8. 每周失败实验室与复盘模板

每周选一条真实或隔离缺陷，先由学员独立复现，再回答：

1. 当时目标、门槛、输入和成功/失败/未知是什么？
2. 第一个错误发生在理解、合同、证据、实现、交接还是外部环境？
3. 哪一个门禁本应发现？为什么没有发现？
4. 是否需要停线、拒收、升级、回滚或补充权限？实际做了吗？
5. 修复改变了什么工件/流程/夹具/工具？旧版本和首次失败是否保留？
6. 原例、受影响范围和陌生变体如何复验？哪些仍未验证？

复盘输出必须包含责任 `role_id`、截止条件和下一次检查日期；“已复盘”不是关闭状态。`PM` 维护行政状态，专业 `role_id` 维护领域修复，`QA` 维护独立结论。

## 9. 90 天结束时的交付与限制

`PM` 汇总一张十五 `role_id` 状态表：岗位、训练版本、各层级证据、独立测试结论、未通过项、责任 `role_id`、返修/复验、建议授权和仍需用户/真人专家/生产/市场证据。`CURR` 更新补学路径；`QA` 出具独立验收报告；岗位负责人不得把自己的自查报告当最终结论。

本文件完成只表示训练方案可执行，不表示员工已达标。只有在独立测试实际执行、原始证据可定位、返修和复验闭环后，才能对某一岗位和某一授权范围给出局部“在本方案范围内达标”。原有八项产品门槛、真实用户效果、真人专家审核、行业对比、生产经济性和学员职业能力仍须分别取得证据。
