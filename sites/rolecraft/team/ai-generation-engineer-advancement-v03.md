## 4. 分阶段学习与产物

### 阶段 A：D0 收口与 L0→L1 准入（第 0–14 日）

学习主题：

- 共同基础：任务合同、证据账本、版本/hash、停止/升级和交接。
- AI 生成机制：规则降级、结构化输出、来源绑定、工具契约、人工 gate。
- 故障机制：schema、空工具、重复回调、超时、旧 checkpoint、来源冲突和租户拒绝。
- 外部主张：LangGraph/课程/API/模型费用和版本必须区分理论来源、运行观察和未验证项。

练习与作品：

1. E-AI-L0-001：重写 v0.4 的状态合同。学习者逐项解释 tenant、source_refs、schema_version、external_action、status 和停止条件；不得只复述代理报告。
2. E-AI-L0-002：第二套 sandbox。替换文档形状、字段命名和工具返回顺序；至少注入 schema 错、来源冲突、超时和重复回调中的三项。
3. E-AI-L0-003：方案取舍卡。针对同一内部教材检索任务，在固定工作流、规则降级和图 Agent 中选一个初始方案，写出用户问题、质量/成本假设、停止线和何时拒绝使用图框架；不要求实现或外部调用。
4. W-AI-L1-001：生成服务契约包。包含输入/输出 schema、工具契约、来源四元组、状态迁移图、失败矩阵、版本和未运行项。
5. U-AI-L0-001：由非作者冻结，仅改变 checkpoint 短暂不可用或工具不幂等其中一项；学习者写出新假设、停止/降级策略和需重测指标。

阶段失败实验：

- 未授权租户或来源：生成前拒绝，不能把错误写成无来源答案。
- 空工具结果、超时、迟到回调：停止顺序、有界重试和重试耗尽。
- 重复回调：持久 callback_id 记录；若无法证明持久性，状态标为 insufficient_evidence。
- 部分输出/旧 checkpoint：丢弃不完整草稿，从可信工具结果重放。
- schema/来源冲突：交接前失败，保留首次 malformed payload。

L0→L1 准入条件：

- 五项 D0 原始回答和上述两个沙箱工件均有 EvidenceCard。
- D1–D5 至少有可复核初步证据；`E-AI-L0-003` 必交，且必须提供一条 D6 用户问题—质量/成本假设—停止线—方案取舍证据；D7 有计划和一次留出尝试。
- 两套夹具原例、受影响回归和留出任务均可重建；无未关闭 P0/P1。
- 内容审校员确认机制/来源/版本措辞；测试工程师确认运行、失败和迁移证据；接收岗位签收或有据拒收。
- 任何未运行真实运行时、模型、云服务或人工 gate 必须显式标注 not_run，不阻断 L1 的沙箱资格，但不得写成真实能力。

未满足时保持 L0_guided；不得以 v0.4 代理报告或课程观看记录授予 L1。

### 阶段 B：L1 受指导贡献（第 15–30 日）

学习主题：

- 在固定工作流与 LangGraph 图之间做选择；循环上限、人工介入和可观测性。
- 受限模型适配：离线模型或批准的临时 API，超时、限流、成本上限和安全过滤。
- 声明式来源：claim_type（机制/版本/观察/假设）、段落或文档定位、hash 和复核日期。
- 接口交接：把生成结果交给客户端/后端/内容审校，明确谁复核什么。

练习与作品：

1. U-AI-L1-001：L1 阶段独立留出迁移任务。非作者冻结一个新 fixture，只改变一个约束（回调顺序、来源版本或工具可用性三选一），学习者需重写假设、停止/降级策略与需重测指标；使用全新 EvidenceCard `EC-U-AI-L1-001`，不得复用 `U-AI-L0-001` 或其卡片。

2. E-AI-L1-001：在本地无网络条件下实现或绘制固定工作流基线和一条图工作流；两者用同一输出合同，比较可预测性、循环风险和调试成本。
3. E-AI-L1-002：独立运行 schema/来源/安全检查器；故意提交 malformed payload、冲突来源、空答案和额外键，记录首失败和修复差异。
4. W-AI-L1-002：小型生成适配器包。包括模型/规则模式选择、超时/重试、预算计数、来源绑定和人工 review-only handoff；无外部发送。
5. H-AI-L1-001：跨岗交接包，交给 QA 和后端数据工程师，接收方可拒收缺少字段或版本的产物。

L1 保持条件：

- 至少两个不同沙箱场景持续通过，指导人不逐步提示关键判断。
- 一次失败恢复和一次拒收/补件已完成；首次失败仍保留。
- 领域作品的外部 claim、版本和许可字段完整；不可访问或动态信息标记为 unknown。
- 独立 QA 无未关闭 P1；内容审校无未关闭来源/机制 P1。
- L1 仅允许低风险、隔离、可回滚任务；不授真实生产写入或无监督模型调用。

### 阶段 C：L1→L2 的真实形状隔离任务（第 31–60 日）

学习主题：

- 真实形状数据的最小权限、脱敏、数据保留和可回滚。
- 真实进程重启、耐久 checkpoint、幂等键、竞态和恢复目标；若无真实存储，记录替身限制。
- 模型质量和运营指标：事实性/来源覆盖、结构化通过率、拒答正确率、P95 延迟、token/费用、重试率、人工升级率。
- 评估设计：黄金样本、反例、留出集、版本锁定和变更影响。

练习与作品：

1. E-AI-L2-001：受限真实形状生成任务。使用脱敏或临时数据，接入已批准的本地模型或隔离 API；每次调用记录模型版本、预算、输入输出哈希和 external_action。
2. E-AI-L2-002：真实进程重启/持久恢复演练。强制进程结束后从耐久 checkpoint 恢复；验证重复回调只保留一个结果，记录 RPO/RTO 或明确 not_measured。
3. W-AI-L2-001：检索增强生成服务包。包含检索来源、claim 四元组、模型适配、schema、权限、重试、人工 gate、观测指标和回滚说明。
4. W-AI-L2-002：质量—成本—延迟评估报告。对规则、离线模型和批准模型（若可用）分别记录结果，不把课程/模型宣传当运行事实。
5. U-AI-L2-001：非作者冻结的陌生任务，只改变一个约束（例如来源版本升级、预算减半或工具不可用）；学习者须重写假设并说明哪些指标必须重测。
6. H-AI-L2-001：跨岗正式交接包，接收岗位可在隔离环境按命令复跑；未通过则有据拒收。

L2 准入条件：

- 一个隔离真实形状任务、一个留出变体、一次失败恢复和一次跨岗接收均有独立证据。
- 真实运行时和模型的实际状态如实记录；若模型/API不可访问，不能以离线替身直接判定 L2，需保留为 L1 或 insufficient_evidence。
- schema、权限、来源、人工 gate 和 external_action 检查在生成/交接前执行；无未关闭 P0/P1。
- QA 复跑原例、最差案例、受影响回归和未知变体；内容审校逐条核主张、版本、许可和适用边界。
- 产品经理确认任务合同和内部授权；后端数据工程师确认持久性/账户边界（涉及数据库时）；接收岗位完成签收。
- L2 只表示可在有边界、可回滚的内部真实任务独立交付，不等于生产无监督权限或职业认证。

### 阶段 D：L2 稳固与 61–90 日迁移

学习主题：

- 两项约束同时变化时分辨优先级和停止线。
- 供应商失败、模型升级、成本超限、权限变更和来源漂移的组合恢复。
- 复盘、教会他人和改进评估夹具；把改进交给 QA/内容审校复验。

练习与作品：

- U-AI-L2-002：版本冲突 + 工具不可用的双约束未知任务。非作者冻结；记录提示次数、决定树、首次失败和最终未测项。
- E-AI-L2-003：把一次真实失败转成新的离线反例夹具，交由 QA 盲测。
- W-AI-L2-003：90 日能力快照，包含连续两轮证据、最差案例、返修差异、内部反馈和下一周期计划。
- C-AI-L2-001：辅导一名同岗或相邻岗位执行者重建产物；辅导者不得代执行，保留提问和拒收记录。

L2 稳固条件：

- 两个不同情境连续有合格证据；最差案例已复验；无未关闭 P0/P1。
- 能说明可迁移原则和必须重测的供应商/版本/费用事实。
- QA、内容审校及接收岗位独立记录；作者不能自审晋级。
- 缺真实用户/生产/外部专家证据时，保持 L2 或 lower，不得宣称 L3/L4。

## 5. EvidenceCard 合同

每个 D0、练习、作品、失败实验和迁移任务各自一张卡；卡片不可用新版本覆盖旧卡。必填字段如下：

| 字段 | 要求 |
| --- | --- |
| card_id / card_version | 稳定 ID、版本和创建/更新时间 |
| role_id / owner / reviewer | AI；执行人；内容审校员、测试工程师及按需的后端/接收岗位；作者不得担任独立 reviewer |
| diagnostic_id / exercise_id / exercise_version | 绑定 D0-AI-20261015-001 或新任务 ID；版本变更新建卡 |
| level_target / capability_dims | L0、L1 或 L2，以及 D1–D7 观察维度 |
| purpose / user_scenario / non_goals | 要练的机制、问题形状和不做项 |
| prerequisites / resource_refs | 先修、PLR-AI-006、教材/课程版本和来源限制 |
| contract_hash / fixtures_hash | 任务合同、身份、权限、输入和夹具哈希 |
| environment | OS、运行时、包/API/模型版本、网络、模型模式、预算 |
| inputs / authorization | 数据来源、租户、允许工具、人工 gate、external_action 预期 |
| expected_normal / expected_boundary / expected_failure | 正常、边界、失败的可观察断言 |
| output_schema / schema_version | 允许/必需键、字段类型、枚举、来源引用规则 |
| source_refs | document_id、source_version、location、hash、hash_type、claim_type、recheck_at、access/ACL 状态 |
| run_receipts | 命令、开始/结束时间、输入输出哈希、调用数、token/费用、P50/P95、重试和状态序列 |
| first_failure / stop_record | 首失败代码、payload/日志哈希、停止/拒收/升级决定和时间 |
| repair_diff / regression | 返修版本、原例复验、受影响回归、未关闭风险 |
| transfer_case | 非作者冻结、只改变的约束、学习者计划/实际、提示次数、迁移结论 |
| handoff / signoff | 接收岗位、复验命令、签收或有据拒收；无签收不能写交接通过 |
| independent_review | 内容审校结论、QA 结论、复核版本/哈希、缺陷 ID |
| decision / limitations / next_action | pass、pass_with_limitations、fail 或 insufficient_evidence；限制、责任人、日期和复验方法 |
| external_action | 明确为 null、approved_test_only 或实际授权动作；不得省略 |
| learner_raw | 原始回答、原始工件和自评；禁止用代理输出代替 |

EvidenceCard 的来源、版本、权限、external_action、首次失败和复核状态缺一即为 insufficient_evidence。卡片可以记录未运行；未运行必须写明原因，不得作为通过证据。


## 5A. 练习—缺口—闸门机器可读交接

本版本新增 `practice_crosswalk`（同步写入 v0.3 JSON），固定“缺口→练习→EvidenceCard→阶段闸门→独立复核”链。`E-AI-L0-003` 是 L0→L1 必交 D6 证据；Stage B 使用全新 `U-AI-L1-001`，不得以 `U-AI-L0-001` 重复计数。crosswalk 中的 `required_for_gate=true` 只表示证据必交，不表示训练已执行或等级已授予。

## 6. 独立复核与职责分工

| 工作 | 责任 | 独立复核 |
| --- | --- | --- |
| 任务范围、用户场景、预算和授权 | 产品经理与 AI 生成工程师共同冻结 | 项目经理检查交接完整性 |
| 学习主题、练习、量规和先修 | 课程架构师 | 内容审校员检查机制与来源边界 |
| 代码/配置/模型适配/返修 | AI 生成工程师 | 测试工程师复跑，不代写 |
| 账户、权限、持久存储和恢复 | 后端数据工程师（涉及其领域时） | 测试工程师复验，保留后端意见 |
| 理论主张、版本、许可、引用 | 内容审校员 | 课程架构师不能审校自己的正文；QA核可复验性 |
| 运行、失败、迁移、性能和可重建性 | 测试工程师 | 项目经理只汇总，不改变结论 |
| 接收、拒收和晋级决定 | 接收岗位/项目经理按门槛记录 | 作者不得独立签署自己的晋级 |

复核顺序固定为：冻结合同和夹具 → 学习者执行 → 内容审校与 QA 分开复核 → 原例复验 → 受影响回归 → 留出/未知复验 → PM 汇总。任何报告完成都不自动关闭失败或授予下一层。

## 7. 停止、退出与降级条件

触发任一条件立即停止当前任务，保存首失败，禁止生成/交接/外发，通知责任人：

1. 读取非授权租户、私有来源、真实密钥或真实用户数据。
2. 未批准的模型、付费 API、云服务、外部写入、发送或发布。
3. source_refs 缺失、版本/位置/hash 不明、来源冲突未解决、生成答案超出来源。
4. schema 类型/版本/枚举错误，或无法证明回调幂等和 checkpoint 完整性。
5. 真实模型输出含敏感信息、提示注入、越权工具请求、危险建议或无法人工复核。
6. 预算、费用、延迟、限流、重试次数或数据保留超出任务合同。
7. 进程/存储恢复后的状态、哈希或 callback 结果不一致。
8. 夹具、环境、包版本、模型版本或任务合同在运行后被未记录地改变。
9. 学习者无法解释关键机制，完全依赖提示，或未知任务只复现原题。
10. QA/内容审校发现 P0/P1，或接收方有据拒收。

停止后状态只能是 fail 或 insufficient_evidence；返修必须保留首次失败并按原例→回归→未知顺序复验。重复触发同一阻断三次仍无外部状态变化时，由项目经理登记 blocked，不能降低门槛。

## 8. 30/60/90 日节奏与晋级闸门

| 时间 | 学习与执行 | 必有证据 | 闸门与结果 |
| --- | --- | --- | --- |
| D0–D7 | 完成五项学习者诊断、边界/机制补学、卡片模板训练 | learner_raw、D0 EvidenceCard、补学计划 | 缺任一原始证据则 L0_guided |
| D8–D14 | 第二沙箱、四类失败实验、一个一约束迁移 | 两个沙箱工件、失败/停止、留出卡 | 内容审校+QA均无 P1 才进入 L1 试运行 |
| D15–D30 | L1 受指导小任务、固定/图方案比较、一次交接与拒收 | W-AI-L1-001/002、H-AI-L1-001、原例回归 | D30：满足两沙箱+七维初步证据→可建议 L1；否则保持 L0 |
| D31–D45 | 真实形状隔离任务预演，确定权限、脱敏、预算和回滚点 | 临时账户/数据证明、合同、风险清单 | 缺授权/预算/回滚则不进入真实形状 |

## 9. 退出条件与非声明

本方案达到的是训练规格完成，不代表实际训练已完成。进入下一阶段的最低规则：

- L0→L1：两个 sandbox、学习者原始 D0、失败/迁移、独立 QA 与内容复核、无未关闭 P1。
- L1→L2：隔离真实形状任务、留出变体、真实或明确限定的恢复证据、质量/成本/延迟记录、跨岗签收、无未关闭 P0/P1。
- L2→更高层：两个周期/情境连续证据、最差案例复验、他人可复用、额外真实用户/同行/专家/生产证据。

当前决定保持 L0_guided、D0 not_assessed、L1 not_granted。若真实 LangGraph/API 或模型无法安全、合法、可负担地访问，训练可继续用本地替身完成机制学习，但不能把替身证据升级为真实运行证据。所有旧 D0、QA、审校和失败记录继续保留；新一轮只新增版本化卡片和复核报告。
