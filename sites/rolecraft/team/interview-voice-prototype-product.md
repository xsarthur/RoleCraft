# 面试语音回答原型产品交接

版本：`interview-voice-prototype-0.1`  
日期：2026-10-15（Asia/Shanghai）  
责任岗位：产品经理  
状态：**可点击演示范围冻结，待设计、客户端实现与独立 QA**

## 目标与本轮结论

用户希望在面试题中先口述回答，再看到针对回答的分析。本轮先交付一个可点击原型，让用户能完整走通“题目 → 录音中 → 录音完成 → 转写 → 分析 → 复练”的体验。原型用于验证页面关系、状态反馈和用户是否理解下一步；它不证明录音、语音识别、AI 分析或实际学习效果已经实现。

本轮固定为当前单职业 **AI Agent 开发者**，从已有题目详情进入。首个演示题使用稳定题号 `Q1`（“如何界定 LLM Agent？你会用哪些可观察行为区分它与普通聊天应用？”），参考分析只展示现有 v12 教材绑定的来源卡，不新写教材答案。若工程需要其他题作视觉占位，必须仍使用已有题目 ID 和来源，不得编造市场频率或个人经历。

## 演示入口与页面结构

入口放在现有题目详情的回答区，主按钮为 **“口述回答（原型演示）”**。不新增主导航，不改变课程、题库、记录和账户结构。点击后进入独立的面试回答工作台；浏览器地址应能保存当前题目和演示步骤，刷新/后退不应把用户送回无关首页。

页面固定为一条主路径：

```text
题目详情
  → 录音准备
  → 录音中
  → 已录音（试听/重录）
  → 转写确认
  → 分析中
  → AI教练反馈
  → 再答一次 / 返回题目
```

页面顶部持续显示题号、题型、当前步骤和 **“原型演示 · 不会上传录音”** 标签。演示标签必须在整个流程可见，不得只放在设置或页脚。

## 冻结的页面状态与交互

### 1. 录音准备（`ready`）

- 显示完整题面、预计回答时长（建议 90 秒）和简短提示“先独立组织观点，再开始口述”。
- 主操作：`开始演示录音`；次操作：`改用文字回答`、`返回题目`。
- 可见说明：这是演示数据，当前不会请求麦克风权限、不会保存音频、不会调用外部服务。
- 点击主操作只进入 `recording`，不弹真实权限框。

### 2. 录音中（`recording`）

- 显示可识别的录音中状态：红色圆点/动效、已用时、暂停和结束按钮；暂停后进入 `paused`，继续可回到 `recording`。
- 波形是视觉占位，不能暗示设备已经采集到真实音频；旁边保留“演示波形”短标签或等价图标说明。
- `结束演示录音`进入 `captured`，使用本地固定示例时长和文本；不得产生真实音频文件。

### 3. 暂停（`paused`）

- 保留已用时和“已暂停”状态，提供 `继续`、`结束并查看转写`、`放弃本次`。
- 放弃回到 `ready`，清除本次临时演示状态；不可显示“已保存”。

### 4. 已录音（`captured`）

- 显示试听控件，但播放的是固定演示音频或无声占位；明确标注“演示播放”。如果客户端不提供占位音频，则显示不可播放的试听卡和同等明确说明。
- 操作：`查看转写`、`重新录音`、`删除演示记录`。
- `重新录音`回到 `ready`；`删除演示记录`回到 `ready`并显示已删除的本地演示状态。

### 5. 转写确认（`transcript`）

- 显示可编辑转写文本；固定示例应包含一句有价值回答、一个可见缺口和一个填充词/停顿提示，便于观察分析卡如何引用。
- 低置信词用非颜色的标记（如下划线或“待确认”标签）；提供 `修改转写`、`确认并分析`、`返回录音`。
- `确认并分析`进入 `analyzing`；原型只读取本地 fixture，不上传文本或音频。

### 6. 分析中（`analyzing`）

- 显示分阶段的轻量反馈：`读取转写` → `对照题目要求` → `生成练习建议`，不显示真实模型名称、token、调用费用或虚假百分比。
- 演示等待应可跳过或在短时内完成；若用户刷新，恢复到 `transcript` 或明确“演示结果未保存”，不能卡在永久加载。

### 7. AI 教练反馈（`feedback`）

反馈页按用户行动顺序固定为：

1. **先做得好的地方**：最多 2 条，必须引用转写中的可见内容。
2. **下一次要补的地方**：最多 3 条，每条是具体可执行动作（例如补充“新观察如何改变下一步”），不输出录用概率或人格判断。
3. **表达观察**：只显示可从演示 fixture 直接观察的时长、填充词或结构提示；不根据口音、性别、情绪或声音推断能力。
4. **教材依据**：列出 `textbook-v12` 的实际小节、摘录和“阅读本节”入口；推荐与原文不匹配时显示来源校验失败，而不是补写答案。
5. **面试官追问**：一个固定追问，点击可进入下一次口述；追问必须来自当前题目数据或产品 fixture，不能声称是真实企业原题。
6. **下一步**：主按钮 `再答一次`，次按钮 `查看关联教材`、`返回题目`。

页面明确写出：**“这是原型中的示例分析，不代表真实 AI 已理解你的回答，也不构成能力认证。”**

### 8. 再答一次（`retry`）

- 再次进入 `ready`，保留本轮只读的“上次缺口”摘要。
- 完成第二次演示后显示前后对照：上次缺口、这次是否补到（仅按固定 fixture 展示）、下一次练习建议。
- 不显示综合分、排名、掌握率或“通过面试”结论；没有真实评估量规时不能做数值评分。

## 原型数据与能力边界

工程使用独立的 `voiceInterviewPrototype` fixture，至少包含：`questionId`、`questionText`、`transcript`、`durationSeconds`、`fillerWords`、`strengths`、`gaps`、`followUpQuestion`、`contentVersion`、`sourceSections`、`demoOnly: true`。fixture 的来源必须指向现有 Q1 和 v12 小节；不要把演示文本写入用户答案、账户数据库、教材索引或长期学习记录。

本轮**允许**：本地固定数据、可点击状态切换、视觉波形、短暂加载、转写编辑预览、来源卡、前后演示对照、页面刷新/返回的演示状态恢复。  
本轮**明确不做**：真实 `getUserMedia` 麦克风权限、音频采集或上传、ASR、真实 LLM/API 调用、云端存储、自动评分、语速/口音/情绪判断、真实面试通过判断、把示例回答写入正式复习队列、付费服务、登录/同步/发布。

如果浏览器或工程师希望接入真实录音用于技术探针，必须另开版本和产品授权；当前原型按钮不得暗中请求设备权限或把音频送出本机。

## 产品验收条件

| ID | 条件 | 通过证据 |
| --- | --- | --- |
| IVP-01 | 从 Q1 题目详情可进入原型并走通主路径 | 隔离浏览器点击记录覆盖 `ready → recording → captured → transcript → analyzing → feedback` |
| IVP-02 | 录音状态可理解且无真实能力暗示 | ready/recording/paused/captured/feedback 均有状态文字；全程可见“原型演示”，无权限框、无网络上传 |
| IVP-03 | 转写可确认并能返回修改 | 可编辑文本、待确认词标记、确认/返回/重录操作均可用；刷新不显示虚假保存成功 |
| IVP-04 | 反馈与题目来源绑定 | feedback 显示 Q1 题号、v12 版本、至少一个可点击真实小节；来源失配时显示错误态，不生成替代内容 |
| IVP-05 | 反馈指导下一次表达 | 至少 2 条优点、2 条缺口、1 条固定追问和再答按钮；不出现综合分、录用概率、能力认证或真人经历编造 |
| IVP-06 | 再答可形成可读对照 | 第二轮从 ready 开始，能看到前次缺口及固定的前后对照；不会写入正式用户记录或复习队列 |
| IVP-07 | 异常与退出诚实 | 放弃、删除、刷新、后退、无 fixture、来源失配均有可恢复状态；无永久 loading、无“AI 已分析”成功文案 |
| IVP-08 | 键盘与窄屏可操作 | 主按钮、状态、转写编辑、折叠卡和返回均可键盘到达；320–375px 宽度不遮挡结束/确认/再答按钮；焦点回到触发控件 |

以上只授 **“语音面试交互原型可点击演示”** 范围通过。它不授真实录音、ASR、AI 分析、学习效果、职业能力、真人专家认可或完整产品通过。

## 与后续真实能力的交接边界

未来真实版本需由产品、AI 生成工程师、后端数据工程师、设计师和测试工程师另行冻结：麦克风授权与撤回、临时音频生命周期、ASR 置信度、分析模型与教材来源核对、失败/超时、隐私删除、成本和异步任务恢复。真实版本不能直接把本原型的 fixture、演示状态或反馈文案当作生产结论。

产品自查：已冻结单职业入口、8 个交互状态、演示数据边界和 8 项验收条件；未修改应用代码、教材、数据库或用户记录，未调用付费模型、上传录音或进行真人用户测试。独立 QA、设计实现和真实语音能力仍待后续岗位交付。
