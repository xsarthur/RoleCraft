# 门禁主动接力（常驻）

日期：2026-10-23。用户 Sheng 明确：岗位验收通过后必须立刻主动交给下一门岗，不得等用户再追问「发给 XX 了吗」。

本文件是员工常驻流程，绑定产品设计师、测试工程师、项目经理及所有验收岗位。项目长期记忆的同一条记录在 `.workbuddy-ai/memory/MEMORY.md` 的「门禁主动接力（2026-10-23）」。

## 谁负责接力

**项目经理拥有门禁接力协调。** 设计、QA、工程执行并签发本领域结论，把结果报给项目经理。项目经理收到 Pass 后立刻派下一门，留下交接记录（目标、版本、证据位置、下一责任人）。例如设计 Pass 后，项目经理派 `core-qa-engineer`（测试工程师）做合入前功能验证。

项目经理同时做这三件事：

- 跟踪设计门与 QA 门。两门都过，合入才开放。
- 把缺陷派给修正责任人，并在修复后安排原验收岗位按新版本复验。
- 只把各部门已经通过的决策板交给 Sheng。未通过、未派发和证据不足的门留在协调记录里，不混进交给用户的已通过材料。

项目经理不代签设计、QA 或工程结论，也不代写专业交付。

## 规则

1. 当前门禁 Pass 后，签发岗位把同一版本的结论报给项目经理；项目经理立刻派下一门岗。
2. 设计签发 Pass 后，项目经理立即派测试工程师做合入前功能验证。
3. 下一门岗发现问题，走该领域的修正流程：项目经理把缺陷交给唯一修正责任人；修复后由原验收岗位按新版本复验。
4. Sheng 只验收各部门已经通过的内容。项目经理汇报时优先给决策板图片，少写长文。
5. 设计 Pass 不等于可合入。合入前必须设计门与 QA 门都过。

触发背景：PR #12 设计门通过后未主动交 QA，需用户再推一步才派测。此后同类停顿视为流程未执行。

## 设计签发与独立 QA 的边界

两条门禁分开签发，结论不能互相代替。

- 视觉表达、信息层级、状态与可访问性按 [`DESIGN_COMMUNICATION_STANDARD.md`](DESIGN_COMMUNICATION_STANDARD.md)。该规范要求设计先交可审阅画面，并写明：应用实现交软件工程师，独立复核交测试员；设计稿、脚本或自查不能代替当前应用的真实操作验收。
- 设计验收由产品设计师签发。测试/功能验收由测试工程师签发。工程交付由对应工程岗位完成并自检后报项目经理。项目经理收集这些结论、立刻派下一门、跟踪缺口，并在领域失败时把缺陷派给修正责任人；项目经理不代签设计验收、测试/功能验收或工程结论。操作边界见 [`employees/core/project-manager/ACCEPTANCE.md`](employees/core/project-manager/ACCEPTANCE.md) 与 [`employees/core/project-manager/ROLE.md`](employees/core/project-manager/ROLE.md)。
- 产品范围不含设计表面时，设计验收可记 `not_in_scope`，但必须有产品交接里的依据。没有这句依据，不能省略设计门，也不能把 QA 门写成设计已过。

## 谁在 Pass 之后立刻做什么

| 刚通过的门 | 谁签发并回报项目经理 | 项目经理立刻派给 | 下一门做什么 |
| --- | --- | --- | --- |
| 产品验收 Pass | 产品经理 | 产品设计师（范围内有设计表面时） | 按设计规范签发设计验收 |
| 设计验收 Pass | 产品设计师 | 测试工程师（`core-qa-engineer`） | 合入前功能验证；对照已签发的设计条件与产品条件 |
| 工程交付待验 | 对应工程岗位 | 当前合同里的下一验收岗 | 执行本领域验收并签发 |
| 测试/功能验收 Pass | 测试工程师 | 项目/发布总闸收口 | 仅在产品、设计、QA 三门都有记录且无未关闭阻断时，项目经理才标项目/发布通过，并把已通过决策板交给 Sheng |
| 任一验收 Fail | 该验收岗位保持失败并回报 | 修正责任人 | 修正后按新版本回到原门复验，通过后再由项目经理派下一门 |

内容审校、课程规格、检索或其他专项验收同样适用：本门 Pass 的当轮由项目经理派给产品合同里写明的下一责任人，不把「等用户问」当作交接完成。

## 合入条件

合入候选必须同时满足：

- 设计门：产品设计师对当前版本签发 Pass，或产品交接写明 `not_in_scope`。
- QA 门：测试工程师对同一版本的合入前功能验证签发 Pass，证据含原例或约定反例。
- 有问题的条目仍在修正流程中，不并入已通过结论。

只有设计 Pass、QA 尚未派发或尚未出具结论时，状态保持「设计已过、合入未开放」。项目经理继续跟踪这组双门，直到 QA 出具同一版本的结论。

## 对用户的交付

项目经理只把各部门已经通过的决策板交给 Sheng，并说明本版通过了哪一道门、证据在哪。优先用决策板图片，少写长文。未通过、未派发和证据不足的门留在协调记录中。
