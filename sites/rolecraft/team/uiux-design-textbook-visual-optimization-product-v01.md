# UI/UX 教材整套视觉优化：产品与验收合同 v0.1

日期：2026-10-16（Asia/Shanghai）  
责任岗位：产品经理  
状态：`ready_for_curriculum_design_author_and_qa_handoff`

本合同把 UI/UX 教材的视觉表达、视觉判断与视觉质量证据定义为一项跨全书的产品改进。范围覆盖 `textbooks/uiux-design-v02/` 的 24 章，以及 `textbooks/uiux-design-v03/` 的 VA01–VA04。它是产品范围和验收条件，不是教材正文、设计资产、内容审校或测试结论。

## 1. 产品目标与用户阅读场景

视觉优化的目标是让读者在阅读时看见“问题—视觉决定—状态/任务后果—验证”的关系，并能把视觉判断迁移到真实设计工作。视觉美被定义为在用户、任务、内容、品牌、媒介、可访问性和实现约束下形成清楚、协调、有记忆点的关系；它不等于装饰数量、流行风格或个人偏好。

教材需要同时保护任务可达、状态诚实、来源与风险、可访问性和工程可复现性。没有真实用户或品牌证据的图稿必须标为教学构造、设计假设或待验证，不能借静态视觉稿声称用户偏好、可用性、就业能力或行业先进。

### 1.1 主要阅读场景

| ID | 阅读场景 | 读者应能完成的判断 | 最小视觉证据 |
|---|---|---|---|
| VO-U01 | 章节入口与诊断 | 看懂本章问题、视觉变量、先修和要交的工件 | 目标/受众、输入约束、可达入口和图例 |
| VO-U02 | 机制深读 | 从同一内容的反例与修正版看出焦点、层级、比例、节奏、统一/差异、对比/和谐、语气/材质的因果 | 成对对照、标注、短文字说明 |
| VO-U03 | 状态与失败阅读 | 识别正常、等待、空、错误、拒答、来源冲突、恢复和未验证，不被颜色或动效误导 | 状态板、对象身份、动作/结果、非颜色编码 |
| VO-U04 | 跨端与长内容阅读 | 看到桌面、约 760px、窄屏、长译文、灰度、大字号、缺图/字体回退后的关系变化 | 同一工件多条件预览与限制说明 |
| VO-U05 | 练习与参考解法 | 依据 brief、约束和证据选择视觉方向，解释保留/放弃，完成 before/after 与复验 | 题面、源文件、决策表、参考分析、未验证项 |
| VO-U06 | 交付与复盘 | 把视觉规则交给工程/内容/QA，并能指出哪些尚未实测 | Token/组件/资产/版本/降级/验收字段 |

## 2. 范围与交付边界

### 2.1 纳入范围

1. v02 24 章的视觉入口、图文分工、关键视觉示例、状态/响应式对照、练习与参考解法中的视觉证据。
2. v03 VA01–VA04 的专项正文、专项工件、练习和交付说明，与 v02 章节形成可追溯交叉入口。
3. 教材内视觉资产的来源、版本、许可/字体/AI 使用记录、文字替代、可访问性提示和未验证边界。
4. 章节级导航、图注、图例、视觉变量命名、before/after 与批评记录的统一格式。
5. 仅为教学复核所需的离线渲染、灰度/缩放/窄屏预览；不将预览当成浏览器或辅助技术实测。

### 2.2 不纳入范围

- 不改写 v02/v03 的核心产品能力、章节 ID、先修、原 UX02 门槛或 VQG 量规；本合同是视觉优化覆盖层。
- 不在本文件中编写正文、绘制/替换 SVG/PNG、修改应用程序、数据库、课程工作台或发布内容；资产由设计师按交接另行产出。
- 不指定一种品牌、配色、字体、插画风格、设计工具、模型或单一审美流派。
- 不把教学构造、作者答案、AI 生成图、静态截图、点赞或自评写成真实用户理解、偏好、专家认可、就业或行业优势。
- 不替代内容审校、QA、用户研究、实训评估、浏览器/读屏/性能、工程实现、竞品实测或运营经济证据。
- 不恢复应用导航、题库、账户、外部上传、发布或付费模型调用。

## 4. 章节级视觉入口合同（v02 24 章）

每章至少提供一个视觉入口；入口可以是图、对照板、状态/流程图、可编辑源文件或明确指向 VA 工件的链接。图不得替代必要正文、题面、出处、错误原因或无障碍名称。

| 章 | 视觉入口与应表达的决定 | 推荐配图/工件类型 |
|---|---|---|
| 01 决策与证据 | 用视觉变量把“漂亮”变成可承担的决定与证据链 | 视觉 brief、证据台账、批评前后板 |
| 02 可验证问题 | 把目标、用户任务、成功条件和视觉假设分开 | brief 对照、任务焦点/噪声标注 |
| 03 研究方法 | 展示研究输入如何改变视觉方向，而非用风格先验替代证据 | 研究记录到设计决定的链路图 |
| 04 矛盾证据 | 标出冲突证据、反例和优先级如何改变层级/节奏 | 证据聚类、反例视觉批评板 |
| 05 业务对象与信息 | 让对象、导航、筛选、无结果和跨租户身份可见 | 对象地图、信息架构、无结果状态板 |
| 06 可恢复任务流 | 让正常、失败、重试、批量和退款轨迹可读 | 用户流/状态泳道、逐项批量板 |
| 07 状态契约 | 分开对象/请求/外部效果/用户判断，避免假成功 | 状态矩阵、事件轨迹、非颜色编码 |
| 08 原型保真度 | 说明视觉保真度只提升未知项，不伪造已验证效果 | 三轮线框/高保真对照、保真度决策表 |
| 09 视觉层级 | 直接训练焦点、分组、比例、色彩、对比和节奏 | 改前/改后关键屏、灰度/缩略图板 |
| 10 跨端与能力 | 保持任务关系在断点、语言、键盘、缩放和长文案下成立 | 三宽度重排、焦点序列、长文本板 |
| 11 组件合同 | 把视觉规则落实到 token、语义状态、组件变体与例外 | Token 层级、组件状态矩阵 |
| 12 系统治理 | 让变更、迁移、例外、回滚和采用证据可见 | 迁移前后、影响地图、回滚流程 |
| 13 AI 扩展空间 | 区分 AI 发散与研究证据，记录人工选择和风险 | AI 输入/输出/人工修订轨迹 |
| 14 AI 草稿体验 | 表达来源、候选、置信/未知、编辑和拒答的视觉身份 | 来源卡、候选/拒答/人工接管板 |
| 15 异步与副作用 | 让等待、超时、外部可能已受理和取消边界诚实可见 | 时序图、待核对/恢复屏 |
| 16 Agent 与多模态 | 保持任务面板、上下文、权限和多模态结果的视觉秩序 | 面板层级、输入/结果/控制状态板 |
| 17 多租户、批量与并发 | 表达作用域、逐项结果、冲突和版本身份 | 租户边界图、批量分母/冲突板 |
| 18 跨系统交接 | 保留来源、接口、责任和失败恢复的连续视觉线索 | 服务交接图、责任/状态映射 |
| 19 评估与返修 | 用对照和观察定位视觉问题，不以审美偏好收尾 | 评估记录、问题严重度、返修 diff |
| 20 指标与实验 | 把视觉方向连接到假设、分母、护栏与不确定性 | 指标/护栏图、合成数据判读板 |
| 21 设计交付合同 | 让工程、内容、QA 可复现视觉规则和降级 | handoff 包、资产/Token/验收清单 |
| 22 跨职能冲突 | 展示品牌、可访问性、风险、成本冲突下的视觉裁决 | 决策记录、取舍矩阵、异议标注 |
| 23 个人贡献与追问 | 让视觉决定回指本人证据、版本和被否决方向 | 作品集案例板、口述路径、来源卡 |
| 24 未见任务与独立评审 | 将视觉语言迁移到陌生约束，保留未知项与复验 | 陌生任务包、盲评前后、复验记录 |

章节入口不要求每章新增独立插图；可复用工件必须保留原文件身份、版本和指向章节的语义，不得用装饰图充数。

## 5. v03 VA01–VA04 专项接收范围

| 专项 | 必须补强的视觉能力 | 最小工件 |
|---|---|---|
| VA01 视觉感知 | 用可观察语言诊断焦点、层级、比例、节奏、噪声与反例 | `VA01-critique-board`、基线/批评/返修链 |
| VA02 构图与节奏 | 比较网格、留白、密度、比例、折叠线与响应式重排 | `VA02-composition-study`、三宽度/灰度/放弃方案 |
| VA03 视觉语言系统 | 将语气转成字体、色彩、形状、材质、图标、动效、Token 与例外治理 | `VA03-visual-language-kit`、来源/许可/状态表 |
| VA04 精修、动效与交付 | 用逐项 diff 证明精修价值，说明减少动效、跨端、语言、回退和工程限制 | `VA04-polish-and-delivery-pack`、未验证清单 |

VA 专项是 v02 的视觉覆盖层，不取代 v02 原章节职责；VA 工件被 v02 章节引用时需有双向链接和版本标识。

## 6. 统一配图与资产合同

每项配图在正文邻近位置提供：`目的/受众`、`主信息与动作`、`输入与状态`、`视觉变量`、`图例`、`结果/失败后果`、`来源与版本`、`短文字替代`、`完整文字说明（必要时）`、`响应式/灰度/大字号边界`、`未验证项`。状态、来源、风险、失败、等待和版本身份至少使用文字、形状、位置、边界或线型等冗余线索，颜色和动效只能补充。

允许的配图类型包括：视觉 brief/证据链、前后对照、A/B 方案板、信息架构/用户流/时序图、状态矩阵/泳道、关键界面与组件状态、Token/变体矩阵、响应式重排板、灰度/缩放/长文案检查板、批评与返修 diff、工程 handoff 图。每张图须服务一个可复核问题，不能仅以“更高级”“更有氛围”命名。

资产来源必须标记原创、教学构造、开源/许可、字体来源、AI 辅助及人工修订；不能使用无来源的受版权约束素材。源文件可编辑并与正文引用一致；导出图、预览图和运行截图分别标识身份。

## 7. 可观察验收条件

条款状态仅允许 `pass`、`fail`、`insufficient`，必须绑定当前版本证据；报告写完不等于通过。

| ID | 验收条件 | 证据要求 |
|---|---|---|
| VO-P01 范围完整 | 24 章与 VA01–VA04 均有入口、链接、版本与责任，不漏章、不改 ID | 当前文件清单、章节矩阵、双向链接检查 |
| VO-P02 视觉因果 | 关键图能说明视觉变化如何影响任务、状态、信任或阅读 | before/after、变量标注、参考分析 |
| VO-P03 多方案与失败 | 至少一组可比较方向或失败版本，说明取舍、放弃和修复条件 | A/B 或返修链、决策记录 |
| VO-P04 状态诚实 | 正常/等待/空/错误/拒答/来源/恢复可辨，不能靠颜色或动效单独表达 | 状态板、文字/形状/位置编码 |
| VO-P05 跨端韧性 | 桌面、约 760px、窄屏、长文案、灰度/大字号/缺图等条件仍能完成视觉阅读 | 当前资产预览、条件与限制记录 |
| VO-P06 可访问性 | 对比、焦点、读序、名称、非颜色编码和减少动效边界有记录 | 静态检查或实测证据，未运行项标明 |
| VO-P07 图文/版本一致 | 正文、图、Token、状态、练习和参考解法中的对象与规则一致 | 锚点/路径/版本核对、缺陷复验链 |
| VO-P08 来源与许可 | 图像、字体、参考、AI 辅助和教学构造均可追溯 | 资产来源表、许可/版本字段 |
| VO-P09 可交付可复现 | 工程/内容/QA 能据 handoff 复现规则，不能实现处有降级 | 源文件、Token、状态、断点、资产和验收字段 |
| VO-P10 证据边界 | 静态稿、离线渲染、浏览器/读屏、真人理解和真实产品效果分开记录 | 运行矩阵与 `not_run/not_verified` 项 |
| VO-P11 练习可迁移 | 练习含输入、约束、产物、检查点和参考解法，至少一个视觉约束改变的变体 | 题面—产物—分析—变体链接 |
| VO-P12 独立复核 | 作者、内容审校、QA 的职责和返修/复验链可区分 | 三类记录、原问题与当前结果 |

若 VO-P01–P12 在当前版本均有独立可追溯证据，只能称 `met_within_visual-textbook-scope`；不推导真实学习、用户偏好、职业胜任、专家认可、市场优势或生产质量。

## 8. 实施批次与依赖

1. **B0 产品/课程冻结**：确认 24 章矩阵、VA 工件身份、图例/来源/可访问性字段和不纳入范围；产品经理与课程架构师交接。
2. **B1 入口与关键反例**：先覆盖 01–12 及 VA01–VA02，建立统一图注、before/after、状态和响应式模板；设计师与教材研发员并行，禁止改正文能力边界。
3. **B2 高级系统与 AI 状态**：覆盖 13–18、VA03，重点是来源、租户、异步、组件 Token、例外和治理；须依赖 B1 的状态/视觉语法。
4. **B3 评估、交付与迁移**：覆盖 19–24、VA04，补齐实验、handoff、冲突、作品集和陌生任务；须依赖已有工件与版本链。
5. **B4 独立复核**：内容审校逐章核论证/来源/边界，QA 核资产可打开、渲染、链接、状态和受影响反例；作者按缺陷返修，原例在当前版本复验。
6. **B5 版本复盘**：产品经理按 VO-P01–P12 复盘限定范围；项目经理记录差距、责任人、下一步和整体 `not_met` 状态，不把教材交付当完整产品达标。

批次可以在同一批内并行，但不得由两个岗位同时修改同一交付物。任何新增图稿先登记来源、版本、文字替代和未验证项，再进入审校与 QA。

## 9. 证据边界与整体判定

本合同继承 `uiux-v02-product.md` 的 UX02-01—14、`uiux-visual-harmony-product-v01.md` 的 VH-P01—P09、`DESIGN_VISUAL_QUALITY_STANDARD.md` 的六项视觉关系，以及 v03 VQG 八维描述量规；不替换它们，也不把 0–3 量规平均成就业或审美分数。视觉优化完成只能说明教材视觉工件在限定范围内可检查。真实读者理解、审美接受、无障碍使用、浏览器/读屏/性能、真人专家、学习者迁移、竞品优势和运营经济须由对应岗位另取证据。

当前本合同不授任何章节、作品或学习者通过结论；未运行的浏览器、读屏、真实用户、专家、模型、生产服务和市场测试必须保留为 `insufficient` 或 `not_verified`。旧教材、历史审校/QA、应用数据和原八项产品门槛保持收到状态，不因新增视觉优化记录而覆盖或继承为新结论。
