# 参考答案最低质量要求 · 产品交接

日期：2026-10-14  
岗位：产品经理  
交付：[ANSWER_QUALITY_STANDARD.md](ANSWER_QUALITY_STANDARD.md) v1.0

## 目标与本轮范围

将用户“多角度的细致回答……是起码需要达到的要求”落为正式参考答案的可观察最低标准。覆盖面试参考答案和解释型教学问答；不将用户仅要求摘要的场景强制扩成长文。本轮只新增两份产品标准/交接文件，不改应用、原型、教材、历史审校或原八项门槛，不开展全量题解重写。

## 读取依据与现状

- 已读取 `team/TEXTBOOK_WRITING_STANDARD.md` 的完整正文要求和审校流程。
- 已读取 `team/interview-prep-v1-product-design.md`：产品要求参考答案、追问和来源/版本关联，未限制每题三条。
- 已读取 `dist/interview-prep-v1-prototype.html` 的 10 条题目数据及参考回答渲染逻辑：每题预置三条答案、两条追问；不是运行时按教材生成完整题解。
- 超时题的三条文字触及结果不确定、操作身份/幂等、核对与故障测试，但未展开完整机制、分支、实施与条件；当前只按提纲定位。本岗位未逐题审校其余九题，不对其技术正确性作完整判断。

## 标准的关键决定

1. AQS-01 至 AQS-08 分别核对直接回答、多角度机制、可操作路径、案例/关键分支、条件/取舍、验证、来源/不确定性和可读性。这些为答案质量编号，与原八项产品门槛独立。
2. 不按角度数量、字数、代码长度或栏目数给分。缺少核心机制不能用额外段落、口号或限制说明补救。
3. 摘要和面试口述提纲可以短，但不能替代默认的完整学习解析；具体界面呈现后续由设计及客户端岗位承接。
4. 各题按相关性选择表达方式，不适用项给理由；实现题必须说明关键契约，概念题不强制代码，项目经历题不得编造学习者经历。
5. 内容作者、内容审校员和测试工程师分别承担编写/返修、独立技术审校和交付/实际验证；返修须回到原例复验。

## 产品领域自查

| 自查项 | 实际结果与位置 |
| --- | --- |
| 用户原话与最低要求明确 | 标准“用户要求与范围”原文引用，并解释多角度和深度的意义 |
| 可观察且不机械化 | 标准 AQS 表逐项给交付证据与检查点；不适用项需理由 |
| 覆盖简答例外但不稀释完整解析 | 标准“简答、摘要与完整解析”区分用途和交付状态 |
| 超时题有具体核对范围 | 标准“本题示例的质量核对范围”给六类因果检查问题，未代写完整答案或保证实现 |
| 新旧证据不混用 | 标准“交付、审校与复验”“当前内容状态”明确新版本独立检查及现有 10 题未完成全量审校 |
| 保持职责与授权 | 本岗位只新建本标准和本交接；未修改其他领域产物、未执行测试/真实服务或调用付费模型 |
| 完整产品判定不越权 | 原八门槛保持；标准落地不授职业培养、用户理解或行业先进目标通过 |

以上为作者岗位自查，不是独立 QA 或内容审校结论。
