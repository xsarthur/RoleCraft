# UI/UX 教材视觉美与和谐教学交接

设计岗位；2026-10-15（Asia/Shanghai）。

## 交接目的

用户指出：设计教材有大量逻辑性内容，也必须训练视觉美与和谐；视觉质量是设计的核心竞争力。本交接把这项要求转成可教、可练、可复盘的设计能力，不修改课程 ID、产品范围、应用代码或既有验收门槛。

这里的“美”不是给页面加装饰，也不是让所有人接受同一种审美。它是**在目标、内容、品牌、媒介和包容性约束下，有意识地组织感知关系**，使用户更快理解、更愿意继续、更容易信任，并能记住产品的独特气质。视觉判断仍需由作品、比较、迭代和真实反馈支持；设计师的品味不能替代用户证据。

## 核心模型：美由关系产生

教材应把“好看”改写成可以观察和修改的关系。每次视觉评审至少回答以下六项：

| 关系 | 学习者要能观察什么 | 常见失效 | 练习中的动作 |
| --- | --- | --- | --- |
| **目的与焦点** | 第一眼落在谁/哪条信息；焦点是否服务任务 | 装饰、插画或高饱和色夺走主信息 | 三秒遮挡/灰阶检查，标出焦点和次焦点 |
| **层级与比例** | 标题、正文、证据、动作的权重差；元素尺寸是否成组 | 所有内容同样大、粗、亮；按钮比结论更抢眼 | 只改字号、字重、间距做三版层级比较 |
| **秩序与节奏** | 网格、对齐线、间距阶梯、重复与停顿是否可预测 | 卡片边缘不齐、间距随机、长文没有呼吸 | 叠加网格和间距标尺，记录每次偏离的理由 |
| **统一与差异** | 字体、颜色、圆角、图标、图像语气是否属于同一系统；关键状态是否有足够差异 | 组件像不同产品拼接；或为了统一而抹平错误/风险 | 先做 token 规则，再做一个有理由的例外 |
| **对比与和谐** | 明暗、冷暖、粗细、密度和形状有张力但不互相打架 | 低对比导致不可读；对比过多造成噪声 | 同一版式做“克制/强对比”两版，写出适用场景 |
| **语气与材质** | 颜色、圆角、阴影、图像光线和动效共同传达何种性格 | 用渐变、玻璃或阴影直接模拟“高级” | 把“可信/温和/专业”各写成三条可见约束，禁止只写形容词 |

六项不是线性打分公式。一个页面可以很有秩序但没有个性，也可以很有个性但损害任务；学习者要说明冲突、取舍和待验证项。

## 教学落点与课程交接

课程架构师在不改 26 个单元 ID 和先修关系的前提下，将以下内容交给教材研发员；这是一组跨章能力线，不要求新增一门装饰性“审美课”。

| 现有单元 | 加入的视觉能力 | 最小教学产物 | 不得用什么替代 |
| --- | --- | --- | --- |
| `01-foundation-diagnostic` | 识别焦点、层级、间距和读屏风险 | 同一页面的灰阶/网格诊断，标 5 个具体问题 | “我觉得乱/高级”的意见 |
| `06-synthesis-prioritization` | 把用户情绪和品牌语气翻译成视觉约束 | 语气词 → 色彩、字体、图像、动效约束表 | 直接挑一套流行色 |
| `09-wireframes-interaction` | 低保真也要有比例、节奏和留白；逻辑与审美互相校正 | 两种信息层级草图及删减理由 | 先做高保真再补任务流 |
| `10-visual-interface` | 构图、网格、字体、颜色、形状、材质、动效和美观/可读性冲突 | 高保真关键屏、token 表、视觉决策表 | 只交一张“最终图” |
| `11-responsive-localized` | 视觉关系如何在窄屏、长文、放大、翻译和 RTL 中重排 | 桌面/平板/窄屏同内容对照板 | 把桌面图等比缩小 |
| `12-design-system` | 通过 token、组件变体和例外治理持续保持和谐 | 色彩/字体/间距/圆角/图标规则与例外记录 | 把每页手工调到相似 |
| `15-ai-uncertainty-states` | 等待、无结果、失败、拒答等状态的视觉节奏；美感不能掩盖未知 | 正常/等待/失败/恢复状态板 | 只换颜色或放旋转图标 |
| `18-usability-accessibility-evaluation` | 让视觉偏好进入可观察任务和包容性检查 | 盲评任务、灰度/200%/减少动效复核记录 | 设计师自评“很美” |
| `20-engineering-handoff-qa` | 交付后保持间距、字体、裁切、动效和状态语义 | 实现前后对照、偏差清单、修复优先级 | 仅凭 Figma 截图宣布还原 |
| `24-portfolio-interview` | 用作品讲视觉判断、冲突和迭代证据 | 一页 before/after、决策与验证边界 | 只展示漂亮成品和工具列表 |

教材正文仍需分别说明哪些是教学构造、哪些已运行、哪些来自真实用户；视觉板不能把示意结果写成上线效果。

## 建议的实作阶梯

贯穿同一个内容和任务，逐步改变视觉关系，避免把审美练习和产品逻辑割裂：

1. **看见问题**：同一内容做灰阶、缩略图和 200% 放大检查；指出焦点、层级、对齐、间距和可读性问题。
2. **建立秩序**：用 4/8/12/16 等候选间距、两级圆角和有限字重构成 token；每个偏离写理由。
3. **建立语气**：为“可信、温和、专业”各做一套颜色/字体/形状/图像约束，同一内容做盲评；记录误读和偏好，不宣称转化结果。
4. **形成和谐**：在统一规则内加入一个有目的的焦点、节奏停顿或对比；解释它如何帮助任务和记忆。
5. **承受约束**：在窄屏、长文、译文、低亮度、减少动效、错误和无结果状态中重排，保持关系而不是保持像素。
6. **接受批评并迭代**：让同伴先描述“看到了什么/下一步是什么”，再说喜不喜欢；作者根据事实、任务和证据修改，保留前后版本。

每阶都要留下源文件、版本号、选择理由和未验证项。AI 只能辅助发散、配对或检查，不能代替设计师解释焦点、事实和包容性。

## 视觉质量评审表（教学提案，非自动通过门槛）

课程架构师和产品经理可从下表选择当前项目需要的项；设计岗位不自行把总分变成职业认证。每项用 0–3 描述：`0 未表达`、`1 有意图但关系不稳定`、`2 在给定约束下可复用`、`3 经比较/用户或 QA 证据支持`。

| 维度 | 2 分应能看到 | 3 分需要的证据 |
| --- | --- | --- |
| 任务焦点 | 一眼可找到主任务和关键结论 | 盲看/任务观察中，参与者能说出主任务与下一步；样本和局限有记录 |
| 层级比例 | 标题、正文、证据、动作有稳定差异 | 灰阶、缩略图、长文和放大检查仍保持正确阅读顺序 |
| 节奏秩序 | 网格、对齐和间距规则能复用 | 工程实现或多页面对照证明规则没有漂移 |
| 和谐语气 | 色彩、字体、形状、材质和动效互相支持目标语气 | 同伴/目标用户能描述预期语气，且没有牺牲事实或可读性 |
| 差异记忆 | 关键状态/品牌特征有可辨的对比 | 参与者能在相似页面中找出状态或品牌线索；未把偏好写成效果 |
| 包容稳健 | 非颜色、非悬停、非动画也能获得含义 | 键盘、读屏、灰度、200% 缩放、窄屏和减少动效均有实际记录 |
| 迭代证据 | 交前后对照和具体修订理由 | 修订由观察/测试/工程限制触发，并保留失败版本及未验证项 |

“美观”与“可用”冲突时，先保护任务、事实、安全和包容性，再用构图、层级、材质和动效寻找更好的表达；这不是降低审美要求，而是把审美放到真实约束中训练。

## 视觉示意与审阅证据

配套对照板为 [`uiux-visual-aesthetic-board.svg`](uiux-visual-aesthetic-board.svg)。A、B 两栏使用同一内容、同一动作和同一状态：A 只满足逻辑但间距、层级、颜色和组件语气互相冲突；B 通过网格、比例、留白、有限色彩和状态重复编码让内容更易扫描，同时保留必要文字。它是课堂示意，不是当前应用截图、真实用户结果或品牌定稿。

设计师交付时至少提供：

- 原始可编辑稿和一份实际渲染预览；
- A/B 或 before/after 的同内容比较，标出改变了哪项关系；
- 设计决策表（目标、约束、方案、取舍、未验证项）；
- 桌面、约 760px、窄屏、200% 缩放、灰度和减少动效的检查记录；
- 正常、等待、无结果、失败、恢复和历史/版本状态的视觉样例（若本任务涉及）；
- 文字替代、图例、颜色角色和来源/版本绑定。

视觉稿通过静态自查不等于应用实现通过。客户端工程师负责按合同实现，测试工程师负责独立浏览器、键盘/读屏和响应式验证，用户研究员负责“看懂什么、找到什么、是否记住”的真实证据。

## 交接给各岗位

- **产品经理**：确认当前版本需要表达的任务焦点、品牌/语气约束和可观察验收项；决定是否把盲评或任务观察纳入本轮门槛，不由设计师自定总分。
- **课程架构师**：按产品合同的首批接收范围 `C05/C06/C07/C08/C10/C11/C13` 挂接视觉关系、练习阶梯和证据字段；`C12` 的设计系统治理内容作为相邻消费方保留，保持逻辑、视觉、AI 状态和工程协作的先修关系。
- **教材研发员**：将上述内容写成机制、案例、失败轨迹和分层练习；引用本视觉板时标明其为教学构造，不把“高级/和谐”写成普遍事实。
- **软件工程师**：接收 token、组件状态、响应式重排和动效减少规则；遇到无法实现处保留设计意图并记录替代方案。
- **测试工程师**：按产品确认的验收条件独立复核实际渲染、灰度/对比、键盘/读屏、缩放、窄屏、状态辨识和工程还原；不能只测文件、字数或颜色值。
- **用户研究员/实训评估员**：分别取真实理解证据和按量规评价作品；不把设计师自评、AI 生成或静态示意当学习效果/职业认证。

## 设计自查与边界

已覆盖视觉美、和谐、层级、比例、节奏、色彩、材质、动效、响应式、可访问性、实践和验收交接；没有修改教材正文、产品范围、应用代码、数据库或用户记录。配套 SVG 仅为可审阅教学示意，尚未进行浏览器、屏幕阅读器、真人用户或行业专家验证。本交接不关闭现有产品或教材的 `not_met` / `met_with_limitations` 结论。
