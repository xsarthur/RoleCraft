# 代码折叠跨端变更同步记录 v0.1

日期：2026-10-16（Asia/Shanghai）  
协调岗位：项目经理  
变更状态：`planned`  
影响范围：v13 教材试读稿、教材渲染/学习工作台展示、视觉规范、开发实现、独立 QA。

## 变更来源

用户反馈：篇幅较长的代码默认收起，超过 10 行增加展开/收起；图示不只放在开头，长篇阅读中穿插少量有语义的视觉材料，并用克制色彩改善阅读接受度。

项目经理纠偏：代码折叠改变读者与教材内容的交互方式，属于跨端产品功能，不能由教材编辑单独决定。编辑只提供代码块用途、长度、输入/输出、关键分支、验证状态和来源；产品、设计、开发、测试共同冻结和验收行为。

## 当前约定

- 11 行及以上代码默认折叠；10 行及以下默认展开。
- 折叠摘要必须保留用途、输入/输出、关键分支、验证状态、来源和行数等必要信息。
- 关键短代码、错误分支、结论性最小片段不得因为长度规则被隐藏。
- 展开/收起状态必须支持键盘和读屏；颜色不能承担唯一含义。
- 刷新、深链接、后退、脚本或样式不可用时，内容仍需可读；是否保存用户展开状态由产品合同决定。
- 中段视觉材料必须有理解任务、邻近正文、文字替代和来源；不得只增加装饰图。

这些是当前交接基线，不表示应用已经实现。

## 实施顺序与关闭条件

1. 产品经理冻结合同字段、默认状态和是否保存展开状态。
2. 设计师交可审阅的桌面/窄屏/键盘/读屏状态稿。
3. 软件工程师实现渲染、稳定代码锚点和降级行为。
4. 内容审校员按当前教材版本检查摘要和折叠边界。
5. 测试工程师在真实目标页面独立验证并保留复现证据。
6. 项目经理记录缺陷、返修、复验和版本绑定。

在步骤 5 的实际渲染与交互证据完成前，代码折叠保持 `planned`；不能用 Markdown 中存在 `<details>`、静态源码检查或作者自查代替产品功能通过。

## 用户反馈后的实现复盘（2026-10-16）

用户实际阅读 v13 后指出中段仍看不到图和颜色。检查确认：当前 `learning-workbench.js` 原 Markdown 渲染器不解析 `<details>` 折叠，也不运行 Mermaid；因此编辑稿中的 Mermaid 只会作为源码/连续文字处理，且 v13 尚未接入当前 v12 语料链。软件工程师已完成最小渲染器支持：折叠代码可识别，普通静态图片保留，Mermaid 保留源码降级；产品预览范围仍保持隔离 `planned`，未替换 v12 正式入口。

为减少对 Mermaid 渲染的依赖，三篇 v13 章节已各加入中段静态 SVG：任务合同的三类证据卡、信任边界的资料到写入卡、控制循环的动作账本与恢复卡。当前静态图已通过 XML 结构检查，浏览器、窄屏、字体、读屏和真人理解仍需 QA 复验。
