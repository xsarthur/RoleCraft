# 教材长代码折叠跨端产品合同（v01）

日期：2026-10-15（Asia/Shanghai）  
责任岗位：产品经理（目标、范围、验收条件）  
同步岗位：课程架构师、教材研发员、内容审校员、设计师、软件工程师、测试工程师、项目经理  
状态：跨端交接稿；尚未实现

## 1. 产品判断与范围

“长代码默认折叠”会改变读者的初始视图、阅读顺序、深链接、键盘和读屏路径，并可能影响阅读记录。因此它是产品功能变更，不能只写进编辑规则。编辑提供内容元数据，产品冻结行为，设计定义表达，开发实现，测试独立验收，项目经理维护交接和版本。

本合同只定义教材展示功能，不修改教材正文、账户、数据库、历史记录、外部模型调用或代码执行能力。

## 2. 默认规则

- 最终渲染后超过 10 行（11 行及以上）的代码块默认折叠；10 行及以下默认展开。
- 空行和注释行计入行数；不得为规避阈值把同一示例拆成多个连续代码块。
- 代码、伪代码、JSON、YAML、日志和终端输出若用代码围栏呈现，均遵循阈值。
- 教学上必须逐行展示的例外，需提供 `collapsePolicy: "always-open"` 和 `exceptionReason`，经产品、课程架构和设计确认。

折叠状态下必须直接可见：用途标题、语言/版本（已知时）、行数、输入、预期输出、关键错误或边界、运行/伪代码/外部依赖/未验证状态、来源章节/版本和“展开代码”操作。核心输入、输出、关键分支和结论不得只藏在代码中。

## 3. 展开、收起和内容边界

- 控件使用可访问按钮；文本为“展开代码（共 N 行）”与“收起代码”，并同步 `aria-expanded`。
- 展开不跳到页面顶部，不改变章节/小节定位；收起后焦点回到代码标题或控件。
- 支持 Tab、Enter、Space；点击复制或下载不应意外切换状态。
- 可同时展开多个代码块；“全部展开/收起”需另行产品确认。
- 代码块不可执行；沙箱必须另立产品合同。
- 展开/收起只改变当前阅读会话视图，不改变教材版本、学习进度、作品状态或能力判断。

## 4. 刷新、深链接和阅读记录

- 默认刷新恢复折叠初始状态；不得把折叠状态写入账户学习进度。若要恢复会话偏好，产品需另行冻结范围。
- 每个代码块使用稳定锚点，如 `code-{unitId}-{sectionId}-{codeId}`。深链打开显示章节、小节、代码标题和版本；默认定位但不自动展开。
- 版本失配或锚点失效要显示原因和章节入口，不静默替换其他版本。
- 脚本关闭、静态导出或加载失败时，摘要和全部代码仍可阅读。
- 本合同不新增“已掌握”等状态。任何交互埋点需另行冻结事件、字段、期限和隐私边界，未冻结前不采集正文或账号私有数据。

## 5. 元数据字段

每个代码块由编辑/课程提供以下字段，开发不得猜造：

| 字段 | 必填 | 用途 |
| --- | --- | --- |
| `codeId`、`unitId`、`sectionId` | 是 | 稳定身份与定位 |
| `sourceVersion` | 是 | 教材版本 |
| `language`、`runtime` | language 是 | 语言与环境 |
| `lineCount` | 是 | 折叠阈值 |
| `collapsePolicy`、`exceptionReason` | policy 是 | 默认或例外规则 |
| `title`、`summary` | 是 | 折叠态用途、输入、输出摘要 |
| `keyBranches` | 条件 | 直显的关键分支/错误 |
| `verificationStatus` | 是 | `executed`、`pseudocode`、`external-dependent`、`unverified` |
| `runtimeVersion`、`sourceHash` | 否 | 实际验证和来源绑定 |
| `accessibilityText`、`updatedAt` | 是 | 无障碍说明和更新时间 |

## 6. 无障碍、视觉与错误状态

- 读屏顺序：标题 → 摘要 → 语言/行数 → 验证状态 → 展开控件 → 展开后的代码；隐藏内容不可重复朗读。
- 颜色只能辅助表达，必须同时有文字、图标或边框；高对比、大字号和键盘操作不能覆盖代码、文字或按钮。
- 长代码允许滚动，但不得以横向裁切隐藏内容；静态降级必须保留全文。
- 元数据缺失显示“展示信息不完整”；来源失配显示“当前版本来源未确认”；加载失败保留静态代码；脚本不可用时直接展示全文。

## 7. 跨端验收条件

### 产品
- 11 行以上默认折叠、10 行及以下默认展开，例外有审批记录。
- 折叠态直接可见摘要、行数、来源、验证状态和关键边界。
- 展开/收起不改变定位、学习进度、作品状态或能力判断；不引入代码执行。
- 刷新、返回、深链、版本失配、脚本关闭均有合同内行为。

### 设计
- 控件、摘要、徽章和代码层级清晰；箭头、装饰线、徽章不得覆盖文字或代码。
- 桌面、窄屏、键盘、读屏、高对比和长标题可读；颜色有文字冗余。

### 编辑与课程
- 每个代码块有真实用途、输入、输出、关键分支和来源；教学结论有正文或摘要等价路径。
- 验证状态忠实于证据，不能把伪代码或外部依赖标成已运行。

### 开发
- 仅依据冻结元数据实现；使用稳定锚点和可访问控件；无脚本保留全文。
- 缺字段、版本失配、加载失败使用受控状态，不改变账户数据。

### 测试
- 独立核阈值、例外、摘要、来源、状态、交互和静态降级。
- 覆盖鼠标、键盘、读屏、高对比、窄屏、刷新、后退、深链和错误状态；记录浏览器/设备/字体条件。

## 8. 交接顺序与状态

产品冻结受影响代码块清单 → 课程/编辑确认直显语义 → 内容审校核来源与验证 → 设计交视觉稿 → 开发实现 → 测试独立验收 → 项目经理复盘缺陷与复验。

本合同状态为 `planned`。写入合同不等于功能完成；必须有各岗位证据和独立 QA 才能标记限定范围通过。
