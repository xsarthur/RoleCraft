# AI 产品经理长期记忆条目格式

## 用途

此格式用于记录可跨项目复用的 AI 产品偏好或协作约定。它把用户明确偏好、项目局部决定和待验证假设分开，避免把一次模型选型或单次验收结果当成永久规则。

## 必填字段

| 字段 | 要求 |
| --- | --- |
| `id` | 稳定唯一标识，例如 `AIPM-MEM-0001`；不因文字润色而复用旧 ID。 |
| `title` | 简短描述记忆内容，不把推测写成事实。 |
| `statement` | 用可执行、可观察的句子写偏好或约定。 |
| `evidence` | 用户原话、明确决策、重复行为或可定位的项目记录；至少写来源和日期。 |
| `scope` | 适用的岗位、产品类型、AI 能力、项目、阶段或其他边界；跨项目必须明确写出条件。 |
| `confidence` | `confirmed`、`strong`、`tentative` 或 `unknown`。只有直接确认或满足团队约定的重复证据才可用 `confirmed`。 |
| `confirmation_status` | `user_confirmed`、`awaiting_user`、`inferred`、`superseded` 或 `rejected`。 |
| `version` | 语义版本，例如 `1.0.0`；内容变化时递增并保留变更说明。 |
| `recorded_at` | ISO 日期，注明首次写入时间。 |

## 推荐字段

| 字段 | 用途 |
| --- | --- |
| `constraints` | 不得越过的边界、例外或需要重新确认的条件。 |
| `non_inferences` | 明确列出没有从证据推断出的相邻偏好，例如具体供应商、提示词或界面画法。 |
| `last_reviewed_at` | 最近复核日期；长期未复核的条目应降级或重新确认。 |
| `change_log` | 版本、变更原因、证据和确认人/来源。 |
| `related_projects` | 仅列证据所在项目；不要把项目名本身当作推广授权。 |

## Markdown 模板

```markdown
### AIPM-MEM-XXXX — 标题

- **偏好/约定**：
- **证据**：
  - 来源：
  - 日期：YYYY-MM-DD
- **范围**：
- **限制**：
- **未作出的推断**：
- **置信度**：`tentative`
- **确认状态**：`awaiting_user`
- **版本**：`0.1.0`
- **记录日期**：YYYY-MM-DD
- **最近复核**：YYYY-MM-DD
- **关联项目**：
- **变更记录**：
```

## 状态与升级规则

1. 新观察先写入项目交接记录或“待确认记忆候选”，状态为 `awaiting_user` 或 `inferred`，不得直接写入已确认区。
2. 用户明确说“这是我的长期偏好/以后都这样”时，记录原话并可升级为 `user_confirmed`；若只是一次项目决定，保持项目范围。
3. 多项目中出现一致行为可以提高置信度，但不能替代用户确认，除非项目规则另有明确约定。
4. 记忆冲突时不静默覆盖：创建新版本，标记旧条目 `superseded`，说明冲突证据和适用范围变化。
5. 任何条目都不能改变 `AGENTS.md` 的岗位边界、用户授权、隐私要求或测试独立性，也不能把本岗位扩展成界面设计或模型实现。
6. 删除或降级记忆时保留审计记录；不得把被拒绝或过期的偏好继续用于新项目。

## 读取与写入协议

- 新项目开始：读取角色说明和已确认记忆；只把与当前 AI 范围匹配的条目作为建议输入。
- 任务进行中：把新的观察写到项目记录，附来源、范围和不确定性。
- 任务结束：提交记忆候选和证据，等待用户或项目经理确认后再更新本文件。
- 跨岗位共享：只共享已确认且与对方职责相关的条目。AI 产品经理不替产品经理、AI 设计师或工程师创建其专业记忆。
