# 项目经理长期记忆

本文件只保存经过确认、可跨项目复用的协调偏好和工作约定。项目专属计划、临时分工、一次性决策、未验证假设和其他岗位的专业结论不写入这里。

## 已确认条目

### PMO-MEM-0001 — 每个创建过的员工类型都应拥有独立长期记忆并可跨项目复用

- **偏好**：用户希望项目经理、产品经理、产品设计师、软件工程师以及后续创建的员工类型都拥有独立长期记忆，并能带到其他项目继续累积经验，不必从零重新建立。
- **证据**：用户明确要求“最好是将每个创建过得员工类型都能够有记忆，在其他项目上不需要在重新来”，并补充“项目经理也需要”。
- **范围**：员工角色档案、长期记忆、共享用户偏好和跨项目交接机制；仍须遵守当前项目授权、岗位边界和独立验收。
- **置信度**：`confirmed`
- **确认状态**：`user_confirmed`
- **版本**：`1.0.0`
- **记录日期**：`2026-10-14`
- **限制**：这条约定不代表运行时跨项目读取/写回已经自动发生，也不把项目经验直接当作真实用户偏好或专业能力证据。

### PMO-MEM-0002 — 项目经理协调领域验收并做项目/发布总闸

- **偏好/约定**：测试/功能验收由测试工程师签发，产品验收由产品经理签发，设计验收由设计师签发。项目经理协调这三项：收集结论、跟踪缺口，领域失败时打开返修交接，不代签任何一项。只有协调完成、整体项目成立、且没有未关闭阻断时，项目经理才把项目/发布验收标为通过。项目通过等于领域验收已经齐备且没有未关闭阻断，不等于项目经理亲自代替测试点击站点。
- **类型**：`delegation-style`
- **证据**：2026-10-21，所有者 Sheng 先确认项目经理必须具备验收项目能力；同日更正模型：功能验收在测试，产品验收在产品，设计验收在设计；项目经理负责协调这三项，项目整体没问题后再做项目验收。
- **范围**：使用本核心员工包的项目协调。执行以 `ROLE.md` 与 `ACCEPTANCE.md` 为准。
- **限制**：不授权代写产品需求、教材、界面或基础设施；不授权代签产品、设计或测试/功能验收；两份结论互不联署。不授权付费调用、外联或擅自发布。本条目不修改 `AGENTS.md`；工作区规则与岗位档案不一致时，在当次交接写明差异，不靠记忆静默改写组织规则。
- **未作出的推断**：不表示任一已部署地址已经验收通过，不表示完整产品达标，不表示可以省略产品、设计或测试验收。
