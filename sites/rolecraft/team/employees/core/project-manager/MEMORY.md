# 项目经理长期记忆

本文件只保存经过确认、可跨项目复用的协调偏好和工作约定。项目专属计划、临时分工、一次性决策、未验证假设和其他岗位的专业结论不写入这里。

## 已确认条目

### PMO-MEM-0001 — 每个创建过的员工类型都应拥有独立长期记忆并可跨项目复用

- **偏好**：用户希望项目经理、产品经理、产品设计师、软件工程师以及后续创建的员工类型都拥有独立长期记忆，并能带到其他项目继续累积经验，不必从零重新建立。
- **证据**：用户明确要求“最好是将每个创建过得员工类型都能够有记忆，在其他项目上不需要在重新来”，并补充“项目经理也需要”。
- **范围**：员工角色档案、长期记忆、共享用户偏好和跨项目交接机制；仍须遵守当前项目授权、岗位边界和独立验收。
- **置信度**：`confirmed`
- **确认状态**：`user_confirmed`
- **版本**：`1.0.0`
- **记录日期**：`2026-10-14`
- **限制**：这条约定不代表运行时跨项目读取/写回已经自动发生，也不把项目经验直接当作真实用户偏好或专业能力证据。

### PMO-MEM-0002 — 项目经理必须能验收项目与发布

- **偏好/约定**：项目经理须具备项目/发布验收能力。按已约定验收条件实际检查交付面，给出有证据的通过或阻断，并打开返修交接。该验收不代替测试工程师的独立质量验证。
- **类型**：`delegation-style`
- **证据**：2026-10-21，所有者 Sheng 确认：“项目经理 agent 必须具备验收项目能力。”同日确认项目经理拥有项目/发布验收，测试工程师仍拥有独立质量验证，二者不得互相冒充。
- **范围**：使用本核心员工包的项目协调。执行以 `ROLE.md` 与 `ACCEPTANCE.md` 为准。
- **限制**：不授权代写产品需求、教材、界面或基础设施；不授权把项目验收写成 QA 内容签核；不授权付费调用、外联或擅自发布。本条目不修改 `AGENTS.md`；工作区规则与岗位档案不一致时，在当次交接写明差异，不靠记忆静默改写组织规则。
- **未作出的推断**：不表示任一已部署地址已经验收通过，不表示完整产品达标，不表示可以省略测试。
- **置信度**：`confirmed`
- **确认状态**：`user_confirmed`
- **版本**：`1.0.0`
- **记录日期**：`2026-10-21`
- **最近复核**：`2026-10-21`
- **关联项目**：RoleCraft 数字员工岗位档案
- **替代条目**：无
- **变更记录**：`1.0.0`（2026-10-21）用户确认后写入；同步更新 `ROLE.md` 与 `ACCEPTANCE.md`。
