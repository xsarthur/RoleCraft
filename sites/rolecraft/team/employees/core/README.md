# 核心员工长期记忆系统

本目录保存可跨项目复用的核心岗位记忆包。截至 2026-10-14 为九类：项目经理、产品经理、产品设计师、软件工程师、课程架构师、教材研发员、内容审校员、测试工程师和实训评估员。测试工程师是当时既有岗位之一，增加其记忆包不代表当时新增职业岗位。

2026-10-22 并列登记两名新岗位，不替换产品经理或产品设计师：

- AI 产品经理：`ai-product-manager/`，标识 `core-ai-product-manager`，角色键 `ai_product_manager`。
- AI 设计师：`ai-designer/`，标识 `core-ai-designer`，角色键 `ai_designer`。

这些员工不是常驻后台进程，也不是独立账号。每次在新项目中调用时，代理会读取对应岗位的 `ROLE.md`、已批准的 `MEMORY.md` 和本项目的交接文件；任务结束后先提交记忆候选，经过用户或项目经理确认后，才更新长期记忆。项目交接沿用本目录的 `HANDOFF_TEMPLATE.md`。

| 产品设计师 | `product-designer/` | 信息架构、交互、视觉、可访问性和响应式表达；签发设计验收 |

各岗位共享 `user-profile/approved-preferences.md` 中经用户确认的稳定偏好，但各自的专业判断和工作记忆必须保持独立。`manifest.json` 里产品验收、设计验收和测试/功能验收的签发人仍是产品经理、产品设计师和测试工程师。AI 产品经理与 AI 设计师不接替这两项签发。

### 编辑跨职业的已确认标准

用户已明确要求：多角度、细致、有参考价值并真正帮助读者，是所有职业编辑长期采用的最低标准。具体稳定条目见 [共享偏好 CORE-PREF-EDITOR-001](user-profile/approved-preferences.md) 与 [教材研发员记忆 TEXT-MEM-0002](textbook-developer/MEMORY.md)。编辑由现有教材研发员承担，不新增或合并岗位责任。

启动任何职业的编辑任务时，先读取这两个条目，并在项目交接“可复用的已确认偏好”中列出其ID，再按本职业读者、实践与证据适配。不能只携带标准名称或失效链接；迁移包须保留记忆正文的可执行要点。当前项目细则见 [答案质量标准](../../ANSWER_QUALITY_STANDARD.md)，不可把其中Agent示例当作所有职业统一教材。

这里确认的是长期文件记忆和读取约定，不代表平台会自动把本目录注入所有未来聊天；真实跨项目加载与执行应在对应任务中留下读取和交接记录。

### 测试参与内容验证

用户已明确要求测试也长期记住同一编辑质量标准，用于验证。测试启动时读取 [测试岗位档案与记忆](qa-engineer/ROLE.md)、共享偏好及当前项目的答案标准；逐题核内容是否直接解答问题、解释机制与关键关系、提供可操作方法或适当案例、讲清边界取舍并有可核依据。测试不能只核文件存在、字段数量或链接，也不能替作者编写答案或用AI验证冒称真人专家认可。实际本轮结果另见当前项目逐题QA记录，不沿用旧配置审核结论。

## 在其他项目中使用

新项目开始时：

1. 读取 `user-profile/approved-preferences.md`。
2. 读取对应岗位目录的 `ROLE.md`、`MEMORY.md` 和 `MEMORY_SCHEMA.md`。
3. 创建该项目自己的 `handoffs/<employee>.md`，记录本项目特殊背景、输入、版本和限制。
4. 任务结束后写入该岗位目录的 `memory-proposals/`（若不存在可创建），不要直接把未经确认的观察写入 `MEMORY.md`。
5. 经确认的条目才合并到 `MEMORY.md`，并在 `CHANGELOG.md` 记录来源、日期和替代关系。

Codex 的本地记忆可作为辅助召回；本目录的版本化文件才是员工身份、职责和长期经验的正式来源。

## 记忆质量规则

- 每个条目都要有证据、适用范围、置信度、确认状态和最后验证时间。
- 项目特例不能自动升级为跨项目偏好。
- 旧偏好被修正时保留变更记录，不静默覆盖历史。
- 不存储密码、密钥、私密令牌或不必要的个人敏感信息。
- 记忆不能改变岗位唯一责任，也不能替代产品门槛，或代替产品验收、设计验收、测试/功能验收。
- 项目经理按 `project-manager/ROLE.md` 与 `ACCEPTANCE.md` 协调三项领域验收，并只在它们齐备且没有未关闭阻断时标记项目/发布通过。项目结论与各领域结论分开保存，互不联署。
