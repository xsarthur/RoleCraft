# 教材研发员长期记忆条目格式

## 用途

此格式用于记录可跨项目复用的用户教材写作偏好或协作约定。它把用户明确确认的长期偏好、当前项目决定和待验证假设分开，避免教材研发员把一篇稿件的要求、一次返修或一次运行结果误认为永久写作标准。

## 必填字段

| 字段 | 要求 |
| --- | --- |
| `id` | 稳定唯一标识，例如 `TEXT-MEM-0002`；内容改写或版本升级不复用已废弃的 ID。 |
| `title` | 简短描述记忆内容，不把推测写成事实。 |
| `statement` | 用可执行、可观察的句子写用户偏好或协作约定。 |
| `evidence` | 用户原话、明确批准、重复一致的跨项目行为或可定位记录；至少写来源和日期。 |
| `scope` | 适用的岗位、教材类型、项目、读者、阶段和例外；跨项目必须写明条件。 |
| `confidence` | `confirmed`、`strong`、`tentative` 或 `unknown`。只有用户直接确认的偏好才能标为 `confirmed`。 |
| `confirmation_status` | `user_confirmed`、`awaiting_user`、`inferred`、`superseded` 或 `rejected`。 |
| `version` | 语义版本，例如 `1.0.0`；内容、范围或证据变化时递增。 |
| `recorded_at` | ISO 日期，注明首次写入时间。 |

## 推荐字段

| 字段 | 用途 |
| --- | --- |
| `constraints` | 不得越过的课程、产品、授权、隐私、来源或独立审校边界。 |
| `non_inferences` | 明确列出没有从证据推断出的相邻写作偏好。 |
| `supersedes` | 被本条取代的旧记忆 ID；没有替代关系时写 `none`。 |
| `last_reviewed_at` | 最近复核日期；长期未复核的条目应重新确认或降级。 |
| `change_log` | 版本、变更原因、证据和确认来源。 |
| `related_projects` | 仅列证据所在项目；项目名称不等于跨项目推广授权。 |

## Markdown 模板

```markdown
### TEXT-MEM-XXXX — 标题

- **偏好/约定**：
- **证据**：
  - 来源：
  - 日期：YYYY-MM-DD
- **范围**：
- **限制**：
- **未作出的推断**：
- **替代关系**：`none`
- **置信度**：`tentative`
- **确认状态**：`awaiting_user`
- **版本**：`0.1.0`
- **记录日期**：YYYY-MM-DD
- **最近复核**：YYYY-MM-DD
- **关联项目**：
- **变更记录**：
```

## 状态与升级规则

1. 新观察先写入当前项目交接记录或“待确认记忆候选”，状态为 `awaiting_user` 或 `inferred`，不得直接写入已确认区。
2. 用户明确说某项是长期教材写作偏好或要求以后跨项目沿用时，记录原话、范围和日期，才可升级为 `user_confirmed`。
3. 多个项目出现相同做法可以提高置信度，但不能替代用户确认；项目内的课程架构、版本和产品门槛仍不自动推广。
4. 记忆冲突时不静默覆盖：创建新版本，标记旧条目 `superseded`，说明冲突证据、适用范围和替代原因。
5. 任何条目都不能改变 `AGENTS.md` 的课程岗位边界、用户授权、来源核验、独立审校或测试独立性。
6. 具体文风、专业深度、信息密度、章节结构、练习门槛和读者先修必须有明确用户证据；没有证据就保持候选或空白。
7. 删除、撤回或降级记忆时保留审计记录；被拒绝、过期或仅限项目的偏好不得继续用于新项目。

## 读取与写入协议

- 新项目开始：读取 `ROLE.md`、`MEMORY.md`、`MEMORY_SCHEMA.md`，再读取当前项目的 `AGENTS.md`、课程架构和教材交接；只把与本项目范围匹配的条目作为建议输入。
- 编写过程中：把新观察写到项目记录，附原话或定位证据、范围、未验证项和建议责任人。
- 交付和返修：提交记忆候选，不把作者自查、静态示例或审校意见直接升级为用户偏好。
- 用户确认后：更新本文件，递增版本，填写 `change_log`，并保留被替代条目及其来源。
- 跨岗位共享：只共享已确认且与对方职责相关的条目；教材研发员不替课程架构师、内容审校员、产品经理或工程岗位创建专业记忆。
