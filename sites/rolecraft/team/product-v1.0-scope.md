# 职造 1.0 产品范围与验收合同

- **产品版本**：`Rolecraft 1.0`（本地候选发布合同）
- **当前实现基线**：`local-workbench-0.15-p0`
- **日期**：2026-10-15（Asia/Shanghai）
- **责任岗位**：产品经理
- **状态**：`scope_frozen_for_implementation; overall_not_met`
- **本文件性质**：根据 `product-review-current.md`、`design-review-current.md`、`product-learning-optimization-scope-v2.md`、v0.12 双输入合同、P0 客户端/检索交接和项目总交接形成的 1.0 产品交接。它冻结产品范围、用户任务、交互状态、验收条件和延期项，不代替设计稿、工程实现、内容审校或独立 QA。

## 1. 1.0 的发布口径

1.0 是一个**本地可运行的学习工作台候选版本**：读者可以选择已发布职业、继续当前学习任务、阅读版本绑定的 Agent 教材、用自然语言定位教材小节，并为至少一个练习提交可追溯的作品证据。默认使用本地检索/规则降级，`providerCalled=false`；本轮不进行付费模型调用、上传、外部联系或公网发布。

当前 `local-workbench-0.15-p0` 只是收到实现基线，不自动成为 1.0。客户端、服务、教材索引、题库/练习数据冻结后，必须以同一 1.0 发布清单重新验收。页面、健康接口、静态资源和构建清单要共享一个 `releaseVersion=rolecraft-1.0`；`agent-system-v0.12` 与 `workbenchVersion=local-workbench-0.11` 可作为兼容协议字段保留，但不能再被误写成发布版本。

1.0 的产品结论只允许写成“限定范围可用/待复验”。它不授予职业认证、岗位胜任、就业结果、真人专家认可、行业领先、真实模型生成能力或生产可靠性。

## 2. 目标用户与核心任务

产品服务三类公开任务：

| 用户类型       | 进入问题                | 1.0 应完成的任务                         | 完成证据                    |
| ---------- | ------------------- | ---------------------------------- | ----------------------- |
| 新人         | 不清楚 Agent 开发岗位和学习起点 | 输入目标或约束，选择已发布职业，按当前任务阅读并完成一个练习入口   | 当前职业快照、当前任务状态、练习提交/证据状态 |
| 业内人士/面试准备者 | 想核对某个机制、失败模式或面试主题   | 用自然语言找到具体教材小节和原文，回到题库/练习或继续阅读      | 请求状态、版本化引用、打开小节记录、本人自述  |
| 专业人士       | 已有经验但发现知识盲区         | 在当前职业教材内定位解释、比较、复习或下一步练习，并保留可回看的来源 | 检索卡、当前/历史版本、练习作品证据和复盘记录 |

主流程固定为：**确认当前任务 → 阅读/检索 → 完成练习 → 提交作品证据 → 获得反馈状态 → 复盘并选择下一步**。阅读、浏览、题目自评和本人自述都不能自动变成“已掌握”。

## 3. 1.0 必须交付的产品能力

### 3.1 单一当前任务入口（P0）

首页只突出一个“当前任务”主卡，至少显示当前职业、当前阶段/章节、任务目标、预计动作、产物/证据提示和唯一主按钮。目录、工程全景、检索助手和低频工具都是次级入口，不与主行动使用相同视觉权重。

主卡必须能表达四种事实状态：

1. **未开始**：没有有效当前版本阅读足迹，动作是“开始学习”；
2. **进行中**：有有效位置，动作是“继续学习”；
3. **已中断**：上次任务有明确中断位置或失败原因，动作是“恢复任务/查看原因”；
4. **本任务已浏览**：当前任务浏览动作完成，动作是“回顾或提交证据”。

这些是产品流程状态，不是能力等级。刷新、后退、关闭助手和换职业时，主卡不得把旧职业或旧版本误当当前任务。1.0 的产品验收必须让首次进入、已有记录、已中断和已浏览用户各自只有一个清晰的下一步；“5 秒内说出下一步”留给用户研究取真实证据，静态 UI 不能代替该证据。

### 3.2 职业输入与确认边界（P0）

`career_input` 只探索 `status=published` 的职业目录：

- 输入自然语言后返回 1–3 个候选，显示标题、匹配理由、仍需确认的差距、职业内容版本和建议起点；不显示未经校准的百分比或“你一定适合”；
- `React` 等多义表达返回最多 3 个澄清选项，不能替用户选定；目录外职业返回 `no_match`；目录或教材暂不可用返回 `unavailable`；
- 推荐、查看路径、取消和换候选均不写账户；只有用户点击“确认选择”并通过服务端重新核对 `published`、教材版本、索引版本、教材 ID 和 corpus hash 后才允许改变当前职业；
- 没有独立教材 corpus 的动态职业保持 `unavailable/career_content_unavailable`，不回退到 Agent 教材；
- 确认使用幂等键和版本快照，冲突返回可恢复错误；跨重启幂等是否支持必须在 1.0 QA 中明确标记，不能以进程内 map 证据替代。

### 3.3 有出处的学习内容检索（P0）

`learning_input` 只能消费当前职业绑定的公开教材索引和正文，支持定位、解释、比较、规划、复习和下一步练习。每张肯定结果卡必须包含：

- 用户意图/结果类型、候选小节、单元与小节标题；
- 原文摘录和稳定定位链接；
- `textbookVersionId`、`contentVersion`、`corpusHash`、`indexVersion`、`unitId`、`sectionId`、来源路径和 `sourceSha256`；
- 一句话“为什么推荐”、匹配依据、限制/不确定性和实际 `engineMode`；
- “阅读这一节”“查看出处”“复制引用”及必要的重试动作。

检索助手按设计复盘采用默认折叠的“问教材”入口和侧抽屉；打开/收起不丢输入、当前章节上下文、查询历史、结果滚动位置或焦点。`useCurrentContext` 默认关闭，只有用户主动开启当前章节后才发送位置。返回状态必须可见且可恢复：`pending`、`recommended`、`needs_clarification`、`no_match`、`related_uncovered`、`unrelated`、`unavailable`、`invalid_input`、`stale_version` 和 `anchor_unavailable`。服务故障不得伪装成无匹配；规则降级要明确写“当前使用规则检索”，不能称为通用语义模型或外部模型。

无匹配给改写示例或课程目录入口，歧义先给选择，失败给重试/目录入口，来源失配要求刷新；任何结果不能没有教材版本和原文定位，也不能自动改教材、学习记录、能力字段或题目答案。

### 3.4 练习—作品—反馈最小闭环（P0）

课程架构师与产品经理共同指定至少一个 1.0 试点单元，声明：问题与输入、产出类型、完成条件、正常路径、关键失败路径、运行/截图/日志证据、评分维度和下一步复盘。工作台提供草稿保存、提交证据、查看反馈状态和回到来源小节的路径。

记录至少区分：`draft`、`self_report`、`ai_suggestion`、`professional_review`、`human_review`，以及作品流程状态“未开始/已提交/待独立复验/复验发现问题/证据不足”。缺证据时不得显示“已掌握/已通过/可录用”；版本升级不得覆盖旧提交。AI 建议、专业审校、真人评审和学习者自述必须分层显示并可回链到提交证据和课程版本。

1.0 不要求一次性为全部 30 个 v12 单元伪造独立评审；未具备练习合同的单元显示真实的“尚未提供练习/证据”状态，并进入后续责任清单。

### 3.5 题库、复习与自评可发现性（P0）

当前题库、复习、检验实现存在但主导航仍可能显示“后续开放”。1.0 必须修正产品矛盾：学习主导航或当前任务卡一次点击可到达题库、复习和检验，实际页面不得再显示占位文案。

- 题库标明当前题组身份、教材来源和版本；固定 100 题与市场补充 14 题保持集合身份，不删除历史集合；
- 复习只读取当前版本且本人标记为 `weak` 的题，记录“仍未掌握/已掌握”的时间、题目版本和自评性质；
- 检验只从当前版本已访问知识点抽题，排除需要真实个人经历的题，题数不足要诚实显示；结果是本次自评，不改变专业审核、真人评审或能力认证状态；
- 每题能回到对应教材知识点和原文；题库、复习和检验的版本标记必须与 1.0 发布清单一致。

### 3.6 版本、历史和来源身份（P0）

1.0 页面、服务、静态资源、教材索引、题库数据和构建清单必须有同一发布身份，并能显示当前内容版本。当前 v12 语料 hash `1a385b179c0cb8a5b838d17b9d2606a0c1a7e27636d97db45dba5e2a52b2840e`、v12 教材和历史 v10 的身份继续保留，具体冻结值以 1.0 收到清单为准。

历史教材/记录使用明显的“只读历史”标识，不显示与当前内容相同的主操作；检索结果、练习提交、笔记、收藏和导出均带职业、版本、来源和必要 hash。若当前正文与索引 hash 不一致，相关目录、检索和学习查询进入 `unavailable/stale_version`，不得静默使用旧索引或旧摘录。

### 3.7 视觉优先与可恢复状态（P0/P1）

按 `DESIGN_COMMUNICATION_STANDARD.md`，当前位置、主任务、步骤关系、状态和操作结果优先用卡片、边界、图标、箭头、徽章和布局表达，文字只补精确命名、无障碍名称、来源和真实错误。

1.0 至少交付并实现：当前任务卡、问教材胶囊/抽屉、加载/无匹配/歧义/失败/规则降级/成功结果七态、当前/历史版本徽章、练习证据状态槽。状态不能只靠颜色；问答打开时正文末段、保存、分页和练习提交仍可见可聚焦；关闭后焦点回到触发控件。

## 5. 明确延期到 1.1 或另行授权

以下事项不因 1.0 本地候选完成而自动进入发布，也不得用占位文案假装已具备：

- 跨设备账户同步、冲突处理、导出/删除策略的完整生产实现；
- 由诊断与独立作品证据自动调整路线、完整产品创造七阶段和八门槛闭环；
- 真实模型供应商调用、外部协议、沙箱、OAuth、MCP/A2A、持久生产恢复、RPO/RTO、限流和真实账单；
- 公网 80/443、域名/DNS、PM2/Nginx 和面向外部试点的线上服务；
- 真人学习者任务完成、学习迁移、作品独立评分、真人专家技术审核、竞品公平比较和运营经济基线；
- 就业、岗位认证、职业胜任、行业先进或自动生成可靠教材的承诺。

其中 A1 路线图是否采用、信息密度和最小状态集合仍须产品经理与设计师共同决策；在 A1-00 形成前，P0“继续学习”四态卡不等于正式路线图，课程架构师和客户端不得自行创造路线状态字段。

## 6. 不可降低的旧门槛与保护对象

1.0 只新增版本合同，不改动原八门槛、历史 QA、冻结教材、题集分母、账户边界和用户记录。当前完整目标状态继续为：

| 原门槛                     | 当前状态              | 1.0 不得声称的结果           |
| ----------------------- | ----------------- | --------------------- |
| `user_value`            | `insufficient`    | 真实用户价值、留存和完成效果        |
| `teaching_quality`      | `insufficient`    | 真人专家确认、真实学习效果         |
| `real_generation`       | `fail`            | 真实模型/档案驱动生成           |
| `comparative_advantage` | `insufficient`    | 同条件行业优势或先进性           |
| `learner_creation`      | `insufficient`    | 学员陌生任务、MVP 和独立作品能力    |
| `reliable_delivery`     | `fail`            | 公网生产、恢复和稳定服务          |
| `operating_economics`   | `insufficient`    | 真实成本、预算和维护经济性         |
| `iteration_trace`       | `pass`（仅已记录的局部闭环） | 新版本不自动继承旧通过，仍须重新冻结和复验 |

保护对象包括 v10/v12 教材源和 hash、历史 v0.12/0.15 交接、原八门槛与缺陷链、固定 100 题/市场 14 题/原型题集合身份、正式账户数据库和浏览器历史。测试必须使用隔离临时数据，不迁移、删除或覆盖正式记录。

## 7. 岗位交接顺序

1. 产品经理冻结本合同、1.0 发布清单模板、试点单元 ID 和事件/状态字段；不修改教材或代码。
2. 设计师交当前任务卡、抽屉七态、版本/证据状态和窄屏/无障碍视觉稿；视觉优先但不替工程实现。
3. 课程架构师/教材研发员交试点单元的练习与作品证据规格；内容审校员核论断、来源和边界。
4. 内容检索工程师绑定当前教材索引、来源 hash、版本和无匹配/歧义状态；不得编教材外答案。
5. 软件工程师、后端数据工程师按合同实现客户端、接口和隔离记录；不得把协议兼容字段当发布版本，不得改账户/正文范围。
6. 测试工程师冻结当前源后独立执行 V1-01～V1-09；发现缺陷交唯一责任岗返修，返修后按原例和受影响范围复验。
7. 项目经理汇总版本、证据、缺口、责任、复验和整体 `not_met`，更新复盘账本；不能以本文件或任务完成关闭完整产品门槛。

## 8. 产品自查与当前结论

已完成：三类用户任务、主流程、1.0 核心范围、状态与来源边界、视觉与可恢复要求、延期项、验收 ID、岗位交接和旧门槛保护。

未完成：当前实现尚未按本合同冻结并由独立 QA 复验；真实浏览器/HTTP、真人理解、真人专家、学习效果、生产部署、真实模型和成本证据均未形成。因此本文件把 1.0 定义为可实施的**本地候选产品合同**，不把产品复盘、设计复盘或历史局部 QA 改写成 1.0 通过。
