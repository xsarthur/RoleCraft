## 真正生成教材时的状态呈现

以下是已提出生成流程的界面状态规范建议，是否纳入首版及允许的操作需产品经理确定；内容审核条件由课程架构师提供，设计师不定义审核标准。

| 状态 | 页面必须让用户理解的内容 | 建议交互 |
| --- | --- | --- |
| 尚未生成 | 职业、基础、目标、预计产出及资料范围 | 显示待确认摘要与清晰主操作 |
| 排队／生成中 | 当前阶段、已完成章节、更新时间 | 保留已完成内容；显示实际阶段，不编造百分比或剩余时间；允许操作由产品确认 |
| 部分完成 | 哪些章节可读，哪些尚未完成或失败 | 章节列表逐项标状态，避免整本教材显示“完成” |
| 生成失败／资料不足 | 失败阶段、已保留内容、可执行下一步 | 保留原始输入与已完成章节；重试针对失败步骤，重复点击期间避免重复提交 |
| 待审核／审核未通过 | 生成与审核是不同状态，审核结果和问题指向 | 章节头部展示审核状态；未通过意见定位到具体段落或示例 |
| 已发布 | 教材版本、适用环境、来源核对时间及各项审核证据 | 章节级展开查看来源与审核详情，避免用单个“已认证”概括全部证据 |
| 来源过期／待更新 | 哪一来源或示例需复核，受影响章节 | 使用文字＋图标提示；更新时保留旧版阅读与进度衔接，迁移规则交产品确认 |
| 保存失败／离线 | 当前内容是否保存、保存位置和恢复方式 | 使用就地持久提示；数据恢复后更新状态，无需用户猜测 |

## 给软件工程师的交互规范

1. 主导航保留可见中文名称；图标作为辅助。每次切换更新当前项，新页面标题可聚焦，浏览器历史能恢复之前页面。章节状态用文字表示“未学／概念测验通过／待审核”等，概念结果与作品评审分开展示。
2. 档案弹窗使用标题和说明关联；打开后焦点进入弹窗、关闭后回到触发按钮；支持 Escape；提交后焦点进入路线标题。调整档案后的保留与重置规则必须明确展示，并遵循产品交接。
3. 备注就地展示保存状态；自动保存成功不频繁读屏播报，失败及时播报并持久展示。失效的主操作给出原因与下一步，不能只降低透明度。
4. 同一章节同时显示生成、来源核对、示例运行、专业审核等独立字段，状态由实际数据驱动。等待页提供文字阶段与更新时间；状态变化用温和播报，不抢焦点。
5. 建议普通文本至少 14 像素，正文 16 像素左右、行高 1.7–1.9；必要的小标签不承载关键信息。普通文本对比度目标至少 4.5:1，较大文字至少 3:1。绿色仅辅助表达通过状态，失败和过期必须配文字。
6. 建议触控操作区至少 44×44 像素；320 像素宽时主页面不横向溢出，代码区允许独立滚动；200% 缩放仍可读可操作。焦点可见样式覆盖按钮、链接、表单与代码滚动区；减少动态效果偏好下禁用平滑滚动。

## 给测试工程师的界面验收点

这是一份待执行清单，本次没有宣称任何检查通过。

- 320、375、768、1024、1440 像素布局及 200% 缩放：导航可理解、标题／操作不重叠、正文不截断、代码独立滚动。
- 仅键盘完成导航、档案调整、章节切换、测验和项目备注；每一步能定位焦点，弹窗不泄漏焦点并正确返回。
- 读屏检查当前页面／章节、测验选中和结果、弹窗标题、保存失败与生成阶段变化；不能仅靠颜色获取状态。
- 检查实际文本对比度、触控区域和减少动态效果偏好；记录浏览器、视口、复现路径及截图。
- 刷新、后退／前进与直接链接访问，页面和教材章节恢复一致；输入备注后导航不丢失用户已输入内容。
- 未来接入后覆盖生成失败、部分完成、审核未通过、来源过期和保存失败，检查提示是否与真实状态一致以及重试是否保留既有成果。

下一步输入依赖：产品经理确认首版范围及状态可用操作；课程架构师提供章节结构和审核字段。设计师据此完善页面流程，工程师实现，测试工程师独立执行上述验收。
