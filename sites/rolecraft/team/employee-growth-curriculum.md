# 数字员工职业培养体系 · 课程架构

日期：2026-10-14  
责任岗位：课程架构师  
版本：`employee-growth-v1.0`  
状态：`training_specification_ready_not_assessed`

本文件把“交付时专业负责，并在工作中持续提升技能与专业知识”落成可执行的共同课程规格。它是训练与证据的设计，不是任何员工的能力结论、职业认证、真人专家意见、用户效果或行业先进性结论。实际结论必须由对应责任岗位产出、由独立测试或专业复核按当前版本验证。

## 1. 适用范围和边界

体系适用于当前十五个岗位：项目经理、产品经理、课程架构师、设计师、软件工程师、测试工程师、教材研发员、AI生成工程师、后端数据工程师、用户研究员、竞品研究员、实训评估员、运营分析员、内容审校员、内容检索工程师。

培养结果分成两条账本：

- **交付账本（Delivery）**：本次任务合同是否完成、产物是否满足该岗位的验收门槛。
- **成长账本（Growth）**：是否有独立证据证明某项能力在新情境中提高。

一条账本不能覆盖另一条。读完教材、提交文件、自评、模型评分、字数、调用次数或任务结束都不能单独证明能力。没有真实用户、同行、真人专家或生产证据时，必须写明缺口。

本课程架构只写共同能力、学习路线、岗位学习规格、练习合同和证据要求；不改应用、数据库、用户记录、旧教材、产品需求、历史QA或其他岗位的交付物。岗位专业标准由岗位责任人维护，测试工程师负责独立核验，项目经理负责协调与汇总。

## 2. 七维能力矩阵

每个岗位按同一七维框架描述本领域能力。岗位专属知识放在第6节，不能用共同描述抹平领域差异。

| ID | 能力维度 | 可观察行为 | 主要证据 | 不能作为证据 |
| --- | --- | --- | --- | --- |
| `D1` | 职责、边界与判断 | 说明自己的唯一责任、权限、禁止越界和升级条件；遇到缺证会暂停或拒收 | 任务合同、范围变更、拒收/升级记录 | 口头宣称“知道边界” |
| `D2` | 专业知识与机制 | 用本领域概念解释机制、版本、假设、取舍和适用边界；能指出未知 | 带来源的解释、机制图、版本绑定的决策记录、反例分析 | 术语清单、背诵答案、未核来源 |
| `D3` | 受约束的任务执行 | 在给定输入、工具、时间和预算内完成可复现产物；记录环境和失败 | 产物、运行/观察记录、输入输出哈希、成本/耗时 | 截图、一次成功演示、未运行伪代码 |
| `D4` | 质量、风险与恢复 | 识别正常/边界/失败；保护数据、权限、版本和安全；按证据恢复或停止 | 独立反例、缺陷、回滚/恢复、拒绝和升级轨迹 | “看起来正常”、删除首次失败、把模拟写成真实 |
| `D5` | 协作、交接与可复现 | 交付目标、依赖、接口、来源、已验证/未验证、风险和复验步骤；能接收或有据拒收 | 版本化交接包、接收确认、复验命令、跨岗反馈 | 仅转发文件、含糊的“请查看” |
| `D6` | 产品与行业创造 | 从真实问题、用户/行业证据和已有方案提出可证伪假设，比较可比条件并迭代 | 问题证据、竞品矩阵、实验设计、作品/反馈/迭代链 | 营销声称、合成材料冒充用户研究、功能数量 |
| `D7` | 复盘、迁移与教会他人 | 从失败找根因，提出可验证改进，在留出或未知任务迁移，并让另一人复用 | 复盘卡、原例与留出变体、返修差异、辅导记录 | 自我总结、只在原题调参、训练天数 |

每条能力主张至少绑定一个任务版本、一个证据条目和一个独立复核状态；安全、权限、隐私、数据破坏和错误对外承诺属于强制阻断维度，不得用其他维度平均抵消。

## 3. 成长层级与晋级规则

层级描述“在什么证据条件下可承担什么复杂度”，不是薪酬级别，也不是永久标签。层级变更保留旧结论和失败记录。

| 层级 | 目标 | 最低可观察证据 | 允许承担的任务 | 不满足时 |
| --- | --- | --- | --- | --- |
| `L0` 准备与边界 | 理解岗位章程、共同基础、工具/资料边界和停止条件 | 入组诊断、岗位边界复述、至少一项失败识别；关键边界错误记为阻断 | 只做阅读、示范观察和无副作用练习 | 补共同基础或边界训练；不能独立交付 |
| `L1` 受指导贡献 | 按模板和脚手架完成小任务并正确交接 | 两个不同夹具的沙箱工件；七维均有初步证据；独立复核无P1 | 低风险、隔离、可回滚任务；需指定指导人复核 | 保留L1；返修后重跑原例，不能只凭提交关闭 |
| `L2` 独立交付 | 在真实形状的受控任务中独立完成，并处理已知反例 | 一次隔离真实任务、一次留出变体、失败恢复和完整交接；无未关闭P0/P1 | 有边界和回滚的内部真实任务；仍需独立复核 | 留在L1或标记`insufficient_evidence`，补练习/补证 |
| `L3` 稳健负责 | 在版本冲突、资源变化、权限/风险边界和多方交接下保持稳定 | 两个周期、两个情境的连续证据；最差案例复验；能修复系统性缺陷并让他人复用 | 复杂跨岗交付、方案取舍、复盘与指导 | 不授L3；列缺口、责任人与下一周期复验 |
| `L4` 产品创造与领域带教 | 用真实问题和外部可比证据创造/验证新方案，沉淀可迁移方法 | 真实用户/同行/专家或生产反馈链、可比测量、迭代结果；能审慎教会他人 | 设计新产品切片、定义领域标准、带教和校准 | 保留L3或以下；没有外部证据时只能写“待验证” |

晋级必须由当前任务合同指定的独立复核人确认；作者不能自审自己的晋级，课程完成率不能替代晋级。`pass_with_limitations`不得直接升级到要求处理未知任务的层级；`fail`和`insufficient_evidence`必须保留并安排复验。

## 4. 共同培养路线

所有岗位走同一骨架，再接岗位专属模块。课程架构师维护学习规格，岗位责任人提供领域内容，测试或内容审校岗位独立核验。

### 4.1 入组诊断（D0）

在开始学习前冻结岗位、版本、环境和诊断夹具。每人完成以下五项，结果写入成长账本，不因补学覆盖：

1. **边界题**：说明自己的责任、不做项、升级条件和不可使用的权限。
2. **机制题**：解释一个岗位核心机制，指出假设、版本和未知。
3. **熟悉任务**：在脚手架下完成一个低风险小任务并交接。
4. **失败识别**：从含一个已知缺陷的产物中定位预期/实际差异和风险。
5. **迁移预告**：对未见过但同能力的短任务写出计划、停止条件和需要的证据，不要求马上完成。

诊断输出：`diagnostic_id`、岗位和岗位版本、题目/夹具哈希、环境、原始回答/产物、每一维观察、阻断风险、建议补学、独立复核人和状态。诊断只给出起点（通常L0或L1），不授予职业能力。

### 4.2 共同基础

共同基础先于岗位专属学习，最少覆盖：

- 任务合同、唯一责任和范围变更；
- 证据账本、版本/hash、来源与未验证标记；
- 正常/边界/失败三类验证、缺陷等级和复验；
- 数据、权限、隐私、密钥和外部副作用的基本边界；
- 交接包、接收/拒收、依赖和升级；
- 复盘根因、改进行动、留出变体和迁移；
- 合成/离线/模拟、真实用户、真人专家和生产证据的区别。

共同基础可以引用v10/v12已有正文；学习者仍需按诊断补学，不能用阅读记录直接标记掌握。

### 4.3 岗位专属模块

先读岗位章程与领域标准，再从本岗位课程/教材进入机制、案例、反例、实作和交接。每个岗位至少形成一个岗位作品（`W-role-*`）和一个未知任务（`U-role-*`）。第6节给出首版锚点，不限制领域负责人增加内容。

### 4.4 练习到真实任务的梯度

1. **沙箱/脚手架**：虚构身份、数据和工具替身；无外部副作用；练习机制和停止条件。
2. **沙箱/独立实现**：学习者独立选择方案、记录版本和失败；仍隔离、可重置；由指导人提供反例。
3. **真实形状的隔离任务**：输入结构与真实工作相同，使用临时数据或脱敏副本；允许回滚；测试岗位冻结锚点和留出变体。
4. **内部真实任务**：取得明确授权和任务合同，限制权限、预算、时间和外部写入；责任人交付，独立岗位复核。
5. **未知/迁移任务**：非作者保留新情境或改变一个关键约束；学习者不能预先调参；复验迁移和停止判断。

升级梯度必须逐级有证据。沙箱成功不能写成真实效果；真实任务的偶然成功不能跳过未知任务。

## 5. 练习合同与证据规格

每项练习、作品或未知任务必须有以下字段；缺字段就标`insufficient_evidence`，不靠补写叙述关闭。

| 字段 | 要求 |
| --- | --- |
| `exercise_id` / `exercise_version` | 稳定ID和变更版本；旧版不可覆盖 |
| `role_id` / `owner` / `reviewer` | 唯一责任岗位、执行人、独立复核人；作者不得兼任独立复核 |
| `level_target` | 目标层级（L0–L4）及所需七维 |
| `purpose` / `user_scenario` | 要练的机制、真实问题形状和不做项 |
| `prerequisites` | 课程单元、先修证据、诊断补学路径 |
| `mode` | `sandbox_scaffold`、`sandbox_independent`、`isolated_real_shape`、`internal_real`、`unknown_transfer` |
| `inputs` / `fixtures_hash` | 输入、身份、权限、数据来源和夹具哈希；合成资料须明示 |
| `constraints` | 时间、预算、工具、网络、数据、权限和副作用限制 |
| `expected` / `acceptance` | 正常、边界、失败的可观察预期和通过条件 |
| `submission` | 代码/正文/设计/研究/数据/交接包等实际产物及路径 |
| `evidence` | 日志、运行命令、版本、来源、截图/快照、反馈和哈希；伪代码标未运行 |
| `failure_and_rework` | 首次失败、缺陷级别、返修版本、原例复验、受影响回归和残余风险 |
| `transfer_case` | 留出/未知任务、只改变的约束、迁移结果和未测范围 |
| `decision` | `pass`、`pass_with_limitations`、`fail`、`insufficient_evidence`，含理由 |
| `next_action` | 补学、责任人、截止日期和复验方法；关闭前不得删记录 |

练习必须至少包含一条“停止/拒绝/升级”行为；需要外部副作用时先用替身，再由产品与后端等责任岗位明确授权。测试工程师记录证据和结论，不替作者补正文或修代码。

岗位学习应链接到岗位现有标准、教材和交付记录；本表不授予任何岗位当前通过状态。

## 7. 复盘、返修与迁移

### 7.1 复盘卡

每周异步记录高影响或重复偏差，每月校准矩阵。复盘卡字段：事实（目标/基线/版本/环境）、偏差（预期/实际/首个失败）、根因假设（需求/知识/实现/协作/验证/资源）、停止/降级/修复决策、要补的知识、改进行动、唯一责任人、截止日期、证据、原例回归和状态。

复盘只关闭改进行动，不删除首次失败。复验顺序是：同夹具原例 → 受影响回归 → 一个留出变体；若夹具或环境无效，关闭的是夹具问题并重建证据，不把产品/能力改判通过。

### 7.2 迁移

迁移任务由非作者冻结，至少改变一个维度：用户目标、数据形状、权限/版本、工具错误、资源限制或协作对象。记录学习者选择、停止判断、修改的假设和证据。只在原题上调参、背出教材、由指导人逐步提示完成，都只能保留为练习证据，不能算未知迁移。

### 7.3 30/60/90日复验

- **D0**：完成诊断、冻结合同和基线；输出L0/L1起点及补学路径。
- **D1–30**：共同基础、两个不同沙箱夹具、一次拒收/补件；目标L1。
- **D31–60**：一个隔离真实形状项目、一个陌生变体、一次失败恢复和跨岗交接；目标L2。
- **D61–90**：版本/权限/资源至少两个变化的综合未知任务、返修与回归、一次帮助他人复盘；具备连续证据时才建议L3。

每个检查点记录四种结果（`pass`、`pass_with_limitations`、`fail`、`insufficient_evidence`）、P0–P3、缺陷逃逸、证据完整率和未测范围。L4需要另行收集真实问题、可比行业证据和外部反馈，不能由90日训练自动授予。

## 8. 与现有教材和内容检索Agent的关系

### 8.1 v10教材

`textbooks/v10/`提供20单元工程全景、运行闭环、任务验收、信任边界、检索、工具、持久恢复、评价、安全、成本和独立交付等专业正文。它作为共同基础和Agent开发岗位的机制深读来源；阅读顺序、章节原文和历史SHA保持原记录。课程体系只引用和安排诊断/练习，不把v10阅读完成写成能力通过。

### 8.2 v12教材

`textbooks/v12/`把原20单元与10个问题驱动专题合成30单元，补充Python/模型基础、上下文记忆、规划反思、工具/MCP、进阶检索、图、多Agent、评估项目、沙箱和长任务运行。v12的正式先修、练习和作品规格是Agent开发岗位的主干专属路径；其作者/审校/QA状态和未验证限制照原记录保存。其他岗位借用相应单元时，要把机制翻译成本领域任务并重新取得本领域证据。

### 8.3 内容检索Agent

内容检索Agent只做“用户表达 → 当前公开教材的小节候选、原文、来源和定位”，不编写新教材、不回答教材之外的业务问题、不确认职业能力。训练中可把它当作学习入口和取证工具：

1. 以当前教材版本/索引版本检索相关章节；
2. 学习者打开原文，写出机制解释和练习合同；
3. 记录查询、候选、来源哈希、歧义/无匹配和实际阅读位置；
4. 由课程/岗位责任人判断是否适合作为先修或补学材料；
5. 由测试或内容审校验证引用与版本，不能把检索命中率推成学习效果。

规则降级、离线语义模型和真实外部模型调用必须在记录中分开。当前本地检索默认使用版本化公开教材索引和本机语义模型；缺模型、版本失配、无匹配或复杂歧义应诚实返回不可用/需澄清。检索Agent返回章节不是对学员的答题代写，也不能作为L1–L4独立证据。

## 9. 记录、责任和状态词典

建议在团队记录中维护：诊断卡、任务合同、练习证据卡、交接包、复盘卡、独立QA和能力快照。所有记录至少保存岗位、版本、输入/夹具哈希、环境、责任人与复核人、原始结果、限制和下一次复验。

状态只表达证据状态：

- `planned`：规格已写，尚未执行；
- `in_progress`：有执行记录，尚未独立复核；
- `pass`：合同、证据、反例和独立复核均满足；
- `pass_with_limitations`：主流程通过但限制已登记，不能跳过对应未知门；
- `fail`：阻断缺陷或复验失败；
- `insufficient_evidence`：未运行、版本/环境/输入输出不完整或不可复现；
- `not_assessed`：本体系或员工尚未接受该检查点。
