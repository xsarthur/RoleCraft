M102｜把请求状态放进Python列表或字典时，别名与浅拷贝会怎样污染另一个任务？请说明不可变容器的边界，并解释如何用装饰器封装工具日志而保持函数行为。

答案版本：interview-answers-v1.0.0。完整参考解析；示例及测试计划未由本稿执行。

Python赋值共享对象，浅拷贝只复制外层容器。若两个请求共享内层messages，某请求追加结果会污染另一个请求；这与是否多线程无关。不可变外层也不递归冻结成员，因此“tuple里放list”仍可变。

下面是未执行的完整小例，可在Python 3.14离线运行：

python · 仅供阅读
from copy import deepcopy

a = {"messages": [{"tags": []}]}
b = a.copy()
assert a is not b
assert a["messages"] is b["messages"]
b["messages"][0]["tags"].append("B")
assert a["messages"][0]["tags"] == ["B"]
c = deepcopy(a)
c["messages"][0]["tags"].append("C")
assert a["messages"][0]["tags"] == ["B"]
t = ([],)
t[0].append("still mutable")
assert t[0] == ["still mutable"]

设计上每任务创建独立可变状态，共享不可变资料快照；不要使用可变默认参数如messages=[]。deepcopy适合明确的纯数据树，不适合复制连接、锁或身份上下文；持久化的并发覆盖还需revision/事务，深拷贝不能解决。上述对象边界与Python copy文档一致，核查于2026-10-14。

日志装饰器应观察调用，不改变参数、返回值和异常，也不暗中重试。同步函数包装真正调用，异步函数包装真正await；否则记录到的只是coroutine对象创建。下面是未执行的同步/异步实现，日志只写函数名和状态，不写敏感参数，普通日志故障采用尽力忽略策略（生产应有独立丢日志计数）。

python · 仅供阅读
import asyncio
import inspect
from functools import wraps

def logged(emit):
    def safe_emit(event):
        try:
            emit(event)
        except Exception:
            pass  # 教学策略：日志错误不覆盖业务返回或异常

    def decorate(fn):
        if inspect.iscoroutinefunction(fn):
            @wraps(fn)
            async def async_wrapper(*args, **kwargs):
                status = "raised"
                try:
                    value = await fn(*args, **kwargs)
                    status = "returned"
                    return value
                except asyncio.CancelledError:
                    status = "cancelled"
                    raise
                finally:
                    safe_emit((fn.__name__, status))
            return async_wrapper
        @wraps(fn)
        def sync_wrapper(*args, **kwargs):
            status = "raised"
            try:
                value = fn(*args, **kwargs)
                status = "returned"
                return value
            finally:
                safe_emit((fn.__name__, status))
        return sync_wrapper
    return decorate

wraps保留常用元数据与__wrapped__，不自动保证业务语义；本装饰器不处理异步生成器、生成器或同步函数返回awaitable的特殊接口，应另定义合同。functools.wraps，核查于2026-10-14。

验证时给原函数一个唯一返回对象，要求包装后仍是同一对象；让它抛预先创建的异常，要求异常对象不被换成None；取消异步任务后核finally事件和CancelledError继续传播；检查名称/文档和默认参数调用不变。再让emit抛普通异常，业务结果仍保留。别名测试必须真正修改最深层成员并核另一任务不变，只比较初始值相等发现不了共享。代码和这些验证步骤尚未在本稿实际执行。

1 对象共享必须是设计选择

`state2 = state1` 只给同一个对象另一个名称。`state1.copy()` 会产生新的外层字典，但它的 `messages` 值仍可指向同一个列表。于是两个请求看似有独立状态，第二个请求 append 一条工具结果时，第一个请求也看到了它。这不需要多线程，只要共享可变对象就会发生。
