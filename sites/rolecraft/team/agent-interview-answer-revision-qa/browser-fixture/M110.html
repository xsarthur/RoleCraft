M110｜提示模型返回JSON、使用JSON模式和按Schema约束生成分别能保证什么？遇到拒绝、截断、类型合法但语义错误时，应用怎样处理？

答案版本：interview-answers-v1.0.0。完整参考解析；示例及测试计划未由本稿执行。

三种方式约束的层不同。“请返回JSON”只是提示，模型仍可能输出解释、代码围栏或残缺文本；JSON模式通常约束可解析JSON，但未必约束字段和类型；按Schema约束生成可进一步限制服务所支持的结构。三者都不能证明字段指向正确业务对象，也不能授权工具执行。具体服务支持的Schema子集、拒绝和截断语义必须读当前接口合同。Claude结构化输出文档为一种服务示例，核查于2026-10-14；以下内部信封不是其SDK格式。

消费顺序是传输/完成状态→拒绝或截断→解析→结构→语义/证据→当前授权→业务候选。拒绝是明确状态，不是坏JSON；截断时即使前缀可解析也不能当完整业务结果；流式预览只能显示进度，完整验证前不能触发副作用。重试是受限策略，保留原错误与用量，不能用补括号把不完整动作悄悄变成可执行。

import json

def consume(envelope, expected_id):
    status = envelope["status"]
    if status == "refused":
        return "REFUSED", None
    if status != "complete":
        return "INCOMPLETE", None
    try:
        obj = json.loads(envelope["text"])
    except (ValueError, TypeError):
        return "INVALID_JSON", None
    if type(obj) is not dict or set(obj) != {"report_id", "failed"}:
        return "INVALID_FIELDS", None
    if type(obj["report_id"]) is not str or type(obj["failed"]) is not bool:
        return "INVALID_TYPES", None
    if obj["report_id"] != expected_id:
        return "SEMANTIC_MISMATCH", None
    return "CANDIDATE_REQUIRES_EVIDENCE", obj

{"report_id":"r2","failed":true}结构合法却属于另一报告，应返回SEMANTIC_MISMATCH；failed:1不能因为Python的bool/int关系被误当布尔值；多出的admin:true字段要拒绝而不是合并进身份。即使是r1/true，也只是候选，必须核r1实际报告和来源支持，不能把Schema成功当事实已核。

处理策略按原因区分：格式失败可在剩余预算内带明确格式错误重试；资料缺失要补证或等待；语义错对象要重建正确上下文，不能强改ID掩盖问题；权限失败要拒绝，不向模型讨一个新说法；服务拒绝须按拒绝原因处理，不无限重试绕过。测试分别输入拒绝、截断、无效JSON、额外字段、错类型、错ID、无证据和完整合法对照，断言验证前无写调用，并保留每次尝试。本文未执行供应商结构化输出或该本地例。
