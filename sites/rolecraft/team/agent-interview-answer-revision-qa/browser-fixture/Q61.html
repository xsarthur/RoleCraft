Q61

原题

什么实验或业务证据会使你选择多 Agent，而不是给单 Agent 增加工具或步骤？

完整解析

选择多Agent需要证明可分工带来目标内收益，而不只是角色更多。先提出可被推翻的假设：某些子问题能独立调查，或需要不同权限/专长与独立复核，分开处理能减少特定错误；再以单Agent增加相同工具和合理步骤为强基线，在总预算相近时比较。

先排查单Agent失败原因。资料没入库、工具返回错误、任务定义不清时，多Agent大多会共同继承问题；若复杂度来自一个无法并行的外部写入瓶颈，增加研究者也不会加快该关键路径。真正适合分工的例子是政策证据与实现证据可独立读取，之后才汇合对齐；两者允许范围不同，也可用专业子任务减少无关上下文暴露。

构造实验：单Agent有读政策、读代码和核证工具；多Agent将前两项分别交给只读专家，协调者用同样标准汇总，最终写入仍只有一个所有者。固定任务、资料版本、模型等级、权限、输出要求、总调用/token/期限，记录成功率、无依据结论、冲突漏报、交接丢条件、重复工作、费用及端到端时延。各子任务的超时也保留在分母中，不能只比较成功的协作轮次。

业务证据还要回答收益对谁有用：目标用户是否少返工、处理同一难题是否更完整、同样质量是否减少等待。独立专业判断需要真实评阅，不是另开三个相同模型就能得到三份独立事实。若声称行业优势，需要可比对象和条件；本题的架构实验本身不构成这种证明。

可做消融：保持总预算但取消角色分工，或保留分工取消复核，分辨改善来自更长上下文、额外计算还是专业任务结构。多Agent若只让说明更长而关键错误未减，应放弃；若合格率微增但交接和维护代价超过产品容忍，也不值得。发现只在少量跨域题获益，可按需升级而非全量启用。

验证应包含双证据一致、冲突、一个必要节点超时、旧版本结果和重复写入风险。预期分工改善预先声明的缺陷，协调者仍拒绝无证据共识，缺席不当成功。本文给出可验证选择依据，没有实际多Agent收益或真实用户证据。

多 Agent 的升级点是可分工 而不是人数

升级多 Agent 的具体条件可写成可证伪假设：“两类证据能独立调查，在总预算不增的情况下减少漏掉测试夹具问题，且不会增加无支持根因和越权读取。”若实验只显示更长说明、更多引用而关键错误没有减少，就放弃升级。若瓶颈是一个不可并行的外部写调用，多 Agent 也不能移除它。

怎样做一个公平且能定位原因的比较
