Q4 · 工具调用、状态维护、规划和长期记忆，哪些取决于具体场景，并非每个 Agent 都需要？

版本：interview-answers-v1 / Q4-r1。本文为完整参考解析；案例和验证方案除特别注明外均为教学构造，未在本次写作中执行。

工具、显式计划和长期记忆都按任务需要启用；复杂持久化也不是每个 Agent 的标配。不可省的是能够解释当前运行的目标、已有观察、正在做什么和为什么结束；短时可重做任务可以只在内存保存，长任务或有外部副作用时则必须考虑持久恢复。不要把“无需长期记忆”误解为“无需任何状态”。

能力什么时候需要什么时候可以省
工具调用必须获取当前输入没有的事实，或执行获准环境动作已提供完整材料，只需一次分析或生成；这通常也无需动态 Agent
工作状态多步依赖、等待、预算、未决效果；需说明已做和待做不能完全省，但简单任务只需很小的临时状态
显式规划产物有依赖、可并行、需要预估资源或重新安排一步输出或固定短流程；逐步观察决策也未必先生成全计划
长期记忆跨任务稳定偏好、已核事实、可复用经验，并且有来源、作用域和更新规则一次报告、临时失败日志、一次批准，不应写入永久画像

一个最小化例子

用户提交完整报告，请求提取失败断言并解释差异。输入齐全时直接生成候选、核验引用即可：不需要检索工具、计划图或长期记忆。如果任务改为“调查未知根因，等待明天维护者审批后建单”，则需读工具、带目标版本的持久状态、准确批准和未决动作账本；是否需要显式计划取决于调查的依赖复杂度。明天恢复任务使用原账本，不需要把批准写成“用户总是同意创建工单”的长期偏好。

组件越多，新增的不只是存储或代码量，也包括错误记忆传播、工具误调用和计划失效的维护责任。可以做逐项删除实验：移除长期记忆后同一任务是否仍完成；移除规划后是否丢依赖；移除持久状态后写后崩溃能否核对原操作。若某项只让流程更长、没有填补缺失能力，就没有启用依据；若删除造成重复写或丢未决动作，它就是当前任务必须具备的工程能力。验证对象是任务语义和失败恢复，不是组件数量。
