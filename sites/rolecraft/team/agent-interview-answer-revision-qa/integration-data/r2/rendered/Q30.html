Q30 · Tool Calling、MCP、Agent Skills（可复用技能说明与资源包）和 A2A，分别解决什么问题？

版本：interview-answers-v1 / Q30-r1。本文为完整参考解析；案例和验证方案除特别注明外均为教学构造，未在本次写作中执行。

这四者处在不同层次，能够组合，不能因为都含JSON或“Agent”一词就相互替代。

机制解决的问题不自动提供的保证
Tool Calling模型用工具名和参数表达行动建议，宿主关联结果真正执行、权限、业务合法性
MCP宿主客户端发现并调用外部工具、资源与模板业务目标正确、下游幂等、任意客户端兼容
Agent Skills可复用的任务说明、参考资料和可选脚本按需加载远程通信、脚本执行授权、描述一定正确
A2A独立Agent系统之间交换任务、消息、状态和产物对方结论可信、整体验收通过、副作用自动撤销

这里Skills指题面中的说明与资源包；当前公开格式以SKILL.md及可选目录组织。MCP沿用2025-11-25教学版本；A2A仅作职责对照，实际接入应冻结双方协议版本与能力。

走一条组合流程

宿主加载“报告分析”Skill，知道应区分事实与假设；通过MCP发现获准的报告工具，并把其契约提供给模型；模型Tool Calling提议读R71，宿主校验后经MCP执行。如果需要一个独立政策研究服务，可经A2A提交有版本、范围和产物要求的子任务，再校验它返回的来源和状态。最后本地宿主承担整体合成与验收，必要写入仍沿自己的批准和动作账本。

若只有三个自有函数，直接Tool Calling适配可能足够，不必为形式引入MCP；若没有远端Agent，A2A没有必要；仅有Skill说明不能替代真正可调用的检索接口。反之，把远端Agent包装成“一个工具”也不能丢掉远端任务ID、等待、取消和产物语义。

检验是否分清了边界

把Skill中脚本改为要求发布，宿主应仍按任务权限拒绝；把MCP连接换成直接函数适配，Tool Calling模型提议的业务意义不变；让A2A任务返回completed但缺必需证据，整体任务仍不能通过；让Tool Calling输出合法JSON但跨租户，执行仍拒绝。测试这些反例能暴露混层设计，比背四个定义更有用。

采用这些层会增加版本、认证、观测和故障处理成本。每层只在确有复用、跨服务或跨Agent协作需求时加入，并对其实际合同独立验收；名称相同不意味着不同产品实现了同样的可靠性。
