# v0.11 学习工作台与内容检索交接

2026-10-11。岗位：设计师 `/root/design_workbench_v11`，仅负责信息架构、交互、视觉和可访问性。本文件不编写教材或应用代码，不重定产品门槛，也不代表新页面已实现或经用户验证。用户本轮明确要求根据原型与教材推进程序，添加按用户表达推荐内容的检索 Agent；此次程序授权覆盖以前的暂停范围，线上发布与真实付费模型调用仍不是本文范围。

## 给工程师的直接交接

1. 保留职造绿色品牌，把默认入口变成可直接开始阅读的 Agent 学习工作台。主区提供“学习路线 / 课程目录”切换，使用 v10 的 20 篇及原顺序，点击进入完整正文，不继续以 v0.6 单章示范作为当前教材。
2. 底部常驻一个“找教材”输入入口。提示为“描述你想解决的问题，我来找对应教材”。用户可直接阅读，不必先提问；展开检索结果时保留当前阅读位置，收起后继续阅读。
3. 展示“本地教材意图检索（未调用大模型）”，同时按实际 `engineMode` 区分系统句向量或本地概念检索，不能硬编码不存在的模型成功。推荐卡必须有真实章/小节、原文摘录、对应需求的理由和到正文的稳定链接；不显示生成式教学答案或虚构命中率。
4. `recommended`、`needs_clarification`、`no_match` 分别展示推荐、单一澄清问题、诚实无匹配说明。提交仅检索，不自动跳章、不记录掌握或职业胜任，不触发教材生成。
5. 输入旁展示学习起点及当前章上下文，可清除。保持用户输入、检索结果与其提交时的上下文绑定，翻页不能把旧结果伪装成针对新章的推荐。
6. 正文单列，桌面阅读宽度 680—760px，17px / 1.85 行高；移动 16px 起。v10 两张图原样展示，支持放大，图例和章节对应表仍可阅读；表格/代码只在自己的容器内横向滚动。
7. 保留当前标准、来源、项目、复盘、生成和历史教材入口，统一收进“更多工具”，不把内部验收材料铺在默认学习页。版本与验证详情放可展开的“教材说明”，正文保持完整且优先。
8. 键盘可以输入、发送、收起、打开卡片、跳到小节。跳转后焦点到真实目标标题；移动输入栏和键盘不得盖住页面末尾、操作或结果。

产品经理已确认上述界面边界及模式、无匹配文案。范围冻结依据为 `team/app-v11-product.md` 的 `app-v11-product-1`、APP11-01—06 与 R11-01—24；输入/错误/边界按其合同。每个独立意图最多3项，总结果最多6项，推荐理由与出处必需。本文不自行设置检索分数线。

## 学习工作台的信息层级

桌面保留左侧导航与右侧内容框架，侧栏约 220—240px，顶栏约 56—64px。顶栏只显示当前位置和“本地研发版”；学习操作放对应内容附近。顶部不再重复头像、学习记录或多个大按钮。

主要操作为学习路线、课程学习、项目工坊、学习记录。现有路线/教材/项目/复盘可按产品确定的映射进入，不凭新名称伪造新的题库、同步账户或记录功能。若主导航映射还未冻结，至少让“学习工作台”和“课程目录”直接可见，其余原功能放“更多工具”完整可达。原 `standards`、`curriculum`、`creation`、`product-review`、`sources`、`generation` 及历史阅读/测验不删除、不改权限。更多工具是可展开的明确文字入口，不是只有图标的隐藏菜单。

工作台第一屏内容顺序：

| 位置 | 内容 | 操作 |
| --- | --- | --- |
| 页首 | “Agent 开发者”及简短学习说明 | 不用总完成率、掌握率、职业等级进度条 |
| 起点行 | 当前用户选择的基础，或“尚未选择学习起点” | 沿用真实档案编辑入口；零基础可进入第2篇诊断；不自动猜用户基础 |
| 阅读入口 | “从认识 Agent 工程开始”，或有真实阅读记录时“继续上次阅读” | 前者进入第1篇；后者只在实际存在对应版本/位置时出现 |
| 路线 / 目录切换 | 相同 20 篇的两种浏览方式 | 切换不改变章节顺序、记录、进度或检索上下文 |
| 工程全景 | 实际全景图预览、简短说明和“查看工程全景与章节位置” | 可放大或进入开篇对应小节；预览不能替代开篇完整图；全景不是每个产品必须配齐的部件清单 |
| 常驻输入 | 统一“找教材”入口 | 只在主动提交后检索 |

“学习路线”使用 v10 开篇已有六个学习阶段和所属篇，不将工程全景分组偷换成正式先修。每阶段一行或一张浅色区块，显示阶段名称、应产物、其真实章节链接。阶段从上到下；无需制作缩放画布才能阅读。原先修提示通过真实教材数据保留，缺基础时给补学入口，不锁住浏览。

“课程目录”显示 01—20、导航短名和实际 H1。长 H1允许自然换行；章节编号不用内部模块 ID 替代。当前章同时以文字“当前阅读”与背景表示。章下小节可展开，由实际 Markdown 标题生成，不制造与正文不一致的知识点层级。无需搜问题也能到达全部篇章。

## 章节阅读

桌面章目录宽 220—250px，正文优先，宽屏才额外显示精简的“本章小节”；空间不足时小节收成正文上方的可展开列表，不挤压正文到窄栏。主体宽 680—760px，使用连续段落，而非每段一张卡片。章题就是实际 H1，短名仅作目录导航。

页首依次为返回课程目录、章序号与实际标题、简短教材身份，再进入原文。身份可以为“教材 v0.10 · AI 作者草稿；真人专家审核与真实学习效果待验证”。不在每段重复作者、hash和审核记录；在“教材说明”中提供当前版本、来源文件、独立审校范围与历史验证说明。不能把旧验证冒充当前行为实跑。

正文须完整呈现段落、各级标题、列表、引用、代码、表格、原文链接和两张教学图。原有参考分析、练习和边界说明按正文位置保留，不凭前端重组改变教学内容。网页不执行教材代码；没有接入的测试、答案生成或作品评估不提供假按钮。

上/下一篇按 v10 阅读顺序跳转。来源中的本地章链接进入相应篇或小节；稳定推荐链接进入实际目标标题，不能只到章首后称“已定位小节”。目标缺失时显示“这处教材位置暂不可用，可打开本章”，保留原查询与章入口，不自动找相似标题代替。

### 教学图与表格

运行闭环与工程全景消费 v10 已交 PNG/SVG，图名、图例及说明相邻。正文内图宽不超过内容列，保持纵横比。工程全景缩略后标签可能较小，所以每图提供明确的“放大查看”；放大应显示原图，并保留可关闭/返回控制。可选择可访问图片对话框或直接打开安全本地 SVG，依据工程现有组件确定，不要求另造交互绘图。

放大图不能成为唯一章节导航，开篇原 20行对应表全部保留链接。图在手机作为全貌预览，同时提供放大和正文对应表；不要裁去侧边反馈线或末端箭头。表格、长代码在独立容器横向滚动，正文与整页不能产生横向溢出。

## 内容检索助手

### 单输入与上下文

沿用原型“底部一个输入”的意图。本轮不复制原型语音、微信、外网资料或模拟头像。收起态是一条可聚焦输入或打开输入的按钮，包含清楚标签“找教材”；无第二个页面内自然语言输入。展开态标题“找对应教材”，右侧“收起”，底部仍使用同一个输入状态。示例问题是可点击填入的短语，不自动提交。

工作台示例可为“我是零基础，先从哪里开始”“程序已经写好，怎么判断效果有没有变好”。章阅读示例可为“工具超时后，怎样避免重复创建工单”。示例只提供表达方式，不暗示每次都应得到某个固定答案。

输入有可见标签，不只靠 placeholder。旁边展示“学习起点：已有编程基础 / 未选择”“结合当前章：检索证据”等真实上下文及清除操作；传入当前小节时也显示其标题。清除当前章后显示“在全部 20篇中查找”，同时清除其小节条件；清除起点是此查询取消起点条件，不悄悄修改持久档案。用户显式提出新问题时优先对应新问题，不能用当前章压过表达。用户改表达时保存新输入；字面、上下文和服务解释的任务意图分别展示，不能把解释当用户确认。

提交后出现“正在当前教材中查找…”，只在实际 pending 时显示。收起后保留阅读与请求；结果返回时用轻量状态“推荐已就绪”或“需要补充一个信息”，不自动弹开、不抢焦点、不移到新章。快速连续提交由工程协议处理，界面只展示归属于当前请求的结果；结果头保留查询短文本，必要时展开全文。

### 推荐卡

结果区标题“推荐阅读”。下方先显示服务返回的简短意图解释，例如“你想解决工具超时后的重复写入风险”；明确为检索判断，不称“我已完全理解”。多意图按意图分组，例如“中断恢复”和“任务成本”各有自己的卡片，不能拼成不存在的小节。明确排除方向可简短显示“这次不推荐：模型接入”，不能仍作为主结果；先修补充标“起步建议 / 目标预览”，不挤掉核心意图。卡片按服务合法结果顺序显示，每意图最多3项、总最多6项，设计不擅自设最低分或补齐数量。

| 卡片字段 | 展示方式 |
| --- | --- |
| 教材位置 | “第12篇 · 持久恢复”，再展示实际小节标题；原H1可在出处处完整查看 |
| 推荐理由 | 一至两句，解释任务概念怎样与该节对应；不给通用赞语，不推断用户能力 |
| 原文摘录 | 服务返回、可对照的原文，清楚标“教材原文”；保留意思与上下文；代码长块不塞进默认卡片 |
| 来源身份 | “Agent 工程教材 v0.10”；旁边“查看出处”展开真实文件、小节及hash，内部路径不是主标题 |
| 行动 | “阅读这一节”，点击进入稳定位置并收起助手；查询和结果保留，回开可继续找 |

卡片使用白底、细边框、绿色主操作，不画虚假星级/命中率。摘录无需截取成三行的不可展开省略；若服务片段较长，默认约四至六行并有“展开原文摘录”。理由是匹配解释，摘录是教材事实，两者排版分开。不得把摘要伪装为原文，或把置信数值变成学习者看到的正确概率。

点击卡片前不导航，不写已学习/掌握标记。正文定位后在小节标题附近显示轻量“从内容推荐进入”，随后可自然阅读；不长时间用亮色背景覆盖正文。点击仅产生产品授权的阅读历史时，也应只记阅读事实，不推导职业能力。

### 澄清、无匹配与异常

| 状态 | 正文与操作 | 保留状态 |
| --- | --- | --- |
| 未提交 | 短提示、2—3个填入示例 | 阅读不受阻，空输入不发送 |
| 正在查找 | “正在当前教材中查找…”及收起；若协议支持取消则展示取消 | 原输入可见，当前阅读仍可继续 |
| 需澄清 | 单一具体问题，例如“你想了解资料查找，还是工具执行后的结果核对？”；按服务返回互斥按钮，也可修改表达 | 选项显式作为补充提交；不能替用户选择；不混入当作已确定的推荐 |
| 无匹配 | “当前 Agent 教材没有找到足够对应内容。”；说明覆盖当前 v10 20篇，允许修改表达或打开课程目录 | 不声称行业没有答案，不硬推荐一堆薄弱相关章节 |
| 空白/超长输入 | 靠近输入说明实际约束 | 原输入保留，聚焦输入，不弹学习失败提示 |
| 本地检索服务不可用 | “暂时无法检索。你仍可通过课程目录阅读。”；重试和课程目录 | 不用旧结果伪装新成功，不切到另一版本 |
| 目标章节/锚点不可用 | 明确位置不可用，提供真实章入口 | 保留查询、出处和对应结果，交QA复现 |

页面可显示模式说明“本地教材意图检索（未调用大模型）”。技术追踪信息集中于结果“来源说明”，保留实际数据版本和hash；正文不显示 JSON、token、索引ID、代理内部状态或日志。若后续真正更换语义模型，标签必须由对应实现与验证决定，不能仅替换文案。

客户端与检索岗位暂定推荐链接为 `#learn/agent/<unitId>/<sectionId>`。该形式是实现交接，不在主界面展示；工程两岗需统一解析、标题锚点和刷新恢复后冻结，不能前端自行剥去小节或另取相似目标。索引加载失败必须保持 `unavailable`，不把空 results 直接认定 `no_match`；版本/sourceHash不匹配时不给“最新可用”身份。

## 视觉、移动与键盘

使用现有 `--green:#21734e`、`--ink:#1d2d2a`、纸色背景和白底细边框，沿用站点字体及系统中文fallback。不为此任务增加外部字体依赖。说明文字建议不浅于 `#53675e`；当前过浅的灰绿不承担唯一状态。底部助手有细边/轻阴影，与正文区分，不使用发光效果或营销装饰。

桌面内容页边距约24—32px，正文17px，行高1.85；正文标题28px，小节标题21px、次级18px。卡片与导航文字14—16px，重要操作触控区至少44px，出处辅文不少于13px。色彩之外用“当前阅读”“需澄清”等文字状态。

900px 以下主导航改成有中文名称的顶部入口，不只留图标；更多工具可展开。阅读章节目录/本章小节折叠，不横滑20张卡找章节。手机320px宽的内容内边距16px，单列；底部输入旁只保留发送/收起所需操作，上下文自然换行。助手展开为可滚动底部面板，最多约70dvh，避免将正文永远遮住。收起态预留约80px加安全区，末尾分页/下载/来源不被盖住；软键盘出现后输入和发送仍可见。

辅助助手是非阻断面板，不铺全屏暗色遮罩迫使停止阅读；展开后仍可收起。键盘焦点可以进出面板，Esc收起并返回打开控件；若采用真正模态图片放大，则仅图片对话框使用焦点圈定与关闭后返回。结果返回只用 `role=status` / `aria-live=polite` 提示，不抢焦点；输入错误用可见关联文字。

提交使用显式“查找”按钮。若工程支持Enter快捷键，必须排除中文输入法组合期间的Enter；多行框Shift+Enter换行。查询状态忙碌时防止重复提交，不禁用收起和课程导航。所有目录、卡片、来源展开、图放大与关闭均能用Tab/Enter/Space操作。路由到新章聚焦H1，小节跳转聚焦目标H2/H3，焦点圈清楚可见；浏览器后退恢复原章/小节，不自动回到首页。

## 领域自查与独立检查交接
