# P01｜Agent 与普通模型调用有什么区别？

答案版本：interview-answers-v1.0.0。完整参考解析；构造示例与计划不代表已执行或真实经历。

Agent与一次普通模型调用的主要差别是控制过程：模型调用对给定输入产生一次候选；Agent系统围绕目标保存状态，依据新观察选择后续动作，经过宿主准入后与环境交互，再用观察判断继续、等待或完成。模型仍是其中一个组件，不因多次调用就自动具备Agent意义上的动态决策。

用故障工单说明。若文件、失败报告和规则都已给齐，一次模型调用足以提出有引用的说明，应用再校验。若第一份日志只说“依赖加载失败”，下一步可能查版本锁，也可能查注册模块；模型根据刚读到的证据改变调查对象，形成“观察→提议→准入→执行→新观察”的反馈链。读取范围、预算、准确批准和是否已产生工单仍由宿主程序掌握，不能让模型自己宣布有权限。

一个完整教学轨迹是：用户要求定位构建失败并形成草稿→读取获准报告，看到依赖版本异常→提议查lock文件→宿主核项目/修订与预算后读取→新证据显示版本一致但注册路径不符→改查注册代码→证据仍缺业务说明时停在待补证；证据够时生成标注事实/假设的候选。若后续获准创建工单，写工具只接受准确批准并保存稳定动作身份，超时先核对而非重写。

反例是脚本固定运行三轮“总结—润色—翻译”，不论观察内容都走同样路径；它可以是有用工作流，却没有展示观察驱动的路径选择。固定流程也可以有条件分支、重试和人工等待，因此“有循环”“有工具”“跑很久”均不能单独定义动态Agent。

工程取舍应从缺失能力出发。确定字段和公式用普通程序；材料齐全的一次归纳可用单次模型；稳定步骤与可枚举分支先用工作流；下一步资料/动作必须依语义观察变化且收益能验证时，再增加动态路径。动态性带来错误路径、恢复、费用和评测复杂度，多Agent也不是必要配置。

完成必须由任务合同判定：所需主张有证据、产物符合要求、必要效果已核实且无未决动作。模型说“完成”只是提议；超预算、缺证和无权限是不同停止原因，不应涂成成功。验证时用相同任务给出会改变调查方向的两种观察，看后续是否合理调整；再给无解材料，要求正确等待，固定程序基线用同样资料和预算比较。本稿只给构造轨迹，未证明某实际Agent有效。

## 原追问与延伸

**什么情况下不用 Agent 反而更合适？**

固定规则、输入已齐或步骤可枚举时，普通程序、单次模型或固定工作流通常更省复杂度；以相同任务结果和总成本比较后选择。

**如何判断 Agent 的任务已经完成？**

用独立任务验收核证据、产物、授权和必要业务效果；缺证、等待批准或效果未知都不等于已完成。
