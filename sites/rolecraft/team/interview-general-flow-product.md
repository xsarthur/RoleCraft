# 通用面试流程教练产品交接 v0.1

责任岗位：产品经理  
日期：2026-10-15（Asia/Shanghai）  
状态：范围与验收合同；待课程架构、设计、客户端、AI 生成和测试岗位交接

## 目标

在现有“题目 → 口述回答 → 转写确认 → AI 教练反馈 → 重答”之外，为用户提供一条可以反复练习的通用面试流程。它帮助用户理解每个环节要完成的沟通任务，给出可执行的准备方法，并让用户用自己的经历练习，而不是背一份脱离岗位和经历的固定话术。

本功能的核心闭环是：

```text
选择面试情境 → 了解流程 → 练习当前环节 → 语音或文字回答 → 核对转写/内容 → 获得有依据的建议 → 重答或进入下一环节 → 面试后复盘
```

它是面试准备和表达训练工具，不是招聘方、面试通过率预测器或职业能力认证。通用建议、岗位教材和用户自己的事实必须在界面上分开标记。

## 用户进入与情境设置

从“面试准备”首页进入“通用流程教练”。在开始练习前，用户可以填写：

- 目标岗位和职业方向；
- 面试轮次：电话/筛选、技术、项目/行为、系统设计、终面或未知；
- 面试预计时长；
- 已知的面试方角色（招聘、直属经理、技术面试官、未知）；
- 用户希望重点练习的环节。

未知项可以跳过。系统只能根据已填写信息调整建议，不得把推测的公司流程写成事实。进入后展示一条六阶段时间线，允许用户查看顺序、跳过、返回和暂停；完成某一阶段不等于真实面试通过。

## 六阶段产品范围

### 1. 开场与自我介绍

**用户要完成的任务**：在约 60–120 秒内，让面试方知道“我是谁、做过什么与岗位相关的事、产生过什么可核验结果、为什么此时讨论这个岗位”。

建议卡必须给出目的、结构、示例、常见失误和练习动作：

1. **定位**：当前角色/专业方向，以及与目标岗位最相关的能力范围；
2. **证据**：一至两个相关项目或经历，说明问题、本人负责部分、关键取舍和结果；
3. **匹配**：把证据连接到本岗位要解决的问题；
4. **动机与过渡**：说明此次机会想进一步解决的工作问题，并邀请面试方进入具体项目。

建议使用真实事实、范围、指标或验证方式；没有指标时明确说明可观察结果和限制。系统应提示用户删掉与岗位无关的履历罗列、空泛形容词、未经证实的“行业领先”和背诵式长稿。

练习结果至少反馈：是否完成定位/证据/匹配/过渡，是否超过目标时长，哪些句子缺少本人行动或结果。不能根据口音、性别、情绪或声音特征推断适配度。

### 2. 理解问题与澄清

**用户要完成的任务**：在回答前确认问题的对象、范围、约束和成功标准，避免回答了另一个问题。

教练引导用户按以下顺序练习：

- 用一句话复述问题；
- 识别题型（概念、项目、行为、设计、排障等）；
- 询问一至三个会改变方案的关键条件；
- 说出准备采用的假设，并在假设不成立时说明如何调整；
- 得到足够信息后开始回答，而不是无限追问。

系统要展示“有帮助的澄清”和“不会改变答案的追问”对比。未知信息不能被系统补成事实；用户选择继续时，要在反馈中保留该假设。

### 3. 结构化回答

**用户要完成的任务**：根据题型组织答案，使面试方能听见结论、依据、取舍和边界。

系统不强制所有题目使用同一模板，而是按题型提供可切换骨架：

| 题型 | 推荐骨架 | 必须练到的证据 |
| --- | --- | --- |
| 概念/原理 | 先给定义 → 机制 → 适用边界 → 小例子 | 术语准确、边界清楚 |
| 项目/行为 | 背景/目标 → 本人行动 → 取舍与协作 → 结果 → 复盘 | 本人贡献、证据、失败或限制 |
| 系统设计 | 需求与约束 → 方案 → 关键组件 → 可靠性/安全/成本 → 验证 | 为什么选它、替代方案、风险 |
| 排障/场景 | 现象与影响 → 假设 → 观测/实验 → 修复 → 防复发 | 诊断顺序、证据、回滚或监控 |

每种骨架都要提供短回答版、展开版和“时间不足时先说什么”。反馈先引用用户说出的内容，再指出缺失的结构要素，最后只给少量下一步动作；不得以字数、语速或模板命中率替代技术判断。

### 4. 处理追问与不同意见

**用户要完成的任务**：在被追问、质疑或要求具体化时保持回答连贯，承认未知并用证据推进。

教练提供分支练习，例如：

- 面试方要求给出刚才结论的依据；
- 面试方改变约束（规模、延迟、预算、权限）；
- 面试方指出一个可能的反例；
- 用户没有真实经历或不知道精确数字；
- 面试方让用户比较两个方案。

推荐回应顺序为：直接回应 → 明确假设/不确定性 → 给证据或验证办法 → 根据新约束修正取舍。系统不得教用户掩盖不知道的内容、编造经历或把不同意见当作敌意。

### 5. 向面试方提问

**用户要完成的任务**：用问题了解工作是否适合自己，同时展示对目标和约束的认真思考。

在面试准备末尾和真实面试结束前提供问题卡，按目的分组并允许用户改写：

- **成功标准**：入职后 30/60/90 天最重要的成果是什么？团队如何判断做得好？
- **当前问题**：团队目前最希望改善的技术或业务问题是什么？现有方案的主要限制在哪里？
- **协作与决策**：这个岗位如何与产品、数据、安全或运营协作？重要取舍由谁参与？
- **学习与反馈**：新人通常如何获得代码、设计或项目反馈？哪些能力最需要在前几个月补齐？
- **岗位边界与后续**：这个岗位当前不负责什么？接下来的面试环节和时间安排是什么？

系统必须说明适用时机和追问方式：先根据前面谈到的内容提出一个具体问题，再选择一个长期工作方式问题。问题应能帮助用户作出双向判断，不能只给“聪明问题”清单。关于薪酬、福利、远程政策等问题不应被禁止，但应提示用户结合轮次、公开信息和双方语境安排；系统不得替用户判断某个问题一定会导致拒绝。

### 6. 结束与面试后复盘

**用户要完成的任务**：清楚结束对话，确认后续安排，并把本次经验转成下一次可执行的改进。

结束练习包含：

- 用一句话复述自己与岗位的相关点；
- 表达感谢，并提出一个经过前文铺垫的最后问题；
- 确认后续步骤、联系人和预期时间（若面试方未提供，不自行猜测）；
- 记录自己实际被问到的问题、使用的假设、未答好的部分和需要补证据的项目；
- 生成下一次练习动作，例如重录自我介绍、补一个项目指标或练一个改变约束的追问。

复盘只记录可观察的练习证据。它不输出“你适合/不适合该公司”“面试一定失败”等结论，也不把一次演示反馈写成长期能力等级。

## 语音教练的连接方式

每个阶段都可以选择“口述练习”或“文字练习”。口述沿用语音原型的状态合同：`ready → recording → transcript → analyzing → feedback → retry`。真实版本中必须先让用户核对转写，再分析；权限、分析模式、来源绑定和不确定性始终可见。

阶段反馈至少区分三层：

1. **流程观察**：是否完成了当前阶段的沟通任务；
2. **内容观察**：是否出现题目所需的机制、证据、取舍或边界；
3. **表达观察**：可从转写/音频直接观察的时长、重复、停顿或填充词。

反馈顺序固定为“引用观察 → 说明影响 → 给一个重答动作 → 提供下一步追问”。无转写、低置信、来源失配或分析服务不可用时，系统只能保留可用信息并明确降级，不得伪装成完成了 AI 分析。

## 建议质量标准

通用流程建议要达到当前答案质量底线：对一个建议同时说明**要解决的问题、为什么重要、如何做、一个具体例子、何时不适用、如何练习和如何核对**。不同职业、面试轮次和用户经历可以改变例子和优先级，但不能把通用启发式写成硬性规则。

每条系统建议至少带有以下身份信息：

- `adviceType`：通用流程 / 岗位领域 / 题目内容 / 用户事实；
- `sourceStatus`：已绑定教材、通用建议、用户提供或未验证；
- `applicableContext`：适用轮次、题型和前置假设；
- `uncertainty[]`：缺失信息、争议或待用户确认项；
- `nextAction`：用户下一步能在本次练习中完成的动作。

不允许的输出包括：替用户编造经历、成果或数字；以面试官/公司内部消息口吻声称未知流程；根据声音、口音、性别、情绪或人格推断录用结果；没有来源时虚构“行业标准”；把模板命中、字数、完成题数或 AI 自评当作职业胜任证明。

## 交接与待办

- 课程架构师：把六阶段与现有课程/面试题能力映射，标出哪些建议需要职业领域证据。
- 设计师：先交六阶段时间线、自我介绍、提问卡、复盘卡和降级状态的视觉稿；文字只补充必要操作和无障碍说明。
- 软件工程师：消费本合同，实现入口、阶段状态、练习记录和语音原型连接，不自行编写新教材答案。
- AI 生成工程师：定义转写/分析接口、来源绑定、失败和异步恢复；缺配置时保持诚实降级。
- 后端数据工程师：设计可删除的练习尝试、复盘和权限数据，不迁移或覆盖历史用户记录。
- 测试工程师：按 GIF-01–12 独立验证，并单独报告内容准确性、来源证据、可访问性、真实语音能力和用户效果。

产品自查：本文件只新增产品范围、建议合同和验收条件，未写应用代码、教材正文或测试结论；未授权付费模型调用、上传音频、外部联系或发布。完整产品仍需按当前八门槛复盘，不能因流程建议完成而自动达标。
