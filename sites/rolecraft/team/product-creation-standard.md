# 产品经理交付：从学习到创造产品

日期：2026-10-10；需求与标准草案，不是测试通过报告。

## 双目标与闭环

同时培养生产级 Agent 应用工程能力及从 0 到 1 创造有竞争力产品的能力。路线围绕“问题与用户证据 → 现有方案及基线 → 差异化假设 → MVP → 测试和用户验证 → 成本运营 → 迭代复验”。每阶段须有产物、证据和进入下一阶段的条件，课程架构师定义教学内容。

基线覆盖现有行业产品、研究及专业评审；记录来源、日期、版本、任务、样本、约束和指标。比较前确定目标阈值，以相同任务、资源与评分方法实测。招聘标准仅为能力参考，不能代替竞争基线；没有可比证据不得宣称行业先进。网站帮助创造与验证，不自动授予创新、竞争力或录用保证。

## 本网站正式系统的八项必需门槛

1. 用户价值：目标人群和问题有实际用户证据，并达到事先定义的验证阈值。
2. 教学质量：能力—章节—练习—作品关联完整，覆盖与深度经内容核对及专业复核。
3. 真实生成：模型按档案生成教材，主要论断有可追溯来源，示例验证及生成失败状态真实。
4. 可比优势：选定行业产品与研究基线，在相同条件下有差异化指标实测及专业评审。
5. 创造能力：学习者实际产出 MVP，经测试、目标用户验证和独立作品评审，达到预定评分条件。
6. 可靠交付：持久化、权限隔离、异常恢复与版本记录经独立验证；展示原型不能代替生产功能。
7. 成本运营：记录真实成本、耗时、质量及维护机制，并满足预定资源预算。
8. 持续复盘：每次产出绑定版本、门槛、实际证据、差距、原因、责任人、下一步与复验条件及结果。

任一必需项失败即“未达标”；无失败但证据缺失为“证据不足”；全部通过才可“在明确范围内达标”，不算平均分。先进性必须另有可比实证。现有静态原型缺少真实生成和正式运行验证，正式系统未达标。

## 本轮实施与交接

静态版新增 0→1 路线、产品达标复盘页。支持提交产品目标、产物版本、基线来源及比较条件、逐项实测证据和上述复盘字段，保存多条、编辑、刷新恢复和导出；缺少基线或证据不得自评通过。

自评结论单独标注；独立 QA 审计结论与专业评审状态另栏展示，只读取带范围、版本、证据及审计人的真实交付，用户编辑不能改变审计。区分“本轮静态功能验收”和“正式系统”，前者通过不覆盖后者失败。

课程提供路线结构与能力证据；设计表达两种范围及证据状态；工程消费 product-gates.json 并实现记录；测试验证失败优先、缺证、全项通过及保存导出，复核审计不能被自评改写。真实生成、用户实测、运行与专家流程继续列为未完成项。
