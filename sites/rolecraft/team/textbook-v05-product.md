# 教材重生成 v0.5 · 产品范围与验收交接

日期：2026-10-10。责任岗位：产品经理，仅产品需求。本文件冻结本轮范围，既不是教材正文，也不是测试通过报告。网站建议版本为 `local-mvp-0.5-textbook`；教材独立版本由课程架构师冻结。继续沿用 `product-creation-2026-10-10`、`product-gates.json` 原八项必需门槛及失败优先规则，不改门槛ID、原标准、既定量规或旧审计报告。

## 目标与明确范围

用户要求“根据上面的资料再次生成教材”。本轮交付面向 Agent 开发者的十二模块完整作者草稿，并在现有本地网站提供单章与全书阅读。培养目标同时包含专业工程能力，以及真实问题、行业基线、差异化假设、实现、可比评估、真实使用反馈和迭代构成的从0到1产品创造路线。不能只以岗位招聘要求编排课程。

升级原十二模块：`f01` 编程、HTTP与软件测试；`f02` 模型调用与上下文基础；`c01` 工作流、Agent循环与方案选择；`c02` 资料治理、检索与有据回答；`c03` 工具契约与业务动作；`e01` 状态、检查点与失败恢复；`e02` 评估集、追踪与回归；`e03` 安全边界与对抗输入；`e04` 部署、可观测性与运行维护；`e05` 性能、成本与规模取舍；`p01` 业务理解、技术协作与文档；`p02` 综合作品、答辩与复盘。保留原模块ID、学习记录身份及旧版本产物，不把已完成旧版模块自动解释为掌握新正文。

“完整作者草稿”指十二模块均有按既有九段式教学结构编写的实质正文、案例、分层练习、参考解析、验证方式与来源状态；目录、占位文本、短摘要或机械重复模板不算完成正文。它不等于完整教材质量获专业确认，也不等于学员职业胜任。

## 编写与证据约束

1. 领航教材作为目标—知识点—题目映射、情景题解析、误区、迁移和复验组织方式的参考；课程架构师记录实际阅读的文件及版本，教材研发员按新规格整合。参考内容须明确来源，不宣称领航已整体技术、人类专业或教学审核通过，不自动继承其结论。
2. 采用分阶段生产交接：能力与章节规格 → 资料及论断清单 → 作者正文 → 案例、分层练习与解析 → 独立审校 → 可执行案例验证 → 返修与阅读接入。来源不足、先修冲突或未核验论断进入问题单，不补造资料。跨章术语、案例设定、先修和评价由课程架构师统一。
3. 按既有模板与量规服务零基础、已有开发基础和进阶读者。先修缺口应有诊断及补学指引；练习从脚手架、独立任务到未知场景迁移。沿用原0—3量规及适用维度至少2分、安全关键不得失败的待行业校准规则，不增加“读完即可认证”的门槛。
4. 每章关键论断关联资料位置、版本或访问日期、支持范围和未知项；原创教学设计另行标识。完整案例给出环境、依赖、输入、预期输出、正常/边界/失败验证方法。只有实际执行并留存证据的项目才能标为已运行；伪代码、离线模拟、预期结果与真实模型/系统实测分别表达。
5. 本轮数字员工编写标为 AI 作者草稿。不得包装成网站依据账户档案执行了真实供应商生成，不虚构供应商、模型、调用ID、费用、真实学员、用户或专家。新稿不能继承旧版独立审校、运行或专业结论；作者自查、独立AI内容审校、案例执行、人类行业专业审核、学习效果分别绑定新教材版本。

## 阅读接入验收条件

- 从现有 Agent 教材入口能访问十二模块新正文；支持单章完整阅读和按顺序阅读全书。原模块目录、路线、练习、作品及复盘仍可到达。阅读正文及来源、案例、练习和参考解析不能只显示摘要。
- 清楚展示本次教材版本、作者草稿身份及实际证据状态。缺少人类专业审核或学习效果数据时显示未完成，不得使用“行业先进教材”“专家认证”“已验证学习效果”作完成标识。
- 保留旧教材/审计历史，明确当前与历史版本，不把历史审核复制给新稿。任何当前审计须匹配当前网站与教材版本；尚无本版独立审计时显示未独立审核。
- 保护现有旧学习记录和自评：不主动清空、自动迁移或覆盖用户数据；原模块ID继续可关联。新正文阅读不改变用户原进度、作品、档案、凭据或独立评审身份。是否阅读不直接推导能力得分。
- 现有 `#generation` 的 e03受控输入、接口及数据库产物保持原冻结版本与契约。升级静态作者教材不静默覆盖模型生成输入，不将新正文注入私有账户，不触发收费供应商调用。真实生成仍依原安全配置和实际授权预算。
- 原本地账户、会话、任务、提交、导出、取消/重试以及版本追踪不被教材阅读更改；客户端独立验证受影响路径。正文按不可信内容处理，来源链接与代码显示不得形成脚本执行或凭据泄露。

本轮不新增证书、职业胜任自动认定、付费模型运行、动态资料检索、代码沙箱、公开部署或生产运维承诺。未完成的完整系统目标继续保留。

## 岗位交接

课程架构师交十二模块冻结规格、先修与能力覆盖、统一九段式、既有量规、来源/参考使用说明及作者结构契约；教材研发员只按其规格编正文并交作者自查、版本和未验证清单；内容审校员独立检查论断依据、衔接、练习/解析和证据身份，出具体问题单，返修由作者处理；工程师负责阅读消费、版本/记录保护及实现自检；QA独立检查内容交接完整性、受影响功能、证据状态、当前报告版本绑定并提交当次产品审计。案例实际执行交相应工程责任人与独立测试，不由内容审校员以阅读代替执行。项目经理串联问题、责任和复验，不能代作者或测试员执行。
