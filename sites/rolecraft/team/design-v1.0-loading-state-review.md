# Rolecraft 1.0 请求等待状态视觉与交互复核

设计师；2026-10-16（Asia/Shanghai）。本记录只读核对当前设计合同、客户端静态资源和已部署公网静态资源，没有修改客户端、教材、数据、服务或历史验收记录。

## 结论

用户反馈“请求等待时没有加载交互”与当前可见版本一致。工作区中的客户端已经有新的等待稿，但 `http://111.231.8.78` 返回的仍是旧版 `learning-workbench.js/.css`，因此用户实际看到的远程版本没有新的加载视觉。

本地静态实现满足等待状态的大部分设计意图：提交后显示“正在查找教材依据”、旋转标记和不确定进度条，查询按钮变为“正在查询…”并禁用；保留输入和阅读位置，允许收起，成功、无匹配、澄清和失败各有独立状态。远程资源仍只有静态“…”和旧文案，发送按钮没有新的禁用/忙碌表达，CSS 也没有新的 spinner/进度条规则。

因此本轮 UI/UX 等待状态不能验收通过，状态为 `not_met_remote_binding`。问题责任是客户端版本同步与部署缓存，随后由 QA 重新做真实浏览器视觉、键盘和读屏复验。当前没有把本地源码证据当成远程运行通过证据。

## 设计合同对照

设计标准 `design-v1.0-learning-workbench.md` 的检索状态合同要求：

- 检索中使用进度形状和“正在查找教材依据”；保留当前阅读，可收起继续读，不自动夺焦点，并防止同一请求重复提交。
- 等待、无匹配、澄清和失败分别用 `role=status` 或 `role=alert` 及短文本播报；颜色只能辅助表达。
- 发送按钮、输入、收起和结果在窄屏与软键盘出现时仍可见、可聚焦；迟到响应不得覆盖新问题。

这对应 `DV1-RET`、`DV1-A11Y-02`、`DV1-A11Y-03`、`DV1-RWD-03` 和 `DV1-RWD-05`。这些条款要求运行版本证据，静态文件存在不能代替浏览器操作记录。

## 证据

### 工作区候选

- `dist/learning-workbench.js` SHA256：`8f3c434d9c6ab0daf02d2de69660922d1f04422dd5917528f8cc6bce0c34ceb9`。
- `dist/learning-workbench.css` SHA256：`1a53e9fc115513b04404fa9656b626c9945efc483e36f5da30beb36e65b63c52`。
- JS 第 663 行的 `pending` 分支包含 `role="status" aria-live="polite"`、`正在查找教材依据`、旋转标记和不确定进度条。
- JS 第 689、693–694 行在等待期间显示“正在理解问题并查教材。请稍候，发送控件已暂时禁用”，并给发送按钮设置 `disabled`、`aria-disabled="true"`、`aria-busy="true"`；表单和结果容器也标记忙碌。
- JS 第 733 行对相同问题和相同上下文的未完成请求直接返回；第 736–738 行为每次请求分配新请求 ID、取消旧控制器并先渲染等待状态；第 759 行之后只接受当前请求 ID 的结果。这些是源码层面的防重复和迟到保护。
- CSS 第 21 行及其后定义 `lw-query-spinner`、`lw-query-indeterminate`、`lw-query-submit-spinner` 和 reduced-motion 处理，说明等待是有视觉动作的设计稿，而不是只有文字。

### 公网实际资源

- `http://111.231.8.78/learning-workbench.js` 返回 SHA256：`2086c9ae26ee158e1bf4c89a296513b24b9173fb65a098bf03f9cd27c065668e`，与工作区候选不同。
- 远程 JS 的等待分支仍是静态“…”和旧文案“保留当前阅读位置；你可以收起抽屉继续学习，结果返回后会保留在这里”，未包含工作区的 `lw-query-spinner`、`lw-query-indeterminate`、`正在查询…` 或禁用按钮。
- `http://111.231.8.78/learning-workbench.css` 返回 SHA256：`b35eaef44e73a56e2b1df0985fdfe8c960393ca086ffecaeba96b51bf798336c`；可见 `lw-state-loading` 和 `lw-state-mark`，但没有工作区候选的 spinner、进度条和查询按钮样式。
- 远程静态资源响应包含 `Cache-Control: public, max-age=3600`。在同名 JS/CSS 直接覆盖而不更改缓存策略时，用户可能继续拿到旧文件，即使服务器文件已经更新。

### 当前入口限制

用户当前打开的是 `file:///.../dist/index.html#learn`。客户端在 `find()` 设置 `pending` 后，会在同一请求流程检查 `location.protocol === 'file:'` 并立即转为“静态阅读入口不可用”错误；请求过快或立即失败时浏览器可能来不及绘制中间等待帧。这只能解释静态入口的观感，不能代替远程 HTTP 版本验收。真实等待必须在 HTTP 服务上用受控延迟或慢网络复验。

## 交接和复验条件

1. 客户端软件工程师与部署责任人把工作区候选 JS/CSS 与其 hash 同步到远程；保留 HTML 的版本身份，禁止只重启服务而不更新静态资源。
2. 为静态资源使用版本化 URL、发布清单或明确的短缓存/重新验证策略，确认普通刷新和新标签页都取得同一 hash；不能要求用户手工清理缓存作为验收条件。
3. 测试工程师在公网 HTTP 版本注入可控 1–2 秒响应延迟（只用于测试环境/测试请求），记录 1280、390、375、320px 下：提交前、等待中、成功、无匹配、失败、收起后返回结果六个状态的截图与 DOM/AX 属性。受控延迟用于让等待态可观察，不代表生产接口应人为变慢。
4. 键盘/读屏复验：发送按钮在等待期间不可重复提交且有可理解名称；输入仍保留；状态通过一个简短 `aria-live` 播报；收起不夺焦点，迟到结果不滚动阅读页或覆盖新问题；`prefers-reduced-motion` 下仍有非动画文本和边界表达。
5. 远程复验通过后，QA 将本报告的 `remote_binding`、`DV1-A11Y` 和 `DV1-RWD` 结果绑定到具体部署 hash；产品经理再决定是否关闭本轮等待交互缺口。当前不能以本地源码、旧 VM 夹具或 HTTP 200 代替上述证据。

责任人：客户端软件工程师（客户端候选和静态资源）、部署协调/项目经理（同步与缓存策略）、测试工程师（真实浏览器独立复验）、设计师（视觉和交互复核）。
